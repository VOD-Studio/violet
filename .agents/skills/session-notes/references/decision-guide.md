# 分诊、拆条与脱敏参考

仅在 `SKILL.md` 指定的边界不清时读取对应小节。

## 功能级

同时满足：功能完整落地、已有行为验证、存在可复用的设计或实现链路。完整不等于值得写文章。

正例：

- 完成文章系列的领域模型、接口、管理端和端到端验证，可解释完整跨层链路。
- 将审计事件从聚合根接到 EventBus、订阅者和持久化，并验证真实审计记录。
- 完成长文目录的新状态模型、动画实现和浏览器验收，包含非显然设计决策。

反例：

- 只修改按钮文案、CSS 间距或一个自解释配置值。
- 只搭建结构，关键路径未实现或未验证。
- 常规依赖升级没有迁移问题或可复用结论。

## 经验级

必须包含未来可复用的明确坑、根因、修法或工程教训。

正例：

- GORM 字段权限同时影响 struct 保存和 map 更新，特定聚合保存时需显式 `Omit` 外域列。
- React 委托事件无法由不冒泡的 `mouseenter` 触发，自动化应派发冒泡的 `mouseover`。
- 删除已应用的迁移文件前必须执行 down，否则迁移器无法构造版本链。

反例：

- “重启后好了。”没有根因或复用动作。
- “可能是缓存问题。”未经验证。
- 已有同主题笔记，本次没有新增边界、事实或修法。

## 琐碎或重复

即使内容真实也不沉淀。价值不明确时按此处理。

正例（应丢弃）：

- 变量从 `result` 改名为 `data`。
- 运行 formatter、查询配置值或记录临时端口。
- 重复执行已有修法，结果与原笔记完全相同。

反例（不可误判）：

- 一行修复背后定位出框架的非显然边界行为。
- 常规命令失败后发现项目特有的环境约束。
- 旧问题出现新触发条件，可更新原笔记。

## 拆条

按独立检索主题和失效边界拆分，不按文件数量拆分。

正例：

- 将“GORM map Updates 受字段权限限制”和“跨聚合保存应排除外域列”拆为两条；二者可独立检索。
- 将“代理内核死亡的诊断步骤”和“错误映射不得吞掉下游 EOF”拆开；一个是运维诊断，一个是代码规则。
- 同一故障的现象、根因、修法和验证保持一条，避免丢失因果。

反例：

- 一条笔记同时记录路由、数据库、视觉偏好和部署流程。
- 把同一因果链拆成三个没有上下文的碎片。
- 仅因涉及三个文件就拆成三条笔记。

## 意图测试

补全：“未来遇到 **触发场景** 时，这条笔记会帮助我 **做出动作或判断**。”两处都无法具体回答则丢弃。

正例：

- 未来删除已应用迁移时，帮助我先回滚数据库再切换工作树。
- 未来 React 悬停自动化失效时，帮助我选择可冒泡的事件。
- 未来容器仍为 running 但下游 EOF 时，帮助我检查容器内实际监听进程。

反例：

- 未来需要时，帮助我知道今天做了什么。
- 记录“终于修好了”的情绪。
- 记录“当前完成 80%”的临时状态。

## 语义脱敏

保留组件角色、因果和可复用步骤；移除真实标识。机械扫描 `clean` 不代表语义安全。

应脱敏：

- `ssh root@prod-01.internal` → `连接生产服务器`。
- `/Users/alice/company/private-service` → `本地项目目录` 或仓库相对路径。
- 真实客户邮箱、订单数量和内部实例名 → `测试用户`、`某次真实业务流量`、`生产数据库实例`。

无需因语义而脱敏：

- 公开仓库中的相对路径，如 `web/src/features/posts/`。
- 框架名、标准协议、错误类型和无法映射真实系统的虚构示例。
- `example.com` 这类保留示例域名；但若脚本因同一文本中的 IP 或凭证命中，仍必须降级处理。

错误做法：

- 只用 `***` 遮住密码，却保留真实用户名、主机和端口。
- 保留 token 前后各四位用于辨认。
- 脱敏成“某处有问题”，使知识失去技术意义；此时应只存草稿并标注待人工处理。

## 扫描脚本自测期望

命中用例均应逐条输出 `行号: 模式名: 命中片段`、片段不超过 60 字符并退出 `1`：

1. `server=192.168.10.2` → `ip_literal`。
2. `https://alice:pass1234@example.com/path` → `url_cred`。
3. `api_key = super-secret-value` → `secret_assign`。
4. `token: violet_pat_abcdefghijklmnop` → `secret_assign` 与 `known_prefix`。
5. `-----BEGIN OPENSSH PRIVATE KEY-----` → `private_key`。
6. `ssh -p 29888 root@example.com` → `ssh_endpoint`。
7. `ssh deploy@example.com` → `ssh_endpoint`。
8. `postgresql://user:pass@db.example.com/app` → `dsn`，也应命中 `url_cred`。
9. `AWS_ACCESS_KEY_ID=AKIAABCDEFGHIJKLMNOP` → `known_prefix`。
10. `xoxb-1234567890-secretvalue` → `known_prefix`。

清洁用例应只输出 `clean` 并退出 `0`：

- `修复后通过 make web-typecheck，并在浏览器验证交互。`
- `应用通过环境变量提供 PostgreSQL 连接信息。`

脚本没有白名单；示例文本也不享受豁免。
