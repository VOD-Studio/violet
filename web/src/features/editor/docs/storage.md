# 存储与有损

文章保存时的双写边界、旧数据修复指引与暂不支持清单。编辑器为 Tiptap 富文本，保存时双写 `content_html`（展示权威源）与 `content_md`（Markdown 源，降级展示/导出用，有损）。

## 双写与格式边界

- **源码直接保存**：源码输入实时同步文档，保存草稿或导出 `.md` 无需先切回富文本；源码模式导出保留当前输入的引用式链接等写法。
- **content_html 是展示权威源**：下划线、文字颜色、高亮颜色、对齐这些 Markdown 表达不了的样式只存在这里，文章页始终正确。
- **content_md 仍有格式边界**：文字颜色、下划线等无原生 Markdown 表达的样式可能丢失。普通表格保留管道符转义、行内代码和列对齐；合并单元格、列宽等以 HTML 表格载体保留，不能强行降为普通 Markdown 表格。
- 脚注、公式、任务勾选状态、高亮、图块和可运行代码源码可在编辑、保存与重新打开之间往返。脚注定义保留源码顺序，显示编号按首次引用顺序更新。
- 正文上下标、提示块与折叠内容可在编辑器、API 转换和两条阅读链路之间往返。若脚注引用位于必须保留的 HTML 载体内部，Markdown 导出会保留整篇 HTML，避免 HTML 引用与 Markdown 定义使用不同 ID；普通脚注仍导出 `[^label]`。这不会替换已有文章的 `content_html`。
- 编辑器使用 marked 的围栏解析规则，支持反引号或波浪号围栏；可运行围栏接受 `run` / `runnable` 与带空格的 JSON 资源参数。普通代码中的 `$...$`、`==...==` 和围栏示例不会被当作正文公式或高亮。
- 已知 `content_md`（包括版本预览）按 Markdown 解析，允许白名单内的原生 HTML 混排；`content_html` 仍直接走安全 HTML 阅读链路。公式、Mermaid、可运行代码、任务列表、高亮、提示块与折叠内容共用阅读组件，链接锚点与脚注回链留在当前页。任意脚本、事件属性和危险链接不在允许范围内。

## 可运行代码块的载体

可运行标记写入围栏 info string：`<lang> runnable {<ResourceLimits JSON>}`（如 `python runnable {"timeout_secs":10}`）。HTML 载体为带属性的 `<pre data-runnable="true" data-lang="python" data-overrides="{...}" data-source="原始源码">`，`data-source` 携带 HTML 转义后的原始源码供阅读器无损提取（避免反解高亮 HTML）。

## 旧文章脚注仍显示源码时

解析器升级不会重写已经保存的 `content_html`。若正文仍显示 `[^note]`，先检查原始 `content_md` 是否保留对应的 `[^note]: 正文`，以及 HTML 是否已经把两者存成普通段落；直接打开旧 HTML 再保存不会自动恢复脚注。

修复按文章逐条进行：

1. 备份原始 Markdown、HTML 和可编辑元数据，确认脚注定义完整且不是代码示例。
2. 用当前转换器从原始 Markdown 生成候选 HTML，在预览中检查引用编号、定义正文及每个回链目标。
3. 对照旧 HTML，确认脚注以外的正文、标题锚点、链接、表格、公式和图块未变。若 HTML 另含颜色、对齐、合并单元格等独有格式，不能直接用整篇 Markdown 转换结果覆盖。
4. 仅更新核验过的文章，保留原始 Markdown 与元数据；通过 MCP 更新时须显式保留标题、slug、摘要、封面、标签、转载来源和签名设置。当前 MCP 不能无损保留非空 SEO 字段或精选标记，这类文章应使用能保留这些字段的编辑入口。
5. 回读保存结果，打开公开页面实测引用与回链，并确认代码示例中的脚注标记仍为文字。

不要全站批量清空 HTML 强制降级，也不要在阅读时重新解析 HTML 段落里的所有 Markdown 标记；两者都会绕过作者已经保存的内容语义。

## 暂不支持

- 学术文献引用与书目管理：不解析 `[@citekey]`，未接入 BibTeX、CSL 或自动参考文献列表；普通引用式链接和脚注不等同于这项能力。
- Wiki 链接、定义列表（`术语` / `: 定义`）与缩略词声明（`*[HTML]: …`）尚未作为专用语法接入。
