# 正文公式（及未来图块）采用浏览时渲染
Status: accepted（2026-07-21）；决策 4（双态编辑）已被 ADR-0005 取代为弹层编辑

## 背景

文章双列存储：`content_md`（Markdown 源）与 `content_html`（展示权威源，由前端编辑器产出，后端不渲染 Markdown）。接入数学公式（及后续流程图等图块）时必须决定：KaTeX HTML / 图 SVG 在保存时烘焙进 `content_html`，还是浏览时再渲染。

调研锚点：GitHub 走服务端烘焙，但那是服务端渲染架构；本项目是「前端产 HTML + SPA 展示」架构。Notion / GitLab / Obsidian Publish 均为浏览时渲染。Typora / Obsidian / Notion 的编辑交互收敛于「选区感知双态」：未选中显示渲染结果，选中显示源码 + 实时预览。

## 决策

1. **`content_html` 只存语义化标记**：公式存 `<span data-type="inline-math" data-latex="...">` / `<div data-type="block-math" data-latex="...">`，最终形态（KaTeX HTML / 未来图 SVG）在读者浏览器渲染，保存时不烘焙。
2. **编辑器与阅读端共用同一渲染核心**（`shared/ui/katex`）与物理宏表，保证「写作所见 = 发布所渲染」。
3. **化学式走 mhchem**（`\ce{}` / `\pu{}`）；**物理宏包命令经共享宏表模拟**（`\dv` `\ket` 等；`\div` 不覆写，散度用 `\divg`）。
4. **编辑交互为双态编辑**（覆写官方 NodeView），不用弹窗。
5. **图块（Diagram Block）预留同模型**：通用 `format` 属性节点 + 围栏块 Markdown 载体 + 浏览时渲染 + 渲染器注册表 + 双态编辑。本期仅公式。

## 理由

- **体积**：KaTeX 烘焙 HTML 一个公式数百个 span，Mermaid SVG 数十 KB；语义标记仅一行。
- **主题**：浏览时渲染可跟随站点明暗主题（图尤为关键），烘焙则主题写死。
- **源文本保留**：可搜索、可复制、可再编辑；升级渲染器（KaTeX/Mermaid 版本）不迁移存量文章。
- 与「前端产 HTML + SPA 展示」架构自洽。

## 代价

- 阅读端需加载 KaTeX（未来 Mermaid）：以懒加载缓解，仅含公式的文章页拉取，CSS/字体随异步 chunk 拆分。
- 无 JS 环境只见源文本：可接受的降级（latex 源码本身可读）。

## 已否决

- **保存时烘焙**：体积膨胀、主题写死、源文本丢失、升级渲染器需刷存量文章。
- **弹窗编辑公式**：滚动容器裁剪、焦点管理、撤销栈同步的边缘 case 多；双态编辑内联无此问题。
- **自动折叠 `\\` → `\`**：`\\` 是合法 LaTeX 换行命令（矩阵、多行对齐），折叠会破坏合法公式；源内容双写反斜杠属数据问题，应在数据层解决。
