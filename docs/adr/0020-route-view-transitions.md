# 前台页面转场只用淡入淡出与共享元素变形

前台路由切换统一使用 View Transition，形态只有两种：默认的**错峰淡入淡出**（旧页快速淡出、新页稍后淡入，避免半透明的双重曝光），以及在其上叠加的**共享元素 morph**（列表卡片封面与详情封面、推文头像与主页头像等有真实空间对应关系的元素）。页面转场不使用位移与缩放。

转场规则是一张「例外清单」：后台、实验页与文档站内部不做转场，其余导航默认淡入淡出，所以新页面不需要登记就有转场。共享元素通过点击时登记的**意图**（元素种类、实体 id、有效路由范围）触发：只有意图匹配的元素才带 `view-transition-name`，导航离开范围时意图被清除，浏览器后退时意图仍在，因此返回列表会反向 morph。Header 与公告条单独命名并保持静止，页面动画只作用于 root 的视口快照，长页面不会因快照过大而卡顿。

拒绝的方案：沿用按 URL 首段推断前进或后退的整页翻页动画——它依赖手写的导航顺序，新页面不在表里就没有动画，而且普通页面切换没有明确的空间来源，与「方向性运动只表达真实空间关系」的约束冲突；给 `main` 命名整页元素做转场——长文章的元素快照会占用大量内存；让各 feature 各自持有共享元素状态——转场名必须全页唯一，分散管理容易重名，一次重名会让整次转场失败。

代价是共享元素的接入需要两端成对放置并在来源链接上登记意图，同一实体在来源页重复出现时还要用实例或退出机制避免重名；接入步骤见 [页面转场指南](../guides/view-transitions.md)。
