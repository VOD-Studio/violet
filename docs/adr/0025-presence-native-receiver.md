# 站点自己实现 Nowbeam 接收端，状态只在内存

Nowbeam 客户端通过 `nowbeam.v1` WebSocket 协议把站长允许分享的前台应用、窗口标题与媒体快照推给接收端。Violet 在 API 内直接实现接收端（`/api/v1/presence/ingest`），不部署 Nowbeam 独立接收服务再轮询它的 presence 接口。理由：客户端直连站点，少一个需要备份、升级和单独做 TLS 的服务；设备授权复用后台 RBAC 与审计，不另持一套所有者凭证；状态变化可以直接经 SSE 推给访客，不受轮询间隔影响。

代价是要在本仓库维护协议状态机（连接接管、序号与重复 ACK、45 秒租约、严格 JSON 解码、关闭码）。实现按 Nowbeam 独立接收服务移植，测试覆盖同一组场景；协议升级到 `nowbeam.v2` 时需要同步改这里。

活动快照只放在 API 进程内存，不落库、不进 Redis：协议要求不保留历史、服务重启不恢复旧活动，内存正好满足。这也意味着 API 必须单实例运行——多实例时上报连接与访客推送可能落在不同进程。横向扩展前要先把注册表换成共享状态。

设备凭证只存 SHA-256 哈希；公开读取默认关闭，与设备是否上报无关。术语见 `CONTEXT.md`「实时状态」，接入步骤见 [Nowbeam 接入指南](../guides/nowbeam.md)。
