# 聊天采用扁平引用回复模型

Status: accepted

聊天引用回复作为普通不可变消息上的可选引用关系，而不是新的消息类型或独立线程。消息只能引用同一会话内当前可见且未删除的文本/图片消息；引用回复可再次被引用，但界面只展示一层预览，原消息删除后不得通过引用快照泄露内容。

## Considered Options

- **引用元数据**：发送请求携带目标消息 ID，读模型动态返回紧凑的 `reply_to` 预览。采用此方案，保持现有 `text`/`image` payload 约束，并让软删除状态在所有客户端一致生效。
- **完整引用快照**：否决。快照会保留被删除内容，并在多客户端之间产生不一致。
- **独立线程或 `reply` 消息类型**：否决。会引入线程导航、嵌套展示、未读与实时事件的新语义，超出当前集中式聊天边界。

## Consequences

- API 在现有消息发送资源上增加可选 `reply_to_id`；消息读模型返回动态生成的 `reply_to`，文本预览最多 120 个 Unicode 字符，图片使用缩略图。
- `chat_messages.reply_to_id` 使用可空自引用并在物理删除目标时 `ON DELETE SET NULL`；软删除目标显示“消息已删除”，物理清理目标后引用块消失，回复消息保留。
- 引用不改变未读、普通通知和 `message.created` 事件语义；事件仅增加可选目标 ID，完整预览仍由消息查询提供。
- 前端在消息气泡中展示可点击引用块，目标未加载时复用 cursor 历史分页定位；引用选择状态限于当前会话，发送失败保留、发送成功清除。
- 本期不支持系统事件引用、文字片段引用、仅引用发送、跨会话引用、特殊引用通知或线程面板。
