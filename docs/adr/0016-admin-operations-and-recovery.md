# 后台运维授权与恢复边界

Status: accepted（PRD-0027 设计决策，待实施）

站长已明确选择在后台提供读写 SQL 与 DDL，并要求设置、运行日志、系统诊断和备份恢复完整落地。保留既有操作审计与 opaque session；新增运维能力不以普通设置权限授权，不通过 MCP 或通用远程 Shell 暴露。

## 决策

- 运行日志与操作审计分开。运行日志允许有界异步写入、实时读取和保留期轮转；审计保留追加语义。高危 SQL 与恢复的控制记录另保存在被操作业务库之外，避免一次恢复抹去该操作本身。
- 查询、导出、DML、DDL、备份管理和恢复分别授权。高危动作还需要绑定当前会话与操作类别的短时验证。数据库角色和连接预算独立于业务池；SQL 分类提示不能替代真实数据库权限，不向操作者授予宿主机程序执行或超级用户能力。
- 备份采用原生数据库归档与有明确范围的配套素材包，缺少工具直接失败，不回退为仅数据 SQL 冒充完整备份。自动来源记录在备份身份中，不从文件名前缀推断。
- 完整备份以短暂暂停业务写换取数据库与可变素材的一致性。恢复由独立维护执行进程完成，控制状态不依赖目标业务库；恢复前保存当前状态，失败维持维护窗口，核对数据库和素材后才重新开放。
- 自动物理清理必须先建立全站素材引用和可见候选预览，默认关闭。SQL 写入与 DDL、素材及回收站自动永久删除，均在恢复演练通过后交付。

## 取舍

只读 SQL 的暴露面更小，但不满足已确认的维护需求；通用数据库超级用户或 Docker Shell 则超出业务数据库维护范围。原始 SQL 仍能绕过领域用例和破坏业务不变量，授权、备份和审计不能消除这种风险，界面不得宣称写入后能自动修复任意数据。

仅备份数据库无法恢复已丢失的本地素材；只按文件名或校验和判断导入包可信，也无法防止归档携带可执行数据库对象。因此采用显式备份集、受信来源和隔离恢复演练。代价是完整备份存在短暂写入维护窗口，并需要独立备份存储和维护执行进程；本轮不承诺零停机或异地容灾。
