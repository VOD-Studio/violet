# 主题颜色由种子色算法生成

现有色板逐值手写，明暗各调一套，没有对比度约束：coral 主按钮文字在浅色下只有 3.80:1，中性色色相写死为紫色，每个色板只提供 6 个主色变量，组件只能自行 `color-mix` 或写裸色值。改为主题 = 种子色 + 旋钮，全部颜色由自研的零依赖 TS 包（`@violetjs/*`）生成。算法在 OKLCH 中为品牌、中性、状态色与分类色各生成 12 档色阶（档位分工沿用 Radix Colors），每档以对背景的目标对比度定义并反解亮度（Adobe Leonardo 的思路），超出 sRGB 时按 CSS Color 4 的映射只降色度；品牌与中性另生成透明度色阶。中性色跟随品牌色相，状态色与分类色色相固定。算法是不依赖 Node 的纯函数：构建时生成预设主题的静态 CSS，SSR 时为自定义主题现算。

对比度门槛要求文字与控件组合同时通过 WCAG 2.2 AA 与 APCA。WCAG 2 是现行规范，但在深色区间预测失真；APCA 区分极性、深色更准，但 2026-09 的 WCAG 3 草案仍未确定对比度算法，参考实现的许可证也限定于网页无障碍与非商业用途。因此运行时求解只用 WCAG 2 比值与 OKLab 亮度差，APCA 只在测试中用官方 `apca-w3` 遍历全部色相与色度验证；站点若转为商业用途，删除这组测试即可，产品代码不变。系统开启 `prefers-contrast: more` 时整体上调目标值。种子色过不了门槛时，只调整实色档的亮度。

组件与页面只使用语义 token，沿用 shadcn 命名，色阶不注册为 Tailwind 工具类。保留 public / tool / immersive 三种方言，方言只负责把语义 token 映射到色阶档位，不再重复写色值；工具方言的主要动作仍为高对比中性色。站点专用色取消：neon 拆为分类色与装饰，paper 已无消费方，直接删除，persona 收回人设页局部。

外观与主题分开，代码中指明暗的 `theme`（cookie、切换器）改名为 appearance。首批预设主题为春夏秋冬，默认跟随季节，按站点时区 Asia/Shanghai 的月份判定，保证 SSR 与水合一致。自定义主题只开放种子色，但主题数据带版本号，旋钮是可扩展字段。装饰套件是与主题并列的独立偏好，经装饰插槽投放；`@violet/ui` 只暴露 CSS 钩子，不依赖任何主题。偏好暂时只存版本化 Cookie，账号同步延后。

本 ADR 取代 ADR-0015 中「暖珊瑚为默认强调色」「由用户种子派生 hover、薄雾、焦点环」与配色方案持久化的表述；ADR-0015 的视觉方言边界、主题切换器水合规则与样式文件分层继续有效。

拒绝的方案：
- 继续手写色板：每加一个主题都要手调数十个值，也无法保证自定义种子达标。
- Material HCT：色调差能保证 WCAG 比值，但要引入 CAM16、另算 APCA，风格也偏 Material。
- Radix 模板混合：观感成熟，但对任意种子没有硬保证。
- 运行时调用 APCA：产品代码会受其许可证约束。
- 以「配色方案 / color scheme」命名主题：与 CSS 中指明暗的 `color-scheme` 冲突。
- 同时生成 P3 值：收益只在高饱和实色，却让每个主题的生成与验证翻倍，所以只把目标色域保留为参数。

代价是现有的 `primary-base`、neon、paper 类名，以及 205 处 `color-mix`、215 处裸色值都需要迁移；迁移期间用基线模式的颜色守门（存量白名单只减不增）阻止新增漂移。四季种子色、切换入口与装饰内容留到设计样稿阶段确定。
