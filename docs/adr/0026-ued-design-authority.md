# 以 UED 设计稿为准，少数组件以项目为准

站点视觉与交互以归档的 UED 设计稿（`docs/design/ued/`）为准。与已采纳的 ADR 或术语表冲突时设计稿优先，由新 ADR 逐项取代（见 ADR-0027、ADR-0028）。设计稿是一次整站改版；本轮只做地基（token、字体、纸面）、组件展示页与组件。12 个前台页、19 个后台页与站点结构重组（路由改名、301 迁移）各自独立立项。

项目为准组件：灯箱（图片预览）、链接卡片、react-tweet 外站推文嵌入、代码块。它们保持现有结构与行为，只换新 token；设计稿对它们多出的内容（链接卡的日期、↗ 箭头、图片失败退链接图标等）不采纳。灯箱的遮罩属于材质，跟随设计稿：浅色下 90% 纸色加 20px 背景模糊，不用黑色，深色下自动变深。代码块的设计稿尚缺可编辑态，补齐后只读展示、运行与编辑按新设计一起重做，在此之前整体保持现状。

设计稿内部有两处自相矛盾，裁决如下。加载：块状等待（通常 32px 及以上）用当季花形，控件内加载用细圆弧，「状态·加载」写的“只用圆弧”按此修正。动效：「基础」页的 180/120ms 与“只动颜色、透明度、描线、裁切，不缩放，不做方向滑入”只是默认值，组件设计稿明文规定的时长与位移以组件稿为准，AGENTS.md 的动效约束同步改写。

默认字体由 Maple Mono 改为宋体：Noto Serif SC 沿用现有 jsdelivr `@font-face` 的做法按 unicode-range 分片加载，首屏关键字重 preload；Maple Mono 只留给等宽与品牌场景。

组件展示页取代 `/ui` 的组件库文档，旧站整体删除，不迁移。路由仍为 `/ui`；是否迁入“项目 · violet · 文档”随站点结构重组另行决定。

对设计稿的有意偏离：导航药丸里聊天成为一级入口，登录后才显示，项目收进「更多」（设计稿的六个一级入口不含聊天，聊天在「更多」里）。聊天同时是铃铛面板的一个标签，铃铛角标是通知与聊天未读之和，右药丸不再有独立聊天图标。公告浮条在多条公告时淡入淡出轮换，设计稿只画了一条。实时状态的封面与应用图标在采集协议提供数据前显示占位，不隐藏。头像组在指针悬停时展开压叠，设计稿没有设计这一交互，沿用站点既有行为。日期范围触发器中间，设计稿是「至」字，按产品负责人的要求改为自绘的区间符号（一条细线两端各一道短竖，按图标规范的 24 网格、1.75 线宽、16px 绘制），并比正中略偏左。
消息面板里「全部标为已读」只在通知标签出现（设计稿在两个标签都画了它，聊天没有批量已读）；通知的未读依通知稿：文字加深加粗、右侧危险色圆点，不填底色（面板稿的通知行是左侧季节色小点、同样没有底色，两稿不一致时取通知稿）；聊天行用未读数徽标表达未读，不另加圆点；新聊天消息的轻提示只淡入淡出、不做位移，设计稿没有给出动效；公告通知点开落到公告详情页。

文章与推文评论按产品负责人确认共用多表情回应，补齐推文评论后端，不新增独立赞按钮；旧稿固定「赞，6」改为表情名、真实人数与 `aria-pressed`。作者皇冠与头像环使用季节装饰语义色，不固定金色。回复会话与状态以 #745、#753 为准，不恢复旧稿的两条折叠，也不覆盖新状态规格。

## 代码块补齐后的落实

`1793923319-b913` 已补齐代码块的页内编辑、Vim 与执行输出设计。[T42 / #735](https://github.com/VOD-Studio/violet/issues/735) 据此结束上文“整体保持现状”的临时安排：只读、运行与读者编辑统一使用 `@violet/ui` 的 code-block 单元，真实 CodeMirror / Vim 内核与语义配色同包交付，执行策略和请求留给宿主。作者编辑器仍使用 Tiptap，复用外壳样式与输出组件，并保留文件名和作者标行载体。
