# 宠物服务与 Violet 的身份、活动与授权契约
Status: proposed（#522 的评审输出，待确认标注为「待决定」的条目）

## 背景

PRD-0036 要求宠物服务独立于 Violet API 与数据库。两者之间只剩三条通道：谁在操作（身份）、发生了什么（活动事实）、普通用户如何在 CLI 上授权。本文盘点 Violet 目前能提供什么，定义这三条通道的契约，并列出 Violet 必须补齐的通用能力。以下事实均来自 2026-10-13 对 `release/2.0` 代码的核对，未核对处已标明。

## Violet 现有事实盘点

| 行为 | Violet 现状 | 能否直接作为宠物活动来源 |
|---|---|---|
| 有效阅读 | 只有匿名累计的 `view_count`（`UPDATE … SET view_count = view_count + 1`），前端没有停留或进度信号，也没有账号维度记录。 | **不能。** 浏览计数不含账号、不可去重。需要新建账号级阅读资格。 |
| 发布文章 | `post.published` 事件。聚合内 `Publish()` 在状态变为 published 时记录，**归档或退回草稿后再发布会再次触发**。事件只带标题快照，不带作者与操作人。`authorID` 创建后不变；持有 `post:publish` 权限者可以发布他人文章，所以操作人不一定是作者。 | 可用，但消费方必须以文章 ID 去重而非事件 ID，且需另行查询作者。转载（`canonical_url` 非空）是否算合格见「待决定」。 |
| 推文点赞 | `tweet.liked` 事件，带 `AuthorID` 与 `ActorID`。仅当发布时刻查到尚未点赞才触发；**取消后再点赞会再次触发**；`IsLiked` 与 `Like` 非原子，并发下可能重复。 | 可用，资格身份必须是（点赞者，推文）。 |
| 文章点赞 | 不存在。 | 不可用。PRD 已规定不为本需求顺手新建。 |
| 文章评论 | `comment.approved`（人工审核制，创建即 pending）。事件**不带评论者、文章与作者**，只有评论 ID 与 `Auto` 标志。评论者 `userID` 可为空（访客评论），评论带 `isAI` 标志。 | 需要按评论 ID 回查权威记录。合格条件至少应是：已通过、登录用户、非 AI。 |
| 推文评论 | `tweet.commented` 事件，带推文作者、评论者、评论 ID、被回复作者。其余字段未逐项核对。 | 可用，同样以评论 ID 为资格身份。 |
| 收到互动 | 由上述事件的作者字段推出（`TweetLiked.AuthorID`、`TweetCommented.TweetAuthorID`）；文章评论需回查。 | 只影响情绪与纪念，不直接发资源（PRD）。 |

**事件总线不能保证送达。** `EventBus` 当前是进程内同步实现：handler 依次串行执行，失败只记录日志，不重试、不持久化；进程在提交之后、分发之前退出，事件就丢失。因此「订阅事件」只能作为低延迟优化，**不能作为事实来源**。

**账号标识会失效。** 登录态是 opaque session cookie（ADR-0003），Violet 没有签发身份断言的密钥，也不是 OAuth 提供方；GitHub 与 Google 只是登录来源。PRD-0033 的账号合并会在单事务内迁移约 30 张表，被合并账号的用户 ID 随之消失；PRD-0034 的注销是软删除，邮箱与用户名会被释放可重新注册，用户 ID 本身保留。

## 决策

### 1. 身份：由 Violet 签发短期身份断言，宠物服务自建凭据

- 主体由 `(issuer, subject)` 标识。`issuer` 是接入方站点的稳定标识，`subject` 是该站点的用户 ID（UUID）。不使用邮箱或用户名。
- Violet 新增**通用的身份断言签发能力**（不属于宠物模块）：用已登录的 session 换取一枚短期签名断言，字段为 `iss`、`sub`、`aud`（目标服务）、`exp`（不超过 5 分钟）、`jti`。公钥以 JWKS 形式公开，支持密钥轮换。
- 宠物服务只信任它配置的发行者公钥，校验断言后签发**自己的**访问凭据（短期访问令牌加可轮换的刷新令牌）。之后的请求只使用宠物服务凭据，不再回到 Violet。
- 这与 ADR-0003 不冲突：断言不是登录态，不进入浏览器 cookie，只用于向第三方服务证明身份。需要在实现该能力的 PR 中补充对 ADR-0003 的说明。

### 2. 普通用户的 CLI 授权：设备授权流程

CLI 使用 RFC 8628 设备授权流程：

1. CLI 向宠物服务申请设备码，得到用户码与验证地址。
2. 用户在已登录 Violet 的浏览器打开验证页并确认；Violet 页面向宠物服务提交该用户的身份断言。
3. CLI 轮询取得宠物服务的访问令牌与刷新令牌，存入系统钥匙串。

明确**不使用**：管理员 MCP PAT（`violet_pat_…`，其 scope 是为 MCP 服务器设计的）、复制浏览器 cookie、客户端自报 owner。

### 3. 活动契约

Violet 侧的连接器把可信事实转成下面的事件送给宠物服务。事件只证明「来源声称发生了」，是否合格、是否发奖、是否超出上限由宠物服务裁决，**不接受客户端或连接器指定经验或余额**。

| 字段 | 含义 |
|---|---|
| `source` | 连接器标识，宠物服务据此选择验签密钥。 |
| `event_id` | 来源内唯一的事件身份，用于幂等重放。 |
| `eligibility_id` | 业务资格身份，同一资格只结算一次。形如 `post.publish:<postId>`、`tweet.like:<tweetId>:<actorId>`、`comment:<commentId>`。**去重以它为准，不以 `event_id` 为准。** |
| `subject` | 行为人。 |
| `owner` | 作品或内容的所有者，仅在需要时出现（发布奖励的对象，或「收到互动」的接收者）。 |
| `action` | `read`、`publish`、`like`、`comment`、`received_like`、`received_comment`。 |
| `content_ref` | 内容引用：`kind` 与 `id`。不携带正文。 |
| `occurred_at` | RFC 3339。 |
| `topics` | 接入方映射后的主题标签，**在资格形成时固定**；之后改标签不改变已发奖励。 |
| `signature` | 来源签名，只证明发送者身份，不证明内容有效。 |

宠物服务的响应只表示是否已持久收件（已接受、重复并返回原结果、被拒绝），奖励结算异步进行。可区分的错误：`invalid_signature`、`unknown_source`、`subject_unknown`、`ineligible`、`rate_limited`、`request_conflict`（同一 `event_id` 换了内容）。

### 4. 送达与对账：以权威记录对账，事件只做加速

内容平台提交与宠物结算是两个事务，不宣称跨库原子。连接器采用两条腿：

- **加速**：订阅现有领域事件，提交后尽快送出。
- **对账（兜底，必须有）**：按游标定期扫描权威表（文章的发布时间、推文点赞、评论审核状态），补送缺失的事实。宠物服务按 `eligibility_id` 去重，重复送达无害。

宠物服务故障或不可达时，原站的阅读、发布与评论照常成功；连接器自行重试，不阻塞业务请求。

### 5. 账号生命周期

身份契约必须覆盖主体变化，否则会出现宠物挂在已不存在的 subject 上：

- **账号合并**（PRD-0033）：Violet 在合并事务提交后向宠物服务发送 `subject.merged`（旧 subject 到新 subject）。两个账号都有宠物时的处理见「待决定」。
- **账号注销**（PRD-0034）：发送 `subject.deleted`。宠物进入纪念状态、不再接受照料与收益，不删除出生记录与纪念。恢复账号时发送 `subject.restored`。

## 必须在 Violet 补齐的通用能力

这些能力是平台通用的，不夹带宠物业务逻辑，各自独立提交：

1. **身份断言签发与 JWKS**，以及设备授权的确认页。
2. **账号级有效阅读资格**：前台停留、进度与去重的记录，带可核验的内容身份。
3. **可对账的事实读取**：文章发布、推文点赞、评论审核的游标查询（只读，服务凭据鉴权）。
4. **账号合并与注销的生命周期通知**。
5. 发布事件补充作者标识，或提供按文章 ID 查询作者的权威接口。

## 待决定

| 编号 | 问题 | 建议 |
|---|---|---|
| D-1 | 账号合并时两个账号都有宠物，如何处理？ | 保留主账号（primary）的宠物，被合并账号的宠物转为纪念并保留出生记录；不合并库存。 |
| D-2 | 账号注销后宠物是否保留？ | 进入纪念状态，恢复账号时可恢复照料。 |
| D-3 | 转载文章（`canonical_url` 非空）是否算合格发布？ | 不算，避免搬运换奖励。 |
| D-4 | AI 标记（`isAI`）的评论是否算合格评论？ | 不算；评论者不是真人行为。 |
| D-5 | 访客（`userID` 为空）评论是否计奖？ | 不计，宠物只与账号绑定。 |
| D-6 | 有效阅读的阈值（停留时长与滚动进度）。 | 交由 #519 数值评审，契约只要求「可核验的资格」。 |

## 后果

- 宠物服务可以只依赖本契约开发，不读取 Violet 的任何表。
- Violet 需要新增身份断言、阅读资格、可对账读取三项通用能力，工作量与风险都集中在这里，应作为 #528 的前置子任务单独排期。
- 对账腿要求连接器保存游标并容忍重复，增加少量运维面，换来不依赖事件总线可靠性的送达保证。
- 本文未涉及：宠物服务内部的奖励数值与上限（#519）、出生协议（#518）。
