# 站内聊天采用集中式私域边界

Status: accepted（2026-08-20）

## 背景

Violet 需要让现有登录用户互相发送文本和图片，并在离线时保留消息、产生未读提醒。需求使用“类似 Matrix”的体验描述，但没有要求跨服务器互通或接入 Matrix 客户端。

如果直接按 Matrix 完整语义建设，协议兼容、联邦、端到端加密、设备密钥与群组密钥管理会把站内聊天扩大为独立通信基础设施。它们还会改变消息搜索、审核、通知预览和账号恢复的边界。

## 决策

第一版采用 **Violet 集中式私域聊天**：

- 参与者复用现有登录 User，不另建聊天账号。
- 支持一对一私聊与私有多人房间；房间通过邀请加入，不提供公开可搜索房间。
- 消息由 Violet 持久化，支持文本消息与图片消息、历史记录、未读计数、离线后的多设备同步。
- 浏览器通知支持页面后台提醒与关闭页面后的 Web Push；通知预览由用户设置控制，会话可单独静音。
- 第一版不承诺 Matrix 协议兼容、跨服务器联邦或端到端加密。

## 理由

1. 集中式边界复用现有 User、opaque session 和站内媒体能力，能直接满足“几个登录账号互相聊天”的目标。
2. 私有房间覆盖小范围群聊，同时避开公开房间需要的发现、审核、反垃圾和举报体系。
3. 持久化消息与 Web Push 是聊天通知和离线体验的核心；它们比协议互操作更直接地服务本次需求。
4. 明确不承诺 Matrix 语义，避免用户误以为消息可被外部 Matrix 客户端读取或具备端到端加密。

## 代价

- 消息内容由服务端承载，第一版不能提供端到端加密的服务器不可读保证。
- 未来若需要联邦、外部客户端或端到端加密，需重新评估消息模型、设备身份、密钥生命周期和通知预览，不应在现有模型上隐式追加。
- Web Push 需要浏览器权限、Service Worker 和推送订阅生命周期管理。

## 否决的替代方案

- **直接实现 Matrix 协议/联邦**：超出站内聊天目标，并引入协议、设备和密钥管理成本，否决。
- **第一版实现端到端加密**：会改变服务端检索、审核、备份、通知预览和账号恢复边界，当前需求未要求，否决。
- **只做在线转发**：无法满足聊天历史、未读数和离线通知，否决。
