# 主题配色与视觉方言边界

Violet 采用一套共享视觉基因、三种视觉方言，而不是把首页布局和配色直接覆盖到所有界面。公开内容语言强继承首页；后台、编辑器、设置、个人中心与聊天使用高密度工具语言；灯箱和媒体查看器使用中性沉浸语言。`/lab/*` 保持实验豁免，不参与正式一致性验收，也不能反向改写全站 token。

主题接口把外观模式（`system / light / dark`）与配色方案分开。暖珊瑚是当前默认强调色；后续官方预设与用户自定义方案仍遵守“一界面一个品牌强调色”。用户只可提供强调色种子，系统负责派生 hover、薄雾、焦点环和强调前景，并校验对比度。画布、正文、表面层级以及 destructive、warning、success 等行为语义色保持受控，不能被自定义配色改写。

共享控件保留一套接口，不复制公开版和后台版。公开内容与登录入口的主要动作使用品牌强调色；工具语言的主要动作使用高对比中性色，品牌强调色只承担焦点、选中、当前导航、链接和进度。行为状态色在所有方言中保持固定含义。

匿名偏好写入版本化 Cookie，供 SSR 首帧读取。登录用户的偏好同时写入账号与 Cookie；账号已有偏好时账号优先，账号尚无偏好时把当前匿名选择升级为账号偏好。两者都不存在时使用站点默认方案，`system` 外观再由操作系统解析实际明暗。

`web/src/styles.css` 只保留为全局导入入口。theme 映射、基础 token、配色适配、视觉方言与页面转场拆到 `web/src/styles/`；组件专属样式就近放 `*.module.css`。运行时富文本等必须使用全局选择器的规则由对应 feature 持有，不回流到全局杂项文件。

否决三种方案：全站先套首页再堆局部覆盖会形成级联债务；公开与后台各复制一套控件会让状态和无障碍行为分叉；开放完整 token 编辑会让可读性与状态含义失去系统保证。
