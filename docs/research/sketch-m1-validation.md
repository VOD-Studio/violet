# 手绘绘图库 0.2.0 验收记录

日期：2026-10-09。规格：[PRD-0035 规格](../prd/0035-手绘绘图库M1规格.md)。对象：`web/packages/sketch` 0.2.0（M1 手法与填充，以及随同交付的 M2 压感与笔、M3 卡通风格与整图时间轴）。

## 结论

- **自动验收通过**：35 项行为测试、类型检查、构建、tarball 隔离消费与确定性复现。
- **性能部分达标**：实心圆角路径、128 段曲线与密排线（gap 1）的生成加序列化快于 Rough.js，输出字节在曲线与排线场景只有 Rough.js 的一半到六分之一；直线、矩形、圆角路径描边与疏排线（gap 4）持平或更慢，详见下表。
- **播放帧率**：真实 Chromium 中 24 节点 Mermaid 图整图播放，152 帧无一帧超过 20 ms；规模更大的图与真实设备尚未测。
- **视觉验收未完成**：需要用户在 `/lab/sketch` 确认画面，各里程碑才算完成。

## 行为测试

`pnpm exec vitest run packages/sketch` 共 35 项通过：

- 生成与扩展（9 项）：确定性与图元隔离、钉住端点、两种孔洞规则、闭合重叠与断笔越界、预算超限、外部扩展经 SVG 与 Canvas 渲染，以及角点检测（凹角与光滑曲线）。
- 压感、笔与卡通（9 项）：钢笔两端收尖中段最宽、扁笔尖粗细随行笔方向变化、马克笔分批叠色、条带有圆帽且闭合、签字笔默认走原生描边、卡通三层输出与派生线色、派生色偏冷偏暖、阴影随图形大小变化、图元线宽覆盖。
- 编排、播放器与显现（17 项）：三种编排模式、播放暂停恢复跳转变速取消重播、SVG 与 Canvas 按时间显现（含钢笔条带前缀与签字笔虚线偏移）、合成区域不被拆成子路径、倒放不改变笔画。

按时间显现的测试发现过两个只有挂载动画才暴露的缺陷并已修复：SVG 属性 `data-trk` 缺少值导致文档不是合法 XML；evenodd 合成的月牙被拆成子路径各自填充而变成整块。后者补了回归测试。

## 包消费与体积

- `pnpm --filter @violet/sketch build` 产出 ESM 与声明文件；`path-data-parser` 作为外部依赖。
- `pnpm pack` 得到 `violet-sketch-0.2.0.tgz`，在仓库外的临时目录用 npm 安装：TypeScript 5（NodeNext，`skipLibCheck: false`）对新公开接口（`createSchedule`、`createPlayer`、`cartoonStyle`、`cartoonPalette`、`@violet/sketch/svg`）类型检查通过，Node 运行通过。
- 打包体积用 esbuild 压缩。笔与卡通风格以具名导出提供，只引入用到的部分：

| 引入内容 | 压缩后 | gzip |
|---|---:|---:|
| 生成 + SVG，签字笔 | 21,419 B | 9,406 B |
| 再加压感钢笔 | 24,513 B | 10,702 B |
| 卡通风格与派生配色 | 27,825 B | 12,297 B |

默认用法压缩后小于 Rough.js，gzip 后大 2.5%，没有达到“不高于 Rough.js”的目标。时间轴那一行没有包含卡通，所以不比上一行大。

## 性能

环境：Apple M2、macOS arm64、Node v23.10.0、Rough.js 4.6.6。每个场景预热 5 批、测量 21 批，下表为中位数（单位 ms）。只测生成与路径数据序列化，不含 DOM 与绘制。

- Rough.js 使用 PRD 基线配方（roughness 2.2、bowing 1.2、双笔复画）；本库使用自然手法、签字笔，线宽 1.25。
- 两者不是同一造型质量，结果不能解释为同质量下的绝对优劣。
- 原始数据：[sketch-m1-benchmark.json](./sketch-m1-benchmark.json)。

| 场景 | 图形数 | 生成 Rough / 本库 | 序列化 Rough / 本库 | 合计 Rough / 本库 | 每图形字符 Rough / 本库 |
|---|---:|---:|---:|---:|---:|
| 直线 | 1000 | 1.39 / 3.14 | 0.93 / 1.06 | 2.31 / 4.21 | 176 / 83 |
| 实心矩形 | 1000 | 4.30 / 10.83 | 7.50 / 7.91 | 11.81 / 18.74 | 867 / 716 |
| 实心圆角路径 | 1000 | 41.40 / 28.89 | 17.26 / 11.91 | 58.65 / 40.81 | 2152 / 1182 |
| 圆角路径描边 | 1000 | 25.67 / 28.14 | 11.57 / 11.19 | 37.25 / 39.34 | 1470 / 1065 |
| 圆角路径描边（Rough 关闭复画） | 1000 | 23.37 / 28.08 | 5.38 / 11.11 | 28.76 / 39.19 | 735 / 1065 |
| 128 段三次曲线 | 100 | 71.32 / 57.20 | 16.02 / 15.70 | 87.33 / 72.90 | 31855 / 17237 |
| 矩形排线 gap 4 | 100 | 3.80 / 6.73 | 4.72 / 2.24 | 8.52 / 8.98 | 10822 / 2134 |
| 矩形排线 gap 1 | 100 | 10.56 / 21.40 | 19.45 / 7.08 | 30.00 / 28.48 | 41040 / 6490 |

**未达标项**：直线与矩形这类极小图元的生成慢 2.3–2.5 倍；圆角路径描边与疏排线（gap 4）合计持平或略慢。主要是每个图元的固定开销：展平、笔画规划、随机作用域与批次构造。Rough.js 对一条直线只生成两段贝塞尔。

**已采取的优化**：定点数字格式化替代浮点 `toString`；控制点位置与切线只求一次；批次直接写入倍增的类型化数组；两轮 PCG 随机；细分跳过角点区间。

**下一步可验证的方向**：直线与无曲线多边形走专用展平快路径；批次与轮廓对象池化。

压感钢笔与马克笔的条带轮廓在 24 节点 Mermaid 上单次生成约 4 ms，未做与 Rough.js 的同口径基准，因为 Rough.js 没有等价能力。

## 时间轴播放

环境：无头 Chromium（Playwright），DPR 2，视口 1440×1000，场景为真实 Mermaid 24 节点图，并行编排、1× 速度，整图约 2.5 秒。记录播放期间每个 `requestAnimationFrame` 回调的间隔：

| 后端 | 笔 | 帧数 | 中位数 | p95 | 超过 20 ms |
|---|---|---:|---:|---:|---:|
| SVG | 签字笔 | 152 | 16.7 ms | 16.7 ms | 0 |
| SVG | 压感钢笔 | 152 | 16.7 ms | 16.8 ms | 0 |
| Canvas | 签字笔 | 151 | 16.7 ms | 16.8 ms | 0 |
| Canvas | 压感钢笔 | 152 | 16.7 ms | 16.8 ms | 0 |

rAF 间隔反映主线程是否跟得上，不等于画面已经呈现；没有测 GPU 完成时间。无头环境不代表真实设备，24 节点也小于 PRD 的百节点目标，所以这一条只说明在该规模下没有掉帧，不能作为“百节点 60FPS”的证据。

## 视觉自检

用 Playwright 截图查看了：卡通插画（SVG 与 Canvas、播放中途帧）、图元表在三种笔下的画面、七种填充、孔洞与 Mermaid。截图用于排查缺陷，不能替代用户的视觉评审。排查中发现并修复了：越界线头过长形成十字（缩短为线宽量级）、星形内凹顶点的转角只有约 50° 而被当成平滑曲线（角点阈值由 55° 降到 28°，星形退化为菱形）、卡通高光被裁剪到整个图形而多出一圈内框、插画图元被统一指定实色填充而没有阴影。
