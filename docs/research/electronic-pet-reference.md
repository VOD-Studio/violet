# 电子宠物：需求决策、独立包与 Skill 设计

调查日期：2026-10-13。本文是**需求访谈资料**，用于区分参考对象的事实、用户明确提出的目标和待讨论建议；**未实现电子宠物产品或原型**，不构成已确认 PRD，也不承诺第三方产品兼容性或素材授权。

阅读入口：[已确认范围](#访谈已确认的范围)、[独立包方案](#独立包与可信宿主)、[语言候选](#语言与运行时候选)、[养成与生命模型](#核心养成与生命模型)、[形象规范](#动态形象与跨风格规范)、[Skill 契约](#skill-的交付契约)。下方 Claude 资料只用于识别参考对象与授权边界。

## 结论摘要

1. **参考对象可以确认是 Claude Code 的 `/buddy`。** Anthropic 官方 `v2.1.89` 发布记录明确写出“`/buddy` is here for April 1st — hatch a small creature that watches you code”；该版本发布于 2026-04-01 01:07:06 UTC。不是只能由社区复刻反推的传闻。[官方发布记录][S1]
2. **它是已结束的愚人节功能，不宜作为长期依赖。** 官方第 14 周产品摘要明确标注“An April Fools' joke, no longer available”。这能证明官方当前将其描述为不再可用，但不能证明用户宠物在游戏规则里会“死亡”。[官方周报][S2]
3. **本次官方材料没有提供完整养成机制规范。** 物种清单、随机种子、唯一性保证、完整动画状态、经验值、进化、死亡、存档与跨端同步，不能从“孵化一个陪你写代码的小生物”这一句推导出来。[官方发布记录][S1]、[官方周报][S2]
4. **浏览器与 CLI 双端、每个用户的宠物不同、升级、进化、死亡、动态呈现，是本次用户提出的产品目标。** 不应写成“照搬 Claude 已有机制”。尤其社区 issue 曾把 XP、升级、进化、喂食和训练列在“Requested Enhancements”，不是官方已交付清单。[用户增强提案][S3]
5. **借鉴陪伴式体验，不直接复用 Claude 素材。** 官方仓库许可证是“All rights reserved”，不是 MIT/Apache 等开放源码许可；未找到对 Buddy 角色、ASCII 图案、动画帧或文案单独授权复用的官方说明。[官方许可证][S4]、[商业条款 F 节][S5]

- **社区报告**：第三方提交到官方仓库的 issue、评论及第三方仓库的自我描述。官方仓库只是托管位置，**不使用户发言自动成为官方声明**。
- **未证实**：未获得官方材料直接支持，也未自行运行官方历史版本验证。这里的“未证实”不等于断言功能从未存在。
- **建议 / [INFERENCE]**：基于证据提出的设计方向，必须经需求访谈决定；不冒充参考对象事实或用户已确认决策。

参考资料核查读取了官方发布记录、历史 changelog、官方周报与命令文档、公开 issue、许可证与商业条款，以及第三方仓库的公开元数据。官网与帮助中心检索未取得更详细的 Buddy 官方机制手册；这是检索结果，不是“官方绝无此文档”的证明。[历史 changelog][S6]、[当前命令文档][S7]

未读取泄露源码、相关 source map 或第三方复刻实现；未下载、反编译或运行 Claude 历史版本及复刻产品。本次未实现新电子宠物产品或视觉原型；实际执行的哈希 / 分布研究试算另节记录，不提供新宠物的帧率、性能或视觉一致性结论。

## 对本项目的启发与需求边界

### 值得借鉴，但还不是已确认设计

- **建议：以“陪在工作旁边的小生物”为参考核心。** 官方发布文案直接支持这种定位；不必复刻 Claude 的命令、外观或品牌才能表达陪伴感。[官方发布记录][S1]
- **建议：把首次诞生与日常陪伴分成不同体验。** 社区报告提供孵化动画、卡片、动态反应的参考线索；本项目是否采用孵化、出生或认领，以及如何进入日常状态，仍需确认。[动画报告][S8]
- **建议：保留可主动触发的轻互动，不默认引入聊天模型。** `/buddy pet` 仅为社区报告；喂食、抚摸、训练、对话分别应有什么效果，不能由参考名词自动决定。[互动提案][S3]
- **建议：用原创角色、原创动态和自有文案实现同类体验。** 这是基于许可边界的工程建议，不是关于法律安全的保证。引入外部素材前应逐项确认其授权、署名与再分发条件。[官方许可证][S4]、[商业条款][S5]

### 访谈已确认的范围

以下是本轮用户需求与多轮回答确认的产品边界，不是 Claude 的功能说明。实现语言按用户最新要求保留 TypeScript、Go、Rust 三种候选，留待 PRD 评审；本轮不锁定语言或开始产品实现。

- 独立包放在现有 packages，支持浏览器与 CLI；包可以独立运行，接入 Violet 时同账号共享宠物。
- 面向外部开发者交付 SDK、CLI 与可自部署服务，Violet 只是参考接入方，不运营统一 SaaS。各接入方拥有独立世界，同一世界内网页与 CLI 共享；不默认跨站迁移或漫游。
- 需要后端时使用独立宠物服务，不把宠物接口、规则、状态、表或迁移放入现有 `api/`，也不借用 Violet SSR 承担宠物后端。
- 持久化通过统一契约接入，接入方选择随产品提供的适配器或实现自己的存储；不强制使用 Violet 的数据库或账号体系。TypeScript / Node、Go、Rust 方案全部写入候选，在 PRD 阶段评审。
- 宠物必须动态呈现，支持升级、进化、死亡；长期离线有休眠保护，回归最多生病并保留救治机会，不直接结算不可逆死亡。死亡不可逆，保留纪念后重新领养；自然寿命由接入方统一配置，开启时各物种不同，关闭时无自然寿命上限。
- 每只宠物身份唯一，外观有明显差异，允许少量相似，不要求全球视觉绝不重复。
- 网页允许用户选择精细风格；同一个体在不同呈现方式下保留身份。
- 稀有度采用五档，概率可由接入方配置；影响外观、动作与进化分支，不提供普遍的数值优势。出生不保底，出生档位不变，但成长可以解锁罕见形态。
- 生成要求出生凭据可重建、哈希决定稀有基因、过程可公开验证；不采用算力挖矿。宠物默认领取，领养冷却仍需结合生命节奏校准。
- 当前同时一只主宠，保留未来家园扩展。物种可以覆盖原创幻想生物、现实宠物、机械 / 数字生命、植物 / 元素生命。
- 阅读、创作、本人点赞评论等有效互动参与养成，提供经验、主题倾向，以及食物或探险资源。阅读采用停留 / 进度等轻量资格信号与收益上限；评论同样计奖。收到他人互动只影响情绪或纪念，不直接发资源。
- 性格随养成渐变，保留出生底色；满足条件后，用户从合格分支中选择是否进化。
- 用户主页展示主人的宠物，可自由走动；获准后可以自主恶作剧。“吃掉推文”只临时改变当前浏览者的视觉状态，可恢复，不删除推文数据。
- 主题探险收藏、家园装扮、好友协作、繁育遗传与家谱纳入设计方向；多宠家园、携带宠物拜访属于后续方向。
- 基础生成和全部基础养成不依赖 AI，后续接入 AI 能力时才使用模型；AI 对话与共读为可选后续能力。
- Skill 属于正式交付设计，覆盖生成操作、合规形象与动态素材、所有能力的发现和调用；当前尚未创建可执行的宠物 Skill 或接口。
- 健康死亡由持续失养、预警、生病和可救治阶段逐步发生，不随机暴毙。
- CLI 同时提供独立入口与嵌入能力。账号模式离线仍可动画陪伴和无收益轻互动，养成写操作需联网；本地独立模式完整离线运行。
- **`/lab/mascot` 的界面设计已废弃，明确排除于本功能的设计参考。** 不沿用该界面的造型、布局、交互或动效方案；本轮研究不删除旧实现。

## 稀有度初始提案与实际试算

用户已选择五档、概率可配置、出生不保底和后天可得罕见形态。下表是获选结构的初始默认提案，不是平衡性实测结论或 Claude 概率复刻。默认领取保证用户获得一只宠物，出生档位仍由生成规则抽取。先决定档位，再从该档位的兼容组合中生成形象，不用“多个部件分别抽取后取最高档”悄悄改变公示概率。

| 出生档位 | 提案概率 | 100,000 次研究输入的实际计数 | 实际比例 |
|---|---:|---:|---:|
| 常见 | 60% | 60,016 | 60.016% |
| 少见 | 25% | 25,085 | 25.085% |
| 稀有 | 10% | 9,877 | 9.877% |
| 史诗 | 4% | 3,997 | 3.997% |
| 传说 | 1% | 1,025 | 1.025% |

试算于 2026-10-13 在 Node 兼容的 `node:crypto` 中执行：研究种子为 `SHA-256("public-research-fixture:" + i)`，`i` 从 0 到 99,999；以种子为 HMAC-SHA-256 密钥，输入 `pet-research/v1/birth-rarity/<counter>`。将输出前四字节按大端无符号整数读取，拒绝不小于 `floor(2^32 / 10000) * 10000` 的值，再对 10,000 取模；阈值依次为 6,000、8,500、9,500、9,900、10,000。拒绝后只增加该标签的 counter。

同一研究种子在执行 300 次独立 `animation-preview/<i>` 标签派生前后，出生档位抽样值一致。另用 `hkdfSync("sha256", ...)` 核对 [RFC 5869 附录 A.1](https://www.rfc-editor.org/rfc/rfc5869#appendix-A.1) 的 42 字节输出，结果匹配。这些是密码原语和研究分桶的运行记录，不是产品生成器、公开公平协议或视觉系统已通过验收。

在独立抽样假设下，100 次领取均未出现 1% 传说档位的概率为 `0.99^100 = 0.3660323412732289`。平均概率不是保底；用户已选择出生不保底，以成长中的罕见成果提供可努力获得的目标。

提案约束：

- 物种与稀有度分别定义，各物种均可覆盖不同档位；常见个体也有完整造型与动画。
- 稀有差异落实到可辨认部件、花纹、招牌动作或进化候选，不只改名称或细微色差。
- 出生档位固定，后天罕见形态单独记录；普通出生也能通过养成获得罕见成果，此项已获用户确认。
- 领取重试恢复同一出生记录；动画随机和基因随机分开；上述公开研究种子不能直接用作正式账号生成凭据。

## 独立包与可信宿主

逻辑上分为规则核心、SDK / 呈现 / CLI 与独立服务，放在 packages 范围内。前端 SDK 可沿现有 pnpm workspace 放在 `web/packages/pet/`，暂记 `@violetjs/pet`；独立服务可放在并列的 `pet-server/`，但原生 crate / Go module 的具体拆分由 PRD 选型决定，不能因当前 workspace 使用 pnpm 就预设后端是 Node 包。目录布局不代表依赖站点 Web 运行时。本次不创建空包或未实现入口，也不并入 `@violet/ui`、现有 `api/` 或旧吉祥物实验。

### 比较三个 Interface

以下签名只说明模块形状，均未实现。

**A：纯函数规则模块**

```text
transition(rulebook, storedState, trustedInput) -> Decision
project(rulebook, state) -> PetView
verifyBirth(receipt, verificationContext) -> Verification

宿主：读取状态 → transition → 原子保存成功结果 → project
```

规则模块隐藏出生派生、状态推进、照料、成长、性格和合法动作判断。调用者持有身份、逻辑时间和持久化事务，不能把函数返回值当作已经提交。目标是在浏览器本地、本地 CLI 与可信服务端复用同一份规则；是直接运行还是通过 WebAssembly 调用，取决于 PRD 选型。

**B：有状态运行实例**

```text
open(mode, adapters) -> Runtime
Runtime.snapshot / subscribe / command / attach / dispose

页面：open → attach(renderer) → command(feed) → dispose
```

消费者接线少，订阅与连接可由实例统一管理；代价是运行模式、队列、计时器、关闭竞态都进入公共契约。实例串行仍不能解决跨端并发，容易让每个客户端误以为自己拥有宠物生命。不作为核心的默认形状。

**C：能力协议优先**

```text
client.describe() -> CapabilityCatalog
client.request(typedIntent) -> CommittedResult

CLI / Skill：发现能力 → 读取状态 → 发送有类型的动作 → 核对结果
```

适合 CLI、账号 API 和后续 AI，前置条件、权限、错误与参数同源；如果把帧动画也消息化，会平白增加序列化与网络成本。同运行时内直接传对象，网络与 WebAssembly 边界分别定义编码，不每帧重传整份领域状态。

**推荐合成**：以 A 作为唯一养成规则模块，以 C 描述宿主调用与能力发现；渲染拥有单独的轻量挂载、替换投影、局部反馈和销毁接口。借用 B 的明确清理习惯，不建立一个包办身份、存储、网络、计时和多宠世界的全局 runtime。

这里的三个核心入口不代表整个包只有三个方法。平台 adapter、渲染器与 CLI 是独立模块，各自有小而明确的 Interface；不靠一个任意参数对象伪装接口很小。

### 语言与运行时候选

**评审状态：三种方案并列保留，不在本轮作选择。** 用户先提出服务端接口考虑 Go / Rust，随后明确要求 TypeScript 也纳入 PRD 评审。以下是架构候选与已核实的工具链事实，不是产品性能测试结论。

| 候选 | 唯一规则核心 | 独立 API 与 CLI | 浏览器与 JS 嵌入 | 主要代价 |
|---|---|---|---|---|
| TypeScript / Node | 纯 TypeScript 模块 | Node API 与 CLI 直接调用核心 | SDK 直接调用，无须 WebAssembly | 服务需 Node 运行时；必须验证边界输入与可替换持久化，不能把客户端计算当权威。 |
| Go | 无平台 I/O 的 Go 包 | Go API 可原生调用；CLI 可原生实现或使用 Node 包装 | Go WebAssembly 与 TypeScript 包装；JS 嵌入不重写规则 | 分发匹配版本的 Go WebAssembly 支持文件；包体、冷启动和桥接成本需实测。 |
| Rust | 无平台 I/O 的 Rust crate | Rust API 可原生调用；CLI 可原生实现或使用 Node 包装 | WebAssembly 与 TypeScript 包装；JS 嵌入不重写规则 | 引入 Rust 与绑定生成工具链；需校验目标兼容、发布加载及跨端数据编码。 |

无论选哪种，都不默认采用“Go / Rust 接口再调用 Node 规则服务”的双服务方案，也不维护一份 JS 养成逻辑和一份原生养成逻辑。渲染、网络、存储与规则分开：动画不需要每帧调用后端，原生核心也不负责直接操作网页 DOM。

已核实的工具链约束：

- [Go 官方 WebAssembly 文档](https://go.dev/wiki/WebAssembly)说明 `GOOS=js GOARCH=wasm` 的浏览器与 Node 路径；编译器与 `wasm_exec.js` 必须使用文档规定的匹配 Go 版本。不能只发布 `.wasm` 文件而漏掉运行支持。
- [Rust 的 wasm32-unknown-unknown 目标文档](https://doc.rust-lang.org/rustc/platform-support/wasm32-unknown-unknown.html)说明该目标的最小宿主假设，也明确文件系统和线程等标准库能力不可直接使用。规则输入应显式提供时间与随机材料，持久化留在宿主外层。
- [wasm-bindgen 部署文档](https://wasm-bindgen.github.io/wasm-bindgen/reference/deployment.html)区分浏览器、bundler 与 Node 输出；Node ESM 目标仍标为实验性，不能假定一个生成文件未经验证就适配所有消费者。[CLI 文档](https://wasm-bindgen.github.io/wasm-bindgen/reference/cli.html)说明会生成绑定的 TypeScript 声明，但这不等于任意序列化 DTO 会自动得到完整类型契约。

PRD 评审应比较相同功能切片，而不是语言印象：

1. 用相同出生凭据与生命周期输入，在浏览器、CLI、服务端得到一致的基因、状态和错误；确定整数范围、字段编码与版本规则。
2. 记录完整发布产物大小、压缩后传输量、冷启动、常驻内存和一次规则调用开销。当前没有这些测量，不预写某方案一定更小或更快。
3. 工作区外安装 SDK，验证 Web / Node 加载、离线运行、SSR 不提前初始化及公开类型；消费者不应为安装 npm SDK 自行编译 Go 或 Rust。
4. 对默认与自定义存储执行相同并发、幂等、回滚和恢复契约；核算接入方是否必须学习另一种语言才能编写适配器。
5. 独立构建并启动服务，核实镜像、配置、升级和发布维护；不把 Violet 当前 API 的可用性当作宠物服务的能力。

语言选择后再确定原生 CLI 或 Node 包装 CLI 的交付形态；两者均须满足独立使用与可嵌入要求，不能只交付一次性静态输出。

### 平台与宿主的职责

| 部分 | 归属与约束 |
|---|---|
| 根核心 | 确定规则、已解析形态、状态转换、投影与核验；不访问 DOM、文件系统、网络、系统时间或系统随机源，所需输入由调用边界提供。 |
| 浏览器 / React 子入口 | 画风、动画、显式页面目标、可访问交互、挂载清理；React 不进入核心依赖。 |
| 终端入口 | 字符帧、颜色与尺寸、独立命令、嵌入区域、本地存档；原生或 Node 实现由选型决定，平台依赖不泄漏到浏览器入口。 |
| 素材目录与规则档案 | 对部件、动作、兼容关系与生成版本寻址；历史个体不会随最新目录变脸。 |
| 独立宠物服务 | 账号宠物权威状态、出生与签发、库存、奖励收件与去重、配置、凭据与同步；有独立的持久化边界、数据版本和部署。 |
| Violet 参考接入 | 连接已有身份与内容事实、选择公开投影、登记页面目标和临时隐藏；不拥有宠物规则或数据库。 |
| Skill 与机器能力目录 | 随包交付，引用同源 schema 和实际能力，不依赖本会话的隐含知识。 |

公开用户主页保留 SSR，宠物行为在 hydration 后挂载；不同 SSR 请求不能共用可变宠物状态。核心包可被其他站点和本地 CLI 独立消费，不导入 Violet 的 cookie 客户端、路由、业务 DTO 或数据库。

### 独立服务，而不是本站 API 的子模块

独立服务采用哪种语言由 PRD 从上述三个候选中评审。它直接执行唯一规则核心并编排自己的事务，而不是仅充当现有 API 的转发层。接入方已有 Go、Rust 或其他后端都可通过 HTTP 协议连接身份与活动事实，无需重写养成规则。Violet 现有 Go API 与 SSR 都不是宠物服务的运行前提，也不为宠物存档承担迁移。

服务应具备与选定语言对应的独立包 / module / crate、启动入口、配置、构建、镜像、数据升级与部署说明。存储由接入方选择，通过统一适配契约注入。默认服务端实现可采用 PostgreSQL，但数据库类型不是产品前提；宠物数据拥有独立命名空间与权限，不读取 Violet 业务表，不把其迁移放进现有 `api/`。本地 SDK / CLI 存档不要求数据库服务。

一次账号动作在宠物服务中完成：验证自己的会话与 owner，恢复相同请求已提交结果，读取状态和业务资格，执行规则，原子提交宠物 / 库存 / 奖励去重 / 命令结果，再返回新投影。正式领取先固定出生请求，失败重试不重新抽取。客户端只提交意图，不上传自算后的权威状态。

各接入方是独立世界。默认一个自部署实例对应一个世界；不同网站需要不同规则和数据时使用各自实例，同一实例内的网页与 CLI 是同一世界的客户端。不提前建设托管多租户平台，不因邮箱、用户名相同自动关联其他站点的宠物。

账号来源用明确的发行域与稳定 subject 映射，不能假定外部账号是 Violet UUID。公开出生凭据绑定世界与发行者；本地自选种子可复算，不自动成为独立服务签发的正式个体。

### 三种外部消费方式

| 接入方式 | 开发者需要做什么 | 不要求什么 |
|---|---|---|
| 本地网页 / CLI | 安装包，选择规则和素材，使用对应存档与呈现 adapter。 | 不需要 Violet、宠物后端、账号服务或 AI。 |
| 自部署账号模式 | 启动宠物服务及独立存储，让网页和 CLI 使用该服务的身份与状态。 | 不依赖 Violet API / SSR，不需要运营统一 SaaS。 |
| 连接现有网站 | 实现或配置身份与活动事实 adapter，注册页面可交互目标。 | 不修改核心去认识文章表，不共享站点数据库，不把服务密钥放进浏览器。 |

接入方可按规范增加物种、素材、画风和活动规则，但不是上传任意脚本给服务执行。目录和规则变更经过校验、版本化发布；同一输入仍有明确可重建结果。

### 独立服务如何信任外部身份与内容事实

身份 adapter 只负责证明外部主体，宠物服务签发和撤销自己的会话 / 访问凭据并检查 owner；自部署可提供由管理 CLI 签发的个人访问凭据，网站可使用既有身份提供方兑换，普通用户 CLI 可走浏览器确认的设备授权。不要求另做一套 Violet 注册系统，也不能让浏览器携带接入应用的服务密钥。

活动入口接受已登记接入方的有限事实：来源事件 ID、主体、内容引用、行为类型、发生时间和主题。先持久保存收件与业务去重，再由宠物自己的规则决定资格、上限和收益；不接受外部直接指定经验或余额。来源签名只能证明谁发送，不证明内容真的有效，可信接入方必须核验其业务事实。

Violet adapter 将本站身份与内容转换为这个协议；其他博客、课程、写作工具可提供自己的行为类型。宠物服务不读取 Violet 表，也不强制每个接入方都有文章、推文或相同主题分类。

**跨服务不能假装有一个数据库事务。** 内容平台先成功提交事实，连接器负责可靠送达或从权威来源对账，宠物服务对重复收件幂等结算。源事件缺失不能只靠客户端补一句“评论成功”解决。若接入平台没有可验证事件或查询能力，应明确补充通用连接接口；不得为此把宠物资格、奖励表或生命规则塞回原平台 `api/`。

本地模式由本地存储拥有权威，账号模式由独立宠物服务拥有权威。服务离线时继续本地陪伴并禁用养成写操作，不能让客户端或 Violet API 临时接管规则。

### 持久化与其他适配契约

纯规则模块不依赖存储接口；负责执行动作与提交结果的外层才使用持久化适配器。产品定义一套契约，接入方提供实现，不由每个项目发明不同的宠物 API。

进程内接口用对应语言表达：TypeScript interface、Go interface 或 Rust trait；浏览器本地存储使用 SDK 的 TypeScript 契约。共享的是状态 schema、原子提交与错误语义，不是能跨语言直接调用的接口对象。使用现成独立服务的接入方只需配置默认存储，不必亲自编写适配器；确需定制服务端存储时，应实现该服务语言的接口。HTTP 客户端接入则不受服务实现语言限制。

| 边界 | 产品提供 | 接入方负责 |
|---|---|---|
| 本地存档 | 网页 IndexedDB 与 Node 文件适配器；仅内存实现用于原型或明确不保存的预览。 | 选择现成实现；有特殊环境时按同一契约替换。 |
| 服务端存储 | 一个可直接运行的默认实现、存档结构版本、升级说明与存储契约验收。 | 配置后端，或实现自己的数据库适配器并通过相同验收。 |
| 身份 | 外部主体映射与宠物凭据的验证边界。 | 连接自己的账号体系；不能让客户端自报 owner 就获得授权。 |
| 活动事实 | 类型、来源身份、幂等语义与资格结算协议。 | 提供可验证事实和主题映射，处理来源送达与对账。 |
| 页面目标 | 动作权限与取消 / 恢复契约。 | 登记真实目标并拥有临时视觉状态，不交出业务删除权限。 |
| 呈现 | Web / 终端默认实现与素材规范。 | 选择或扩展画风，不必重新实现整个动画系统。 |
| AI | 后续实现时接入受限能力调用。 | 可选配置模型；当前基础功能不要求 AI provider。 |

持久化不能只有 `loadPet / savePet`。它必须保证状态版本检查、冲突结果、宠物与库存及奖励记录的原子提交、请求重试恢复，以及出生凭据持久保存。默认适配器要兑现这些行为，不把错误恢复与防重复发奖留给每个接入项目猜测。

优先采用事务式工作单元包住相关读写，而不是把数据库连接暴露给规则模块。事务回调中不做网络或模型调用；重试使用事先固定的出生输入，不重新抽签。文件存档需要单写者保护与原子替换，不能把一次普通 JSON 覆盖称为事务。

自定义适配器验收覆盖失败回滚、并发冲突、同请求重放、重启恢复与作用域隔离；只通过“保存后能读取”不够。无法提供这些保证的存储不能用于权威账号模式。具体方法签名在可运行原型中确定，不提前发布无法实现的通用事务承诺。

账号模式只有服务端适配器持有权威状态，网页与 CLI 通过相同客户端协议访问它，不各自保存另一套有效库存。本地模式才各自使用 IndexedDB 或文件。动画从内存投影驱动，不逐帧访问持久化。

### 面向外部开发者的交付

SDK、独立服务和机器能力协议声明兼容版本；规则与素材也各自版本化，不能用本站版本号代替。公开入口不依赖仓库路径 alias，React 为可选呈现入口，CLI 不要求浏览器。服务私有配置和接入方密钥不进入 SDK 发布包。

交付内容包括包内接入文档、无框架网页示例、CLI 使用、独立服务部署、身份 / 活动 / 存储适配说明及外部消费验收。Violet 示例是其中一个，不是所有示例的运行前提。

代码许可建议沿用现有 `LICENSE` 与独立包 `web/packages/inkline/LICENSE` 的 MIT；素材另附来源、修改及分发许可，不能因代码开源就默认图片和 Claude 图形可自由使用。SDK、服务及素材目录的公开分发仍是后续发布工作，本轮不执行发布。

## 核心养成与生命模型

本节区分已确认的产品规则与实现建议；尚未实现，具体数值不冒充经过体验验证的平衡参数。

### 不把所有状态塞进一个等级

| 状态组 | 内容与规则 |
|---|---|
| 出生身份 | 个体 ID、物种、已解析基因、出生稀有度、出生凭据；出生后不可重新抽取。 |
| 身体状态 | 饱食、精力、健康；照料和活动影响，不由动画帧数推进。 |
| 成长 | 经验、等级、已选进化形态、候选分支、主题倾向；成长不修改出生档位。 |
| 性格 | 出生气质与长期养成偏移；初始可用好奇、亲近、活跃、调皮等连续倾向，名称与维度数属于可调整设计。 |
| 情绪 | 当前开心、疲倦、饥饿、警惕等短时状态，先影响表情和动作，不立即永久改性格。 |
| 生命 | 自然寿命策略、有效年龄、生病与救治阶段、休眠、死亡记录；自然寿命关闭仍保留健康死亡。 |
| 陪伴记录 | 阅读、创作、进化和探险里程碑；死亡后保留纪念，不将私密阅读内容自动公开。 |
| 表现状态 | 当前画风、位置、动作相位、临时页面效果；不作为经验、存活与物品的权威来源。 |

日常循环为照料、有效内容活动、取得经验或资源、形成主题与性格倾向、解锁可选进化，再继续陪伴。喂食恢复饱食，休息恢复精力，玩耍影响情绪与长期倾向，治疗作用于疾病阶段。动作有前置条件和收益上限，不能靠每秒重复抚摸无限刷级。

成长方向从宿主传入的已认定主题中积累。例如自然主题可以增加植物形态候选，技术主题可以增加机械形态候选；具体表现由物种兼容目录决定，不让任何动物随机长出不兼容部件。缺少标签的内容仍能获得基础成长，不强制调用 AI 分类。

性格采用有上限的缓慢偏移；重复短时刺激的边际作用递减。出生气质保留约束范围，短期心情可恢复，历史记录用于解释变化，不作对用户真实人格的推断。同一个体的好奇影响探索与观察倾向，调皮影响获准后的恶作剧选择，而不是给它额外操作权限。

### 离线、休眠和死亡

- 生命计算接受明确逻辑时间；账号模式采用独立宠物服务的可信时间，本地模式采用本地时钟。持久状态记录上次结算点，恢复时计算经过的有效区间，不逐秒补跑数周的动画。
- 动画使用单调时钟。后台 rAF 暂停或 CLI 掉帧不改变生命规则；多端同时连接也不重复累计年龄或消耗。
- **已确认的离线保护规则**：短期离线可以消耗状态，长期进入休眠；离线回溯最多进入需照料 / 生病状态，不直接宣判不可逆死亡，回归保留救治窗口。建议休眠同时冻结继续恶化与自然年龄；精确宽限与窗口需快进原型校准。
- 健康路径为正常、状态不足、预警、生病、救治失败后死亡；一次点击失败、模型输出、网络错误和未经选择的随机事件不触发死亡。
- 自然寿命关闭时没有老死；开启时按物种定义有效年龄范围，接近寿终提前显示衰老变化。建议寿命配置默认只影响新领养个体，避免站点改参数让在世宠物突然寿终。
- 死亡是终局，不恢复原个体、不清空再当作原宠物。纪念页保留名字、形象、成长与死因说明；下一次默认领养使用新的出生记录。
- 账号模式断网不接受待同步的扣物品、领奖、进化命令，不用最后写入覆盖合并冲突。无收益的动画与轻互动属于本地呈现；恢复联网后重新读取权威状态。

## 出生凭据与公开验证方案

选用公开、版本化的哈希派生规则；不以 `hash(userId)` 直接决定全部结果。后者可以被猜测，而且同用户下一代缺少独立出生身份。账号正式领取与本地试养必须区分来源，本地自选种子不自动变成账号模式的公证个体。

建议账号生成过程：

1. 服务端为一次领取建立唯一出生请求，绑定世界、发行者、账号归属、不可重复使用的领取序号、生成版本、规则及素材目录摘要。请求重试恢复原记录。
2. 服务端先对该次专用随机输入作承诺，再接收客户端随机输入；客户端输入必须在看到承诺后确定。服务端随机输入是本次专用值，不是长期服务密钥。
3. 已接受的客户端输入持久固定后，才揭示服务端输入；按明确字节编码与哈希规则派生出生种子，保存承诺、输入、结果与签名凭据。不能在揭示后换客户端输入，也不能按不喜欢的结果静默重抽或重新分配领取序号。
4. 从出生种子按 `species`、`birth-rarity`、部件、花纹、初始性格等用途分别派生随机流。生命事件与动画随机不消耗出生随机流；加一种闲置动作不让未来进化变样。
5. 按公开权重与兼容性规则生成已解析基因，保存结果和版本。验证器检查承诺、签名来源、规则摘要和重新派生结果，返回具体不一致项。

这是一种待实现、待安全审查的承诺—揭示方案，不是仅因使用 SHA-256 就已证明公平。它可以检验给定输入是否被替换、结果是否符合公开规则；**不能单凭一份结果证明服务方从未选择性拒绝请求、用户没有多账号，或整个抽取人群不存在偏差**。正式承诺范围应明确，已接受请求的恢复和揭示记录应可核对。

公开核验所需的出生上下文不包含 Cookie、访问凭据、邮箱或原始活动记录。账号归属由服务维护，公开记录使用不暴露登录身份的出生引用；不同世界的签发凭据不能冒充同一世界的正式个体。

生成版本、权重、素材兼容目录必须一起固定。升级目录只影响新出生或明确的新成长事件；老个体继续使用已保存的基因与形态。历史验证所需的规则档案要保留，不依靠当前最新目录猜测旧结果，也不重新调用 AI 生成同一形象。

哈希扩展可使用 [RFC 5869 HKDF](https://www.rfc-editor.org/rfc/rfc5869) 的上下文区分；带权抽样明确拒绝取模偏差。组合数不能按所有部件数量直接相乘当作真实视觉容量，兼容约束、遮挡、对称和终端降色都会降低可辨识数量。

## 动态形象与跨风格规范

共享的是形态语义和动作，不把网页精细风格限制为放大的像素图，也不承诺将任意 SVG 自动缩小就能得到好看的 CLI 宠物。

拟定的素材契约包括：

- **物种 / 身体结构**：物种族、姿态骨架、部件槽位、锚点、朝向与层级。四足、飞行、团状、机械、植物等分别定义兼容结构，不做无限制部件拼贴。
- **身份锚点**：耳角、尾形、面部特征、纹路位置等。精细、像素与字符简化都保留大特征，不能只依赖细微色差；进化至少保留若干可辨认线索。
- **呈现资源**：同一部件 ID 对应精细与低分辨率表现。精细可用受限 SVG / 参数化矢量，像素使用校准过的部件或帧；终端消费低分辨率表现，不运行浏览器 DOM。
- **动作语义**：待机、眨眼、走动、观察、进食、玩耍、睡眠、受惊、生病、进化与生命终结的状态表现。不同身体结构可以有不同动作实现，例如悬浮生物不必假装有脚。
- **质量与许可**：每项素材有来源和使用许可；部件、动作、生命阶段、画风的覆盖由目录校验。禁止未声明外链、脚本或任意 SVG 活动内容进入正式素材。

稀有动作应在网页与终端都有可辨认的对应表现，不靠只在高端浏览器出现的粒子特效冒充跨端稀有性。颜色量化、低能力字符模式和减弱动态下仍提供文字状态。

浏览器动画循环由呈现 adapter 管理，优先更新部件姿态而非每帧推动 React 业务树；不可见时暂停非必要绘制。终端独立入口负责输入、尺寸变化、颜色能力和退出清理；嵌入模式由宿主拥有输入和输出区域，包不能夺取整个终端。

[MDN 的 rAF 说明](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)明确多数浏览器暂停后台回调；[Node TTY](https://nodejs.org/api/tty.html)说明 Node 入口的 raw mode、尺寸与色彩探测。raw mode 下 Ctrl+C 不会自动产生 SIGINT，独立入口要自行正确处理；采用原生 CLI 时也须验证对应终端恢复行为。非 TTY 输出一次可读状态或 JSON 后退出，不写动画控制码；这只是管道降级，不取代真实交互终端中的动态宠物。

可用 Unicode 半块将上下两个像素编码到一个字符单元，但要处理默认背景、字宽与调色限制。[Unicode Block Elements](https://www.unicode.org/charts/PDF/U2580.pdf)定义字符，不保证所有终端的字体和行距相同。低色彩或 ASCII 模式需要保留形态线索，不能宣称逐像素一致。

## 与 Violet 内容和用户主页的接入

### 内容奖励的事实来源

| 点赞 | 已有推文点赞；`tweet_repo.go:294-339` 取消会删除当前关系。未找到文章点赞模块。 | 先接已有业务，不顺手新造文章点赞；领奖历史独立于当前点赞关系，取消重赞不重领。 |

| 其他有效互动 | 宿主中不同互动有不同主体、权限和成立条件。 | 通过明确的活动规则加入资格目录；不把任意点击或客户端自报的“有效”当奖励依据。 |

独立宠物服务以世界、主体、来源身份和奖励种类去重，不能把宠物 ID 当唯一去重范围，否则下一代会把旧文章全部重领。其自己的经验、资源和领取历史在同一持久化提交边界生效；每日上限跨端共享，不按窗口分别计数。收到别人点赞评论不增加资源，只生成适量情绪或纪念。

现有 `api/internal/infrastructure/eventbus/inmemory.go:44-78` 在业务提交后内存分发，订阅失败只记录日志；审计也是事后写入。因此不能把“订阅现有事件”当成跨服务可靠送达方案。Violet 连接器要使用可核验的权威查询或可靠通用事件，并支持补偿对账；宠物收件、资格与发放记录全部在独立服务。若需要为平台补通用事件导出，应明确为接入工作，不在 `api/` 新建宠物模块或重建全站事件框架。

### 公开主页上的走动与恶作剧

实际公开入口为 `web/src/routes/users/$username.tsx`，不是 `/profile` 个人设置。页面主人的身份来自 `profile.id`，不取代访问者身份。现有 `UserProfileFeed` 使用文档滚动、cursor 分页和手动加载更多，没有列表虚拟化；过滤会卸载卡片，加载更多会增加卡片。

Violet 宿主为可交互元素显式登记稳定目标 ID、类别、几何信息、许可动作和恢复方法。通用包只消费这些登记目标，不扫描全站 DOM，不导入 tweet DTO、QueryClient 或真实删除 mutation。目标卸载、切换用户主页、撤回授权时取消正在进行的互动。

“吃掉推文”的临时可见性归页面宿主，不删查询缓存、不改统计总量。动作结束或用户要求恢复时还原；刷新恢复正常。当前浏览者的许可与主页主人的公开宠物设置分别判断；主人的允许不能强迫访客接受遮挡阅读的恶作剧。

点击宠物、键盘操作和状态面板必须可访问；漫步层不能拦截整页指针、遮住正在输入的字段或破坏焦点。未来访客携宠相遇通过同一页面作用域扩展，不把当前一只主宠改成多个权威状态副本。

### CLI 账号共享不是复制 Cookie

现有 PAT 管理位于后台，作用于 MCP；普通 REST 仍使用浏览器 session，当前没有完整的普通用户 CLI 授权入口。证据为 `api/internal/interfaces/http/routing/admin_router.go:149-155`、`api/internal/domain/api_token/entity.go:9-43`、`api/internal/infrastructure/mcp/verifier.go:18-72`。不能用已有管理员 PAT、bot 身份或复制 Cookie 假装完成普通用户账号共享。

CLI 授权流程及宠物访问凭据由独立宠物服务拥有，签发最小作用域的可撤销凭据并校验真正 owner；Violet 只作为可替换的身份来源参与浏览器确认。具体接入不能沿用后台 MCP PAT、增加现有 API 内的宠物会话模块或复制 Cookie。独立本地 CLI 不要求任何账号服务、AI 或 MCP。

## Skill 的交付契约

Skill 随独立包交付，而不是仅藏在 Violet 项目的 agent 配置里。拟定一个 `electronic-pet` 入口，按生成、形象制作、养成 / 互动、接入与验收分支读取引用资料；此处是设计，不是已经可调用的 Skill。Skill 与全部引用资料必须进入发布包，外部 agent 不需要 Violet 仓库或本会话；先识别包版本、世界、本地 / 账号模式及当前能力，不默认使用本站路径或凭据。

| 分支 | AI 必须读懂的规则 | 完成条件 |
|---|---|---|
| 生成 / 领取 / 验证 | 正式领取与本地预览的区别、出生凭据、规则版本、基因和档位的不可变字段。 | 通过实际生成入口得到结果，并能用对应版本验证；不自行指定正式稀有度。 |
| 形象与动态素材 | 部件、锚点、兼容结构、身份线索、画风对应、动作覆盖、许可。 | 结构校验和真实多动作预览通过，Web / CLI 能辨认同一个体；单张静态图不算完成。 |
| 养成与互动 | 长期性格与短期情绪、有效活动、进化条件、物品消耗、休眠和死亡。 | 通过实际能力调用产生允许的状态转换；文字宣告不能代替真实变化。 |
| 页面互动 | 宿主目标注册、当前许可、临时效果、取消与恢复。 | 动作只作用于注册目标，可恢复且不改业务数据；目标消失后及时取消。 |
| 能力发现 | 已实现能力、输入输出 schema、前置条件、授权、作用对象、状态影响、错误及幂等语义。 | 先读取当前宿主实际暴露的目录；不把未来路线图中的能力伪装成现成工具。 |
| 接入与验收 | 包版本、运行环境、渲染入口、存储契约、独立服务与外部身份角色。 | 从实际安装包消费，按需选择或实现适配器，运行对应验收；不把宠物后端安装进接入方现有业务 API。 |

能力清单和 schema 是事实源，CLI 帮助、机器可读发现与 Skill 引用从同一份描述派生，不手工维护三份参数列表。每项能力声明只读 / 写入、所需角色或作用域、前置生命状态、资源成本、业务去重键、可取消性与错误。账号服务端执行约束，Skill 本身不是权限控制。

基础能力目录应覆盖状态读取、出生与验证、照料、休息、玩耍、治疗、候选进化查询与确认、物品使用、纪念读取，以及已交付的探险和装饰能力。经验发放、正式稀有度指定、死亡判定和内容删除不是模型可以任意写入的宠物命令。未来繁育、好友协作或 AI 共读上线后再注册真实能力，不预建空接口。

Skill 的流程为识别任务分支、读取当前能力与契约、检查前置条件、调用或制作、执行对应验收、报告实际结果。缺少目标能力、素材或权限时明确指出缺项；不能写一段对白冒充执行，也不能用“已经生成”掩盖无动态素材或未保存结果。

AI 接入后只把确定状态、用户允许的内容上下文与受限工具交给模型，用于对白或行为建议；规则模块仍裁决所有权、基因、收益、资源、进化和生命。基础模式不调用模型，也不要求密钥。

| 装饰、装扮与家园 | 装饰物与出生基因分开保存，角色装扮和生活空间可扩展。 | 当前服务一只主宠的生活空间；多居民家园属于后续方向，不先做多宠管理。 |
| 好友拜访与协作 | 访客有受限友好互动；以后携带自己的宠物相遇、共同活动。 | 当前默认展示主页主人的宠物；访客操作不等于可替主人喂养、消耗或进化。 |
| 繁育、遗传与家谱 | 以后通过双方授权的繁育资格生成后代，按可验证规则继承部分基因与家谱。 | 建议先保留待孵化后代资格，主宠位置空闲才孵化；不把父母死亡当成默认繁育代价。 |
| AI 对话与共读 | 使用性格、情绪和获准文章上下文组织语言，调用实际已授权的互动能力。 | 后续可选接入；不开 AI 仍有完整养成、动画和确定规则。 |

繁育不是复制父母最高稀有度，也不是把所有罕见部件累加到后代；遗传与出生分级必须有独立、公开、版本化的规则。该扩展尚未进入实现，具体遗传概率不冒充已经确定。

## 实现前需要跑出的证据

本次已执行的只有前述密码原语 / 分布研究试算；以下是后续验收目标，尚未执行：

1. **形象原型**：同一批出生结果同时展示精细、像素和终端形态，覆盖不同身体结构、档位与阶段；检验身份线索、动作衔接及配色降级，而不是只看一张静态图。
2. **生命周期快进**：用受控逻辑时间走过照料、病程、治疗、长离线休眠、寿命开关、进化与死亡；关窗口、掉帧、多端连接不改结算结果。
3. **资格与并发**：同篇阅读、重新发布、取消重赞、重复审核、请求重试和双端同时消费均不重复收益；失败操作不扣资源。
4. **主页互动**：走动与临时吃卡片可恢复，切换筛选 / 用户 / 页面或目标卸载能取消；键盘焦点、阅读和推文数据保持正确。
5. **真实终端**：窗口变窄、resize、低色彩、无 Unicode、Ctrl+C、管道输出和嵌入卸载都正确；离开后终端输入、光标恢复。
6. **出生核验与跨端一致性**：浏览器、CLI 与服务端使用同一输入复现基因和状态；原生方案同时验证原生与 WebAssembly 结果。篡改规则摘要或凭据被拒绝，拒绝取模偏差的边界有确定输入覆盖。模拟分布不能替代协议安全检查。
7. **安装包与 Skill**：工作区外安装真实 tarball，验证核心无 DOM / Node 污染，Web 与 CLI 分别运行；让 agent 仅凭包内 Skill 完成生成核验与合规素材任务，不能靠会话隐含信息补规则。
8. **真正独立部署**：在没有 Violet API、SSR 与业务数据库的环境安装 SDK、运行 CLI 和启动宠物服务；用最小通用宿主完成身份与活动接入。只在本仓库 alias 下能运行不算对外交付。

下一步在 PRD 中评审语言与发布形态，并用形象和生命周期原型验证关键问题；原型分别回答“能不能认出同一只、是否真的在动”和“规则是否形成可接受的陪伴体验”，同时提供选型需要的跨端运行证据。确认后再锁定资产规模、数值与实现 tickets，不直接用长文替代这些证据。
