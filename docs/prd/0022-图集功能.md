# PRD: 图集（galleries：UGC 图片/视频合集）

## Problem Statement

博客当前没有**多图公开内容**形态：tweet 最多 4 图且是碎片流，文章对纯图内容太重（标题/TOC/版本历史）。摄影作品集、教程步骤图、壁纸合集、旅行相册这类「一组图 + 少量说明」的内容无载体。素材库（`/admin/media`）是纯私域，不能公开浏览。

需要一个 UGC 图集能力：**任何登录用户可建公开图集（图片为主，视频可含），未登录可浏览**。

## Solution

新增独立 bounded context **`gallery`**，与 tweet / post 平级：

- **UGC 定位，对齐 tweet 治理模型**：任何登录用户可建；**即发即出**（无先审后发，管理员凭 `gallery:delete-any` 事后删除兜底）；独立发布限流防刷屏。
- **可编辑，刻意偏离 tweet 的不可编辑规则**：改标题/描述/封面、加图/删图/调排序是图集的**常态操作**；删了重发会丢 URL 与浏览者收藏，代价不可接受。图集有完整 Update 路径。
- **内容模型**：title + description + **有序媒体列表**（图片/视频，每项可选 caption）。媒体**引用** `upload.File`（`file_id`），不拷贝 URL——引用计数机制天然防误删被引用文件。
- **视频第一版只放行 mp4/webm**（浏览器原生可播）；avi/mkv 浏览器基本不能播，放进公开图集就是坏内容。**不做上传后转码**（ffmpeg 转码队列是大工程，作者自己保证源可播）。
- **浏览面**：`/galleries` 全站浏览流（时间倒序）+ `/galleries/$id` 详情页（网格 + 灯箱逐张浏览）+ 用户主页图集 tab + admin 图集管理页。

### 关键场景

| 场景 | 行为 |
|---|---|
| 摄影作品集 | 建图集 → 从素材库选 20 张或直接上传 → 拖拽排序 → 补 caption → 发布 |
| 教程步骤图 | 图集嵌正文链接分享；单图有 caption 说明步骤 |
| 事后修图集 | 加图插到中间、删掉废图、换封面——URL 与已传播的分享链接不变 |
| 误删素材库文件 | 该文件被图集引用（refCount > 0），删除被拒；先解除图集引用才能删 |
| 管理员治理 | admin 图集管理页下架违规图集（软删，前台不可见） |

## User Stories

1. 作为登录用户，我要建图集（标题/描述/封面），从素材库选图或现场上传，拖拽排序，每张图可写 caption。
2. 作为登录用户，我要能随时编辑已发布图集（增删图、调序、改标题），URL 保持不变。
3. 作为登录用户，图集里可以放短视频（mp4/webm），列表用视频缩略图，点开可播。
4. 作为访客（未登录），我要浏览全站图集流、打开图集详情，灯箱逐张看大图（键盘 ←/→ 导航）。
5. 作为访客，我要在用户主页 `/users/{username}` 看到该用户的图集列表。
6. 作为作者，我要删除自己的图集（解绑媒体引用，不删文件本身）。
7. 作为管理员，我要能下架任意违规图集（软删，对齐 admin.comments 治理形态）。

## Implementation Decisions

### 领域模型（domain/gallery）

```go
// Gallery 聚合根
type Gallery struct {
    shared.AggregateRoot
    ownerID     shared.ID // 创建者，固定不可变
    title       string    // ≤100 rune
    description string    // ≤2000 rune，可空
    coverFileID *shared.ID // 封面（可空，默认取第一项）
    status      string    // published / removed（管理员下架）
    items       []GalleryItem // 有序，重建时由仓储装载
}

// GalleryItem 图集项（聚合内值对象，无独立生命周期）
type GalleryItem struct {
    fileID  shared.ID // 引用 upload.File
    caption string    // ≤200 rune，可空
}
```

- 不变量：`len(items) ≤ 50`；每个 item 的 file 必须 `owner == gallery.owner` 且 file 为图片或 mp4/webm 视频（归属与类型校验在 application 层经 `GalleryMediaChecker` 端口，与 tweet 的 `TweetImageChecker` 同构依赖反转）；`ownerID` 无 setter。
- **可编辑**：`Update(title, description, coverFileID)` + `SetItems(items)`（全量替换落库，增删改排序一次完成——拖拽交互天然对应全量提交）。
- **物理删除作者可做**（解绑引用 refCount-1）；**管理员下架是软删**（status=removed，前台隐藏、保留记录供治理追溯）——两种删除语义并存，对齐 tweet 物理删 + comment 软删治理的各自先例。
- 发布即公开（无 draft 状态机）：图集创建轻量、编辑常态化，草稿价值低；首版即可见符合 UGC 即发即出模型。

### 数据库（migration 110 起，与 feat/chat 的 083-097、series 的 100-102 错开）

- **110**：`galleries(id uuid pk, owner_id uuid ref users, title, description, cover_file_id uuid null, status text default 'published', created_at, updated_at)`；索引 `(created_at DESC, id)`（浏览流）、`(owner_id, created_at DESC)`（用户主页）。
- **111**：`gallery_items(gallery_id uuid ref galleries on delete cascade, file_id uuid ref upload_files, caption text, position int, pk(gallery_id, file_id))`；索引 `(gallery_id, position)`。文件引用计数由 application 层维护（挂接 +1、移除/解绑 -1），`on delete cascade` 只管行级联不管 refCount——删图集用例先解绑再删聚合。
- **112**：seed 权限码 `gallery:view`（管理页可见）/ `gallery:delete-any` + menu 节点 `gallery`。建图集/编辑自己的不需要权限码，登录即可（对齐 tweet）。

### API（/api/v1，写操作走现有 SessionAuth + CSRF）

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/galleries` | 公开 | 全站浏览流，page/limit（更新频率低，非 feed，不引入 cursor） |
| GET | `/galleries/{id}` | 公开 | 详情（含 items 媒体 URL/宽高/缩略图，removed 的 404） |
| POST | `/galleries` | 登录 + 发布限流 | 建图集 `{title, description, items[]}` |
| PATCH | `/galleries/{id}` | owner | 编辑（title/description/cover/items 全量替换） |
| DELETE | `/galleries/{id}` | owner 或 `gallery:delete-any` | 作者物理删；管理员同样走此端点物理删（下架用 PATCH） |
| PATCH | `/galleries/{id}/status` | `gallery:delete-any` | 管理员下架/恢复（removed ↔ published） |
| GET | `/users/{username}/galleries` | 公开 | 用户主页图集列表 |

- 媒体上传：复用 `POST /api/v1/uploads`（登录可用），`purpose=material`（素材库选图与新上传同一池，图集专用 purpose 不必要——素材域已承载归属与元数据）。
- 发布限流：独立限流维度（如 5 个/小时/用户），复用 middleware 限流先例（UploadRateLimit 同构）。

### 前端（FSD）

- **lab 原型期（T0，先于实现）**：`/lab/gallery` 一页并排多个候选方向选型后落生产（对齐公告 lab 先例），静态 mock 不接 API。选型面：
  - 浏览流卡片：封面大卡片 / 九宫格预览 / 杂志横排。
  - 详情网格：等高行（Google Photos justified）/ 瀑布流 / 等宽网格。
  - 灯箱：全屏黑底逐张 / 带信息侧栏 / 上下翻页式。
  - 视频项：列表态缩略图播放钮 / inline 播放；灯箱内播放控件与 caption 位置。
- 路由：`galleries.index.tsx`（浏览流）、`galleries.$id.tsx`（详情）。
- `features/galleries`：
  - `GalleryComposer`：建/编图集（标题 + 描述 + 媒体网格：素材库选择器复用 + 现场上传走 upload 管线 + 拖拽排序 + caption 行内编辑）。
  - `GalleryDetail`：网格布局（响应式列数）+ 灯箱（全屏逐张、←/→ 键盘导航、caption 展示、视频项内嵌 `<video controls>`）。
  - 浏览流卡片：封面 + 标题 + 项数 + 作者 + 相对时间。
- 用户主页加「图集」tab（对齐推文 tab 的既有形态）。
- `admin.galleries.tsx`：图集管理页（分页列表 + 下架/恢复/删除），对齐 admin.comments 治理页模式（usePagedQuery + DataTable）。
- `HeaderNav` 加「图集」入口（视导航容量 T3 实现期定）。

### 装配

- `app/gallery_container.go` 手工 DI（同其它模块），挂 `container.go`。
- 路由挂 `interfaces/http/routing/router.go` 公开区（GET）+ 登录区（POST/PATCH owner）+ admin 权限区（治理端点）。

## Testing Decisions

- **聚合根**：title 边界（空/超长）、items ≤50 边界、caption 长度、Update 改字段、SetItems 全量替换、removed 状态不可由 owner 自设。
- **service**：建图集（媒体归属校验失败分支、类型拒绝分支——非图片且非 mp4/webm 拒绝）；编辑三分支（owner/他人 403/removed 后不可编辑）；删除（作者物理删 + refCount 解绑、管理员删任意）；下架/恢复往返；限流触发。
- **handler**：匿名 GET 通过、匿名 POST 401、无 `gallery:delete-any` 下架 403、removed 详情 404。
- **引用计数**：挂接 +1、移除 -1、删图集全量解绑、被引用文件删除被拒（upload 域已有机制，测集成行为）。
- 不测：灯箱交互细节（前端 UI）、限流中间件本身（已有覆盖）。

## Out of Scope

- **先审后发**：即发即出 + 事后治理，对齐 tweet。若垃圾图集成为问题，后期加状态列是破坏性迁移（同 tweet PRD 的已知代价）。
- **图集点赞/评论/收藏**：互动闭环本期不做，需求出现再议。
- **上传后转码**：不做 ffmpeg 转码队列；avi/mkv 等浏览器不可播格式直接拒绝进图集。
- **音频/PDF 进图集**：upload 域支持但不进图集（图集是视觉内容合集）。
- **私密/仅链接可见图集**：只有公开一种可见性。
- **拖拽批量水印/EXIF 处理**：不做。

## 难逆决策

- **items 引用 file_id 而非拷贝 URL**：引用计数防误删是 upload 域既有机制的正确复用；代价是图集渲染需联查文件表（一次 in 查询，量级可控）。
- **可编辑（偏离 tweet 不可编辑）**：图集有完整 Update 路径与编辑历史缺失的代价（改了什么无审计），换取常态编辑不丢 URL。与 tweet 的差异是内容形态决定的，记录在此防止「统一到 tweet 模型」的回头路。
- **作者物理删 + 管理员软删下架双轨**：作者的私产处置走干净删除；治理动作要留痕走软删。两种删除语义并存是这个域的固有复杂度。
- **无 draft 状态机**：即发即出。后期加草稿是加列迁移（存量全置 published），与 tweet 同一已知代价。
- **视频白名单收窄到 mp4/webm**：upload 域接受更多视频格式，但图集域只放行浏览器可播的两种。白名单是图集域自己的校验层，不动 upload 域。

## 业界参考

- **UGC 事后治理**：X Community Notes / bilibili 举报下架模式——即发即出 + 管理员下架兜底，同 tweet PRD-0013 决策。
- **引用计数防误删**：本站 upload 域既有 refCount 机制（图集项复用），同 「AWS S3 生命周期引用」的通用模式。
- **图集浏览形态**：Google Photos / Flickr 的网格 + 灯箱双态是成熟惯例；键盘 ←/→ 导航是桌面端基线。
- **可编辑合集**：Pinterest board / 微博合集均可编辑排序——合集类内容的常态是持续整理，与瞬时动态（tweet）的生命周期不同。
