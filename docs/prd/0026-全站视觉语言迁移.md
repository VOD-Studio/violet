# PRD: 全站视觉语言迁移

## Problem Statement

Violet 首页已经形成经过真实内容与双主题验证的视觉语言：近白／柔和炭黑画布、低占比暖珊瑚强调、稳定的中文排版、宽松留白、轻边界与克制动效。但其他公开页面、账户入口、聊天、编辑器和后台仍来自不同阶段，颜色语义、表面层级、控件密度与交互反馈不一致。访客从首页进入其他页面时会感到视觉世界中断，维护者也必须在多个局部样式里重复判断同一状态应该如何表达。

直接把首页 token 或布局全局覆盖不是可接受方案。后台和编辑器是高密度工具，灯箱与媒体查看器需要中性舞台，危险、警告与成功状态不能跟随品牌色变化。此前首页明明声明了暖珊瑚 scoped token，Tailwind 工具类却在根作用域提前求值成中性色，导致首页退化成黑白；现有 jsdom 测试无法观察真实浏览器的 CSS 级联，因此该回归能够进入分支。

`web/src/styles.css` 同时承担 Tailwind theme 映射、全局 token、首页方言、页面转场、文章排版、实验舞台、批注与滚动条，已经成为无关改动共享的维护热点。未来计划提供多套官方配色并允许用户自定义强调色；如果本轮继续硬编码暖珊瑚或继续扩张单文件，后续主题能力会要求再次改造所有页面和控件。

## Solution

建立一套共享视觉基因和三种视觉方言，并在不改变业务行为的前提下逐页迁移现有界面：

- **公开内容语言**强继承首页，用单一品牌强调色、近白／炭黑画布、内容优先排版和宽松节奏承载公开阅读、发现与登录入口。
- **工具语言**服务后台、编辑器、设置、个人中心与聊天，沿用品牌基因，但使用更高信息密度、更明确的边界和完整的行为状态。
- **沉浸语言**服务灯箱、媒体查看器与图表舞台，保持中性背景，让媒体内容优先，仅在控件反馈中使用品牌强调色。
- `/lab/*` 保持实验豁免，不纳入正式方言验收，也不能反向改写全站 token。

主题接口把外观模式、配色方案和自定义强调色分离。当前只启用暖珊瑚默认方案，但所有迁移页面都通过 semantic token 消费主题，不直接依赖具体色值。共享控件保留一套行为接口，通过视觉方言决定主要动作色；行为状态色保持稳定。全局样式按所有权拆分，组件专属样式回到组件旁的 CSS Module。

不制作独立视觉原型。迁移按页面家族直接落到真实界面，每个页面在完成浏览器验收后再进入下一页。新增一条永久的薄真实浏览器契约接入 CI，验证实际计算 token、主题首帧、关键控件状态和响应式溢出，不维护整页像素快照。

## User Stories

1. 作为首次访问者，我希望从首页进入其他公开页面时仍处于同一个视觉世界，不需要重新理解颜色和交互含义。
2. 作为读者，我希望博客列表、文章详情、系列、笔记和推文使用一致的内容层级，让注意力停留在作品而不是装饰上。
3. 作为图库与人设访客，我希望图片仍是页面主角，同时导航、链接、焦点和元信息与首页共享品牌语言。
4. 作为访问 About、友链、项目、公告和更新日志的访客，我希望这些页面继承首页原则，但保留各自的信息结构。
5. 作为匿名访客，我希望登录、注册和找回密码页面与公开站点连续，而不是突然进入通用后台表单模板。
6. 作为登录用户，我希望个人中心采用清晰、紧凑的工具语言，避免用首页的大留白降低操作效率。
7. 作为聊天用户，我希望连续消息、输入和状态反馈保持高密度可扫描，同时仍能识别 Violet 的品牌焦点与选中态。
8. 作为内容作者，我希望编辑器优先保证写作画布、工具栏和保存状态，不因公开页面装饰降低可用空间。
9. 作为管理员，我希望列表、筛选、分页、批量操作和弹层保持高信息密度，并使用明确边界组织复杂任务。
10. 作为管理员，我希望主要操作按钮保持高对比中性色，避免大量品牌色按钮形成噪音。
11. 作为管理员，我希望当前导航、焦点、选中与进度仍使用当前品牌强调色，从而与公开站点保持品牌连续性。
12. 作为任何用户，我希望删除、撤权等危险操作始终使用固定危险语义，不因切换配色而改变含义。
13. 作为任何用户，我希望警告、成功和错误状态除颜色外还有文字或图标提示，不依赖色觉区分。
14. 作为媒体浏览者，我希望灯箱使用中性舞台并最大化内容可见度，而不是给图片覆盖大面积品牌色。
15. 作为键盘用户，我希望所有正式方言都有清晰、达到对比度要求的 `focus-visible` 指示。
16. 作为减弱动态用户，我希望方向性位移和装饰循环被取消，但状态变化与焦点反馈仍然可见。
17. 作为移动端用户，我希望正式页面在 `390 × 844` 视口没有横向溢出、被裁切操作或只适合鼠标的交互。
18. 作为桌面用户，我希望正式页面在 `1440 × 900` 视口利用可用空间，同时保持稳定行宽和信息层级。
19. 作为深色模式用户，我希望深色主题不是简单反相，并保持与浅色主题相同的品牌关系与内容可读性。
20. 作为跟随系统主题的用户，我希望系统明暗变化后页面平滑进入正确外观，不产生错误中间状态。
21. 作为刷新页面的用户，我希望 SSR 首帧直接使用正确主题，不先闪出另一套背景或强调色。
22. 作为维护者，我希望首页、工具界面和沉浸界面使用明确命名的视觉方言，而不是在调用方堆叠例外 class。
23. 作为维护者，我希望共享 Button、Input 和表单状态只有一套行为接口，使无障碍与错误修复一次覆盖所有页面。
24. 作为维护者，我希望组件专属样式与组件同目录维护，不必在一个全局样式文件中寻找无关规则。
25. 作为维护者，我希望新增官方配色时只增加一个 palette 适配，不需要逐页替换颜色 class。
26. 作为未来主题功能开发者，我希望用户自定义只提交一个强调色种子，派生与对比度校验由主题模块统一完成。
27. 作为未来账号偏好开发者，我希望主题接口已经区分 Appearance、Palette 和 Custom Accent，避免修改现有页面消费方式。
28. 作为站点管理员，我希望未来能够设置站点默认方案，同时不覆盖用户已经做出的个人选择。
29. 作为实验功能开发者，我希望 `/lab/*` 可以探索不同视觉方向，但实验样式不会泄漏到正式页面。
30. 作为评审者，我希望每个页面家族的迁移都可独立运行、浏览和回滚，而不是面对一次无法定位问题的全站样式大提交。
31. 作为 CI 维护者，我希望真实浏览器能捕获 CSS 自定义属性级联和 SSR 主题首帧问题，而不是依赖 jsdom 推断视觉结果。
32. 作为内容维护者，我希望视觉迁移保留现有真实数据、路由、权限与交互，不制造用于填满版面的伪内容。

## Implementation Decisions

### 主题接口

- 主题模块对调用方只暴露三个概念：Appearance、Palette 和 Custom Accent。页面与共享控件只消费 semantic token，不感知具体 palette 名称或颜色算法。
- Appearance 取 `system / light / dark`，只决定明暗环境；Palette 取官方预设或 `custom`，只决定品牌强调色；Custom Accent 是自定义方案的单一颜色种子。
- 当前迁移只提供暖珊瑚默认 palette 适配。模块接口必须允许后续增加预设或自定义适配而不修改页面调用方。
- Tailwind theme 中引用运行时 CSS 变量的映射必须在工具类使用点求值，保证页面方言作用域能覆盖 semantic token。

### Token 分层

- 基础语义层负责画布、正文、卡片、浮层、静音表面、边界、输入、焦点以及 destructive、warning、success 等行为状态。
- 品牌层负责 accent、accent foreground、accent hover、accent wash 和 accent focus ring。一次界面只允许一个品牌强调色。
- 动作层把“品牌强调”与“主要动作”分开。公开内容与登录入口的主要动作映射到品牌强调色；工具语言的主要动作映射到高对比中性色。
- 方言层只调整任务场景需要的密度、表面和动作映射，不复制基础 token，也不改写行为状态含义。
- 沉浸语言默认使用中性舞台；品牌色只出现在焦点、选中、进度和低占比控件反馈中。

### 视觉方言边界

- 公开内容语言覆盖首页、博客、文章、系列、笔记、推文、图库、人设、友链、项目、About、公告、更新日志和公开用户页。
- 登录、注册、找回密码等公开入口使用简化的公开内容语言。
- 后台、编辑器、设置、个人中心和聊天使用工具语言。
- 灯箱、媒体查看器与内容型图表舞台使用沉浸语言。
- `/lab/*` 不迁移为正式方言；正式组件可以在实验室陈列，但实验规则不能成为全局依赖。
- Header 与 Footer 作为跨页面 chrome 接受 semantic token 审计，但本轮不以“统一风格”为理由破坏已验证的布局与交互几何。

### 共享控件

- Button、Input、Select、Dialog、Sheet、Popover、Badge 等共享控件保留单一行为接口；不创建公开版和后台版分支。
- Button 延续既有 default、secondary、outline、ghost、destructive 和 link 等 semantic variant。方言决定 default 的动作色，调用方不通过 `className` 覆盖颜色语义。
- 现有把普通按钮临时染成危险色或在调用方重复 hover/focus 颜色的用法，应迁移到正式 semantic variant 或对应状态组件。
- 控件尺寸仍由组件 size 与页面密度决定，品牌 palette 不改变触控面积、字体大小或布局尺寸。

### 样式所有权

- 全局样式入口只负责导入 Tailwind、字体和独立全局样式层，不继续承载所有实现。
- theme 映射、基础 token、默认 palette、视觉方言、全局基础行为和页面转场分别维护，降低共享文件冲突。
- 组件专属布局、动效与装饰迁移到组件旁的 CSS Module。
- 富文本、编辑器文档树等运行时生成 DOM 的规则由对应 feature 持有 scoped stylesheet 或受控的全局选择器入口。
- 样式拆分先于页面迁移完成，使后续 issue 在稳定 seam 上工作；拆分只改变所有权，不顺手重做视觉。

### 迁移策略

- 不制作独立原型；直接在真实路由上逐页迁移。
- 先建立样式所有权、主题接口、默认 palette、三种方言作用域和浏览器契约，再迁移页面。
- 页面迁移按可独立验证和回滚的家族推进。每个家族完成真实数据、桌面／移动、浅色／深色与关键交互验收后，下一家族才开始。
- 公开内容先于工具语言，工具语言先于沉浸界面；共享控件语义在首个公开与首个工具页面共同验证后固定。
- 不以视觉迁移为理由改变路由、查询、权限、内容模型或业务流程。

### 未来持久化契约

- 匿名主题偏好使用版本化 Cookie，SSR 直接读取，避免首帧闪色。
- 登录用户的偏好同时写账号与 Cookie；账号已有偏好时账号优先，账号尚无偏好时把匿名选择升级为账号偏好。
- 用户没有偏好时使用站点管理员默认方案；Appearance 为 `system` 时再由操作系统解析实际明暗。
- 本轮不实现配色选择器、账号字段、API、Cookie schema 或自定义颜色校验 UI；这些作为后续独立 feature 使用既定主题接口。

## Testing Decisions

- 新增一条永久的真实浏览器主题契约并接入前端 CI。它是主题和视觉方言的最高测试 seam，必须运行真实 CSS 解析，不用 jsdom 模拟 OKLCH 或自定义属性级联。
- 浏览器契约每种正式方言选择一个真实路由，验证计算后的品牌强调、主要动作、行为状态和画布 token；同时验证全局 token 没有被页面 scope 泄漏。
- 浏览器契约覆盖 `390 × 844` 与 `1440 × 900`，至少覆盖 light 和 dark，并验证 system 的解析结果。断言页面无横向溢出。
- SSR 主题检查在 hydration 前读取首帧 class、背景和强调 token，再在 hydration 后复核，二者必须一致。
- 控件契约验证公开内容方言的 default action 使用品牌强调色、工具方言使用高对比中性色、destructive 始终保持危险语义。
- 普通文字对比度至少 `4.5:1`；大字号文字、控件边界和焦点指示至少 `3:1`。状态还必须存在文本、图标或结构性提示。
- 不维护整页像素截图基线。布局和审美由每个迁移 issue 的真实浏览器截图与交互验收证明；永久测试只锁稳定的语义契约。
- 现有 Vitest 继续覆盖主题切换编排、状态变换和共享控件行为。不得新增读取 CSS 源文本或断言 class 字符串的伪视觉测试。
- 每个迁移 issue 必须运行相关现有行为测试、前端 lint、typecheck 和生产构建；涉及页面视觉时必须额外完成真实浏览器验证。
- 首页黑白回归是浏览器契约的先例：修复前 `text-primary` 实际色度为 `0`，修复后浅色为 `0.19`、深色为 `0.15`。契约应能捕获同类作用域失效，但不锁定这些具体色值，改为验证 palette 与方言的语义关系。

## Out of Scope

- 本轮不提供多套可选 palette、不提供颜色选择器，也不开放用户自定义颜色入口。
- 本轮不新增用户主题偏好字段、数据库迁移、后端 API、站点默认 palette 配置或登录合并逻辑。
- 不把 `/lab/*` 统一成正式视觉，也不删除现有实验候选。
- 不为所有路由制作独立视觉原型或设计稿。
- 不引入整页像素快照测试和大规模截图基线维护流程。
- 不重做首页已通过终审的内容结构，不用其他页面反向改写首页布局。
- 不因视觉迁移修改业务权限、内容数据、分页协议、编辑流程或媒体生命周期。
- 不让用户自定义画布、正文、表面层级或 destructive、warning、success 等行为语义色。
- 不创建公开版与后台版两套共享控件。

## Further Notes

- `DESIGN.md` 是视觉规则的当前规范；ADR-0015 记录视觉方言、主题边界、持久化优先级与样式所有权的不可逆决策。
- 首页暖珊瑚作用域回归已经在当前分支通过独立提交修复，后续基础设施 issue 负责把该行为纳入永久浏览器契约，不重复修补页面颜色。
- 本 PRD 与后续 issues、实现提交均留在当前 feature 生命周期所在分支；按职责拆成可独立回滚的提交，不把全站迁移压成单个提交。
