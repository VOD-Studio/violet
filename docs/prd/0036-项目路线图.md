# PRD-0036：项目路线图

状态：规格定稿；后端 T13–T18 已实现，站点项目页与文章嵌入待接入。术语见 `CONTEXT.md`「项目路线图」「看板组件」两节，决策见 [ADR-0021](../adr/0021-roadmap-manual-maintenance.md)、[ADR-0022](../adr/0022-roadmap-typed-relation-graph.md) 与 [ADR-0023](../adr/0023-roadmap-canvas-drag-controller.md)。

## Problem Statement

作为站点主人，我在维护多个项目（violet、kite、kodama 等），读者看不到它们的进度：现有「项目」页只是一个静态卡片网格，只有封面、描述、技术栈和链接，没有「做了什么、在做什么、规划什么」的概念，没有项目详情页，视觉上也不让我满意。

我没有办法表达一个大功能延伸出的后续扩展、缺陷修复，以及哪些功能被另一个功能阻塞。我也不能在文章里嵌入某个项目的进展。每次想展示进度，只能手写一段文字。

另外我想要一个真正优秀、可复用的看板组件，而不是只为这个页面写一次性的拖拽代码：键盘和读屏可用、拖拽平滑、可撤销、关系可视化，且不绑定本站的业务和样式。

## Solution

为每个项目提供一份由我手工维护的**路线图**，读者在项目详情页只读查看，我登录后在同一页面原地编辑。

- 路线图由**路线图条目**组成，每个条目处于规划中、开发中、已完成三个**阶段**之一，条目之间可以建立扩展、修复、阻塞三种**条目关系**。
- 项目列表页用「叙事大行」，直接回答「现在在做什么、最近完成了什么、进度如何」。
- 项目详情页用可平移缩放的**画布**，条目按阶段自动分区，关系线常显，选中条目时高亮相关连线。窄屏回退为阶段切换器。
- 管理员在画布里直接拖动条目跨阶段、列内排序；支持键盘拖拽、撤销重做、乐观更新与失败回滚。
- 文章中可以用 `roadmap` 围栏块嵌入条目卡片、项目卡片、看板画布和关系画布。
- 交互与关系可视化由一个通用的 workspace 包 `@violetjs/kanban` 提供，本次不发布到 npm。该包还配一个位于导航「更多」下的 `/kanban` 文档与演示菜单。

## User Stories

### 访客：项目列表

1. 作为访客，我想在项目列表看到每个项目现在正在做的事情，以便判断这个项目是否活跃。
2. 作为访客，我想在项目列表看到每个项目最近完成的一条及其完成日期，以便了解最近的交付节奏。
3. 作为访客，我想在列表里看到每个项目三个阶段的条目数量和已完成占比，以便快速比较项目进度。
4. 作为访客，我想在列表里仍能看到封面图、简介、技术栈，以便识别项目是什么。
5. 作为访客，我想点击一个项目进入它的详情页，以便看到完整路线图。
6. 作为访客，我想让没有任何路线图条目的项目仍然正常显示，且不出现空的进度区块，以便不被误导。
7. 作为访客，我想让封面图失效时显示占位图，以便页面不出现碎图。
8. 作为访客，我想按站主设定的顺序看到项目，以便重要项目靠前。

### 访客：项目详情与画布

9. 作为访客，我想通过稳定、可读的网址（例如 `/projects/violet`）访问项目，以便分享链接。
10. 作为访客，我想访问不存在的项目时看到 404，以便知道链接有误。
11. 作为访客，我想在详情页头部看到标题、简介、技术栈、演示与源码链接和进度概览，以便先了解项目全貌。
12. 作为访客，我想在画布上按规划中、开发中、已完成三个分区看到全部条目，以便一眼看出进展分布。
13. 作为访客，我想让每个条目卡片显示编号 #N、标题和条目标签，以便识别并在讨论中引用。
14. 作为访客，我想让已完成的条目显示完成日期，以便知道何时交付。
15. 作为访客，我想让被阻塞的条目带有「被阻塞」标记，以便知道哪些规划受制于前置功能。
16. 作为访客，我想点击条目打开详情弹窗，看到简介、子项清单、条目标签、交付版本、完成日期、关联链接和关系列表，以便深入了解。
17. 作为访客，我想让条目之间的关系线常显，并用线型区分扩展、修复、阻塞，以便不靠颜色也能读懂关系。
18. 作为访客，我想在选中条目时高亮它的相关条目和连线并淡化其余，以便聚焦一条脉络。
19. 作为访客，我想隐藏关系线，以便在条目很多时恢复清爽。
20. 作为访客，我想拖动画布背景平移，以便查看超出视口的条目。
21. 作为访客，我想用 Ctrl/⌘ 加滚轮、按钮或触屏双指缩放画布，并能一键适应窗口，以便在概览和细节间切换。
22. 作为访客，我想让普通滚轮继续滚动整个页面而不被画布劫持，以便正常阅读。
23. 作为访客，我想把画布全屏查看，并用 Esc 退出，以便条目很多时更舒展地阅读。
24. 作为访客，我想让已完成阶段默认只展开最近 10 条并可展开更多，以便页面不被历史条目淹没。
25. 作为访客，我想按关键字搜索条目标题与简介，并按条目标签筛选，以便找到感兴趣的功能。
26. 作为访客，我想让不匹配筛选的条目淡化但保持原位，以便筛选前后不迷失位置。
27. 作为访客，我想在手机上通过阶段切换器一次查看一个阶段，以便文字清晰可读。
28. 作为访客，我想在手机上从卡片上的标记（例如「扩展 #3」「被 #11 阻塞」）看到关系，并能点击跳转到对应条目，以便窄屏下也不丢失关系信息。
29. 作为访客，我想让页面在暗色模式下同样清晰，以便夜间阅读。
30. 作为访客，我想让页面首屏直出而不是先空白再加载，以便快速看到内容并利于搜索引擎收录。
31. 作为访客，我想在保存发生后下次打开页面或切回窗口时看到最新进度，以便总是看到当前状态。

### 键盘、读屏与减弱动态用户

32. 作为键盘用户，我想用 Tab 聚焦条目、用 Enter 打开详情，以便不依赖鼠标。
33. 作为读屏用户，我想从条目的文字描述读到它的编号、标题、阶段、被阻塞状态和关系，以便不依赖连线图形获得同样的信息。
34. 作为读屏用户，我想让关系线有文本等价物（相关条目列表），以便理解图中看不到的连接。
35. 作为键盘用户，我想让聚焦环在可滚动、可缩放的区域里不被裁剪，以便知道当前焦点位置。
36. 作为偏好减弱动态的用户，我想让位置过渡与缩放动画被关闭或显著减弱，以便不引起不适。
37. 作为任何用户，我想让条目在拖拽之外也有明确的操作入口，以便不会被拖拽手势排除在外。

## Implementation Decisions

### 总体结构

- 工作分为四个交付物：`@violetjs/kanban` 包、后端路线图能力、站点项目页与文章嵌入、`/kanban` 文档与演示。依赖顺序为包 → 后端 → 站点 → 嵌入与文档；按 AGENTS.md 的职责边界分开提交（包的能力单独提交，业务接入另行提交，后端提供方先于前端消费方）。
- 业务文档使用业务术语（路线图条目、阶段），包文档使用通用术语（卡片、列、移动）；两套术语不混用。
- 决策依据：ADR-0021（手工维护，不从 GitHub 派生）、ADR-0022（带类型的有向图，同一类型内不成环，阶段不由关系推导）、ADR-0023（画布使用自写拖拽控制器，包内保留引擎无关的接缝）。

### 看板包 `@violetjs/kanban`

- 作为 workspace 包，作用域与 `inkline`、`react-tweet` 一致，MIT 许可，peer 依赖 React 19，不依赖 `@violet/ui` 与任何站点私有模块。本次不发布；发布需要把它加入发布工作流并另行授权。
- 公开入口分层：带样式的根入口、不带样式的入口、不依赖 React 的 `/core`、画布视口入口 `/canvas`、关系图入口 `/graph`、样式表入口。
- 数据模型：卡片泛型只要求 id；看板状态是「列的顺序」与「每列内卡片 id 的顺序」；包不持有卡片内容。
- 移动：描述「某卡片从某列某位置到另一列另一位置」。目标位置是去掉被拖卡片后的列内索引，并附带前后相邻卡片的 id，供使用方持久化。使用方决定接受或拒绝，拒绝时卡片回到原位。移动事件可返回 Promise。
- 规则钩子：`canMove` 返回是否允许及原因。列可声明为自动排序：进入时位置由使用方决定，列内不可手动重排（路线图的已完成阶段即此用法）。
- 被阻塞等派生展示由使用方通过卡片插槽与边类型映射表达，包内不认识「阶段」「完成日期」等业务概念。
- 拖拽控制器：包内有与引擎无关的接缝，默认实现是自写指针控制器。原型实测的关键行为：
  - 指针捕获，移动超过 4px 才开始拖拽，之前仍视为点击；拖拽后抑制随之而来的点击。
  - 被拖卡片跟随指针且不做过渡，其余卡片以位置过渡让位，目标位置显示虚线占位；释放后平滑落位。
  - 指针靠近视口边缘 48px 以内时按帧自动平移。
  - 画布缩放平移下，落点按画布坐标换算，缩放到约 51% 时仍落在正确的列。
  - Esc 或焦点离开取消拖拽。
  - 键盘移动不经过控制器接缝，按离散的列与位置进行：空格或 Enter 拿起，上下方向键在列内移动，左右方向键换列，空格或 Enter 放下，Esc 或焦点离开取消；对自动排序列的上下移动给出拒绝提示；每一步经 aria-live 播报。
  - 提供「移到…」菜单作为拖拽的单指针替代（对应 WCAG 2.2 的 2.5.7）。
- 原型对比 dnd-kit 的实测结论（记录以便复核，不在包内使用）：在 transform 定位的缩放画布里，默认的「忽略自身 transform」测量把起始矩形算偏约 650px；拖拽中被拖节点必须不动，实时让位需另写；浮层内容需手动乘以缩放；没有画布自动平移；SSR 水合需固定 id；键盘需自写 coordinateGetter。
- 动画：位置变化（让位、落位、折叠）用约 200ms 的平滑位移；抬起用软影加描边，不使用 `scale`；全部遵守减弱动态。画布缩放属于「缩放即交互」的例外。
- 撤销与重做：命令式历史，命令携带正向与反向操作；仅限当前会话、最多保留 50 步、刷新后清空。撤销是一次反向操作并走使用方的持久化，失败则该历史项作废。覆盖移动、新增、删除、编辑，由使用方把各类变更包装为命令。快捷键为 Ctrl/⌘+Z，且在输入控件内不拦截。
- 乐观更新：移动先更新界面，持久化失败则回滚并触发错误回调。
- 筛选：接受筛选谓词；不匹配的卡片淡化并保持原位；筛选生效时整板禁用拖拽并给出提示。
- 其余交互壳：列折叠与列头计数、列底快速添加、标题内联编辑；保存与校验由使用方负责。
- 画布视口：背景拖动平移；缩放范围 0.3 到 2，支持 Ctrl/⌘ 加滚轮、按钮、触屏双指与键盘；「适应窗口」默认缩放不低于 0.8，超出部分靠平移；全屏用 Esc 退出，但拖拽进行中的 Esc 优先取消拖拽；普通滚轮不劫持页面滚动；画布内的指针处理不与页面级快捷键冲突。
- 窄屏：按容器宽度自动在画布与阶段切换器布局间切换，阈值可配置（默认约 768px）。窄屏用「移到…」菜单做跨列移动，关系用卡片上的标记表达并可点击跳转。
- 关系：边由「来源、目标、类型」构成，方向读作「来源 扩展/修复/阻塞 目标」。包提供环检测、自指拒绝、邻接查询与自动布局。环检测按类型分别进行，不跨类型合并（见 Further Notes）。画布上关系线常显，选中时高亮相关并淡化其余，另有「隐藏连线」开关；线型区分类型（扩展实线、修复虚线、阻塞警示色加挡条），不只靠颜色；并提供文本等价的相关条目列表。
- 关系图：按阶段分区自动布局，只读，不保存任何坐标；布局对同一输入结果确定；可按指定条目取其相关子图。
- 无障碍：所有操作可键盘完成；聚焦环不被可滚动容器裁剪（裁剪层预留不少于 4px 的内边距）；读屏播报；遵守减弱动态。
- 样式：默认外观用 CSS 变量，遵守仓库视觉红线（功能圆角不超过 16px，仅使用规定的软影，不用 `scale` 做反馈）。原型的视觉不是最终设计，最终视觉在实现阶段按组件库规范重做。
- 文案：内置英文与简体中文，可通过 `messages` 覆盖。

### 后端：路线图

- `Project` 聚合新增唯一的 slug，格式沿用文章 slug 规则（小写字母数字连字符）；存量项目迁移时按标题生成，冲突时加后缀，无法生成时用确定性的兜底值。
- 新增路线图条目聚合，归属项目。字段：项目内自增且永不复用的编号、标题（必填）、纯文本简介、阶段、位置排序键、条目标签（自由文本多选，仅属于所在项目）、关联链接列表、子项清单（有序，每项为纯文本与是否完成，只展示推进细节，不影响阶段与项目进度）、完成日期、交付版本（自由文本，可空）、软删除时间与时间戳。
- 位置使用分数索引（排序键为可排序字符串），一次移动只改一行。移动请求携带目标阶段与相邻条目 id；相邻条目已不存在或已移动时，回退到目标阶段中确定性的位置（末尾）。已完成阶段读取时按完成日期倒序，同日按编号倒序，排序键对其不起作用。
- 阶段规则：
  - 进入已完成：完成日期默认当天（也可显式提供），交付版本可空。
  - 离开已完成：完成日期与交付版本一并清空。
  - 完成日期与交付版本仅在已完成阶段存在。
  - 已完成阶段内不接受手动重排。
- 条目关系：同一项目内的 `来源、目标、类型`，类型限扩展、修复、阻塞；同一类型下 `来源、目标` 唯一；不得指向自身；同一类型内不得成环；不允许跨项目。软删除的条目其关系不再出现在读取结果里，恢复时一并恢复。
- 软删除：删除只标记删除时间；恢复接口还原同一条目（同编号、同位置、同内容）以支撑撤销；本次不做清理与回收站界面。
- 读模型：
  - 进度概览：三阶段数量与已完成占比（整数四舍五入，已完成除以未删除条目总数）。
  - 被阻塞：存在未完成的阻塞前置条目的条目，派生标记，不改变阶段。
  - 列表接口为每个项目附带进度概览、至多 2 条「现在在做」与 1 条「最近完成」及日期。
  - 详情接口按 slug 返回项目、全部条目与关系，全部公开。
- 写接口需要项目更新权限（沿用现有 `project:update`，不新增权限点）：创建、编辑、移动、软删除与恢复条目，创建与删除关系。移动返回受影响条目（含自动清空或记录的日期）供前端对账。
- 操作日志记录新增、删除、编辑、阶段变更，不记录同阶段内的排序；撤销产生的反向操作按同一规则记录。
- 并发：以最后写入为准，不引入冲突界面。
- 保存即生效：写入后相关读取立即失效；本次不做实时推送。
- OpenAPI 与路由对账同步；数据库迁移带可回退的 down。
- 后台项目管理只新增 slug 的编辑，不包含路线图编辑页。

### 站点

- 路由：`/projects` 为列表页，`/projects/<slug>` 为详情页，未知 slug 返回 404；导航里的「项目」菜单不变，不新增顶层菜单。
- 列表页（叙事大行）：每个项目一行，包含真实封面图（失效回落占位）、标题、两行简介、技术栈、「现在在做」（至多 2 条）、「最近完成」（1 条加日期）、进度条与数字。无路线图条目时隐藏进度区。
- 详情页：头部为标题、简介、技术栈、演示与源码链接、进度概览；主体为画布，窄屏回退阶段切换器；带搜索与条目标签筛选；已完成阶段默认展开最近 10 条。
- 编辑：具备项目更新权限的管理员在同一页面直接编辑；条目详情用淡入淡出的弹窗，不使用滑入面板；删除使用「撤销」提示；撤销重做、乐观更新、键盘拖拽、「移到…」菜单与筛选时禁用拖拽均通过看板包的接口接入。
- 数据：使用现有查询库；详情页与列表页在服务端预取以保证首屏直出；保存后使相关查询失效，窗口重新聚焦时重新拉取。
- 迁移分两步：先提供新页面并保留旧调用链，再切换全部消费方并同时删除旧的列表卡片实现与过期测试；最终交付不保留重复实现。
- 动效遵守 AGENTS.md：不为常规反馈使用缩放，不用装饰性的滑入滑出；浮起只用规定的软影。

### 文章嵌入

- `roadmap` 围栏块，JSON 参数：
  - `project`（slug，必填）。
  - `item`（项目内条目编号，可选）。
  - `display`：`card` 或 `canvas`。
  - `view`：`board` 或 `graph`，仅 `canvas` 使用，默认 `board`。
- 分派规则：
  - `card` 带 `item` 为条目卡片。
  - `card` 不带 `item` 为项目卡片。
  - `canvas` 且 `view` 为 `board` 为看板画布。
  - `canvas` 且 `view` 为 `graph` 为整个项目的关系画布。
  - `graph` 带 `item` 时为以该条目为根的关系画布。
- 组件形态：两种卡片是结构不同的两个组件，共用同一个卡片外框（头部、跳转、加载、不存在、出错状态），变体只管密度与主题；两种画布共用画布视口，内容分别是看板与关系图。卡片属于站内 feature，画布使用看板包。
- 阅读时读取当前公开数据，不保存快照；卡片在服务端首屏直出，画布在客户端加载。引用的项目或条目不存在时降级为占位说明，不中断文章渲染；参数非法时给出可读提示。
- 嵌入内的画布同样不劫持页面滚动，可全屏；点击条目打开与项目页相同的只读详情。
- 编辑器：支持围栏块输入，并增加 Slash 菜单项「路线图」，弹层选择项目、条目与形态，编辑区实时预览。该能力归入「语义内容卡片」，不进图块渲染器注册表；在编辑器语法手册里新增对应小节。

## Testing Decisions

- 好的测试只断言外部可观察行为，不断言内部实现；视觉像素不在自动化范围内。
- 三个接缝，各取该层最高的一点：

### 接缝一：看板包的公开入口

- `/core` 纯函数单元测试：移动规则（含自动排序列的拒绝与进入位置）、落点解析、相邻卡片计算、关系校验（自指、成环）、撤销历史（含恢复被自动清空的字段）、布局确定性。
- 组件行为测试（Vitest 加 jsdom，参照 react-tweet 组件测试）：键盘拖拽全流程与播报文案、只读、`canMove` 拒绝与原因、乐观更新失败回滚、筛选时禁用拖拽、窄屏布局切换、「移到…」菜单。
- 真实浏览器测试：缩放与平移下的指针拖拽落点、边缘自动平移、普通滚轮不劫持、Ctrl/⌘ 加滚轮缩放、全屏与 Esc 的优先级、聚焦环不被裁剪；触屏拖拽、双指缩放与读屏必须在真机或真实读屏上人工验收并记录。
- 发布形态验收：在工作区外安装真实 tarball，校验类型、SSR、构建与入口依赖图（参照 react-tweet 与 `@violet/ui` 的消费验收）。

### 接缝二：后端路线图应用服务

- 通过应用服务的接口断言领域不变量，使用手写的仓储桩（参照项目服务的现有测试），并配合领域实体测试：
  - 阶段规则：进入已完成记录完成日期，离开已完成清空完成日期与交付版本。
  - 已完成阶段不接受手动重排，按完成日期倒序读取。
  - 编号项目内自增、删除后不复用。
  - 关系：同类型下唯一、自指、成环、跨项目被拒绝。
  - 软删除与恢复（含关系）、移动时相邻条目缺失的回退位置。
  - 进度概览与被阻塞的派生；slug 唯一与格式；存量 slug 迁移的冲突处理。
  - 操作日志的记录范围（同阶段排序不记录）。
- HTTP 层不另设测试，由现有的路由与 OpenAPI 对账测试覆盖新增路由；迁移需验证 up 与 down。

### 接缝三：站点页面

- 使用 Playwright 加 mock API（参照现有聊天乐观更新等端到端测试）走真实路由：
  - 访客只读：列表页内容、详情页画布、条目弹窗、筛选、全屏、404。
  - 管理员编辑：拖拽、键盘拖拽、「移到…」、撤销重做、软删除与恢复、建立与删除关系、筛选时禁用拖拽。
  - 窄屏：阶段切换器与关系标记。
  - 首屏直出。
  - 文章嵌入的四种形态与降级占位、参数非法时的提示。
  - 控制台无错误。
- 无权限用户没有编辑入口。

## Further Notes

- 关系环检测按类型分别进行：扩展与阻塞的方向语义不同（「A 扩展 B」读作 A 在 B 之后；「A 阻塞 B」读作 A 在 B 之前），合并检测会产生误判。ADR-0022 与术语表已按此措辞，由 T17（#566）实现。
- 完成日期的「当天」应取哪个时区（站点时区或管理员浏览器）规格未指定，实现阶段需明确；默认值可由管理员修改。
- 原型（A/B/C/D 四个变体、假数据与两套拖拽引擎对比）已从工作区移除，以本地 tag `prototype/roadmap-canvas` 留存为原始资料，不并入主线，默认不推送。原型验证范围仅限 Chromium 桌面的指针与键盘，触屏、读屏、多指针未验证。
- 项目页的列表（叙事大行）与详情（画布）方案来自原型评审，原型的视觉不是最终设计。
- 本规格按 AGENTS.md 作为 feature 分支的早期文档：PRD 文件不单独建分支，随 feature 提交；对应 GitHub issue 不加 `ready-for-agent` 等流程性 label（AGENTS.md 的规定优先于 `/to-spec` 的默认做法）。
- 拆票时按「看板包 → 后端 API → 前端项目页 → 文章嵌入 → `/kanban` 文档」的依赖顺序切成可独立验收的小票，并把上面的 Out of Scope 清单逐条登记为后续规划。
