# PRD-0035：可扩展手绘绘图库

状态：用户已确认需求收口；尚未进入正式实现规格。本稿记录交付范围、验收入口和原型决策问题，不表示视觉、算法或性能已经验证通过。

## 要解决的问题

用户认为当前 Rough.js 手绘效果不够美观，希望自研一个更美观、能力更完整、性能可测且方便扩展其他笔迹的绘图库。目标不是增加几个固定预设，也不是只替换 Mermaid 的描边参数。

现有文章图块已有 Mermaid 布局、SVG 净化、手绘处理与导出链路。新库以文章 Mermaid 图表作为首个真实验收场景，但保持通用绘图库边界，不把布局、字体、React 或站点业务放进核心。

## 已确认的视觉范围

下列项目是分别验收的样例，不是核心允许的笔迹名单。同一算法可以服务多个样例，算法和几何工具可以复用；扩展能力由外部算法接入验证，不按预设数量判断。

1. **自然线条**：轻微、连续的不规则变化，图形和文字清楚，避免无目的的复线杂乱。
2. **草稿速写**：可见复线、回描与草稿变化，与自然线条样例在画面中可辨。
3. **铅笔与纤维**：颗粒、断续覆盖与细纤维可见，不只扰动外轮廓。
4. **书写与压感**：粗细变化、收笔、转折与连续曲线形成笔触。
5. **手绘彩漫**：完整彩色画面与手绘线条共同形成漫画表现。不是黑白漫画线稿，也不是仅改变描边颜色；配色和填充不与某种笔迹绑定为固定色板。

术语以根领域词汇表的「手绘绘图」节为准。

## 完整能力清单

### 基础能力

1. 支持直线、矩形、圆、椭圆、折线、多边形、圆弧、曲线和 SVG path；圆角矩形纳入真实图表样例。
2. SVG path 支持相对与绝对命令、重复命令、平滑曲线、圆弧、复合子路径和闭合语义，不把闭合轮廓当成普通开放折线。
3. 填充完整覆盖 `solid`、`hachure`、`cross-hatch`、`zigzag`、`dots`、`dashed`、`zigzag-line`，并支持孔洞、`evenodd` 与 `nonzero` 规则。
4. SVG 与 Canvas 共用生成后的矢量几何；SVG 提供独立导出能力。两后端的几何和绘制顺序一致，不承诺跨浏览器抗锯齿像素完全相同。
5. 相同输入、配置、算法版本和种子产生相同笔迹；不同形状和不同笔墨通道的随机性互不依赖遍历顺序。
6. 保留图表的布局、箭头锚点与文字引用，不以随机笔触替代原有语义骨架。

### 必须新增的能力

1. **压感与变宽**：真实压力、合成压力、沿路径宽度变化、端帽、连接和收笔均纳入验收。
2. **笔尖方向与形状**：验证斜笔、扁平笔尖等形态；笔尖方向与路径方向可独立控制，不把所有笔尖等同于圆形恒宽描边。
3. **颗粒与纤维质感**：支持多种覆盖规律和笔墨层；不得只用随机控制点偏移代表所有质感。
4. **笔迹绘制动画**：沿笔迹逐步呈现与重播，使用已生成的笔迹，不每帧重新随机。
5. **路径装饰**：支持基于精确骨架的箭头、括号、下划线和波浪线等装饰。
6. **外部笔迹扩展**：第三方算法通过公开契约接入，不修改核心或 SVG/Canvas 渲染器；内置笔迹没有特殊绕行入口。

### 整图动画

1. 支持节点、连线和笔墨层的顺序或并行编排。
2. 同一时间轴使用统一时钟和进度。
3. 支持播放、暂停、恢复、取消、重播、变速和进度跳转。
4. 暂停与跳转不改变笔迹，取消与重播不让旧完成回调影响新一次播放。
5. 时间轴是可选能力；静态绘制不被迫创建场景或时间轴。
6. 绘制动画表达笔迹形成过程，不靠缩放或无语义的滑入替代。站点接入遵守动态减弱偏好；首次展示是否默认播放由视觉原型决定。

## 已确认的约束

### 笔迹保持开放

- 不使用封闭的笔迹名称枚举，也不按风格名在核心分派算法。
- 笔迹专属参数由各自算法拥有，不持续堆进统一的全局选项。
- 几何、笔迹、填充、绘制外观与渲染职责分离；彩色画面是这些能力的组合，不把颜色写死在笔迹算法里。
- 普通恒宽描边不必支付变宽轮廓、密集采样或纹理生成成本。
- 主消费接口沿用图元生成与可复用绘制结果的方向；具体类型和函数签名须经外部笔迹原型验证后固化。

### 首批效果保持纯矢量

首批目标效果全部保持纯矢量，包括颗粒、纤维和手绘彩漫。不能用嵌入位图替代纹理后仍宣称为纯矢量。详见 [ADR-0017](../adr/0017-sketch-vector-ink.md)。

这一约束适用于首批目标效果，不封闭未来笔迹种类。若未来需要非矢量笔迹，必须明确其渲染能力和导出边界。

### 固定质量与显式超限

- 在同等视觉质量和相同细节配置下比较性能。
- 不自动减少颗粒或纤维、增大排线间距、放宽几何误差或删去笔墨层。
- 超限必须能由调用方明确识别，不输出看似成功却缺失内容的结果。
- 数值误差与手绘造型偏移分别控制，不能用增大随机偏移掩盖误差。
- 预算单位、阈值和错误接口由原型数据与正式规格确定，不能把未测量的数字写成性能保证。

该策略已选定，详见 [ADR-0016](../adr/0016-sketch-fixed-quality.md)。

## 验收入口

优先从公开绘制接口与真实渲染结果验收，不锁定私有数据布局、源码文本或某组默认参数。

| 验收对象 | 必须观察的行为 |
|---|---|
| 公开绘制入口 | 图元和路径正确、种子稳定、通道隔离、预算不足明确失败 |
| 外部笔迹消费方 | 新算法接入后可在两个后端绘制，不修改核心或渲染器 |
| SVG 与 Canvas | 复合路径、孔洞、裁剪、笔墨覆盖和绘制顺序一致；纯矢量 SVG 可独立消费 |
| 压感与笔尖 | 粗细过渡、转角、端帽、收笔、尖点与掉头处没有异常尖刺或断裂 |
| 时间轴 | 暂停稳定、恢复连续、变速与跳转正确、重播保持笔迹、取消不污染后续播放 |
| Mermaid 图块 | 现有 13 类样例全覆盖，布局、箭头、文字引用、编辑预览、阅读和导出链路不退化 |
| 独立包消费 | 真实 tarball 消费、按需入口和未使用笔迹的打包成本可验证 |

永久测试覆盖消费者可见的边界、状态转换和错误行为；不通过固定目录数量、内部命令列表或源码快照验收。视觉判断需要用户查看实际画面，测试通过不能替代。

## 性能验收范围

用户选择常规图表优先：几十至百级节点是首要负载，动画以 60FPS 为目标。千级场景用于额外压力与超限测试，不预先承诺所有笔迹和纹理组合都能稳定达到该帧率。

1. 原型固定输入、种子、笔迹配置、误差要求、视口、DPR 和设备信息，再比较不同实现。
2. 分开记录解析、笔迹生成、序列化、后端编译、提交与实际可见帧延迟，不把 Canvas 调用返回当成绘制完成。
3. 冷路径与重复绘制分别记录 p50、p95；同时记录输出命令数、字节数、DOM 节点数、内存和主线程阻塞。
4. Mermaid 布局、字体加载和安全净化单列，同时保留端到端体验数据；不删除安全处理来赢基准。
5. 压感、纤维和彩漫等新增能力没有直接等价的 Rough.js 基准时，按已确认的视觉质量与明确预算独立验收。
6. 缓存有界且按实例拥有；更换颜色不应迫使几何和随机笔迹重新生成。Worker、Path2D 和数据布局的收益由实测决定。
7. 插件预算可以约束可计量工作与输出，不能强制抢占任意同步 JavaScript。需要隔离不可信算法时，由宿主与 Worker 负责。

首次显示的毫秒阈值、可接受输出量和内存预算必须在视觉配置确定后填写到正式规格，当前不声称已达标。

## 原型必须回答的问题

### 视觉与彩漫

在相同几何、字号和尺寸下，展示 Rough.js 与五类目标效果。彩漫样例必须包含完整彩色填充与手绘线条；用真实画面确定明暗、线条粗细和纹理细节，不默认等同于黑白排线漫画。

完成条件：用户可查看对照，选定用于正式验收的效果和配置；同时观察端点、闭合接缝、文字可读性、透明叠层与局部放大。图表默认笔迹及首次展示的动画策略在此决定。

### 开放契约与变宽几何

用结构不同的算法接入同一公开契约，例如连续线条、变宽笔迹和纤维覆盖。以实际实现检验是否存在强制所有笔迹密集采样、全局参数膨胀或后端特例。

完成条件：外部算法不改核心与渲染器即可运行；孔洞、尖点、掉头、笔尖方向及宽度快速变化等样例满足已定几何精度。不能把固定宽描边论文当成任意变宽算法的正确性证明。

### 性能与算法取舍

以固定配置测量常规 Mermaid 场景、复杂曲线、稠密纹理、冷启动、热重绘、整图时间轴和大图超限。比较原生曲线保留、必要时的保守细分及局部自适应细分，不仅比较细分函数速度。

完成条件：留下可重放样例、测量脚本、设备与结果；联合视觉误差、CPU 耗时、输出量和可见帧选择算法，并确定正式规格的性能阈值与预算。若目标未达成，记录原因和需要验证的替代方案，不伪造通过。

## 研究与实测依据

### 原始资料

- [Rough.js 官方接口](https://github.com/rough-stuff/rough/wiki)：现有图元与七种填充的能力基线。
- [SVG 路径标准](https://www.w3.org/TR/SVG/paths.html) 与 [圆弧实现说明](https://www.w3.org/TR/SVG/implnote.html)：命令、闭合、退化输入和圆弧转换语义。
- [GPU-friendly Stroke Expansion，2024，v2](https://arxiv.org/html/2405.00127v2)：Euler spiral 中间表示、固定宽轮廓与输出规模优化；GPU 结果不能直接换算成 TypeScript/SVG 的加速比。
- [Polar Stroking，2020](https://arxiv.org/html/2007.00308v4)：按切线角度采样、尖点与连接处理；角度误差不等于屏幕距离误差。
- [Flattening quadratic Béziers，2019](https://raphlinus.github.io/graphics/curves/2019/12/23/flatten-quadbez.html)：作者工程推导，不是论文；用于评估解析细分与非递归实现。
- [Loop / Blinn，2005](https://www.microsoft.com/en-us/research/wp-content/uploads/2005/01/p1000-loop.pdf)：可编程 GPU 曲线渲染；不作为首批 SVG/Canvas 性能承诺。
- [perfect-freehand](https://github.com/steveruizok/perfect-freehand)：变宽轮廓、压力与端帽的工程参考；不能假定任意自交与变宽扫掠已经解决。

### 已执行的 Rough.js 基线

本地 Node v24.15.0、Darwin arm64、Rough.js 4.6.6；预热 5 批、测量 21 批。下表是中位数，只测现有库的生成和路径字符串序列化，不含 DOM、布局、绘制、缓存或 Worker。

| 场景 | 图形数量 | 生成耗时 | 序列化耗时 |
|---|---:|---:|---:|
| 直线 | 1,000 | 1.594 ms | 2.259 ms |
| 实心矩形 | 1,000 | 2.545 ms | 6.581 ms |
| 实心圆角路径 | 1,000 | 30.019 ms | 12.990 ms |
| 每条含 128 段三次曲线的路径 | 100 | 47.704 ms | 12.247 ms |

[原始结果与执行脚本归档](0035-sketch-baseline.json) 保留全部八个场景。它是历史测量记录，不是新库性能，也不能代替后续固定视觉质量的比较基准。

现有源码中，路径采样与描边生成存在重复解析，描边场景也会进行未必需要的折线采样；这给按需计算提供了优化方向，但不是新库已经胜出的证据。

## 从收口稿到实施

1. 在独立原型中回答上述运行问题，保留原型源码、设备、配置与测量结果，不把原型直接包装为正式库。
2. 原型结果回到本需求线程，再形成正式规格，固化公共契约、算法与性能验收。
3. 将正式规格拆成端到端可验收的执行票，声明阻塞关系；不按几何、笔迹、渲染等技术层机械拆分。
4. 先交付独立绘图库及其示例、文档和包消费验收，再迁移站点。组件包能力与站点接入分开提交。
5. 最终切换全部消费方并删除旧实现、旧导出和过期测试，不保留 Rough.js 兼容壳；Mermaid 自身的传递依赖单独核对，不伪称已经移除。

当前阶段不创建实施票，不开始正式库实现，不将仍需原型回答的问题标为已经解决。
