# PRD-0035：可扩展手绘绘图库

状态：第二版需求收口。首版原型（`web/packages/sketch` 与 `/lab/sketch-prototype`）已运行，暴露的模型问题见「首版原型结论」；本稿据此重新定义库的定位、概念模型与首批范围。尚未进入正式实现规格，不表示视觉、算法或性能已经验证通过。

## 要解决的问题

Rough.js 的手绘效果不够美观：它对每条线独立画两遍带随机偏移的贝塞尔曲线，小图显得毛糙，大图每条边弯曲一致；矩形每个角堆叠 8 个线头；填充排线、描边各自计算；只有恒宽描边，没有压感、笔尖、质感与绘制动画；同一 seed 的同尺寸图形抖动完全相同。

目标是自研一个**比 Rough.js 更好看、更快、能力更强、且易于扩展**的手绘矢量绘图库。首个真实消费场景是文章 Mermaid 图表，但库本身保持通用。

## 库的定位

框架无关的手绘矢量绘图库：输入图形或 SVG 路径，输出像真人用某支笔画出的矢量结果，可由 SVG 与 Canvas 渲染、独立导出，并可按落笔顺序播放绘制动画。

## 已确认的决策

| 决策 | 结论 |
|---|---|
| 使用场景 | 只做程序化图形（图表、插图），一次生成；不做实时手写采集。真实压力可作为可选数据传入 |
| 矢量约束 | 允许 SVG 原生滤镜表达质感，仍不嵌入位图，见 [ADR-0018](../adr/0018-sketch-svg-native-filters.md) |
| API | 提供与 Rough.js 相近的便捷层，底层另有组合式 API |
| 首批内置 | 签字笔、马克笔两支笔，以及卡通风格 |
| 质量策略 | 固定质量与显式超限，沿用 [ADR-0016](../adr/0016-sketch-fixed-quality.md) |

## 概念模型

手绘结果由三个**相互独立**的维度组合而成，见 [ADR-0019](../adr/0019-sketch-stroke-composition.md)：

| 维度 | 决定什么 | 首批内置 |
|---|---|---|
| **笔（Pen）** | 笔尖形状与角度、压力如何作用、墨与质感 | 签字笔（默认）、马克笔 |
| **手法（Hand）** | 画得工整还是潦草：抖动、弯曲、断笔、越界、复线 | 工整、自然（默认）、草稿 |
| **填充（Fill）** | 区域如何上色；排线等图案本身也交由笔绘制 | Rough.js 的 7 种，外加手涂（scribble）与错位实色 |

**风格（Style）** 是三者及明暗的组合预设，例如「卡通」。

- **压感是每支笔的属性**，不是一种笔。压力来源可组合：起收笔渐变、速度/曲率模型、噪声、调用方传入的真实压力；每支笔决定压力作用于粗细、浓淡还是透明度。默认恒压时走原生恒宽描边快速路径。
- **笔画（Stroke）是统一中间表示**：一次落笔到抬笔，逐点携带位置、压力与时间。描边、填充排线、箭头与装饰都先成为笔画，再经同一支笔成形，因此风格一致，动画天然按落笔时间推进。
- **语义锚点可钉住**：箭头锚点、连线端点等由调用方标记，手法扰动在锚点附近收敛，其余部分自由变化。

## 首批内置

### 笔

1. **签字笔**：圆笔尖，轻度起收笔压感，墨色实心；图表默认笔。
2. **马克笔**：扁笔尖、可设角度，半透明，笔画重叠处叠色加深。

### 卡通风格

彩色动漫/动画表现，画面以色彩为主体，不是黑白线稿或只给线条上色：

- **多色调赛璐璐上色**：每块填充由基础色派生阴影色与高光色（二至三阶硬边色块）。阴影色按色相偏移与降低明度得到，不是叠加黑色；阴影与高光形状由图形几何和统一光照方向推导，不使用与形状无关的固定模板。
- **彩色勾线**：线色默认取相邻填充色的加深色（色线），也可统一指定；线条两端收尖、粗细有节奏，外轮廓可比内部线更粗。
- **上色与线稿错位**：平涂与线稿轻微错位，保留手绘上色感。
- **配色可插拔**：调用方只给基础色角色，派生色由风格计算；换色不重新生成几何。

卡通风格是笔、手法、填充与明暗的组合，证明「压感是属性」「风格是组合」两条模型约束，不在核心中特判。

### 扩展验收样例

铅笔、毛笔不作为首批内置。至少一支（如铅笔）在包外实现，仅通过公开契约接入，用于验收扩展能力。

## 功能范围

### 对齐 Rough.js

1. 直线、矩形（含圆角）、椭圆与圆、圆弧、折线、多边形、曲线、SVG path。
2. SVG path 支持相对与绝对命令、平滑曲线、圆弧、复合子路径与闭合语义。
3. 填充 `solid`、`hachure`、`cross-hatch`、`zigzag`、`dots`、`dashed`、`zigzag-line`，支持孔洞与 `evenodd` / `nonzero`。
4. 可设 seed；SVG、Canvas 与不依赖 DOM 的生成器。

### 超越 Rough.js

1. **手绘观感**：笔画规划（大转角断笔、交叉越界、闭合曲线错开首尾、复线共享低频形变）与尺度自适应扰动，小图不毛糙、大图不呆板。
2. **压感与笔尖**：每支笔可设压感；笔尖方向与路径方向独立。
3. **质感**：可用路径或 SVG 原生滤镜表达；只生成在目标像素尺度上可见的细节。
4. **统一风格**：填充排线、箭头、装饰与描边经同一支笔成形。
5. **绘制动画**：按笔画落笔时间显现与重播，不每帧重新生成；整图时间轴支持顺序/并行编排、播放、暂停、恢复、取消、变速与跳转。时间轴为可选模块。
6. **换色不重生成**：图层引用颜色角色，换色只更新渲染。
7. **确定性与隔离**：相同输入、配置、版本与 seed 产生相同结果；不同图元、不同随机通道互不影响，调整一项参数只改变对应部分。

### 扩展

1. 笔、手法、填充、风格均可由包外实现，作为普通对象传入使用，无需注册，不修改核心或渲染器。
2. 扩展可替换单个维度，不必实现完整绘制流程；内置实现与外部扩展走同一入口。
3. 每个维度的专属参数归其自身所有，不堆进全局选项。

## API 形态

两层 API，具体签名在正式规格中固化：

- **便捷层**：`sketch({ seed, style })` 创建实例，以 `rect` / `ellipse` / `line` / `path` 等方法生成可重复渲染的绘制结果，便于从 Rough.js 迁移。
- **组合层**：分别定义或组合笔、手法、填充与风格，并直接生成场景。

包按子路径导出核心、SVG 渲染、Canvas 渲染、动画与内置预设；未使用的笔与渲染器不进入打包结果。绘制结果是纯数据，可在 Worker 中生成后传回主线程。

## 不做

- 实时手写采集与增量生成。
- 布局、文字排版、React 绑定、Mermaid 适配（均属消费方）。
- 选中、命中测试等编辑器能力。
- 嵌入位图纹理。

## 性能与体积目标

以下为待 M1 实测后在正式规格中固化的目标，当前不声称已达标：

1. 默认笔与自然手法在 [Rough.js 基线](0035-sketch-baseline.json) 八个场景下，生成耗时与 SVG 字节数均不高于 Rough.js。
2. 100 节点 Mermaid 图在默认笔下整图动画达到 60FPS；动画不依赖逐图层遮罩。
3. 只使用默认笔与 SVG 渲染时，打包体积不高于 Rough.js。

测量方法：固定输入、seed、配置、视口、DPR 与设备；分开记录生成、序列化、后端构建与可见帧；冷路径与重复绘制分别记录 p50、p95，并记录命令数、字节数与 DOM 节点数。Mermaid 布局、字体与安全净化单列，不删除安全处理来赢基准。

## 首版原型结论

首版原型验证了独立契约、双后端与固定质量预算可以运行，但暴露了以下问题，第二版不再沿用对应设计：

- 五个「笔迹」混合了不同维度：自然与草稿是同一算法的参数；压感是宽度属性却单列为笔，且没有手绘扰动；彩漫是填充明暗与轮廓的组合；铅笔只能恒宽。
- 自然线条只扰动直线段，二次曲线与圆弧原样保留且端点精确，画面接近原始矢量图。
- 铅笔纤维与颗粒处于亚像素尺度，输出约 36 万条命令却几乎不可见。
- 彩漫明暗是按包围盒比例写死的模板，与图形无关；填充排线不经过笔迹。
- 动画按图层建立遮罩：Canvas 每帧重建裁剪，SVG 为同一骨架重复建立 mask，未达到 60FPS。
- 每个顶点一个命令对象，生成时立即序列化路径字符串，内存与耗时开销大。

可保留：SVG 路径解析与圆弧换算、自适应贝塞尔细分、扫描线填充的孔洞规则、基于计数器的确定性随机、颜色角色与换色不重生成、固定质量预算的原则。

## 研究与实测依据

### 原始资料

- [Rough.js 官方接口](https://github.com/rough-stuff/rough/wiki)：现有图元与七种填充的能力基线。
- [SVG 路径标准](https://www.w3.org/TR/SVG/paths.html) 与 [圆弧实现说明](https://www.w3.org/TR/SVG/implnote.html)：命令、闭合、退化输入和圆弧转换语义。
- [GPU-friendly Stroke Expansion，2024，v2](https://arxiv.org/html/2405.00127v2)：Euler spiral 中间表示、固定宽轮廓与输出规模优化；GPU 结果不能直接换算成 TypeScript/SVG 的加速比。
- [Polar Stroking，2020](https://arxiv.org/html/2007.00308v4)：按切线角度采样、尖点与连接处理；角度误差不等于屏幕距离误差。
- [Flattening quadratic Béziers，2019](https://raphlinus.github.io/graphics/curves/2019/12/23/flatten-quadbez.html)：作者工程推导，不是论文；用于评估解析细分与非递归实现。
- [Loop / Blinn，2005](https://www.microsoft.com/en-us/research/wp-content/uploads/2005/01/p1000-loop.pdf)：可编程 GPU 曲线渲染；不作为首批 SVG/Canvas 性能承诺。
- [perfect-freehand](https://github.com/steveruizok/perfect-freehand)：变宽轮廓、压力与端帽的工程参考；不能假定任意自交与变宽扫掠已经解决。

### 已执行的 Rough.js 基线

本地 Node v24.15.0、Darwin arm64、Rough.js 4.6.6；预热 5 批、测量 21 批。下表是中位数，只测现有库的生成和路径字符串序列化，不含 DOM、布局、绘制、缓存或 Worker。

| 场景 | 图形数量 | 生成耗时 | 序列化耗时 |
|---|---:|---:|---:|
| 直线 | 1,000 | 1.594 ms | 2.259 ms |
| 实心矩形 | 1,000 | 2.545 ms | 6.581 ms |
| 实心圆角路径 | 1,000 | 30.019 ms | 12.990 ms |
| 每条含 128 段三次曲线的路径 | 100 | 47.704 ms | 12.247 ms |

[原始结果与执行脚本归档](0035-sketch-baseline.json) 保留全部八个场景。它是历史测量记录，不是新库性能，也不能代替后续固定视觉质量的比较基准。

现有源码中，路径采样与描边生成存在重复解析，描边场景也会进行未必需要的折线采样；这给按需计算提供了优化方向，但不是新库已经胜出的证据。

## 从收口稿到实施

1. 用户确认本稿后形成正式规格，固化公共契约、笔画中间表示、算法与性能阈值。
2. 按里程碑拆成端到端可验收的执行票并声明阻塞关系，不按几何、笔迹、渲染等技术层机械拆分。
3. 先交付独立绘图库及其示例、文档和 tarball 消费验收，再迁移站点；组件包能力与站点接入分开提交。
