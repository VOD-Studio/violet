# PRD: 人设档案

## Problem Statement

Violet 目前没有承载原创人设设定的正式产品能力。现有 `/about` 描述站点作者，`/lab/mascot` 验证吉祥物引擎；两者的语义、内容结构和生命周期都不适合人设档案。把人设继续塞进关于页会混淆「作者本人」与「虚构角色」，复用吉祥物模块则会把静态设定资料错误绑定到动画状态机和实验室视觉。

站长已经拥有设定图与设定文档，但缺少上传、编排、预览和公开展示链路。未来可能维护多个人设，公开前台同一时刻只应展示一个当前人设，不能让访客面对后台草稿或多个并列入口。

## Solution

新增独立的**人设档案（Persona Profile）** bounded context。后台可以创建并长期维护多份档案；每份档案包含身份名称、副标题、简介、结构化资料项、Markdown 设定正文和有序设定图。站点通过单例的**当前人设（Active Persona）**选择关系指向其中一份完整档案，公开 `/persona` 始终解析该选择关系，只展示当前人设。

人设与吉祥物没有任何数据、代码或交互关联。人设页面沿用新版首页已经确立的视觉风格——中性浅／深底色、低占比暖珊瑚、轻边界、克制圆角和小幅动效——但不复刻首页排版。页面以设定图和角色资料为主角，建立独立的角色阅读结构；不回退到旧实验室的暗色舞台、霓虹描边、仪表盘卡片或终端面板。

后台复用既有素材库、分片上传器和 Markdown 编辑器。站长可以从素材库选择设定图，也可以直接上传；数组顺序决定公开展示顺序，第一张图是主视觉。设定文档通过 Markdown 编辑器录入或导入，服务端生成并保存安全的 HTML 阅读载体。

领域术语见 `CONTEXT.md`「人设档案（Persona Profiles）」节。

### 关键场景

| 场景 | 行为 |
|---|---|
| 创建人设 | 后台创建空档案，允许分多次补齐，不会自动公开 |
| 导入设定文档 | 在 Markdown 编辑器导入或粘贴原文，保存为档案正文 |
| 选择设定图 | 从素材库多选图片或直接上传，调整顺序、说明与无障碍文本 |
| 激活人设 | 校验档案完整性后原子替换当前选择；此前当前人设立即转为普通档案 |
| 编辑当前人设 | 保存后公开页读取新版本；不完整修改被拒绝，公开页不会进入破损状态 |
| 删除普通档案 | 校验乐观版本后删除档案并释放全部素材引用 |
| 删除当前人设 | 拒绝删除，必须先激活另一份档案，避免无意清空公开入口 |
| 并发编辑 | 过期版本保存或删除返回 409，前端提示重新载入，不静默覆盖 |
| 尚未激活 | `/api/v1/persona` 返回 404；`/persona` 展示明确的未公开状态，不伪造内容 |
| 访问公开页 | 只返回当前人设；非当前档案没有公开详情地址 |

## User Stories

1. 作为站长，我要创建多份彼此独立的人设档案，为未来角色扩展保留空间。
2. 作为站长，我要同一时刻只激活一份人设，让公开入口具有唯一答案。
3. 作为站长，我要创建空档案并逐步补齐，而不是一次提交全部资料。
4. 作为站长，我要从现有素材库选择设定图，避免重复上传。
5. 作为站长，我要直接上传新的设定图，并立即加入当前编辑中的档案。
6. 作为站长，我要调整设定图顺序，用第一张图控制公开页主视觉。
7. 作为站长，我要为每张图填写当前档案语境下的说明和无障碍文本，不修改素材库原始描述。
8. 作为站长，我要录入或导入 Markdown 设定文档，保留章节、列表、表格和代码等结构。
9. 作为站长，我要用可排序的资料项表达生日、身高、身份等不固定字段，不为每种人设改数据库。
10. 作为站长，我要在激活前得到完整性校验结果，避免把半成品公开。
11. 作为站长，我要在两个编辑窗口冲突时收到明确提示，不丢失较早的修改。
12. 作为只读运营人员，我要查看档案列表、当前状态和详情，但不能修改或激活。
13. 作为访客，我要通过稳定的 `/persona` 地址看到当前人设，不需要知道后台档案 ID。
14. 作为访客，我要先看到角色主视觉与身份摘要，再按自己的阅读节奏浏览设定正文和参考图。
15. 作为访客，我要在移动端、深色主题、键盘导航和减弱动效模式下获得完整体验。
16. 作为访客，我不要把人设误解成站长本人或吉祥物实验；页面文案与导航要明确角色档案语义。

## Implementation Decisions

### 领域边界

- Persona 是独立 bounded context，不复用 About、User、Gallery 或 Mascot 模型。
- About 描述真实站点作者；Persona 描述可切换的虚构角色档案；Mascot 是实验室中的动画引擎角色。三者不共享状态或生命周期。
- 人设是站点级内容，不属于普通注册用户。记录保留 `created_by` 作为管理事实，但不建立「只能编辑自己的档案」语义；权限决定管理能力。
- 第一版只有稳定公开入口 `/persona`。非当前档案只存在于后台，不提供 `/personas/{slug}` 或按 ID 的公开访问。

### 档案文档

- Persona 保存完整文档：`name`、`subtitle`、`summary`、有序 facts、有序 images、`content_md` 和服务端生成的 `content_html`。
- `subtitle` 可空，用于一句角色定位；`summary` 是主视觉旁的短介绍；`content_md` 是完整设定文档。
- fact 使用通用的 `label` / `value` 对，数组顺序就是公开顺序。它承载结构化速览，不取代正文，也不为生日、身高、种族等字段建立固定列。
- image 只引用媒体域 File ID，保存 position、caption 和可选 alt override；URL、MIME、尺寸、缩略图和默认 alt 仍由媒体域负责。
- 第一张 image 派生为主视觉，不保存第二份 `primary_file_id`。
- 每次全量保存携带 `expected_version`。调用方提交完整数组，不计算数据库 diff，也不提交 position 数字。

### 完整性与校验

- 草稿态档案允许空 name、零 facts、零 images 和空正文，便于逐步编辑。
- 激活要求：name 去空白后非空、summary 去空白后非空、content_md 去空白后非空、至少一张设定图。
- 当前人设继续保存时执行同一份激活完整性校验，禁止把已经公开的档案保存成不完整状态。
- name 最多 120 个 Unicode 字符；subtitle 最多 240；summary 最多 500。
- facts 最多 24 项；label 与 value 均不能为空，label 最多 40 字，value 最多 300 字；同一档案内去空白后的 label 不重复。
- images 最多 30 张；同一档案不能重复引用同一 File；caption 最多 500 字，alt override 最多 300 字。
- 所有图片必须状态为 ready、未删除且 MIME 匹配 `image/*`。第一版不接受视频、音频或任意附件。

### 当前人设选择

- 当前人设不是档案自身的固有状态，而是站点到 Persona 的单例选择关系；使用独立 `persona_selection` 表表达。
- `persona_selection` 最多一行，固定单例键；`persona_id` 外键限制删除。激活在 PostgreSQL 事务中校验目标档案并原子 upsert 选择关系。
- 系统允许首次激活前没有当前人设，但不提供显式「取消激活」动作。激活另一份档案就是唯一切换方式。
- 删除当前人设返回领域冲突；后台明确引导先激活另一份档案。

### 数据与事务

- 新增 `personas`、`persona_facts`、`persona_images`、`persona_selection` 四表。
- `persona_facts` 对 `(persona_id, position)` 建唯一约束；`persona_images` 对 `(persona_id, position)` 与 `(persona_id, file_id)` 建唯一约束。position 由服务端归一为从 0 开始的连续序列。
- facts、images 随 Persona 删除；persona image 到 File 使用限制删除引用，媒体软删除仍由现有引用计数规则保护。
- 保存、删除、图片引用计数调整和当前选择切换在各自单个 PostgreSQL 事务中完成，不做失败后的补偿写。
- 管理列表按当前人设优先，再按 `(updated_at DESC, id DESC)` 排序，使用 page/limit 分页。
- 迁移从其他本地功能分支已占用的 112 之后开始，使用 113 创建表、114 配置权限，避免后续合并冲突。

### HTTP API

公开接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/persona` | 返回当前人设完整公开投影；未选择时 404 |

内容管理接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/admin/personas` | 创建空档案，返回 201 |
| GET | `/api/v1/admin/personas` | 管理列表，page/limit，支持名称查询 |
| GET | `/api/v1/admin/personas/{id}` | 读取完整档案与当前状态 |
| PUT | `/api/v1/admin/personas/{id}` | 按 expected_version 全量保存档案 |
| POST | `/api/v1/admin/personas/{id}/activate` | 校验并设为当前人设 |
| DELETE | `/api/v1/admin/personas/{id}` | 按 expected_version 删除非当前档案，返回 204 |

- JSON 字段沿用项目现状使用 snake_case。
- 未认证返回 401；权限不足返回 403；记录或当前人设不存在返回 404；输入或完整性校验失败返回 400；版本冲突与删除当前人设返回 409。
- 公开 DTO 不返回 `created_by`、`content_md`、后台 ID 查询能力或版本控制输入；返回安全的 `content_html` 和渲染图片所需投影。
- 新端点同步进 OpenAPI 导出。

### 权限

- `persona:view`：显示人设管理入口，读取管理列表与详情。
- `persona:manage`：创建、保存、激活和删除人设档案。操作始终成组授权，不拆细粒度 CRUD 权限。
- 两个权限默认 seed 给 admin；root 继续走通配。普通注册用户默认没有人设管理权限。
- 后台列表与详情使用 `persona:view`；所有写路由使用 `persona:manage`。

### 后台体验

- 新增 `/admin/personas` 管理列表：名称、资料完整度、图片数、当前状态、更新时间和操作列；使用服务端分页 DataTable。
- 新增 `/admin/personas/{id}` 全屏编辑工作台。顶部承载返回、保存、激活和删除动作；主体按身份摘要、资料项、设定正文、设定图分区组织。
- 设定正文复用 RichTextEditor 的 Markdown 模式，保留文件导入能力；不新造纯文本编辑器或第二套 Markdown 管线。
- 图片复用 MediaPicker 与 Uploader。选择或上传结果进入本地有序列表，编辑 caption / alt override 后随完整文档保存。
- 激活是显式动作；存在未保存修改时拒绝激活，先保存再激活。
- 409 版本冲突提示重新载入，不自动用本地文档覆盖服务端新版本。

### 公开页面与视觉

- 新增 `/persona`。页面结构专为角色资料设计，不复制新版首页的身份—发布目录排版，也不复用 `/lab/mascot` 舞台。
- 首屏是艺术图主导的角色开场：主视觉与名称、定位、简介和资料项形成不对称但自然的阅读重心；不把每个字段包成等权卡片。
- 设定正文保持长文阅读宽度，以排版、留白和发丝线分节；参考图按原始顺序展开，点击进入现有图片预览能力。
- 视觉语言以 `DESIGN.md` 的新版公开前台原则为准：中性浅／深底色、唯一暖珊瑚强调、低对比表面、轻边界、克制圆角、平面优先、小尺度 motion。
- 禁止紫色或霓虹强调、黑色舞台、玻璃拟态控制台、终端文案、仪表盘网格、巨型刊头、杂志编号和旧式悬浮卡片堆叠。
- 动效只服务进入、图片反馈和焦点关系；支持 `prefers-reduced-motion`，不得遮盖内容或制造持续运动。
- 真实内容缺失时收拢对应区域。未激活时只显示简短空状态，不伪造角色名称、图片、事实或设定正文。
- Header 的人设入口从 `/about` 改为 `/persona`；About 继续保留作者介绍职责。

## Testing Decisions

- 领域测试覆盖草稿宽松保存、激活完整性、当前人设保存完整性、字段与集合边界、重复 fact label、重复图片和版本冲突。
- 应用测试覆盖单激活切换、未激活公开 404、删除当前人设冲突、删除普通档案、图片状态/MIME 校验、素材引用计数变化与事务回滚。
- PostgreSQL 集成测试覆盖选择关系单例约束、级联清理、File 限制删除和并发激活最终只有一个当前人设。
- Handler 测试覆盖公开匿名读取、管理端 401/403、400/404/409 映射、分页及 snake_case 契约。
- 前端测试只保留有回归价值的可观察契约：列表状态、编辑完整文档、未保存时禁止激活、409 提示和公开空状态；不测试字段转发或组件内部 wiring。
- 浏览器验收覆盖创建空档案、上传/选图、排序、保存、激活、切换、删除限制、公开页内容、图片预览、移动端、深色主题、键盘焦点和减弱动效。
- 使用站长提供的真实设定图与设定文档完成最终视觉验收；实现中不生成替代人设素材。

## Out of Scope

- 与吉祥物引擎、AI 状态协议、Live2D、动画骨骼或 `/lab/mascot` 建立关联。
- 把人设当作登录用户资料、作者资料、聊天身份或 AI agent 系统提示词。
- 同时公开多个人设、按 slug 浏览历史人设、角色目录和前后台对比页。
- 人设关系图、时间线、语音、音乐、评论、点赞、收藏、统计、RSS、搜索、MCP 和通知。
- 完整修订历史、预发布快照、回滚、多人协作编辑和定时激活。
- 独立封面字段、图片裁切工具、AI 生成图片或自动从文档抽取结构化资料。
- 视频、音频、PDF 或任意文件附件；设定文档第一版以 Markdown 内容入库。
- 修改新版首页布局或重设计现有 Header；只接通人设入口。

## Further Notes

- 分支：`feat/persona-profiles`。
- 本 PRD 的「沿用新版首页」只指视觉与交互语言，不指页面排版；人设页必须建立自己的内容结构。
- 真实设定图和设定文档由站长提供，最终字段文案、事实项和视觉裁切以真实材料为准。
