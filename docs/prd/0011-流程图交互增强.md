# PRD: 流程图交互增强（缩放平移 + 交互开关 + 弹层小屏适配）

## Problem Statement

图块（流程图）已落地（PRD-0005），但存在三个读者/作者侧缺口：

1. **大图无法细看**：阅读端大流程图只有横向滚动（PRD-0005「居中 + overflow-x-auto，而非缩放变形」决策），图密集时（大子图、长时序图）读者无法放大查看细节——PRD-0005 Out of Scope 已明确「点击放大」为后续迭代
2. **编辑器弹层预览同款受限**：弹层预览区（`max-h-72 overflow-auto`）同样无法缩放，作者在弹层里看不清楚大图细节
3. **弹层小屏溢出**：编辑弹层总高无上限（textarea ≤12 行 + 预览 288px + 按钮 ≈ 600px+），容器无 max-height/overflow——小屏（矮窗口/移动端）时 floating-ui flip 换方向也救不了，内容溢出视口不可见（预览、删除按钮丢失）

业界参考（博客场景最完整样本 BookStack Mermaid Viewer 2025-06，及 mermaid 在线编辑器 mermaideditor.io / VS Code Mermaid Preview / Obsidian）已把「Pan & Zoom + 交互开关」做成标配。

## Solution

在 `shared/ui/diagram/` 新增**缩放平移容器组件（DiagramViewport）**，阅读端与编辑器弹层预览共用；弹层做小屏高度适配。交互模型对齐 BookStack：**默认锁定态（可滚动/选文本）↔ 解锁态（拖拽平移 + 滚轮缩放 + 按钮）**，两态用锁/解锁按钮切换——锁定态保留 PRD-0005 的横向滚动决策，解锁态进入缩放，两态共存不互斥。

## User Stories

1. 作为访客，当流程图很大时，我想放大查看细节、缩小看全貌（滚轮 + 按钮），这样复杂图不丢失信息
2. 作为访客，放大后我想拖拽平移查看图的各个区域，这样不用来回滚动页面
3. 作为访客，看完细节后我想一键回到初始缩放与居中位置，这样不用手动对齐
4. 作为访客，我不需要交互时能锁定缩放平移，这样不影响页面正常滚动和选中复制文字
5. 作为文章作者，我在编辑弹层的实时预览里同样能缩放平移大图，这样所见即所得地检查细节
6. 作为文章作者，在屏幕较小的设备（矮窗口/手机）上，弹层不会溢出视口，源码、预览、删除按钮都能滚动到达
7. 作为访客，我可以通过图块工具条复制 mermaid 源码，这样想复用改画时不用切到源码视图

## Implementation Decisions

### 缩放容器组件（DiagramViewport，`shared/ui/diagram/`）

- **实现方式：自研，不引库**（BookStack 同款手写路径）。CSS `transform: scale() translate()` + pointer events，约 150 行可控代码。已否决 `react-zoom-pan-pinch` / `d3-zoom`：为单一固定 SVG 内容的缩放平移引整库不值，且与现有「自研 + 轻依赖」的 diagram 架构一致（渲染核心就是自研的）
- 状态机：`{ scale, translateX, translateY, locked }`。scale 范围 **0.25x – 4x**（对齐业界常见范围，clamp 防抖）
- 交互：
  - 滚轮缩放以**光标为中心**（业界主流行为，GitHub/Obsidian 同款）：wheel 事件 → 计算光标相对容器位置 → 调整 translate 使光标下内容保持不动
  - 拖拽平移：pointerdown/move/up（pointer events 统一 mouse/touch，移动端可触摸拖拽）
  - 锁定态：容器回到普通文档流（滚动/选文本正常），transform 复位
- 按钮组（容器角部，GitHub 图缩放同款布局）：`+` / `−` / 重置（RotateCcw 图标）/ 锁（Lock ↔ Unlock）
- transform-origin: 0 0（BookStack 同款）；锁定态 `user-select: auto`、解锁态 `user-select: none`（防拖拽时选中文本，BookStack 同款 CSS 手法）
- 与现有 `overflow-x-auto` 容器的关系：外层容器保持；锁定态 = 现状行为；解锁态 = 内部 transform 容器接管（外层 overflow 改为 hidden 由解锁态 class 切换）

### 阅读端接入

- `DiagramBlock.tsx` 渲染 SVG 后包一层 `DiagramViewport`（锁定态默认）
- 复制源码按钮：`navigator.clipboard.writeText(source)` + 短暂「已复制」反馈（BookStack Copy Code 同款）；无剪贴板 API 环境降级隐藏

### 编辑器弹层接入与修复（DiagramEditPanel）

- 预览区改用 `DiagramViewport`（同一组件，锁定态默认，作者可解锁缩放）
- **小屏适配（本次修复）**：
  - 弹层容器：`max-h-[calc(100dvh-2rem)] overflow-y-auto`（用 **dvh** 而非 vh——移动端地址栏动态高度）
  - textarea：加 `max-h-48`（现 `resize-y` 可无限拉高，设手动上限）
  - 预览区：`min-h-32`（不再固定 288px 起，小屏弹性压缩）+ 保留 `max-h-72`
  - flex 子项 `min-h-0`（弹性收缩前提）
  - 弹层整体仍由 useFloatingMathPanel 的 flip/shift 定位，max-height 兜底后任何屏幕不溢出

### 组件边界

| 模块 | 位置 | 职责 |
|------|------|------|
| DiagramViewport | `shared/ui/diagram/` | 缩放平移状态机 + 交互 + 按钮组（纯 UI，不感知 mermaid） |
| 阅读端接入 | `shared/ui/diagram/DiagramBlock.tsx` | SVG 外包 Viewport + 复制按钮 |
| 编辑器弹层 | `features/editor/ui/DiagramEditPanel.tsx` | 预览换 Viewport + 小屏布局修复 |
| 编辑器 NodeView | `features/editor/ui/DiagramPopoverView.tsx` | 无改动（弹层承载不变） |

## Testing Decisions

- **DiagramViewport 状态机**（抽纯 hook `useDiagramViewport`）：
  - scale clamp（0.25–4x）、锁定/解锁切换复位、重置回初始
  - 滚轮缩放光标中心公式（纯函数部分）
- **弹层布局**：小屏 class 断言（max-h/overflow/min-h-0 存在），沿用现有组件测试模式
- 不测：阅读端集成（mermaid 渲染链路已有手动验证先例）、拖拽手感（手动验证）

## Out of Scope

- **导出 PNG / SVG / PDF**：需要 SVG→位图转换（canvas 序列化）与下载链路，下一档
- **语法高亮 / 自动补全**：弹层 textarea 换 CodeMirror 是独立改造（PRD-0005 已声明首期不做）
- **多图表格式（plantuml 等）**：与缩放正交，注册表已预留
- **图内元素交互（点击节点跳转）**：mermaid 原生交互能力，独立决策
- **编辑器端小屏整体适配**：本次只修弹层溢出；编辑器工具栏/侧栏的移动端适配是更大课题

## Further Notes

### 决策来源与参照

- BookStack Mermaid Viewer（2025-06，博客场景最完整样本）：Pan & Zoom（拖拽 + 滚轮 + 按钮）、**Interaction Toggle（锁/解锁，防干扰滚动）**、Reset Zoom、Copy Code、文本选择控制——本次功能清单即对齐此样本
- mermaideditor.io / VS Code Mermaid Preview：预览面板缩放为编辑器标配
- Obsidian 论坛（2023）：GitHub 风格 pan/zoom 组件是社区长期诉求，验证必要性
- 光标中心滚轮缩放：业界主流（GitHub/Obsidian），非光标中心会「滚着滚着图跑了」

### 与 PRD-0005 决策的关系

- PRD-0005「横向滚动而非缩放变形」是**容器决策**，本次不推翻：锁定态保留横向滚动（无交互损耗），解锁态是叠加的增强路径
- 弹层「max-h + overflow」修复补齐 PRD-0005 Implementation Decisions「面板内容：max-h + overflow-auto」未覆盖弹层容器本身的疏漏

### 已否决（grill 阶段）

- 引 `react-zoom-pan-pinch` 库：单一 SVG 缩放场景整库过重，自研 ~150 行可控且无新依赖
- 缩放代替横向滚动（去掉锁定态）：读者滚动长文时误触缩放灾难，BookStack interaction toggle 已是社区共识解法
- 弹层用 `100vh`：移动端地址栏收起时 vh 突变导致弹层跳动，必须 dvh
- 复制源码放弹层内部：阅读端工具条是读者入口（BookStack 同款），作者在弹层已有源码编辑，无需重复
