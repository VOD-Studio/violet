# PRD：运行策略配置

## Problem Statement

管理员无法在后台调整真实入口的请求限额、图片缓存与编码策略、文件上传并发和运行器队列策略。部分参数硬编码，部分只能修改部署配置；已有设置保存成功不等于消费者已经应用。上传遇到限流时没有准确等待信息，移除上传行也不会中断上传。

旧系统面板需求已经收敛为五页签。限流、图片、上传和运行器配置独立于系统面板交付；旧 #340 的勾选状态不作为当前配置底座已完成的依据。

## Solution

在既有站点设置中提供四个独立策略分组，复用运行器设置入口和素材上传入口。每组提供场景预设与可展开的高级参数，说明性内容统一放入可键盘聚焦、触屏打开的 Tooltip，不在页面铺设长段说明。

选择预设只修改表单草稿，点击保存才提交；手动修改后标为自定义。升级不自动覆盖现有配置。页面直接展示当前值、生效状态和错误，危险操作仍明确确认。

| 分组 | 预设方向 | 生效对象 |
|---|---|---|
| 限流 | 严格防护、现有限额、宽松限额 | 后续实际请求 |
| 图片与缓存 | 无损优先、均衡压缩、节省空间 | 后续图片处理与缓存维护 |
| 上传队列 | 低并发、日常上传、批量上传 | 后续文件调度 |
| 运行器 | 节约资源、部署默认、高并发 | 后续排队与执行任务 |

预设按模块独立，不提供联动修改四个模块的全站预设。预设描述行为取舍，不承诺自动识别服务器容量或保证不发生限流。

## User Stories

1. 作为管理员，我能分别进入限流、图片、上传和运行器设置，不必在系统监控页面寻找配置。
2. 作为管理员，我能选择一个场景预设查看参数变化，尚未保存时不改变服务行为。
3. 作为管理员，我能展开高级参数微调，明确知道当前草稿已经不再等于原预设。
4. 作为管理员，我能在标签旁按需查看参数说明，而不是阅读堆满页面的解释文字。
5. 作为键盘或触屏用户，我能打开和关闭参数 Tooltip，不依赖鼠标悬停。
6. 作为管理员，我能区分当前保存值、实际生效值和默认来源，知道保存是否成功应用。
7. 作为管理员，我能恢复当前分组的默认配置，而不覆盖其他分组。
8. 作为管理员，我能看到字段错误和版本冲突；另一位管理员的保存不会静默覆盖我的草稿。
9. 作为管理员，我在加载失败时能重试，在离开有未保存修改的页面时得到提示。
10. 作为只读管理员，我能查看策略，但不能通过页面或直接请求修改策略。
11. 作为管理员，我能查看实际绑定入口的限流策略，不看到已经移除或没有消费者的开关。
12. 作为管理员，我能调整时间窗口、请求额度、突发额度和 UTC 自然日配额，并明确理解关闭、零值和恢复默认的区别。
13. 作为用户，我的限流身份不会被客户端伪造的代理头改变；不同用户和匿名来源按入口声明的规则计数。
14. 作为用户，我被拒绝时能看到实际限制原因和可恢复时间，而不是固定的“稍后再试”。
15. 作为管理员，我能在 Redis 故障时看到明确的降级结果，敏感的新策略不会静默失去保护。
16. 作为管理员，我调整限额后能通过真实请求观察变化，而不只是看到表单回显。
17. 作为管理员，我能设置图片缓存的容量、保留期和内存边界，查看清理结果，且正式素材不会被缓存维护删除。
18. 作为用户，损坏或像素超限的图片会在完整解码前被拒绝，不耗尽服务内存。
19. 作为管理员，我能选择无损或真实有损 WebP，质量和编码强度实际影响输出文件。
20. 作为用户，我能看到策略变化或源图覆盖后的新图片，不被旧缓存遮蔽。
21. 作为用户，透明图和动图不会在未提示的情况下失去透明通道或动画。
22. 作为管理员，我能设置文件级上传并发，连续加入多批文件也不会绕过整个队列的上限。
23. 作为上传者，我能区分排队、上传、限流等待、成功、失败和取消状态。
24. 作为上传者，我取消文件时实际请求和上传会话会结束，而不只是删除列表行。
25. 作为上传者，我能单独重试失败文件，复用已上传分片，不重传已成功文件。
26. 作为上传者，我遇到 429 时按服务器实际等待期限继续调度，离页前知道是否还有未完成文件。
27. 作为管理员，我修改上传并发只影响后续调度，不丢失正在处理的文件。
28. 作为管理员，我能配置运行器并发、排队超时和任务保留，并明确看到生效时机。
29. 作为作者和读者，关闭运行器或禁用某种语言后，编辑器、阅读器及后端两条执行路径一致拒绝新任务。
30. 作为管理员，我调整运行器并发不终止已有任务，也不会重复发放执行名额。
31. 作为用户，我能区分排队超时、资源终止和依赖不可用，而不把保存成功当成沙箱可用。
32. 作为管理员，我仍受运行器请求频率限制；提高并发或额度不解除 CPU、内存、执行时长和网络隔离限制。
33. 作为运维人员，我能从已有审计查看策略修改，从结构化运行日志查看应用故障，而不暴露计数身份凭据或密钥。

## Implementation Decisions

### 配置契约

- 复用 settings 分组和既有 `settings:view` / `settings:update` 权限，不增加任意 key 写接口或通用表单引擎。
- 四组独立版本；服务端校验整组后原子保存，旧版本写入返回冲突，不部分覆盖。
- 明确区分省略字段、显式零值、关闭开关和恢复默认。关闭通过显式布尔状态表达，不用数字零值隐式关闭整个模块。
- 默认来源包括部署默认和应用默认；恢复默认只撤销当前分组覆盖。既有有效配置迁移保留，不把前端常量误写为部署默认。
- 返回已保存版本、当前实例实际应用版本及生效时机。应用失败保留上一有效状态并返回可诊断结果，不能只返回成功 toast。
- 生效状态必须描述真实消费者行为；涉及多实例时明确传播范围和时机，不以保存实例的状态冒充所有实例已经生效。
- 配置读取故障不被解释为用户主动关闭或恢复默认。审计不记录密钥、完整计数身份或连接凭据。
- 本次只补四组策略所需的配置契约，不恢复 #340 中的页脚链接、数据库池在线调整或完整启动配置浏览页。

### 限流

- 延续 Redis 计数，不引入进程内替代桶；窗口、突发和日配额在同一原子判定中处理。
- 目录只包含实际绑定入口。现有认证、评论、发码、友链、上传、运行器、推文、MCP、Bot、音乐和匿名访问统计保护均不能在迁移中丢失；图片入口按真实动态处理行为接入，不增加匿名上传能力。
- 现有限额作为迁移基线，预设不会自动启用新的日配额或改写已保存策略。
- 登录用户、匿名来源、站点共享额度与 unknown 来源的身份规则按入口明确；受信代理规则沿用现有安全边界。
- 日配额按 UTC 自然日归零，计数键有有限过期时间；并发争抢最后一个名额和跨日行为可确定地验证。
- 429 包含真实 `Retry-After`、限制原因与恢复时间；前端保留这些信息。拒绝请求不能无限延长封锁时间或制造无限增长的计数集合。
- Redis 故障行为按入口声明，敏感新策略不能静默放行；状态进入结构化运行日志且不泄露计数凭据。
- 上传初始化、分片、合并、状态查询和取消的配额关系必须明确，限流不能让用户无法取消已有上传；运行器两条执行入口遵循一致规则。
- 管理员保持当前统一限流，不启用旧运行器 ADR 中未落实的管理员豁免；沙箱资源上限与请求频率限制彼此独立。

### 图片与缓存

- 只清理可重建图片缓存，不复用会删除正式素材的综合清理操作。
- 缓存先清过期项，再按确定顺序收敛到容量上限；展示清理时间、结果或失败状态。
- 上传和动态处理在完整解码前校验源图单边与总像素；输出尺寸限制不能代替源图保护。
- 保留无损 WebP，并交付实际消费质量和编码强度的有损编码器。工具版本、非 CGO 构建、开发与生产非 root 执行环境一起验收；不假设 FFmpeg 自带 libwebp。
- 编码有并发、时间及输入输出上限，工具缺失或执行失败明确报错，不伪装成功。
- 动态图片在打开和完整读取源文件前取得有界准入；名额覆盖源缓冲与共享任务的生命周期。客户端退出不提前释放共享任务仍持有的名额，未获准的请求可取消，应用关停结束等待。
- 原素材 GIF/WebP 的保留规则、透明通道与动画语义不被无提示破坏。
- 缓存身份包含源内容版本和处理策略版本；覆盖源图或更新策略后重新读取不能命中旧输出。

### 上传队列

- 队列上限按在途文件计数，覆盖连续加入的多批文件；单文件分片仍串行，`maxFiles` 继续只表示选择数量。
- 请求链传播取消信号，并调用服务端取消上传会话；取消与合并的竞争返回真实结果，不承诺已完成合并的文件被撤销。
- 单项重试采用服务端返回的既有会话与分片尺寸，不能因本地策略变化导致续传错位。
- 遇到 429 保留文件与上传会话，按实际等待期限恢复调度；不重传已完成文件或重复计入完成数。
- 新并发策略仅改变后续调度；复用上传器的素材、表情、图集与人设入口保持各自上传契约。

### 运行器

- 复用既有 Docker 沙箱、两条执行路径、并发调度和 Redis 任务存储，不另建运行器。
- CPU、内存、执行时长、输出/源码大小、语言和网络约束由真实消费者执行；非法零值与超范围值在保存前拒绝。
- 并发调整不撤销已有名额、不取消已有任务；排队使用明确超时，任务保留期对应实际 Redis 过期。
- 后台启停与语言开关同时约束前台入口和后端两条执行路径，不能仅隐藏按钮。
- 联网仍须作者声明、语言许可、全局开关同时成立；保留现有容器隔离与资源钳制。
- Redis、配置读取或 Docker 不可用时展示真实错误，运行器可用性不能由设置保存成功推导。

### 界面

- 继续使用站点设置的分组表单和运行器入口，不创建第二套后台。
- 每组预设、高级参数和恢复默认只操作该组草稿；点击保存才生效。与模板不同的值显示自定义，不依靠名字宣称匹配。
- 标签旁提供 Tooltip 入口；说明只在 Tooltip 内出现，不同时在字段下重复铺开。
- Tooltip 支持鼠标、键盘和触屏，按 Escape 可关闭；说明入口有可访问名称，不抢占表单标签关联。
- 字段值、必要单位、保存/生效状态、字段错误、冲突和危险操作确认直接可见，不隐藏到 Tooltip。
- 加载失败可重试，保存期间阻止重复提交，未保存修改有离页保护；冲突时保留当前草稿并允许明确重载。

## Testing Decisions

- 以管理 HTTP → 实际消费者作为主要验收路径，不用字段回显、内部调用次数或成功 toast 代替功能生效。
- 配置通过真实持久化验证版本冲突、原子校验、默认恢复、重启恢复与权限隔离；延续现有 settings HTTP 和仓储测试边界。
- 限流通过实际 HTTP 和隔离 Redis 验证身份隔离、并发最后额度、UTC 日界、真实等待期限及故障行为；延续现有限流中间件的消费者测试。
- 图片用正常、透明、动画、巨大头部和损坏样本观察实际格式、尺寸和输出差异，并验证策略/源图更新后的缓存失效。
- 上传通过浏览器真实多文件上传观察峰值并发、跨批次排队、取消、续传、429 等待和素材列表刷新。
- 运行器通过真实沙箱任务验证并发上限、排队超时、资源终止、语言约束和保留期，不用替身执行器冒充沙箱验收。
- 管理页面覆盖 1440×900、390×844、light/dark、键盘、触屏 Tooltip、只读权限、加载错误和版本冲突。
- 永久回归只保留消费者可见边界、状态转换和并发不变量；测试确定、隔离且可进入完整测试套件。
- 验收使用隔离数据库、Redis 与临时素材，不在生产或参考站数据上执行破坏性试验。

## Out of Scope

- 全站联动预设、自动识别服务器规格或自动调参。
- 重做系统面板、运行日志检索平台、会话安全治理和数据库池在线调整。
- 匿名图片上传、正式素材垃圾清理、文章回收站治理。
- 运行器管理员默认豁免、解除沙箱隔离或扩大默认联网许可。
- 另建运行器、进程内限流替代 Redis、任意 key 配置编辑器。
