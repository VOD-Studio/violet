# PRD-0027：后台运维与数据保护

状态：实施中，按子 issue 验证并分次提交。

架构约束见 [ADR-0016：后台运维授权与恢复边界](../adr/0016-admin-operations-and-recovery.md)。

## Problem Statement

站长需要在后台回答四类问题：配置是否真正生效、异常发生在哪里、资源为什么持续增长、误操作后能否恢复。Violet 已有分组站点设置、操作审计、主机监控、Redis 限流、图片处理和文章回收站，但这些能力尚未组成可操作的运维工作流。

当前操作日志记录业务审计，不提供应用运行日志查询；系统监控已有真实指标和历史曲线，但没有数据库深度诊断、SQL 控制台、数据库导出及备份恢复。多项资源策略仍是启动参数或代码常量。素材引用也尚未覆盖全部内容来源，不能直接把“引用计数为零”当作安全删除依据。

配置展示还需要区分“声明了参数”和“实际使用了参数”。源码调查发现数据库连接池参数有加载与校验，却未找到应用到真实连接池的调用；素材普通删除与延迟物理清理之间也存在需在隔离环境复现的断点。这些是新增能力的前置条件，不应被新界面掩盖。

## Solution

扩充设置、日志和系统三个后台入口，保留现有业务功能及权限边界，按可独立演示的完整功能分期交付。

- 设置负责安全、会话、限流、图片、上传、代码运行器及维护策略；明确来源、保存结果、实际生效值和生效时机。
- 日志同时保留操作审计和新增的运行日志。两者独立存储、独立查询、独立授权，运行日志轮转不删除审计记录。
- 系统在现有监控上增加数据库诊断、只读查询、数据导出、备份和恢复；随后开放已获用户确认的 SQL 数据写入与 DDL。
- 数据生命周期先建立完整素材引用和清理预览，再开启可配置的孤儿素材与文章回收站清理。
- 读写 SQL、恢复、物理删除均有权限、短时运维授权、操作记录和恢复保障。自动任务不继承一个永不过期的人工二次验证凭据。

用户已确认：三个参考页面的能力完整纳入路线图、分期交付；SQL 控制台允许读写及 DDL，不限于只读。

## User Stories

### 配置与站点入口

1. 作为站长，我希望页脚 GitHub 链接可以指向账号或仓库，并能留空隐藏，而不改变贡献图使用的 GitHub 账号。
2. 作为管理员，我希望区分已保存值与当前生效值，避免把保存成功误认为运行时已经切换。
3. 作为管理员，我希望查看配置来源和敏感项是否已设置，而不在页面、网络响应或导出中暴露凭据。
4. 作为管理员，我希望一组配置全部通过校验后再保存，失败时保留原值及我的输入。
5. 作为管理员，我希望省略、清空、关闭、零值和恢复部署默认具有明确语义，避免误覆盖其他配置组。
6. 作为管理员，我希望启动配置明确标注只读或需重启，不能在线修改的字段不提供假保存入口。

### 运行日志

7. 作为维护者，我希望按时间、级别和来源查看结构化运行日志，区分应用异常与用户操作。
8. 作为维护者，我希望组合来源、关键词和时间范围筛选历史日志，避免逐行翻找。
9. 作为维护者，我希望通过 request_id 或 trace_id 关联同一请求的日志，定位具体失败链路。
10. 作为维护者，我希望向前加载历史时顺序稳定，不因新日志插入而重复或遗漏已读取记录。
11. 作为维护者，我希望实时看到新日志，并知道连接正常、断开、重连或存在历史缺口。
12. 作为维护者，我希望暂停自动跟随来阅读旧日志，恢复时能继续看到新增内容。
13. 作为维护者，我希望导出当前筛选范围的运行日志，导出与页面使用相同授权和脱敏规则。
14. 作为站长，我希望运行日志按保留天数和容量边界自动轮转，而不影响操作审计。
15. 作为账号所有者，我希望密码、Cookie、令牌、验证码和 SQL 敏感字面量不进入可浏览的运行日志。
16. 作为站长，我希望日志写入故障或浏览器消费过慢不会阻塞业务，并能看到丢弃或缺口提示。

### 安全与诊断

17. 作为管理员，我希望管理可信来源和可信代理，且伪造转发头不能改变身份识别或绕过限流。
18. 作为站长，我希望生产环境无法通过后台关闭必要的 Cookie 安全约束，错误配置也不会把唯一管理员锁在外面。
19. 作为站长，我希望限制单用户同时登录的设备数，超限时按明确顺序淘汰旧会话。
20. 作为管理员，我希望查看会话设备与最后活动情况，并在有权限时吊销指定会话。
21. 作为高危操作执行者，我希望通过短时二次验证获得绑定当前会话的运维授权，退出或撤权后立即失效。
22. 作为维护者，我希望保留现有 CPU、内存、磁盘、网络与 Go 运行时曲线，而不是用新面板替换掉已有监控。
23. 作为维护者，我希望查看数据库大小、连接使用、迁移版本和数据库依赖状态。
24. 作为维护者，我希望查看表和索引占用、行数估算与死元组，区分真实计数和统计估算。
25. 作为维护者，我希望查看活动查询、等待和锁阻塞，同时避免诊断页面泄露 SQL 敏感值。
26. 作为维护者，我希望查看活跃会话和实际存在的缓存命中情况，无法采集的指标有明确说明。
27. 作为站长，我希望诊断查询有时间与结果上限，不因打开后台扫描整库或占满连接池。

### 资源治理

28. 作为管理员，我希望按认证、上传、图片访问、评论和代码执行等实际入口管理限流策略。
29. 作为管理员，我希望配置请求窗口、突发约束和日配额，登录用户与匿名来源采用明确且不可伪造的计数身份。
30. 作为访客，我希望触发限流时收到准确的重试提示，无法识别来源的请求也不能无限放行。
31. 作为站长，我希望限制图片缓存容量和保留时间，并知道清理释放了多少空间。
32. 作为站长，我希望选择图片编码策略及真实有效的 WebP 质量与编码强度，而不是编辑不会被编码器消费的字段。
33. 作为站长，我希望上传和动态处理在完整解码前检查源图单边尺寸与总像素，避免小文件造成巨大内存占用。
34. 作为素材维护者，我希望批量上传遵守文件级并发上限，连续选择多批文件也不会叠加突破限额。
35. 作为素材维护者，我希望取消真正停止上传，失败可单项重试，限流等待不被错误显示为上传成功。
36. 作为管理员，我希望代码执行资源上限的保存与实际执行一致，非法零值不能绕过限制。
37. 作为管理员，我希望配置代码任务并发、排队等待及历史保留，并知道修改是否只影响新任务。
38. 作为读者，我希望代码运行器关闭或语言禁用后，页面入口与后端执行限制保持一致，联网仍满足既有安全条件。

### 数据操作与保护

39. 作为有数据库查询权限的维护者，我希望执行只读 SQL 和 EXPLAIN，并能取消超时或过大的查询。
40. 作为有导出权限的维护者，我希望按表或只读查询流式导出 CSV、JSON 和 SQL 数据，知道导出不等于备份。
41. 作为权限管理员，我希望系统查看、数据库查询、数据导出、数据写入和 DDL 可以分别授权。
42. 作为高危操作执行者，我希望在后台执行 INSERT、UPDATE、DELETE 等写操作，并看到执行结果与影响行数。
43. 作为高危操作执行者，我希望显式启用多语句和 DDL，执行前看清对象、风险和事务能力。
44. 作为高危操作执行者，我希望失败、取消和连接中断有明确结果；重复点击或重试不会再次执行已经提交的写入。
45. 作为站长，我希望高危 SQL 与恢复操作留下业务库之外仍可追查的操作记录，恢复旧库不抹去本次操作事实。
46. 作为站长，我希望手工创建仅数据库或数据库连同素材的备份集，并知道各自可以恢复什么。
47. 作为站长，我希望备份包含版本、范围、完整性和来源信息，工具缺失或备份不完整时明确失败。
48. 作为有备份管理权限的维护者，我希望安全下载或删除备份集，列表查看权限本身不授予读取全部数据的能力。
49. 作为站长，我希望按指定时区和每天的时间自动备份，页面显示下次执行的确切时间。
50. 作为站长，我希望只轮转自动备份，手工备份不会因为名称相似而被自动删除。
51. 作为维护者，我希望导入备份时先检查来源、大小、完整性、格式与版本兼容性，不直接执行未知备份中的内容。
52. 作为恢复执行者，我希望恢复前保存当前状态并进入维护窗口，业务和后台任务不会继续写入待恢复的数据。
53. 作为恢复执行者，我希望数据库与素材来自同一个备份集，系统明确拒绝无法满足引用完整性的恢复组合。
54. 作为恢复执行者，我希望中途失败或进程重启后仍能看到恢复状态，失败时不把半恢复站点重新开放。
55. 作为站长，我希望恢复成功后旧登录态失效、可重建缓存更新，重新登录能够验证恢复后的真实内容。

### 生命周期与使用体验

56. 作为素材维护者，我希望看到所有持有素材的内容来源，包括工作稿、公开版本和可恢复历史，而不只看到一个引用计数。
57. 作为站长，我希望先预览孤儿素材候选和预计释放空间，保护期内、来源不明或核对未完成的文件不能被删除。
58. 作为内容作者，我希望保存内容与清理任务并发发生时，新引用的素材仍受到保护。
59. 作为站长，我希望正式素材清理覆盖原图和衍生文件，失败可追踪且不会产生“记录删了、文件还在”的假成功。
60. 作为站长，我希望单独配置文章回收站保留天数和自动清理开关，关闭时不会定期永久删除文章。
61. 作为内容作者，我希望文章彻底删除仍执行既有领域清理、素材引用释放和公开投影更新，而不是直接删数据库行。
62. 作为后台用户，我希望这些页面在桌面、手机、明暗主题和键盘操作下都能完成任务，加载失败、无权限、空数据与未保存状态清楚可见。
63. 作为账号所有者，我希望新增运维能力继续遵守 opaque session 与 CSRF 规则，不引入 JWT 兜底、匿名放行或可复用的 URL 令牌。
64. 作为维护者，我希望采样与保留策略可管理，并明确知道指标来自当前容器、进程可见环境还是宿主机。

## Implementation Decisions

### 保留现有模块职责

操作审计继续使用既有审计模块及入口；运行日志新增独立模块与入口，不把日志级别、轮转和实时流塞进审计实体。系统模块保留现有快照和历史，增加数据库诊断及数据库操作。备份有独立的备份集和任务生命周期。配置仍按领域分组，不建立允许任意键写入的通用配置接口。

后台沿用既有 Tool 视觉语言、导航、表单、列表和确认交互，不复制参考站的长页样式或绿色配色。公共层只提取真正被多个模块消费的通用件。原有设置子页、审计入口和监控查询保持可用；新增页面不挂在公开 API 或 MCP 上。

### 配置的保存、生效与来源

- 启动环境保留现有优先级；数据库连接、Redis、存储根、密钥、部署来源等启动项只读展示脱敏快照，不经后台改写环境文件。
- 新运维策略采用明确分组和类型校验；数据库中的显式覆盖优先于该策略的部署默认，未覆盖时沿用现有默认。生产安全底线不能被数据库值降低。
- 组级写入采用版本条件和事务。省略表示不修改，空串、零与 false 由字段契约定义；恢复部署默认是单独动作，不能用零值冒充。
- 返回已保存版本、当前应用版本及生效类型：新请求生效、新任务生效或需重启。不能热应用的策略确实在重启时读取数据库覆盖，而不是仅显示一条提示。
- 动态读取使用受控的类型化快照，避免每个高频请求重复全表读取；更新成功后明确刷新运行时消费者和相关前台查询缓存。加载或应用失败展示原有效状态，不报假成功。
- 首个完整切片包含启动快照、真实数据库连接池参数应用以及一个公开可观察的设置链路。页脚 GitHub URL 与贡献图账号分开，迁移保留原有展示，空值隐藏。

### 安全策略与短时运维授权

保留可信代理 CIDR/IP 列表，不退化为只按代理层数信任转发头。可信来源和 Cookie 规则独立于展示用站点 URL。高危安全变更先校验，再通过绑定当前管理员的限时确认生效；未确认自动回到上一有效配置，生产禁止不安全组合，并保留部署侧恢复入口。

会话数量使用 Redis 原子操作约束，按创建时间淘汰最旧的有效会话，清理过期索引；缩小上限的处理范围和时间在界面明示。会话列表不下发完整会话凭据。正常请求续期不轮换会话 ID；SSR 探活仍不续期、不写 Cookie。

短时运维授权复用已验证密码或账号绑定的可信验证通道，不强迫 OAuth 用户设置密码。授权绑定当前用户、会话、操作类别及有效期；高危提交再校验权限，退出、改密、撤权或吊销会话后失效。普通设置查看与修改权限不自动获得 SQL、导出、恢复能力。首次上线不向普通后台角色批量授予这些新能力。

### 运行日志

沿用结构化日志入口，保留 stderr 输出，增加有界异步持久化链，覆盖需要纳入排障的标准日志来源。运行日志单独存入 PostgreSQL，不复用审计表；批量写入、缓冲上限、保留天数和总量边界均有限制。写入自身失败走独立错误出口，防止日志递归。记录发生时间与接收顺序，携带级别、来源、消息、request_id 及已存在的 trace_id，不伪造追踪信息。

历史日志采用稳定游标和固定顺序；实时流沿用项目已有的认证 SSE 方式，历史续读与实时订阅使用同一续读边界。断线后以游标补读，已轮转的游标明确返回缺口。浏览器自动跟随与流连接分开，慢消费者和前端缓存均有上限。导出沿用同一筛选、授权和脱敏规则，不把大结果一次装入内存。

敏感字段采用结构化白名单和文本脱敏双重约束；Cookie、Authorization、密码、API Key、验证码和 SQL 字面量不落入浏览、导出或数据库中的运行日志。审计保留原有追加语义，运行日志的清理策略不能作用于审计。

### 数据库与主机诊断

扩展实际连接池和 PostgreSQL 系统目录、统计视图的只读采集：库容量、迁移版本、表/索引容量、行数估算、死元组、活动连接、等待及阻塞。大表不在自动刷新中执行 COUNT(*)；精确计数只作为受限的显式请求。查询文本默认规范化并去掉敏感字面量。

保留现有主机和 Go 指标；新增会话及现有缓存统计时必须接入真实采集点，区分容器和宿主机可见范围。采样时间、来源、失效状态与错误原因都随结果返回。诊断使用有预算的专用读取资源，不抢占全部业务连接，不新增宿主机高权限挂载。普通管理表格继续使用项目既有分页契约；运行日志这种持续追加的数据流使用现有游标型读取惯例。

### 限流、图片、上传与代码执行

- 限流扩展现有 Redis 原子计数链，支持按实际路由组设置窗口限额、突发约束与日配额；不同时维护另一套进程内限流系统。新增策略默认保留现有限额，未识别来源进入受限分组。日配额以明确 UTC 日界计数，返回实际 Retry-After；Redis 故障策略按入口明确配置，敏感新策略不得静默失去保护。
- 不因参考站存在匿名传图而新增 Violet 匿名上传能力。策略列表只暴露真实入口，不创建没有消费者的开关或参考站专属的桶 GC 参数；Redis 键通过到期策略回收。
- 图片策略覆盖磁盘缓存容量/保留、内存缓存边界、源图单边/总像素、缩略图和真实编码参数。先读头部检查尺寸再进行完整解码。GIF/WebP 动图与透明通道不得被无提示破坏。
- 现有 WebP 是纯 Go 无损编码，质量字段不能直接套用。保留无损路径，新增受限的有损编码路径；以独立 libwebp 编码工具作为生产适配，不开启 Go CGO，也不假定现有 FFmpeg 一定含 WebP 编码器。工具、版本和开发/生产环境能力随切片一起交付；不可用时明确报配置错误，不能静默忽略质量参数。
- 缓存键纳入源内容版本和处理策略版本。修改原图或编码策略后不返回旧衍生内容；容量驱逐和定时清理只处理可重建缓存，不能删除原素材。
- 上传并发是文件级队列，全队列共享上限；分片串行不等于文件并发限制。取消贯通请求与上传会话，重试仅针对失败项，尊重服务器 Retry-After，不承诺多终端竞争时永远不会触发 429。
- 运行器资源策略对新任务生效，队列容量变化不破坏已运行任务。联网仍须作者声明、语言允许和全局许可同时成立；关闭运行器同步约束前端入口与后端执行。现有沙箱隔离保持不变。

### 数据查询、导出与读写 SQL

只读查询、导出、DML、DDL 分别授权，并使用与业务连接池隔离的受限数据库角色及连接预算。SQL 用户不能获得宿主机文件读写、执行程序、扩展安装或数据库超级用户能力。不能依赖字符串前缀或关键词黑名单作为权限边界；CTE、函数、EXPLAIN ANALYZE 与多语句必须由真实数据库权限和事务规则约束。

只读查询提供 EXPLAIN、取消、时间上限、结果行数/字节上限及截断标记。导出支持按表或只读查询，CSV/JSON/SQL 数据格式与列名选项；表名从允许的数据库对象中解析并引用。SQL 数据导出不含完整恢复所需的所有对象，不能称作备份。

读写 SQL 在备份恢复已通过演练后交付。默认单语句，执行 DML、DDL 或多语句前明确选择模式、完成短时运维授权并确认风险。事务兼容的多语句由系统托管为一个事务，用户语句不能逃逸事务边界；不能在事务中执行的 DDL 必须单独确认执行，不宣称可回滚。提供操作 ID、提交前预览、执行/提交/失败/取消状态和影响行数；自动重连或重复请求不得重放已提交操作。

SQL 会绕过领域用例、素材引用和公开投影；界面必须说明这一点，写后清理可重建缓存并提供数据核对结果，不承诺自动修复任意手写 SQL 造成的业务不变量破坏。DDL 和恢复进入明确的维护窗口。高危操作摘要、SQL 指纹、执行者、目标、时间和结果写入审计，并在被操作业务库之外保留受权限保护的运维记录；不存完整敏感字面量或结果集。

### 备份集与恢复

备份采用 PostgreSQL 原生归档及配套素材包，manifest 记录备份身份、手工/自动来源、范围、应用与数据库版本、创建时间、校验和及受信来源信息。备份目录与 uploads、业务数据库分开持久化；自动身份由记录决定，不由文件名前缀决定。缺少原生备份工具时明确失败，禁止退化成仅数据 SQL 后仍声称可完整恢复。

仅数据库备份使用数据库一致性快照。包含素材的备份需要同一个一致性边界：暂停业务写、素材替换/清理和相关后台写任务，排空在途写后获取数据库及素材，再解除短暂维护窗口；读取仍可用。未完成包不进入成功列表。备份不打包可重建缓存或正在上传的临时分片。

调度保存站点选定的 IANA 时区与本地执行时刻，计算并展示下一次 UTC 执行时间。夏令时缺失时刻顺延到当日第一个有效时刻，重复时刻只执行一次。修改计划后重排，重启后不会在同一计划时刻重复执行；错过的计划在恢复运行后最多补一次。仅在新自动备份成功后轮转旧自动备份，手工备份不参与轮转，当前执行或恢复中的备份不可删除。

导入只接受来自本实例或已显式建立信任关系的备份集；校验签名/信任来源、manifest、路径、解包大小、版本与校验和。完整性检查不等于内容安全。上传的归档不得借路径穿越或符号链接写入备份区之外，也不能使用任意 SQL 文件充当受信备份。

恢复由独立维护执行进程完成，控制状态保存在被恢复业务库之外。流程是预检 → 当前状态安全备份 → 排空业务写并保持维护窗口 → 恢复 → 核对数据库/素材 → 失效旧登录态和可重建缓存 → 恢复服务。只有原生恢复工具无错误退出且核对通过，才能报告成功；原生工具“继续执行后统计错误”不等于成功。

素材恢复必须来自同一个备份集。仅数据库恢复前验证被引用素材是否仍完整存在，不满足则拒绝承诺完整恢复。失败保留原素材及安全备份，维持维护状态并提供回退；进程重启后能继续查看或恢复控制流程。生产演练先在隔离副本进行，不用真实站点做首次恢复试验。

默认不备份 Redis 登录态、任务队列和缓存，不重放恢复前的任务；密钥和部署配置属于外部恢复前提，备份 manifest 明确列出所需密钥身份而不包含明文。自动备份首先解决逻辑误操作恢复，不等价于异地容灾或持续时间点恢复。

### 素材引用与自动清理

素材引用必须覆盖文章正文/封面/可恢复历史、评论、推文、聊天、笔记、图集工作稿和公开版本、人设、账号头像、站点资料、友链、项目及其他实际持有本地素材的来源。每种引用由拥有内容的模块维护，不能把业务解析塞入通用存储层。文本 URL 必须归一到本站素材身份；外链、未知路径或尚未完成核对的来源不得当作可删除候选。

先回填并核对存量引用，再提供可见引用来源和孤儿候选预览。现有引用计数是可核对的投影，不是唯一真相。尚未被浏览器保存的编辑内容无法由服务端推断；新上传素材以保护期保护，界面明确保护期不是永久保留承诺。服务端工作稿、公开版本和仍可恢复的历史都建立正式保护关系。

正式清理前重新验证引用并原子占用候选；内容保存与清理竞争时，只有一方能成功取得素材状态，另一方得到明确结果，不发生“内容保存成功但文件刚被删掉”。默认关闭新增的永久删除策略，管理员先预览再启用。普通素材删除统一接入可恢复的延迟清理流程，修复数据库记录与物理文件的删除断链。原图、缩略图、视频封面和关联缓存按拥有关系删除，错误不会被算入成功数量。

文章回收站另有开关和保留期，按删除时刻计龄，不按文章创建或发布时间。定时永久删除必须复用文章用例，保留审计、引用释放和公开投影更新，不直接执行一条批量 DELETE 绕过领域行为。已有手工恢复和彻底删除保持可用。

## Testing Decisions

主要验证 seam 是带真实认证的管理 HTTP 行为及其浏览器入口；恢复另通过真实维护执行进程验证。复用既有 session、CSRF、Redis 限流、上传、图片、运行器和系统监控测试习惯，不为字段转发、组件 wiring 或固定文案新增测试。

- 配置：验证事务保存、并发版本冲突、零/空/省略语义、运行生效值、重启后有效值与公开缓存刷新；连接池指标必须对应真正被业务使用的池。
- 安全：验证伪造代理头、错误可信来源、生产不安全 Cookie、并发登录淘汰、撤权和二次授权失效；SSR 探活仍不续期、不写 Cookie。
- 日志：通过实际请求产生已知日志，验证筛选、历史与实时交接、断线补读、轮转缺口、脱敏、导出一致性和慢消费者；注入写入故障确认业务不被日志链阻塞。
- 数据库：在隔离 PostgreSQL 上制造锁等待、超时、超大结果、CTE 写入、函数调用和多语句；分别验证只读、DML、DDL 授权，事务失败回滚及事务外 DDL 的真实边界。数据库写操作不自动重试。
- 备份：建立包含文章、评论、私域内容和多种素材的隔离站点，创建备份后改动数据，再实际恢复并核对内容、文件校验和、引用、登录态和公开页面；覆盖坏包、无工具、磁盘不足、版本不兼容、来源不可信及中途退出。手工/自动轮转与夏令时边界需要确定性用例。
- 图片与上传：使用尺寸头部超限、透明、动图、损坏和正常图片，验证解码前拒绝、编码参数真实消费及缓存版本；用多批文件和真实 429 验证全队列并发、取消和重试。
- 清理：用所有实际引用来源、工作稿/公开版本/历史、保护期边界以及并发引用场景证明没有误删；文章自动删除与手工用例产生相同的领域结果。
- UI：在 1440×900 与 390×844、light/dark 下验证设置、日志、诊断、导出、备份、SQL 和清理流程，覆盖键盘焦点、未保存状态、错误、禁用和内部滚动；保留截图与真实操作结果，不以类型检查代替界面验证。
- 在当前会话按依赖连续推进，每个 issue 以可观察行为为验收单位；修改导致的既有测试随契约更新。确有回归风险的边界保留自动化测试，其余通过可移除的 smoke 脚本证明。提交前按 Standards 与 Spec 两条轴评审。

## Out of Scope

- 不替换操作审计，不给审计增加运行日志式的清空或轮转。
- 不重做全站视觉语言；既有视觉迁移 issues 仍独立管理，不在本项目中关闭或改写它们。
- 不引入通用远程 Shell、宿主机文件管理、数据库超级用户控制台，或向 MCP/PAT 开放高危运维能力。
- 不增加 SMTP、第三方通知渠道、多 LLM Provider、对象存储迁移、匿名图片上传等与这三个页面无直接关系的新产品能力。
- 不承诺任意来源备份、任意 PostgreSQL 版本或任意插件的恢复；不把数据导出包装为完整备份。
- 不包含跨地域备份复制、WAL 持续归档、时间点恢复或零停机恢复。这些与完整的单实例备份恢复不同，后续可单独立项。
- 不因本轮源码调查顺手修复 About、SEO 等无关问题；数据库连接池真实性和素材引用/删除断链属于本轮直接依赖。

### 调研依据与证据边界

参考页已经登录真实浏览器查看，系统页五个页签均已切换检查：

- [站点配置](https://rua.plus/admin/settings)

Violet 基线为 `release/2.0` 的 `160de84b`。设置、审计、系统、媒体、限流和会话能力已经过源码链路对照；本轮不宣称已完成其运行回归。素材删除行为推断必须先在隔离环境复现。编码能力探测发现本机 FFmpeg 不识别 libwebp，不能以“已安装 FFmpeg”替代生产编码能力验收。

[PostgreSQL pg_dump 文档](https://www.postgresql.org/docs/16/app-pgdump.html)明确区分数据库一致性备份、原生归档与仅数据输出；[pg_restore 文档](https://www.postgresql.org/docs/16/app-pgrestore.html)指出恢复可执行来源数据库控制的代码。签名、校验和与只读查询校验不是可以互相替代的安全措施。

### 交付顺序

先交付配置真实性，再推进运行日志、安全会话、资源治理和素材引用。数据库查询与导出在诊断和短时授权之后；手工备份先于调度和恢复；恢复演练通过后才开放 SQL 写入/DDL 及自动物理删除。

每个子 issue 交付一个贯通存储、应用、HTTP 和真实界面的完整行为，不拆成“先后端空接口、再前端占位页”。前后端按仓库规范分别提交，完成验证即落本地提交，不积攒全部任务后统一提交；公共改动只有在可独立回滚时单独提交。全部实现在当前会话、同一功能分支内连续推进，以本 PRD 和对应 issue 为输入。
