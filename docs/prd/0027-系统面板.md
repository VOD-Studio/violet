# PRD: 系统面板

## Problem Statement

Violet 的 `/admin/system` 目前只有服务器资源监控，无法在后台完成数据库诊断、受控 SQL、数据导出和备份恢复。

原 issue #339 把站点设置、运行日志、会话安全、限流、媒体治理、代码运行器和数据保护全部归入“系统面板”，形成 64 条用户故事和 17 个子 issue。该范围既不对应参考实现，也跨越多个已经独立存在的 Violet 模块，无法作为一个可验收页面交付。

参考实现为 [VOD-Studio/yggdrasil 的 `/admin/system`](https://github.com/VOD-Studio/yggdrasil/tree/master/src/pages/admin/system)：一个页面、五个页签。Violet 以此为功能边界，复用已有服务器监控，并按现有 DDD、RBAC、opaque session 与 CSRF 约束实现。

## Solution

将 `/admin/system` 从“系统监控”升级为“系统面板”，保留单一路由，通过五个页签承载系统维护能力：

| 页签 | Violet 交付内容 | 权限 |
|---|---|---|
| 数据库状态 | 数据库体积、连接池、迁移版本、表体积与行数估算、索引、活动查询 | `system:view` |
| 服务器状态 | 复用现有主机、Go runtime、PostgreSQL、Redis、磁盘与历史趋势监控 | `system:view` |
| SQL 控制台 | 单语句执行、可选多语句、EXPLAIN、结果表格、耗时与截断状态 | `system:manage` |
| 数据导出 | 按表或只读查询导出 CSV / SQL INSERT 文件 | `system:manage` |
| 备份恢复 | 手动备份、自动备份设置、列表、下载、导入、删除与数据库恢复 | `system:manage` |

### 数据库状态

- 概览显示数据库总大小、当前连接数与上限、表数量、`schema_migrations` 版本和 dirty 状态。
- 表清单显示 schema、表名、估算行数、表大小、索引大小、总大小、死元组、最近 vacuum/analyze 时间。
- 索引清单显示扫描次数、读取元组数和索引大小。
- 活动查询隐藏当前诊断请求，显示 PID、用户、状态、持续时间和查询文本。
- 仅查询 PostgreSQL 统计视图，不对每张表执行实时 `COUNT(*)`；轮询不会随表数量线性放大全表扫描。

### SQL 控制台

- 默认仅允许一条语句；用户显式开启“多语句”后才可提交多条语句。
- `SELECT`、`WITH`、`SHOW`、`EXPLAIN` 返回列和最多 500 行；达到上限时返回 `truncated=true`。
- 单次执行超时 30 秒，返回结果总 JSON 体积受限，防止浏览器和 API 内存被大结果拖垮。
- 永久禁止 `CREATE/DROP DATABASE` 与 `CREATE/DROP SCHEMA`。
- `DROP`、`TRUNCATE`、`ALTER` 及其他写语句需要前端显式确认；`UPDATE` / `DELETE` 缺少 `WHERE` 时拒绝执行。
- 所有写 SQL 请求受 CSRF 与 `system:manage` 保护；错误不得回显数据库密码或连接串。

### 数据导出

- 支持按表或只读 SQL 查询导出。
- 格式仅包括参考实现已有的 CSV 与 SQL INSERT；不新增 JSON 快照协议。
- CSV 使用数据库流式输出；SQL INSERT 逐行写入响应，不将完整导出一次性加载到内存。
- 表名只能从 schema 元数据中选择；查询模式复用 SQL 控制台的只读判定和超时限制。

### 备份恢复

- 数据库备份使用 PostgreSQL 客户端工具生成 plain SQL；API 运行镜像必须包含兼容 PostgreSQL 16 的 `pg_dump` / `psql`。
- 可选将上传目录打包为独立 `.tar.gz` 附件。数据库恢复只恢复数据库；上传归档由管理员下载后按部署手册恢复，界面不得暗示“一键全站恢复”。
- 备份写入独立持久化目录，不放入公开 `/uploads` 路径。
- 手动创建、恢复等长任务异步执行，前端轮询任务状态；同一进程只允许一个备份维护任务运行。
- 导入仅接受由 Violet 签名的 `.sql` 备份，限制文件大小并使用临时文件原子落盘。
- 恢复命令启用单事务和遇错停止；失败必须保留原备份并返回可诊断错误。
- 自动备份按 UTC 每日执行；设置包括启用状态、执行时间、自动备份保留份数和是否包含上传归档。保留策略只清理超出份数的自动备份，不删除手动备份。

## User Stories

1. 作为拥有 `system:view` 的管理员，我能在一个页面查看数据库和服务器健康状态，不需要登录宿主机。
2. 作为拥有 `system:manage` 的管理员，我能执行受限 SQL 并清楚看到语句类型、耗时、影响行数和结果截断状态。
3. 作为拥有 `system:manage` 的管理员，我能把表或只读查询结果导出为 CSV / SQL 文件。
4. 作为拥有 `system:manage` 的管理员，我能创建、下载、导入、删除和恢复数据库备份，并看到异步任务进度与错误。
5. 作为拥有 `system:manage` 的管理员，我能配置每日自动备份和保留策略。
6. 作为只拥有 `system:view` 的运维观察者，我不能调用 SQL、导出和备份写接口，也看不到对应操作页签。

## Implementation Decisions

### API

所有接口位于 `/api/v1/admin/system`：

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/database` | 数据库状态 |
| `GET` | `/schema` | SQL 补全与导出选择所需 schema |
| `POST` | `/sql` | 执行 SQL / EXPLAIN |
| `POST` | `/export` | 下载 CSV / SQL |
| `GET` | `/backups` | 备份列表与自动备份设置 |
| `POST` | `/backups` | 启动手动备份 |
| `POST` | `/backups/import` | 导入受信备份 |
| `GET` | `/backups/{name}/download` | 下载数据库或上传归档 |
| `POST` | `/backups/{name}/restore` | 启动数据库恢复 |
| `DELETE` | `/backups/{name}` | 删除备份及其归档 |
| `GET` | `/tasks/{id}` | 查询备份任务状态 |
| `PUT` | `/backup-settings` | 更新自动备份设置 |

现有 `/snapshot` 与 `/history` 保持不变，继续服务服务器状态页签。

### 权限

- 保留 `system:view`：数据库状态、服务器状态。
- 新增 `system:manage`：schema、SQL、导出、备份和自动备份设置。
- 不按 SQL / 导出 / 备份继续拆分权限点；当前没有独立角色需求，单个管理权限避免角色矩阵膨胀。
- 前端页签与按钮根据权限隐藏，后端路由仍是最终授权边界。

### 前端

- 继续使用 `web/src/features/admin-system/`，不创建第二套 feature。
- 页面级切换复用 `@shared/ui/segmented`。
- 服务器状态页签复用现有监控组件，不复制请求或指标视图。
- 数据库表清单使用现有 `DataTable` 与 `useClientPagination`；动态 SQL 结果使用只读结果表，不套业务分页。
- SQL 编辑器为 `admin-system` 私有组件，复用 CodeMirror 基础包并加入 SQL 语言支持；不把系统面板逻辑塞入代码运行器的共享编辑器。

### 部署

- API 镜像安装 PostgreSQL 客户端与 tar。
- Compose 增加仅 API 挂载的 `backups_data:/app/backups` 命名卷。
- `BACKUP_DIR` 可覆盖备份目录，默认 `backups`；不得配置为公开上传目录的子路径。

## Acceptance Criteria

1. `/admin/system` 显示五个页签，数据库状态与服务器状态对 `system:view` 可用；后三个操作页签仅对 `system:manage` 可见。
2. 数据库状态接口在实际 PostgreSQL 上返回数据库大小、迁移状态、表、索引和活动查询，且不逐表执行精确 `COUNT(*)`。
3. SQL 控制台拒绝数据库/schema 生命周期语句、无 `WHERE` 的 UPDATE/DELETE、未授权多语句和未确认危险语句；只读查询结果最多 500 行并标记截断。
4. CSV 与 SQL 导出从服务端以附件形式下载，表名不能注入 SQL，查询导出只接受只读语句。
5. 手动备份生成可下载 SQL；导入拒绝未签名文件；恢复使用单事务并在任务失败时给出错误状态。
6. 自动备份设置持久化，调度器按 UTC 时间触发，保留策略只删除过期自动备份。
7. 开发与生产容器内均可执行 `pg_dump --version` 和 `psql --version`，备份目录跨 API 容器重建保留。
8. 后端定向测试、前端 typecheck / Biome、实际浏览器五页签与权限可见性验证通过。

## Out of Scope

- 站点设置重做；继续由 `/admin/settings/*` 负责。
- 运行日志检索；现有结构化日志仍由部署环境采集。
- 会话安全、短时提权、系统事件流和安全策略治理。
- 限流配置、图片配置、上传配置与代码运行器配置。
- 媒体垃圾清理、文章回收站和业务数据清理。
- 跨服务一致性快照、对象存储、远端备份复制、加密 KMS、独立控制面恢复。
- PostgreSQL 以外的数据库引擎。
