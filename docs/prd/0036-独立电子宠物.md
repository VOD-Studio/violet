# PRD-0036：独立电子宠物

状态：**待评审草案**。产品边界来自需求访谈；技术方案倾向以 Rust 实现规则核心、独立服务与 CLI，Web 端保持 TypeScript，Go 已退出候选，TypeScript 全栈为回退方案；切片证据通过前不定稿。本稿不表示产品、原型、后端、适配器或可执行 Skill 已实现，不作为跳过评审直接施工的规格。

阅读入口：[用户故事](#用户故事)、[产品规则](#产品规则)、[接口与数据边界](#接口与数据边界)、[技术候选](#技术候选)、[Skill 契约](#skill-契约)、[验收标准](#验收标准)、[评审清单](#评审清单)。

## 要解决的问题

用户需要一只会动、能陪伴阅读与创作、会因经历而改变的宠物，而不是固定造型的页面装饰。不同用户的宠物应有可辨认的差异，出生结果可以复核，成长能带来进化与个性变化；生命终结必须有明确规则，不能因长时间没打开网站而回来就突然死亡。

外部开发者也需要这项能力。他们不应为了接入宠物而使用 Violet 的账号、数据库、React 状态或业务 API，也不应各自实现一套生成、养成和动画逻辑。网页与 CLI 应能独立使用；需要跨端账号共享时，再连接可自部署的独立服务。

## 解决方案与范围

交付通用 SDK、独立且可嵌入的 CLI、可自部署的宠物服务、规则与素材目录、接入文档及随包分发的 Skill。Violet 是参考接入方，不是运行前提。

硬边界如下：

- 宠物后端独立于接入网站的业务 API；不复用 Violet API 或 SSR 托管宠物状态与规则。
- 每个接入方拥有独立的宠物世界；同一世界内的 Web 与 CLI 共享账号宠物，不默认跨站共享或迁移。
- 持久化、身份、活动事实与页面目标通过明确的契约接入。产品提供可运行的默认实现，自定义需求由接入方实现适配器。
- 本地模式可以完整离线运行；账号模式由独立服务持有唯一权威状态。
- 基础生成、养成、动画与生命规则不依赖 AI。后续 AI 只能使用实际授权的能力，不能成为状态裁判。
- 当前同时一只主宠。探险收藏、装扮家园、好友协作、繁育家谱、多宠家园与 AI 共读均保留在完整目标中；扩展的详细规则和交付顺序见评审清单，不因暂未实现而伪装成可调用能力。
- 已废弃的 `/lab/mascot` 界面不是设计参考，不沿用其造型、布局、交互或动效方案。本 PRD 不要求删除旧实现。

## 用户故事

3. **US-03**：作为养宠用户，我希望查看并验证出生凭据，以便确认宠物可以按对应规则重建，而不是每次刷新重新抽取。
4. **US-04**：作为养宠用户，我希望知道出生稀有度与后天成果的区别，以便普通出生也有值得努力获得的罕见形态。
5. **US-05**：作为养宠用户，我希望同一世界内保持一只主宠，并保留逝去宠物的纪念，以便新领养不会抹掉上一段陪伴。
6. **US-06**：作为养宠用户，我希望理解饱食、精力和健康并进行照料，以便喂食、休息、玩耍与治疗产生可理解的效果。
7. **US-07**：作为读者，我希望有效阅读能参与养成，以便日常阅读可以带来成长，而不是反复刷新页面刷奖励。
8. **US-08**：作为作者，我希望有效创作能参与养成，以便自己的作品与宠物经历建立联系。
9. **US-09**：作为社区用户，我希望自己的合格评论、点赞等有效互动获得奖励，以便参与讨论也能照顾宠物。
10. **US-10**：作为内容作者，我希望别人对我的互动能带来宠物情绪或纪念，以便感受到回应，但不制造互刷资源的动机。
11. **US-11**：作为养宠用户，我希望阅读与创作主题影响成长方向，以便宠物能够留下我的兴趣与经历的痕迹。
12. **US-12**：作为养宠用户，我希望长期相处慢慢改变性格且保留出生底色，以便宠物不是随机换人设，也不因一次饥饿就永久改变。
13. **US-13**：作为养宠用户，我希望从合格分支中选择进化方向与时机，以便成长不强迫我立即更换喜欢的形态。
14. **US-14**：作为养宠用户，我希望生病前有预警、生病后有救治机会，以便死亡是可理解的生命结果而不是随机惩罚。
15. **US-15**：作为暂时离开的用户，我希望长期离线后回归最多生病且仍可救治，以便陪伴不会变成必须每天签到的负担。
16. **US-16**：作为接入方，我希望配置自然寿命开关及物种差异，以便选择适合自己产品的生命节奏，而不误把关闭老死等同于关闭健康死亡。
17. **US-17**：作为养宠用户，我希望死亡不可逆但过程和纪念清楚，以便区分真正的新个体与原宠物复活。

## 产品规则

### 出生、身份与稀有度

- 默认领取，不采用算力挖矿或出生保底。再领养冷却仍待数值评审。
- 身份唯一、基因可复现、人眼可辨认是不同承诺；允许少量外观相似，不承诺全球绝不撞脸。
- 五档出生稀有度由接入方配置权重，影响外观、动作与进化分支，不提供普遍的经验、寿命或战力优势。出生档位不随成长重抽，后天罕见形态单独记录。
- 物种与稀有度独立。物种方向覆盖原创幻想生物、现实宠物、机械 / 数字生命、植物 / 元素生命，不把某一类别固定为高稀有度。
- 先确定整体出生档位，再从该档位的合法兼容池生成形态；不能把各部件独立抽出的最高档位冒充整体档位分布。
- 基因、生命事件与动画使用相互隔离的随机通道。增加闲置动作或重播动画不得影响出生、未来进化或资源结果。
- 规则、素材目录与生成算法都绑定版本。既有个体继续按保存的身份、基因与对应资源呈现，不能用最新目录重新随机生成。

**公开核验的候选协议**：一次领取先固定世界、发行者、出生请求、领取资格和版本摘要；服务端先承诺本次专用随机材料，再接受并持久固定客户端随机材料，随后揭示并派生结果。验证器核对承诺、签名来源、规则摘要与重算结果。请求重试恢复原结果，不能在揭示后更换输入。

这是待安全评审的协议，不是已证明公平的实现。它应能证明给定输入与结果的对应关系，但不能仅凭一份凭据证明服务方从未选择性拒绝请求，或不存在多账号偏差。公开凭据不包含登录凭据、邮箱或原始活动记录；用于公开重算的输入与私有账号归属记录应分开。

### 养成、性格与进化

饱食、精力和健康属于身体状态；开心、低落、警惕等属于短期情绪；性格是随长期经历缓慢变化的倾向。三者分别建模，不用一个等级或“心情值”代替全部状态。

喂食、休息、玩耍与治疗有明确前置条件、资源成本及结果。失败动作不扣资源，重复无成本动作不能无限刷经验。性格保留出生气质，并限制短时重复刺激的永久影响；具体维度、幅度和节奏通过原型评审。

基因、等级、主题倾向与经历共同决定合格进化分支。用户可以选择分支或暂缓，未满足条件时应获得可理解的缺项说明。进化不重新抽出生档位，形态保留可辨认的身份线索。

### 内容联动

| 来源 | 资格与效果 | 必须避免的重复收益 |
|---|---|---|
| 有效阅读 | 使用前台停留、进度等轻量信号，结合可核验内容身份形成资格；奖励经验、主题倾向或资源。信号不等于证明读懂。 | 同篇资格重复上报、刷新、多窗口或多端重复领奖。 |
| 有效创作 | 首次取得可验证的合格发布资格时奖励作品 Owner，不把代发布或编辑者等同于作者。 | 重新发布、回滚、改标签或新增版本再次领取同类奖励。 |
| 本人有效互动 | 合格点赞与评论均可计奖；成立条件由可信业务来源定义。 | 取消重赞、重复审核、重复事件或换代后重领旧互动。 |
| 收到别人互动 | 可影响情绪或产生纪念，不直接发放可刷资源。 | 互刷点赞评论直接转化为库存和经验。 |
| 内容主题 | 接入方映射标签 / 话题，资格形成时固定采用的主题；无标签仍可获得基础成长。 | 改标签重新计算并重复发奖，或强制依赖 AI 分类。 |

收益上限按世界内的账号共享，不按窗口或宠物代数分别计算。去重需要来源事件身份和业务资格身份，不能仅依赖事件条数。宠物服务自行裁决资格、上限与收益，不接受客户端指定经验或余额。

Violet 的参考接入使用已有业务：当前有推文点赞与文章 / 推文评论，不为本需求顺手新建文章点赞系统。现有文章浏览计数不具备账号有效阅读资格，内存事件分发也不等于可靠跨服务投递；连接器必须核实权威事实与补偿对账能力。宠物服务故障不应使原站阅读、发布或评论变成失败操作。

### 生命、离线与死亡

- 健康死亡按持续失养、预警、生病、救治失败的过程发生；不随机暴毙，不因一次动作失败或网络错误死亡。
- 短期离线可消耗状态，长期进入休眠。**回归最多生病，保留救治机会，不直接结算不可逆死亡。**
- 自然寿命由接入方统一配置；开启时物种存在差异，关闭时没有老死，但仍有健康死亡。
- 休眠期间如何计算自然年龄、宽限期与救治窗口，以及寿命配置如何作用于在世个体，属于明确列出的评审项。不能在实现中默默选择会让旧宠突然死亡的策略。
- 生命按明确的逻辑时间结算，动画按呈现时钟运行。浏览器后台暂停、CLI 掉帧、多端同时连接不改变年龄与消耗结果。
- 死亡是终局，保留名字、形象、经历与死因说明；新领养产生新身份，不复活或覆写原个体。
- 账号模式离线只保留动画与无收益轻互动，不接受待联网再合并的扣物品、领奖或进化队列；恢复后读取权威状态。本地模式可继续完整养成，但其存档不自动变成服务签发的正式个体。

### 动态形象与素材规范

共享的是形态语义、身份特征与动作，不要求网页精细风格只是放大像素图，也不声称任意 SVG 缩小后自然适合终端。

每套可正式使用的素材须说明：

- 稳定标识与版本，适用物种、身体结构、阶段及兼容部件。
- 骨架 / 槽位、锚点、层级、朝向，以及各画风中保留的身份线索。
- 精细、像素与终端所需的资源或明确对应关系；不能只依赖细微色差区分个体。
- 待机、眨眼、走动或对应移动、观察、进食、玩耍、睡眠、受惊、生病、进化与生命终结的动作表现。
- 来源、修改与分发许可；禁止未声明外链、脚本和任意 SVG 活动内容。

不同身体结构可采用不同动作实现，例如悬浮生物不必有脚。目录校验、结构校验与真实多动作预览共同验收；增加部件不得破坏不相关的既有个体。素材数量、画风细节及视觉合格线需原型评审，不能用组合数代替可辨认数量。

### 页面与终端行为

公开主页显示主人的宠物，访问者身份另行判断。接入页面显式登记允许互动的稳定目标、几何、动作许可和恢复方式，包不扫描全站 DOM 或取得业务删除能力。

自由走动与自主恶作剧不得拦截整页操作、遮挡正在输入的字段或破坏焦点。主页主人允许公开宠物，不等于访客同意被恶作剧；当前访客可关闭并恢复临时效果。目标卸载、筛选切换、跳转或撤回许可后，动作应取消并释放呈现状态。

“吃掉推文”仅临时隐藏或折叠当前浏览者看到的卡片，不删除推文、不修改统计、不删除业务查询缓存。刷新恢复正常。支持键盘交互与减少动效偏好。

CLI 独立模式拥有自己的输入与退出清理；嵌入模式只使用宿主提供的输入和输出区域，不夺取整个终端。需要验证 resize、低色彩、ASCII 降级、Ctrl+C 和卸载后的恢复。非 TTY 输出可读状态或 JSON 并退出，不输出动画控制码；这不替代真实终端中的动态宠物。

### 扩展玩法

| 方向 | 必须保留的用户价值 | 进入实现前需补齐的规则 |
|---|---|---|
| 主题探险与收藏 | 将兴趣倾向与资源用于旅程、见闻及收藏，留下动作和纪念。 | 资源成本、旅程结算、取消与领奖；不默认增加未确认的随机死亡风险。 |
| 装扮与家园 | 装饰与出生基因分开，可改变穿戴和生活空间。 | 槽位兼容、获得与使用方式；多居民家园另行明确，不能暗中突破当前主宠限制。 |
| 好友拜访与协作 | 双方授权的相遇与协作，不自动获得对方消费权限。 | 双方许可、撤回、协作收益和中断结算；当前主页不冒充已支持携宠相遇。 |
| 繁育、遗传与家谱 | 后代有独立身份、可验证遗传与可追溯家谱。 | 双方授权、遗传概率和孵化安置；待孵化资格是候选，不默认为必须牺牲父母才能体验后代。 |
| AI 对话与共读 | 性格、情绪与获准内容影响交流，能力调用仍受程序裁决。 | 内容授权范围、模型接入及可调用能力；关闭 AI 后基础玩法仍完整。 |

这些项目在完整需求范围内，但尚未全部具备可执行规格。对应规则评审完成前，不发布空 API 或用模拟结果宣称扩展已上线。

## 接口与数据边界

### 模块责任

| 模块 | 拥有的责任 | 不拥有的责任 |
|---|---|---|
| 规则核心 | 出生派生、状态转换、合法动作、成长、生命、投影与核验。 | DOM、网络、数据库、系统时钟、系统随机源和接入站点实体。 |
| 动作执行与持久化边界 | 验证主体、取得可信输入、事务提交、幂等恢复和并发裁决。 | 把客户端自算状态直接当作权威，或持有事务等待网络 / AI 返回。 |
| Web / CLI 呈现 | 画风、局部动作、输入、可访问性与清理。 | 以帧数决定收益、直接修改权威库存或生命。 |
| 独立服务 | 账号宠物、自己的凭据、活动收件、资格与奖励记录、状态同步。 | 依赖 Violet API / SSR 持有宠物数据，或直接查询 Violet 业务表。 |
| 接入方适配 | 身份证明、可核验业务事实、主题映射与页面目标。 | 直接指定宠物收益、跳过所有权检查或改变规则核心。 |
| 能力目录与 Skill | 描述当前真实接口、生成操作与合规素材要求。 | 充当权限控制，或将路线图中的功能列为已实现。 |

### 统一契约，不是假装跨语言共享接口对象

纯规则模块接收完整状态、动作、规则版本、逻辑时间与随机材料，返回决定和投影，不自行读写存储。

持久化接口由动作执行外层使用。服务端进程内存储以选定语言的接口实现（当前倾向 Rust trait），浏览器本地存储使用 TypeScript SDK 契约。共享的是状态 schema、提交语义和错误分类，不是可被任意语言直接实现的同一个对象。

使用已部署服务的外部项目通过公开协议接入，不必学习服务实现语言。需要定制进程内存储的维护者实现所选语言的适配器；默认服务必须配有可运行实现，不把所有接入者都变成后端作者。

### 持久化保证

持久化契约至少兑现以下行为，方法签名在语言评审后固化：

1. 读取作用域内的一致状态及版本；冲突可以被调用方区分，不能静默覆盖。
2. 一次动作的宠物状态、库存、资格 / 奖励去重和命令结果原子提交；失败不出现部分扣费或部分发奖。
3. 同一请求重放返回已提交结果；同一请求标识不能被用于悄悄执行另一组参数。
4. 出生请求、已接受随机输入和结果可持久恢复，服务重启或请求失败不重抽。
5. 升级规则或存档格式时仍可解释历史出生与纪念，不把旧状态当最新版本任意解析。
6. 账号 / 世界作用域隔离，另一个接入方或账号不能通过猜测 ID 读写私有状态。

本地文件实现需要单写者保护及原子替换；数据库实现使用可兑现上述语义的事务或等价机制。仅内存存储必须明确其非持久性质，不能在正式服务持久化失败时偷偷作为替代。

账号模式只有服务端存储持有权威数据，Web 与 CLI 不能各存一份有效库存。动画从内存投影驱动，不逐帧访问持久化。

### 身份、活动与公开投影

外部身份由发行域与稳定 subject 映射，不按邮箱或用户名自动跨世界合并。宠物服务验证自己的访问凭据与 owner；不得使用客户端自报 owner、管理员 MCP PAT 或复制 Cookie 来冒充普通用户的 CLI 授权。

活动输入描述来源、事件身份、主体、内容引用、行为、发生时间和主题。来源签名只证明发送者身份，不证明内容有效；接入方仍须核验真实业务资格。

内容平台提交与宠物结算是不同事务。连接器负责可靠送达或权威查询对账，宠物服务持久收件并幂等结算；不宣称一个跨库原子事务，也不把宠物奖励表放回原站来绕过边界。

公开主页只读取允许公开的投影。出生核验与纪念展示不得顺带暴露登录标识、阅读内容或私有事件详情。服务端同步状态变化，不同步每帧坐标；临时页面效果不写成权威生命状态。

### 能力调用语义

| 能力组 | 可观察结果 | 权限或状态边界 |
|---|---|---|
| 状态与出生核验 | 当前可读投影、对应版本的核验结果与明确不一致项。 | 公开投影和私有状态分开，不以知道个体 ID 代替授权。 |
| 领取 | 返回唯一已提交个体与出生记录，重试不重抽。 | 主宠槽位、领取资格与世界规则由权威执行方检查。 |
| 照料与物品使用 | 状态与库存共同变化，失败无部分提交。 | 所有权、生命状态、成本与当前资源。 |
| 进化 | 查询合格候选；确认后得到新的成长形态。 | 用户选择、前置条件与请求幂等；不重写出生档位。 |
| 纪念 | 读取原个体的允许展示信息。 | 不提供以复活原宠物为效果的普通写命令。 |
| 页面互动 | 注册目标上的临时效果及取消 / 恢复结果。 | 当前页面作用域与实际许可，不拥有内容删除能力。 |
| 扩展能力 | 仅返回已实现玩法的真实结果。 | 探险、装饰、协作、繁育与 AI 能力按实际交付注册。 |

每项能力描述输入输出 schema、当前版本、所需作用域、前置状态、资源影响、幂等与取消语义，以及可区分的业务错误。账号模式写操作返回已提交结果；网络中断不等于可由客户端宣告成功。接口命名、协议编码和凭据交换细节列入评审，不在草案中虚构已存在的命令或端点。

## 技术候选

**评审倾向：规则核心、独立服务与原生 CLI 采用 Rust；Web SDK、渲染与浏览器适配器保持 TypeScript。** Go 不进入切片；TypeScript 全栈作为回退方案。本节记录倾向的理由、前提与回退条件，切片证据通过前不定稿，也不声称某方案已经更小或更快。

### 选择的实际范围

渲染、DOM、IndexedDB、可选 React 入口与页面目标登记在任何方案下都是 TypeScript。R-01 选择的是规则核心、独立服务与 CLI 的语言；选 Rust 或 Go 意味着“TypeScript 再加一门语言”，不是替换 Web 端技术栈。

仓库现有的 Go 与 pnpm 工具链是维护成本的输入，但不单独决定结果：宠物服务独立于 `api/`，不复用其模块，可复用的只有团队经验。

### 比较维度

| 维度 | TypeScript / Node | Go | Rust |
|---|---|---|---|
| 确定性约束 | 依赖 lint 与约定。`number` 超出安全整数会失精度；规范允许 `Math.sin`、`exp` 等由各引擎自选近似算法；WebCrypto 摘要为异步接口，同步核心需另带哈希实现。 | 依赖约定与 linter 限制，标准库可直接取得时钟和随机源。 | 核心 crate 可设为 `no_std` + `alloc`，取不到文件系统、系统时钟与系统随机源；clippy 可禁止浮点运算与指定方法。整数宽度显式，原生与 WebAssembly 编译同一份代码。 |
| 状态机表达 | 可辨识联合加穷尽断言，每处分支需自行写全。 | 无和类型，穷尽性依赖测试。 | enum 加穷尽 `match`，新增生命阶段或进化状态未处理即编译失败。 |
| 浏览器核心 | 直接调用，无额外初始化。 | `GOOS=js` 产物携带 Go 运行时与垃圾回收，须分发版本匹配的 `wasm_exec.js`，导出调用依赖常驻运行时实例。 | 无运行时与垃圾回收，导出为普通函数；初始化为异步，需显式调用。 |
| 服务与持久化 | Node 服务；接入方编写适配器门槛最低。 | 原生服务；团队最熟悉。 | 原生服务；async trait 与事务生命周期难写，接入方自定义存储须写 Rust。 |
| CLI 与嵌入 | 可直接嵌入 Node 终端工具；独立分发需要 Node 或打包运行时。 | 单一原生二进制；嵌入 Node 宿主需经 WebAssembly。 | 单一原生二进制；Rust 宿主以 crate 嵌入，Node 宿主经 WebAssembly 嵌入。 |
| 构建发布 | pnpm 单一工具链。 | Go 工具链与配套 wasm 支持文件。 | cargo、wasm-bindgen、wasm-opt 与 TypeScript 类型生成，按 web / bundler / node 分别产出。 |

### 取舍

**Go 不进入切片。** 浏览器本地模式要求核心完整运行在浏览器中，这是使用最多的一端。Go 在这里须携带运行时与版本匹配的支持文件，并以常驻运行时实例承载导出，与“纯函数调用、SSR 导入不产生全局可变状态”的要求相悖。Go 的优势集中在服务端与团队熟悉度，恰好落在实现难度最低的一端。

**倾向 Rust。** 本产品的核心承诺是出生结果可公开重算、三端结果一致。Rust 能把“规则核心不拥有时钟、随机源与 I/O”和“规则不用浮点”从评审约定变为编译约束；Rust 原生与 WebAssembly 的超越函数同样可能不同，因此禁浮点是前提而不是可选项。Rust 不进入 DOM，Web 端仍由 TypeScript 承担。wasm-pack 已迁入 wasm-bindgen 组织并在 2026 年持续发布；仓库所用 Biome 以 npm 按平台可选依赖分发 Rust 二进制，是原生 CLI 经 npm 分发的现成先例。

**TypeScript 全栈作为回退。** 单一语言、嵌入 Node 终端零成本、接入方编写适配器的门槛最低。其确定性风险可以靠 lint、整数约定和固定哈希实现压低，但不能由编译器保证。

### 采用 Rust 的前提

以下条件属于选择本身；不打算兑现时，Rust 的主要收益不存在，应回退 TypeScript。

1. **核心隔离**：规则 crate 采用 `no_std` + `alloc`，禁止浮点运算与指定方法；时间与随机材料只经参数进入；依赖限于摘要 / HMAC / HKDF 与序列化。
2. **数值编码**：线上 DTO 不出现超出 JavaScript 安全整数的数值；需要 64 位时序列化为字符串，并写入 schema 规范。
3. **schema 事实源**：由 Rust 类型生成 TypeScript 声明与能力目录 JSON Schema，CLI 帮助、机器可读发现与 Skill 引用同源产出，不手写第二份。
4. **存储契约形状**：不暴露事务回调，采用“读取版本 + 单次原子提交”。`load(scope)` 返回状态与版本；`commit(scope, expectedVersion, requestId, changeset)` 区分已提交、版本冲突与重放既有结果；changeset 一次包含宠物状态、库存、奖励去重与命令结果。此形状对任何语言都适用，Postgres、SQLite、文件与 IndexedDB 均可兑现，方法签名在切片中固化。
5. **默认存储**：服务端随附 Postgres 与 SQLite 实现及存储契约验收 crate，自定义 Rust 适配器只服务少数场景。
6. **终端帧合成在核心侧**：独立 crate 将投影、画风、尺寸与动作相位合成为字符单元网格，与规则 crate 分别版本化；原生 CLI、Node 嵌入与 Web 端终端预览只负责输出，不维护多套终端渲染。
7. **CLI 交付**：独立入口为原生二进制，异常退出时恢复终端；Rust 宿主以 crate 嵌入，Node 宿主经 WebAssembly 核心加轻量输出层嵌入；经 npm 分发时采用按平台可选依赖。
8. **初始化**：SDK 提供显式异步初始化，模块导入时不加载或实例化 WebAssembly。

### 回退条件

切片出现以下任一情况，改选 TypeScript 全栈：

- 为兼容 SSR、打包工具与 Node ESM，WebAssembly 打包和初始化所需的处理超过核心逻辑本身的复杂度；
- 预期主要接入方需要自定义服务端存储，而不是使用默认实现；
- 前提 1–3 无法落实。

### 切片验证

切片以 Rust 方案实现，覆盖领取与核验、一次带资源消耗的动作、病程快进、一次存档恢复，以及 Web / CLI 呈现；触发回退时再以 TypeScript 实现同一切片。任何方案都不维护一份 JS 养成逻辑加一份原生逻辑，也不采用原生 HTTP 服务再调用 Node 规则服务的双服务结构。

硬门槛，任一不满足即触发回退评估：

- 同一组输入在原生、浏览器 WebAssembly 与 Node WebAssembly 下得到一致的状态与错误；整数范围、规范化编码和规则版本明确。
- 初始化完成后，浏览器内可同步调用规则核心。
- 前端安装发布包不要求消费者安装 Rust 编译器。
- 未使用的服务端驱动、框架绑定和凭据不进入浏览器入口；SSR 导入不提前产生 WebAssembly 实例或可变全局宠物状态。

另需记录完整发布产物（而不是空程序或单个 `.wasm` 文件）的压缩后传输量、冷启动、常驻内存、一次规则调用开销、编译 / 发布步骤、外部安装体验和存储扩展难度。具体性能门槛与支持版本在评审时依据场景固化，不编造本轮没有测量的数字。

## Skill 契约

Skill 与引用资料随产品发布，外部 agent 不需要 Violet 仓库或本会话。入口先识别包版本、世界、本地 / 账号模式及当前能力，再按任务分支读取规范。

| 分支 | 需要的规范 | 完成判据 |
|---|---|---|
| 生成、领取与验证 | 正式领取与预览的区别、出生凭据、随机与版本约束、不可变字段。 | 调用真实入口并取得可重建结果；不能指定正式稀有度或用一句对白冒充生成。 |
| 形象与动态素材 | 结构、锚点、兼容关系、各画风身份线索、阶段与动作覆盖、许可。 | 通过结构校验和 Web / CLI 多动作预览；静态单图不算完成。 |
| 养成与生命 | 身体状态、情绪、性格、成本、进化、休眠与死亡。 | 通过合法调用形成可观察状态转换，不直接编辑库存或生命字段。 |
| 页面互动 | 已登记目标、当前许可、作用域、取消与恢复。 | 效果可恢复且不修改真实内容，目标消失后不继续操作。 |
| 能力发现与调用 | 当前能力目录及同源 schema、错误、授权与幂等。 | 只调用实际存在且获准的能力，缺项明确报告，不创建假工具。 |
| 接入与验收 | 发布包、平台入口、默认 / 自定义适配器、独立服务与验收方式。 | 在无 Violet 环境完成真实消费；不依赖会话暗示或源码 alias。 |

能力目录是单一事实源，CLI 帮助、机器可读发现与 Skill 引用从同源契约产生。新增真实能力时同步目录与对应说明，未实现功能不注册占位命令。

Skill 不是安全边界。程序继续裁决身份、所有权、资源、进化和生命；模型不能直接设定经验、正式稀有度、死亡结果或删除内容。AI 共读只接收用户允许的上下文，关闭模型不影响基础养成。

素材制作与正式个体生成也要区分：AI 可以按规范制作待校验资源，但不在每次出生时任意生成一张无法复现的新图并称其为符合基因的宠物。

### 验证边界与既有经验

主要行为回归落在**公开动作调用到已提交状态读取**这一边界，覆盖权限、状态转换、库存与幂等，不分别为每个转发函数制造 mock 回显测试。存储适配器复用契约验收；失败回滚与并发必须落到真实持久化实现，不靠内存假实现代替。

图形与终端有各自真实表面：浏览器观察动作、焦点与恢复，真实 TTY 检查交互和退出。快照只能辅助固定出生向量或输入输出，不能用类名、函数转发、目录数量或一张静态图代替行为证明。

既有独立包 Inkline 的 tarball 消费流程可作为先例：在工作区外安装，核对公开声明、运行、资源与包体。但宠物还需增加真实动态、跨端状态、独立服务、持久化契约与 Skill 盲消费，不能将已有包的验收结果视作宠物已通过。

## 不在范围内

- 算力挖矿、区块链资产、NFT、交易市场或以付费抽取换数值优势。
- 保证全球视觉绝不重复，或用单份出生凭据声称证明所有参与者绝对公平。
- 统一运营的多租户 SaaS、默认跨站漫游或跨世界复制正式个体。
- 强制 AI 参与出生、基础养成或普通主题映射。
- 未经宿主支持强行嵌入任意终端程序，或取得整站 DOM / 内容删除权限。
- 在 Violet 现有 API 中建设宠物模块，或为本功能重建全站事件框架。
- 使用 Claude 未授权素材、泄露实现，或复用已废弃的吉祥物界面设计。

探险、装扮、好友、繁育、家园与可选 AI 不属于上述排除项；它们仍在完整目标内，只是详细规格与交付顺序待评审。

- Biome 分发先例：仓库依赖的 `@biomejs/biome` 通过 `optionalDependencies` 按平台引入 `@biomejs/cli-*` 原生二进制（见 `web/node_modules/@biomejs/biome/package.json`）。

已有运行证据限于研究中的 RFC 5869 向量核对、10 万种子分桶试算与随机通道隔离检查，以及下述 Rust 切片（`pet/`，2026-10-13，rustc 1.94、wasm-bindgen 0.2.129、Node 本机版本）：

- **三端一致**：同一 12 步场景（出生、喂食、重放、玩耍、未生病治疗、预警、生病、治疗、`9×10^18` 逻辑时间的休眠回归、缺药、时间倒退）在原生 CLI、Node WebAssembly（`--target nodejs`）与 web target（Node 中 `initSync`）下转录 SHA-256 相同。随后补验：headless Chrome 加载 Vite 打包产物，算出的出生 id 与原生一致。
- **行为**：重放返回同一结果；失败动作不扣资源；休眠回归停在生病而非死亡；u64 以字符串编码并通过超大值；单元测试覆盖出生可复现、改任一输入则身份变化、2 万种子的五档分布落在容差内。
- **约束**：核心 crate 为 `no_std` + `alloc` 并启用 `clippy::float_arithmetic = deny`，通过。依赖（serde_json）自身未受该 lint 约束，浮点确定性仍须在评审中单独核对。
- **测量（仅 Node，单机单次，不是性能门槛）**：优化后 `.wasm` 110 147 字节、gzip 46 489 字节，胶水 JS 6 691 字节；同步实例化 2.9 ms；`act` 约 9.9 µs/次，`birth` 约 42.5 µs/次（含 JSON 编解码）。
- **外部消费**：`npm pack` 得到的 tarball 在仓库外、PATH 不含 cargo 的环境安装成功；`initPet()` 前调用 `execute` 报错，导入本身不实例化；Node 与 Vite 构建（`.wasm` 110 KB / gzip 47 KB，入口 JS 3.7 KB）均可用。仅验证 Vite；未验证 webpack、Next SSR 与 Node ESM 之外的打包器。
- **存储契约**：`load` 加带期望版本的单次原子 `commit`，SQLite 实现（`pet/crates/pet-store`）在真实文件库上通过 5 项契约测试：版本冲突与静默覆盖可区分；重放返回原结果且不重复扣费，同一请求标识换参数被拒绝；结果写入失败时状态整体回滚且请求标识未被消耗；作用域隔离；8 线程并发喂食恰好只花掉库存的 5 份。Postgres 实现与自定义适配器的编写难度**未验证**。
- **出生承诺—揭示原型（R-02）**：服务端先签发承诺，持久固定客户端随机后签发接受收据，再揭示并装配证书；验证器（Ed25519 + SHA-256，位于核心）核对来源签名、承诺与揭示一致、客户端随机在先被接受、结果可重算。测试覆盖诚实证书通过，以及改服务端随机、客户端随机、签名、稀有度、世界、规则版本、签发者密钥分别被归类；服务端在看到客户端随机后换种子会因承诺不匹配被识别。证书不含账号标识。验证结果在原生、Node 与 web target 下转录哈希一致。代价：`.wasm` 增至约 196 KB（gzip 70.8 KB）。已知边界，不可用该原型宣称“公平”：不能证明服务方没有选择性拒绝请求或存在多账号偏差；服务端可在承诺前预先挑选种子，只能靠客户端随机使结果不可预知；签名密钥轮换、撤销与历史规则版本验证未设计；未经过独立安全评审。
- **终端帧合成与 TTY（本机 macOS，pty 驱动，`pet/scenario/tty_test.py` 16 项）**：`pet-term`（`no_std`、整数）将投影合成字符网格，原生 CLI 与 WebAssembly 共用同一份；5 种尺寸/姿态（含 3×2 与 200×60）的帧在原生、Node、web target 下转录哈希一致。`pet-cli live` 在真实 pty 中：动画持续输出、宠物位置随帧变化；`q`、Ctrl+C、外部 SIGTERM 均以 0 退出并恢复备用屏、光标与 termios；SIGWINCH 缩放后继续运行；`NO_COLOR` 无前景色码、非 UTF-8 区域输出纯 ASCII、16 色降级用低位调色板、2×5 极小终端不崩溃；管道输出一行 JSON 且无控制码。**未验证**：嵌入宿主模式（Rust 宿主 crate 与 Node 经 WebAssembly 嵌入）、Windows 与其他终端模拟器、SIGKILL 等不可捕获终止后的恢复（原理上不可能，需文档说明）、`TERM`/COLORTERM 之外的真彩与宽字符；画风仅是占位精灵，R-05 的美术与辨识度评审未做。
- **未验证**：Postgres/SQLite 存储与并发、独立服务、嵌入宿主、`wasm32` 之外的 `no_std` 目标（本机缺目标且安装未完成）、`ts-rs`/schema 同源生成、签名密钥轮换与撤销、独立安全评审。SSR 仅验证了 Node 直接导入，未验证真实 SSR 框架；R-01 在其余项补齐前不定稿。

本稿没有产品性能、视觉、终端、存储或服务验收通过记录；切片代码只是 R-01 的评审证据，不是产品实现。
