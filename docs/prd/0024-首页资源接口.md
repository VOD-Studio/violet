# PRD: 首页资源接口

## Problem Statement

当前首页没有自己的公开读模型。路由先读完整站点设置，再并发请求文章、笔记、图集、系列、推文、公告和归档数据，最后在前端把多个领域 DTO 裁剪、映射、合并、排序成首页条目。

这条链路存在四类问题：

- 首次加载最多产生九次 HTTP 请求：设置一次，五类内容一次，公告一次，归档年份一次，再按最近两个年份请求归档明细。
- 最近内容只取各领域的一小页再合并，不能保证得到全站真正最新的五项内容。
- 发布足迹实际由“最近两个归档年份的全部文章”和首页已取到的少量其他内容拼成，不是完整的最近十二个月公开作品。
- 首页读取完整资源 DTO。笔记携带正文 HTML，图集携带完整图片列表，推文携带互动、引用、作者和表情信息；首页只使用标题、地址、时间或两行短文。

页面底部的“留下印记”使用本地常量和组件状态，刷新后恢复，不能表达真实互动。“订阅通信”只有 RSS 链接，缺少可扩展但诚实的通信渠道契约。序章从完整设置对象推导站点身份，并通过弱类型读取尚未进入公开设置契约的首页视觉字段。

## Solution

保留现有资源接口，新增三个公开资源：

1. **站点身份（Site Identity）**：返回公开站点身份、首页视觉和当前可用通信渠道的最终语义值。
2. **发布物流（Publication Stream）**：把文章、笔记和图集投影为统一轻量作品条目，按真实发布时间提供稳定 cursor 浏览。
3. **站点印记（Site Impression）**：允许匿名设备留下至多一次轻量互动，并返回全站计数和当前设备状态。

这些是新增资源，直接进入现有 `/api/v1`。本功能不创建 `/api/v2`，因为没有修改既有接口的破坏性契约。“首页 v2”描述页面迭代，不等于 HTTP API 全局版本升级。

发布物流使用普通投影表 `publication_entries`，不是 PostgreSQL `MATERIALIZED VIEW`。文章、笔记或图集的发布、更新发布、撤回和删除与投影行在同一个 PostgreSQL 事务中提交。首页读取一张窄表，不在请求时跨领域拼装，也不承担异步投影延迟。

## User Stories

1. 作为访客，我要在一次请求中读取首页需要的站点身份和公开链接，不依赖管理设置结构。
2. 作为访客，我要看到全站按真实发布时间排序的最新作品，而不是各类内容局部取样后的近似结果。
3. 作为访客，我要看到最近十二个月完整的文章、笔记和图集发布足迹。
4. 作为访客，我要在内容较多时稳定续取足迹，不因新发布内容产生重复或漏项。
5. 作为访客，我要匿名留下至多一次印记，并在刷新后看到已留下状态。
6. 作为站长，我要让印记数表示“留下印记的匿名设备数”，而不是浏览量或可信独立访客数。
7. 作为站长，我要新增邮件通信能力时扩展通信渠道列表，不改首页身份资源的顶层结构。
8. 作为作者，我要在作品发布成功后立即从统一发布物流中读到该作品。
9. 作为作者，我要在撤回或删除作品后立即从统一发布物流中看不到该作品。

## Domain Decisions

### 发布物

发布物是已公开的叶子作品。第一版包含：

- `article`：已发布文章。
- `note`：已发布笔记。
- `gallery`：存在公开版本的图集。

系列是作品容器，不是独立发布物。系列新章节通过文章进入发布物流；系列本身不进入最近作品或发布足迹。推文属于人声社交流，不进入作品发布物流。

### 发布时间

发布物按公开版本的真实发布时间排序：

- 文章使用 `posts.published_at`。
- 笔记使用 `notes.published_at`。
- 图集使用 `galleries.published_at`。

精选状态不改变发布物流顺序。首页需要主内容时，可从返回条目中的 `featured` 选择精选文章；发布物流仍严格按 `(published_at DESC, kind ASC, source_id DESC)` 排序。

### 站点印记

站点印记是访客主动留下的轻量互动。计数口径为“成功留下印记的匿名设备数”。它不是页面浏览量、独立访客数或反作弊统计。

浏览器持有随机设备 token；服务端只保存 token 的 HMAC-SHA256，不保存明文 token，不使用浏览器指纹。清除 Cookie 或更换设备可以再次留下印记，这是该轻量互动的明确限制。

### 通信渠道

通信渠道只返回当前可用能力。第一版只有 RSS。邮件订阅尚未实现，因此不返回禁用、计划中或占位的 `email` 项。未来邮件订阅完成后，可在同一列表中新增 `email` 项。

## Data Model

### publication_entries

| 字段 | 类型 | 约束与语义 |
|---|---|---|
| `kind` | `varchar(16)` | `article`、`note`、`gallery` |
| `source_id` | `uuid` | 来源聚合 ID |
| `route_key` | `text` | 文章/图集为 slug，笔记为 ID |
| `title` | `text` | 首页最终展示标题；无标题笔记写入发布时派生的展示标题 |
| `published_at` | `timestamptz` | 公开发布时间 |
| `featured` | `boolean` | 仅文章可为 true，其他类型为 false |
| `created_at` | `timestamptz` | 投影行创建时间 |
| `updated_at` | `timestamptz` | 投影最后同步时间 |

约束与索引：

```sql
PRIMARY KEY (kind, source_id)
CHECK (kind IN ('article', 'note', 'gallery'))
CREATE INDEX idx_publication_entries_stream
    ON publication_entries (published_at DESC, kind ASC, source_id DESC);
```

`publication_entries` 不复制正文、摘要、标签、作者、封面、图集图片或互动计数。它只承担首页目录和足迹所需的轻量读模型。

### site_impressions

| 字段 | 类型 | 约束与语义 |
|---|---|---|
| `token_hash` | `bytea` | `PRIMARY KEY`；设备 token 的 HMAC-SHA256 |
| `created_at` | `timestamptz` | 首次留下印记时间 |

不保存明文 token、IP、User-Agent 或浏览器指纹。IP 只在请求期间做限流键，并使用独立 HMAC key 派生；限流键存 Redis 且按窗口过期。

## Transaction Decisions

- 使用普通投影表同步维护，不使用 PostgreSQL materialized view。
- 使用同库事务实现强一致，不使用现有内存事件总线维护权威投影。现有总线允许订阅失败后继续提交，进程退出时会永久漏投影。
- 不引入 Transactional Outbox。Outbox 解决数据库与外部消息系统的双写，并使下游读模型最终一致；当前来源表与投影表位于同一 PostgreSQL，单事务更小、更可靠。
- 每个来源域通过自己的 UoW adapter 在发布事务内维护投影。领域实体不依赖 publication 模块；事务编排位于 application/infrastructure seam。
- 首次迁移执行一次幂等回填：从当前已发布文章、笔记和图集写入投影表。迁移完成后由写路径持续维护。
- 提供后台校验命令或内部维护函数，对比来源表与投影表的缺失、冗余和字段漂移；不在公开请求路径做自动修复。

来源状态转换：

| 来源动作 | 投影动作 |
|---|---|
| 首次发布 | `INSERT ... ON CONFLICT DO UPDATE` |
| 更新已发布标题、slug、精选或发布时间 | 同事务 `UPSERT` |
| 图集更新发布 | 同事务更新标题、route key、发布时间 |
| 撤回公开 | 同事务删除投影行 |
| 删除 | 同事务删除投影行 |
| 编辑未发布工作稿 | 不触碰投影 |

## HTTP Interfaces

所有 JSON 字段使用 `snake_case`，沿用统一响应信封。

### GET `/api/v1/site-identity`

返回首页序章和通信入口需要的最终公开语义值。

```json
{
  "data": {
    "site_name": "Violet",
    "site_url": "https://xunrua.top",
    "owner_name": "xunrua",
    "bio": "记录构建、拆解问题与生活思考。",
    "avatar_url": "/uploads/avatar.webp",
    "location": "杭州",
    "hero": {
      "banner_url": null,
      "quote": "We can only see a short distance ahead...",
      "quote_translation": "我们只能看清眼前的一小段路……",
      "quote_author": "Alan Turing"
    },
    "social_links": [
      { "kind": "github", "label": "GitHub", "href": "https://github.com/xunrua" },
      { "kind": "email", "label": "Email", "href": "mailto:hello@example.com" }
    ],
    "subscription_channels": [
      { "kind": "rss", "label": "RSS", "href": "/feed.xml" }
    ],
    "home": {
      "footprint_enabled": true,
      "footprint_aggregation_days": 7
    }
  }
}
```

约束：

- `hero.banner_url` 没有配置时为 `null`，不返回空串。
- `social_links` 和 `subscription_channels` 只包含可用项，始终返回数组。
- 默认文案、默认引语、GitHub URL 和 RSS URL 在服务端归一；前端不读取 settings key 推导业务语义。
- 不返回登录开关、评论开关、代码运行器开关、关于页布局或任何敏感设置。

缓存：

```http
Cache-Control: public, max-age=60, stale-while-revalidate=300
ETag: W/"<identity-version>"
```

设置更新后无需主动清 CDN；短 TTL 与条件请求提供上界明确的陈旧窗口。

### GET `/api/v1/publications`

查询参数：

| 参数 | 语义 |
|---|---|
| `cursor` | 可选；服务端签名的 opaque cursor |
| `limit` | 默认 20，上限 100 |
| `from` | 可选；RFC3339，包含下界 |
| `to` | 可选；RFC3339，不包含上界 |
| `featured` | 可选；`true` 时只返回精选文章 |

响应：

```json
{
  "data": [
    {
      "id": "article:0199...",
      "kind": "article",
      "route_key": "designing-deep-modules",
      "title": "Designing Deep Modules",
      "published_at": "2026-09-07T08:00:00Z",
      "featured": true
    }
  ],
  "meta": {
    "pagination": {
      "limit": 20,
      "has_more": true,
      "next_cursor": "eyJ2IjoxLC4uLn0"
    }
  }
}
```

cursor 载荷包含版本、`published_at`、`kind` 和 `source_id`，经服务端 HMAC 签名。调用方把它视为 opaque string。非法或被篡改 cursor 返回 400。

首页查询方式：

- 近稿：`GET /api/v1/publications?limit=5`。
- 主内容：优先在近稿中选择 `featured=true` 的文章；若产品要求精选跨越近稿窗口，再独立请求 `?featured=true&limit=1`。
- 足迹：以客户端计算出的最近十二个自然月边界传 `from`、`to`，每页最多 100 条；`has_more=true` 时按 cursor 续取，直到窗口完整。服务端不返回月份、季节、节点坐标或 marker size，避免把 UI 布局写入资源接口。

缓存：

```http
Cache-Control: public, max-age=30, stale-while-revalidate=120
ETag: W/"<query-hash>:<projection-version>"
```

第一页允许公共缓存。带 cursor 的后续页同样可缓存，因为 cursor 固定了时间边界；缓存键必须包含完整查询参数。

### GET `/api/v1/site-impressions`

读取计数和当前设备是否已留下印记。

```json
{
  "data": {
    "count": 4085,
    "impressed": true
  }
}
```

```http
Cache-Control: private, no-cache
Vary: Cookie
```

### POST `/api/v1/site-impressions`

首次请求生成 128-bit CSPRNG token，Cookie 属性：

```http
Set-Cookie: violet_impression=<base64url-token>; Path=/; Max-Age=31536000; HttpOnly; Secure; SameSite=Lax
```

服务端计算 `HMAC-SHA256(server_secret, token)` 并执行：

```sql
INSERT INTO site_impressions (token_hash)
VALUES ($1)
ON CONFLICT DO NOTHING;
```

插入后在同一请求中读取计数，首次与重复请求均返回 200：

```json
{
  "data": {
    "count": 4085,
    "impressed": true
  }
}
```

限流：

- 使用现有 Redis rate-limit 中间件的独立 `site-impressions` 维度。
- IP HMAC 每分钟最多 10 次；超过返回 429。
- Cookie 唯一约束负责并发幂等，限流不承担身份判断。
- `POST` 继续受现有 CSRF 中间件保护；匿名浏览器先使用现有 CSRF token 机制。

## Error and Degradation Decisions

三个资源彼此独立，不存在一个聚合接口中的部分成功问题：

- `site-identity` 失败只影响序章配置，前端可使用静态最小默认值。
- `publications` 失败时显示对应区块错误态，不把故障伪装成空列表。
- `site-impressions` 失败时按钮保持可重试，不影响正文和足迹。

服务端不返回 `200 + null + issues` 的聚合响应，也不实现整页旧快照回退。公共 GET 依赖标准 HTTP 缓存、ETag 和 `stale-while-revalidate`；写接口不自动重试。

## Performance Decisions

### 请求数

首页主数据从最多九次请求收敛为：

1. `site-identity`。
2. `publications?limit=5`。
3. `publications?from=...&to=...&limit=100`，仅足迹启用时请求；高产窗口按 cursor 续取。
4. `tweets?limit=3`，偶得仍属于独立人声社交流。
5. `site-impressions`，独立、私有、非首屏关键。

公告由全局 `AnnouncementBar` 继续读取 `/api/v1/announcements`。删除首页 loader 中请求后丢弃的公告预取。

### 查询

- 发布物流只扫描 `publication_entries` 的覆盖范围，不再执行文章总数 `COUNT(*)`、作者填充、协同者填充、标签 preload、笔记正文读取、图集 revision/items/assets 重建或跨域前端归并。
- cursor 使用 `(published_at, kind, source_id)`，避免 offset 在新作品发布时重复或漏项。
- `GET /site-impressions` 的 `COUNT(*)` 在当前规模可直接查询；若行数和 QPS 实测成为瓶颈，再增加事务内计数器。第一版不同时维护事件表和计数器两份真相。
- 首页文章总数指标不属于当前印记或发布物流契约。若保留“篇沉心之作”，使用 `publications` 的独立按 kind 统计资源或调整为不依赖总数的文案，禁止为五条近稿执行分页总数统计。

### 客户端加载

- `site-identity` 与最近五项 publications 是首屏关键请求，可并行。
- 足迹 publications、tweets 和 site-impressions 不阻塞序章；按区块 loader 或 Suspense 延迟加载。
- 首页不把多个领域的完整 DTO 写入 TanStack Query cache，再额外生成第二份映射数组。

## Migration and Compatibility

1. 从 `release/2.0` 的最高迁移编号之后创建投影表和印记表；实施时重新检查编号。
2. 迁移内回填已发布文章、笔记和图集，验证总数与来源查询一致后再接公开路由。
3. 先在后端上线三个新增资源及 OpenAPI 描述；现有 `/settings`、`/posts`、`/notes`、`/galleries`、`/series`、`/tweets` 和归档接口保持不变。
4. 前端首页改用 `site-identity` 与 `publications`，删除 `HomeSnapshot` 对完整领域 DTO 的依赖和 `buildHomePublications` 映射。
5. 足迹完成 cursor 续取后，删除首页对 `/posts/archive` 与 `/posts/archive/{year}` 的依赖；归档页继续使用原接口。
6. 偶得继续使用 tweets 接口；全局公告继续使用 announcements 接口。
7. “留下印记”替换本地 `4084` 常量和组件内计数；RSS 从 `subscription_channels` 渲染。
8. 新接口稳定并完成浏览器验收后，清理首页专用旧 query keys 和未使用导入，不删除其他页面仍在使用的旧资源接口。

## Testing Decisions

- publication application interface 覆盖严格时间排序、同时间 kind/ID tiebreaker、from 包含、to 不包含、limit 钳制、cursor 篡改、cursor 翻页无重复漏项和精选过滤。
- PostgreSQL 集成测试覆盖文章、笔记、图集首次发布、更新发布、撤回和删除与投影的同事务提交及失败回滚。
- 回填测试覆盖三类来源、无标题笔记展示标题、未发布内容排除和重复执行幂等。
- site identity 测试覆盖默认值、空 URL 归一、只返回可用链接、只返回已实现通信渠道及敏感设置不泄露。
- site impression 测试覆盖首次插入、同 token 重复、并发重复、Cookie 属性、无明文 token/IP 持久化、计数语义和 429。
- handler 测试覆盖统一信封、snake_case、缓存头、ETag/If-None-Match 的 304、非法日期和非法 cursor 的 400。
- 前端浏览器验收覆盖：首页首屏无需等待足迹；最近作品顺序正确；十二个月窗口完整；印记刷新后保持；RSS 跳转有效；任一区块失败不拖垮其他区块。
- 性能验收记录冷缓存与热缓存请求数、响应字节和数据库查询计划。`publications` 必须命中 `idx_publication_entries_stream`，首页不得再请求归档年份与年度全文列表。

## Out of Scope

- `/api/v2` 全局版本迁移。
- 把文章、笔记和图集的写模型合并成通用内容表。
- 系列、推文或公告进入发布物流。
- 邮件订阅、确认、退订和邮件投递。
- 浏览器指纹、可信 UV、风控评分或账号与匿名设备合并。
- 服务端计算足迹月份、季节、节点坐标、marker size 或其他 UI 布局。
- Transactional Outbox、CDC、消息代理或异步投影 worker。
- PostgreSQL `MATERIALIZED VIEW` 和定时全量刷新。
- 整页聚合接口、整页 Redis 快照或部分成功信封。
