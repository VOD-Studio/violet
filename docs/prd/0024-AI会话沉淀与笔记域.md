# PRD: AI 会话沉淀与笔记域

## Problem Statement

博主在 ZCode 编码会话中持续产出有价值的知识——踩过的坑、根因分析、修法、架构经验——但这些产出随会话结束蒸发。现有两个发布容器都不匹配：文章是重打磨作品（slug / 封面 / SEO / 版本 / 精选），推文是 ≤500 字不可编辑的社交广播。轻量知识沉淀没有容器，「AI 对话的价值自动流入博客」没有链路。

同时，开发会话里散布着服务器细节、密钥片段与内网地址，手工整理成文时全靠人自觉剔除，没有强制规则；AI 自动发布若无人审环节，公开内容的风险不可控。

## Solution

两段式建设：

**笔记（Note）**：与文章、推文平级的独立内容类型——markdown 正文 + tags、标题可选、草稿/已发布两态、可编辑可删除。公开侧独立 `/notes` 页（时间倒序 + tag 筛选），不进主博客流，也不进推文时间线。

**会话捕获链路**：violet 仓库内的捕获 skill（触发 + 判断 + 成文层）+ violet-notes MCP server（运输层，PAT 鉴权）。会话收尾时 agent 自主触发：重量分诊（功能级 → 文章草稿 / 经验级 → 笔记 / 琐碎 → 沉默）→ 按知识点拆条 → 按成文规范写成 markdown（敏感信息硬规则）→ 一键裁定（直接发布 / 存草稿 / 不发，选项式）→ 经 MCP 入库。

安全模型两条不变量：**公开可见性由一键裁定的人工点击把关，AI 永不静默公开发布**；**文章默认只进草稿，只有用户明确选择“直接发布”时才调用 `publish_post`**。

领域术语见 `CONTEXT.md`「笔记（Notes）」节（意图测试、重量分诊、一键裁定、拆条、自动化内容不进人类社交流）。

### 关键场景

| 场景 | 行为 |
|---|---|
| 会话收尾，产出 1 条经验 | skill 触发 → 成文 → 敏感扫描 → 一键裁定问一次 → 按选择直发或入草稿 |
| 会话产出 3 个独立知识点 | 拆 3 条笔记，一次裁定批量处理（全部直发 / 全部草稿 / 逐条 / 全部不发） |
| 会话产出完整功能 | 文章毛坯先 `create_post` 入草稿；用户选择“直接发布”且敏感扫描通过时，再调用 `publish_post` |
| 会话琐碎或重复 | 分诊判定不沉淀，保持沉默，不打扰用户 |
| 成文含敏感信息 | 扫描脚本命中即禁止直发路径；可脱敏则脱敏后重扫，不可脱敏则降级草稿并标注 |
| 用户挂起或会话中断 | 未应答的裁定一律按草稿入库（安全默认） |
| 误发笔记 | 后台编辑修正或删除（笔记可编辑、可删除） |
| 读者访问 /notes | 时间倒序笔记流 + tag 筛选，仅见 published |

## User Stories

1. 作为博主，我要会话收尾时 AI 自动判断本场是否值得沉淀，不用手工记录也能留住经验。
2. 作为博主，我要每个独立知识点单独成条笔记，tag 打得准、未来按主题一查一串。
3. 作为博主，我要入库前用一次点击裁定去向（直发 / 草稿 / 不发），公开可见性始终由我把关。
4. 作为博主，我要无应答时内容一律入草稿，AI 永不静默公开发布。
5. 作为博主，我要功能级产出变成文章毛坯，默认入草稿，只有我明确选择时才发布。
6. 作为博主，我要成文自动执行敏感信息硬规则，公开内容不泄露服务器细节、密钥与内网地址。
7. 作为博主，我要在后台发布、编辑、删除笔记（含草稿），修正错漏、回收误发。
8. 作为博主，我要给捕获用 PAT 授予 `posts:publish`，但发布动作仍必须经过一键裁定，AI 不得静默调用。
9. 作为博主，我要笔记不进主博客流与推文时间线，既有信息流的气质不被自动化内容污染。
10. 作为博主，我要手工也能在后台创建笔记，不只依赖 AI 捕获。
11. 作为读者，我要在 /notes 按时间倒序浏览博主的技术笔记。
12. 作为读者，我要按 tag 筛选笔记，按主题集中阅读。
13. 作为读者，我要笔记正文按与文章一致的 markdown 管线渲染（代码块高亮、公式可渲染）。
14. 作为读者，我要打开单条笔记的稳定地址并分享给他人。
15. 作为 AI agent，我要通过 violet-notes MCP 的 create_note 把成文笔记送入博客，不需要人工复制粘贴。
16. 作为 AI agent，我要 create_note 支持指定状态（draft / published），以执行用户的一键裁定。
17. 作为 AI agent，我要沉淀前能查询已有笔记，对同主题做补充而非新建重复条目。
18. 作为 AI agent，我要没有 notes scope 的 PAT 调用被明确拒绝，越权行为在运输层被拦。

## Implementation Decisions

### 领域边界

- Note 是独立 bounded context，与 Post、Tweet 平级。不复用 Post 模型（不背 slug / 封面 / SEO / 版本 / 精选），也不复用 Tweet（不可编辑、社交语义）。
- 笔记无社交交互：无评论、无点赞、无通知、不进用户主页聚合。
- 笔记是作者工具：第一版只对具备内容管理权限的作者开放，普通注册用户不能创建。
- 公开地址按 ID（标题可选，slug 生成不可靠）：`/notes` 与 `/notes/{id}`。

### 数据模型

- 全新 `notes` 表：id、author_id、title（可空）、content_md、content_html、status（draft / published）、created_at、updated_at、published_at。
- 状态机单向：draft → published，发布后可继续编辑（编辑不改状态、不改 published_at）。无「撤回为草稿」；误发走编辑或删除。
- tags 复用现有 Tag 实体（name / slug 语义跨内容类型一致），新增 `note_tags` 关联表。
- 校验：content_md 去空白后非空；title 可空但不超过 120 个 Unicode 字符；tags 0–8 个。正文长度上限对齐文章正文现有惯例。
- content_html 在保存时由 markdown 管线生成；阅读端复用文章的浏览时渲染管线（公式 / 代码块约定一致）。
- fresh migration 从实施时 `release/2.0` 的下一个可用编号开始（当前基线 108，预计 109 起；实施前重新检查）。
- 公开列表按 `(published_at DESC, id DESC)` cursor 分页（对齐推文 / 图集惯例）；后台管理列表 page/limit。

### HTTP API

公开接口（匿名可读）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/notes` | 已发布笔记流，cursor/limit，tag 筛选参数 |
| GET | `/api/v1/notes/{id}` | 已发布笔记详情；草稿 ID 返回 404 |

内容管理接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/admin/notes` | 创建草稿，返回 201 |
| GET | `/api/v1/admin/notes` | 管理列表，状态筛选 |
| GET | `/api/v1/admin/notes/{id}` | 读取（含草稿） |
| PUT | `/api/v1/admin/notes/{id}` | 全量保存 |
| POST | `/api/v1/admin/notes/{id}/publish` | 发布 |
| DELETE | `/api/v1/admin/notes/{id}` | 物理删除，返回 204 |

- JSON 字段 snake_case；401 / 403 / 404 / 400 语义沿用项目惯例。
- 新端点同步进 OpenAPI 导出。

### 权限

- `note:manage`：后台创建、编辑、发布、删除自己的笔记。单一权限，不拆细粒度 CRUD；seed 给 admin，superadmin 走通配。
- PAT 侧按 scope 门禁（工具内 `requireScope`，先例 violet-posts）。

### MCP（运输层）

- 新 server `violet-notes`，挂 `/api/v1/mcp/notes`，PAT 鉴权，按「each server owns one domain」独立于 violet-posts。限流 60/min，独立维度 `mcp-notes`。
- PAT scope 扩展：`notes:read` / `notes:write` / `notes:publish`；管理端 scope 枚举与前端 admin-mcp 页同步展示。
- 工具：

| 工具 | 说明 | scope |
|---|---|---|
| `create_note` | 建笔记；`status` 参数 draft / published | draft=notes:write；published=notes:write+notes:publish |
| `update_note` | 改自己的笔记（含草稿） | notes:write |
| `delete_note` | 删自己的笔记 | notes:write |
| `list_notes` | 列自己的笔记（含草稿），供查重 | notes:read |
| `get_note` | 读自己的单条（含草稿） | notes:read |

- `create_note` 的 tags 不存在时自动创建（复用文章侧 create_tag 语义）。

### 前端接入

- `/notes` 列表页：时间倒序条目流 + tag 筛选；数据 / 骨架 / 空三态；视觉沿用站点编辑排版语言，具体形态实现期做完整设计 pass。
- `/notes/{id}` 详情：正文复用文章阅读端渲染组件，轻头部（标题可选 + 日期 + tags）+ BackLink。
- 导航入口位置实现期设计 pass 决定，不预设进主导航。
- 后台 `/admin/notes`：列表（草稿 / 已发布）+ 编辑（复用现有 markdown 编辑器底座）+ 发布 / 删除。

### 会话捕获 skill（触发 + 判断 + 成文层）

- 位置：violet 仓库 `.agents/skills/session-notes/`，随代码版本化并进 AGENTS.md 技能清单；复制到其他项目即可扩展来源范围（本期不做）。
- skill 契约（生成规范另见 skill 本体）：触发时机（任务收尾、会话有明确产出；支持 `/session-notes` 补录；琐碎会话沉默）、重量分诊标准、拆条规则、成文规范（现象 → 根因 → 修法、标题可选、tags、代码块、诚实低打磨）、敏感信息硬规则（扫描脚本机械门禁 + 模型语义自查双层，脚本命中优先）、一键裁定交互（选项式，唯一人工环节）、安全默认（无应答入草稿）。
- 调用 violet-notes（笔记）与 violet-posts（文章毛坯；先 `create_post`，仅在用户明确选择时调用 `publish_post`）。
- 部署期操作（不进仓库）：violet MCP servers 注册进 ZCode 全局 MCP 配置；签发捕获用 PAT（授 `notes:read/write/publish` + `posts:read/write/publish`）；使用步骤随 issue 文档化。

## Testing Decisions

- 只测外部行为（MCP 工具进出、HTTP 进出、用例结果），不测实现细节。接缝已与用户确认：

1. **MCP 工具接缝（主接缝）**：`create_note` 两种去向（draft / published）、scope 门禁（无 notes scope 拒绝、仅 write 无 publish 时请求 published 拒绝）、tags 自动创建。先例：`application/mcp/series_tools_test.go`。
2. **HTTP 接缝**：公开流仅 published、tag 筛选、草稿 ID 公开侧 404；后台 CRUD / 发布 / 权限。先例：`interfaces/http/handler/tweet/tweet_test.go`。
3. **应用 / 领域层**：状态机单向、正文与 title 与 tags 校验、发布时间语义。先例：`application/series/service_test.go` + `domain/series/entity_test.go`。
4. **前端组件接缝**：/notes 列表与 tag 筛选、后台管理页。先例：`features/tweets/ui/__tests__/`。

- skill 验收不自动化：以真实会话手工清单执行（分诊准确性、敏感规则执行、裁定交互、安全默认），写入对应 issue 的验收标准。

## Out of Scope

- 非 violet 仓库会话与其他 AI 工具（网页对话）的捕获。
- 笔记评论、点赞、通知、用户主页聚合等社交化。
- 笔记 RSS 与全站搜索接入。
- 已发布笔记撤回为草稿（状态机单向，误发编辑或删除）。
- 历史会话的批量回填沉淀。
- 普通注册用户创建笔记。
- 笔记操作审计日志（低风险轻量内容，第一版不写审计）。
