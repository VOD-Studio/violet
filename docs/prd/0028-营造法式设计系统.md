# PRD: 营造法式设计系统

## Problem Statement

站点的视觉决策没有统一裁定处：语义 token 分层藏在样式入口文件里，动效约束写在 AGENTS.md，类名规范在 tailwind skill，色板元数据在 DESIGN.md——各管一角，无人统管。无论是人还是 AI agent，写新界面时都答不上「这个需求该用哪个 token」；已经出现消费不存在 token 的死类（`bg-surface` 引用了从未定义的变量）。刚落地的冷香紫罗兰色彩体系随即废弃为非基准，进一步说明：缺一个**不随色板更迭而失效、以 token 名为锚**的统一决策层。

## Solution

新增正式站内界面**「营造法式」**（`/design-system`，「更多」菜单入口）：站点的活典籍，内容即界面。核心是**快速决策表**——按需求场景裁定「用什么 token」（主按钮底色、次要文字、发丝线、毛玻璃面……），查无此项时回**设计原则**自行推导；辅以 token 词典（运行时探针读真实色值）、布局规格、组件活样例、动效章程等章节。

页面**只锁 token 名、不锁色值**：品牌色板可插拔，冷香紫罗兰不作为基准；未来换色板，营造法式自动跟随展示新值，永不过时。章节架构与视觉语言为原创设计，不沿用站内既有三语系（书卷装帧 / 编辑排版 / 展板工具），典籍气质从名称本身生发。

设计总纲四字箴言：**「有效、清晰、准确、美」**。

## User Stories

1. As 站长，I want 一页看全站点所有语义 token 的名字、分组与当前真实值，so that 改界面时不必翻样式源码。
2. As 站长，I want 快速决策表按需求场景索引 token（而按 token 名倒排），so that 「我要做一个次要文字」这类问题查一行就定。
3. As 站长，I want 决策表查不到时有设计原则可回，so that 表覆盖不到的新场景仍有一致的判据。
4. As AI agent，I want 决策表与 token 词典以代码形态存在、与真实样式同源，so that 动笔前读源码即可获得正确 token 名。
5. As AI agent，I want 决策表引用的每个 token 都经防漂移测试保证真实存在，so that 不会再产出 `bg-surface` 式的幽灵 token 引用。
6. As 站长，I want 未来更换品牌色板时页面自动展示新色值，so that 设计系统文档不随换色过时。
7. As 站长，I want 明暗双域下都能预览 token 值与组件样例，so that 双域观感一处验收。
8. As 站长，I want 三种视觉方言（公开/工具/沉浸）的职责与动作色映射讲在一处，so that 新界面知道挂哪个方言、主色如何被映射。
9. As 站长，I want 组件样例直接渲染真实共享控件而非截图或仿品，so that 样例即真相，不漂移。
10. As 站长，I want 既有动效约束（缩放克制、方向位移克制）连同事由收录进动效章程，so that 约束有设计语境的家，而不只是命令。
11. As 访客，I want 营造法式作为公开页可从「更多」菜单直达，so that 能领略站点的设计章法与匠气。
12. As AI agent，I want 布局规格（4px 网格、容器、字号阶梯、圆角）与间距类名规范在同一页可查，so that 布局决策不必跨多处文档拼凑。
13. As 站长，I want 选定一个主色后由色彩生成算法产出完整色板（品牌色、功能色、中性色、语义色），so that 换色方向时不必手工调配几十个值。
14. As 站长，I want 圆角与投影的红线（上限、禁用项、浮起感替代配方）写在营造法式里，so that 层级手法全站统一，不再各自发明。

## Implementation Decisions

### 定位与落位
- 正式站内公开页（非 lab、非后台），路由 `/design-system`，「更多」secondary 菜单新增入口，命令面板与移动端更多探索随导航配置自动收录。
- 命名遵循站点惯例：诗意中文标签 + 朴素英文路由（同「尺素」之于推文）。典出宋代李诫《营造法式》——其「材份制」模数分级即历史上的设计 token。

### 色板可插拔契约（本 PRD 的第一决策）
- 页面只锁 **token 名**（语义工具类名与 CSS 变量名），不写死任何色板色值；冷香紫罗兰色彩系统废弃为非基准，当前线上色板继续服役，真正的换色属后续独立任务（届时可由营造法式自身驱动）。
- token 的动态值（色值等）经**运行时探针**读取 CSS 变量真实值渲染（先例：mermaid 主题变量映射的 oklch→hex 探针法），不手写 TS 色板常量——lab 色彩实验室的双份维护已证明手写必漂移。

### 设计原则与色彩生成模型
- 设计总纲：「有效、清晰、准确、美」四字箴言，作为快速决策表查无此项时的最高回退原则。
- 色彩模型：**基础色板 = 主色 + 衍生色**——选定一个主色，色彩生成算法推导出完整色板，覆盖四类：**品牌色**（品牌强调层与色阶）、**功能色**（成功/警示/危险等信息色）、**中性色**（画布、表面、文字、描边的中性带）、**语义色**（组件实际消费的语义角色层，由前三类映射而来——主色/次要/强调/静默/边框/焦点环等）。语义层即现有语义 token 体系，算法产出向它对齐，而非另起炉灶。
- 生成算法是「色板可插拔」的机制化：换色 = 换种子主色重跑算法，而非手工改几十个值。营造法式页面含**色板生成器**章节：选主色 → 实时生成四类完整色板，色彩数学复用 lab 色彩实验室已验证的换算先例。

### 布局规格红线
- 间距：按 Tailwind 默认 4px 一档。
- 圆角：功能性圆角上限 `rounded-2xl`（16px），再大只是装饰、不作功能圆角；胶囊（`rounded-full`）是形态不是超限圆角，不受此限。存量超限不专项清理，改到即清。
- 投影：**硬投影禁用**（又重又俗）。浮起感两种配方：`ring-1 ring-border` 描边（没有投影），或 `0 4px 24px / 0.05` 低透明大半径软影；暗色域优先描边。

### 内容与数据形态
- 快速决策表是**纯数据清单**（需求 → token 名 → 一句裁定理由），供表格渲染与防漂移测试共同消费，不散落在 JSX 里。
- 基准章节：设计原则 / 快速决策表 / token 词典（语义色、行为状态色、品牌层、纸面、材质遗留、图表、霓虹）/ 布局规格（4px 网格、容器、字号、圆角）/ 组件活样例 / 动效章程。章节增删在实现期可裁量，六者为核心交付。
- 布局规格如实记录现状（间距无 token、用 Tailwind 默认 + 4px 网格），不在本期新增 token 组。

### 视觉语言
- 原创设计，不沿用书卷装帧、编辑排版、展板工具任一既有语系；气质从「营造法式」名称生发。
- 遵守全站红线：编辑排版而非终端 UI 拟物、非必要不用缩放与方向位移动效、WCAG 对比度底线、文案只用页面语言不夹开发用语。

### 文档同步
- AGENTS.md「前端动笔前读」清单提及营造法式；CONTEXT.md 新增「营造法式」术语词条；DESIGN.md 保持 impeccable 等外部 skill 的机器可读记录层不动，其色彩段的可插拔标注随实现顺带。
- 导航配置新增项随功能提交；页面文案遵循站点 tagline 风格（只说页面是什么）。

## Testing Decisions

- 好测试只测外部行为：**唯一新缝是防漂移对账测试**——决策表数据清单引用的每个 token（类名 / CSS 变量）必须真实存在于映射层，任一侧腐烂即红。这是「设计系统永不引用幽灵 token」的机器保证，也是 `bg-surface` 事故的疫苗。对账测试测数据与样式层的契约，不测页面渲染细节。
- 探针的取值与色彩空间换算沿用现有纯函数模式做单测（lab 色彩实验室的 color-math 先例）；色板生成算法同源复用该色彩数学，生成质量以 WCAG 对比度底线为准绳。
- 页面挂载冒烟测试沿用现有 vitest 组件测试模式。
- 视觉观感不自动化：走截图迭代人工验收（站点 UI 任务既有流程）。
- 色值本身不测：色板可插拔，任何当前值都合法。

## Out of Scope

- 换掉冷香紫罗兰色板、选定新色彩方向（后续独立任务）。
- lab 色彩实验室的去留、改名或并入营造法式。
- 后台主题管理 / 自定义色板编辑界面。
- 新增间距、字号、阴影、动效时长等 token 组（营造法式本期只记录现状）。
- DESIGN.md 重写。
- 修复存量 `bg-surface` 死类：已登记，实现期以独立 fix 提交在同分支顺带修复，不混入功能提交。
