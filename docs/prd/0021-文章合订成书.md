# PRD: 文章合订成书（series：系列书页）

## Problem Statement

博客有**渐进式连载内容**：同主题的文章随时间逐篇发出（如 Java 系列，今天一章、明天一章，还可能中途补一篇基础篇插到中间）。现状下这些文章散落在文章流里，只有 tag 这一无序聚合，读者无法按「书」的方式顺序阅读，作者也无法把已成体系的系列组织成书籍形态展示。

需要一个系列/书能力：**把同主题渐进式文章组织成有章节顺序的书页**。

## Solution

新增独立 bounded context **`series`**，与 post 平级，通过 `posts.series_id` 关联：

- **书是持续生长的组织容器**，不是一次性合并转换：建书 → 挂章（从已有文章批量挂接，或新文发布后随手挂入）→ 拖拽调序补章。没有「合订向导」这种状态切换，挂接归属随时可做可撤。
- **章节保留完整文章身份**：独立 URL、版本历史、评论、批注、MCP `get_post`、RSS 全部不变。书页是**聚合视图，不存正文副本**——文章改了书里的内容跟着变。
- **章节序号手动可调**（chapter_order）：渐进式写作中后补的章节要插到中间，发布时间序不可用。
- **书页** `/series/$slug`：封面 + 简介 + 章节目录（按 chapter_order），复用 Focus TOC 的「阅读罗盘」交互语言（书级目录是文内目录的同粒度扩展）。
- **文章页标注归属**：「属于《XX》· 第 N 章」+ 上一章/下一章导航。散着进来的读者获得书的上下文，从书进来的读者可逐章跳。

### 关键场景

| 场景 | 行为 |
|---|---|
| 已有 15 篇 Java 文章，想合订 | 建书 → 从文章列表多选批量挂接 → 拖拽调成期望顺序 → 发布书 |
| 渐进式：书已发布，明天写新章 | 写新文章（走现有发布流）→ 挂入书 → 拖到正确位置 |
| 中途补基础篇 | 挂入后拖拽插入第 3 章位置，后续章节序号自动顺延 |
| 章节被归档/回退草稿 | 从书页目录隐藏，**归属保留**（恢复发布即回到书中原位） |
| 解散书 | 删除书 = 解绑所有章节，文章全部原样保留 |

## User Stories

1. 作为作者，我要建一本书（标题/slug/简介/封面），先把书建着慢慢挂章节，未发布前不出现在公开书列表。
2. 作为作者，我要从已有文章列表多选批量挂接到书，一次完成「合订」。
3. 作为作者，我要拖拽调整章节顺序，中途补的章节能插到任意位置。
4. 作为作者，我要能把某章从书里摘出来（归属解除，文章不受影响）。
5. 作为读者，我要访问 `/series/java-guide` 按章节顺序阅读整本书，并能看到当前阅读进度（已读指示）。
6. 作为读者，我在阅读某章时能看到「属于《Java 指南》· 第 3 章」以及上一章/下一章入口。
7. 作为访客（未登录），书列表与书页匿名可浏览。

## Implementation Decisions

### 领域模型（domain/series）

```go
// Series 聚合根
type Series struct {
    shared.AggregateRoot
    authorID    shared.ID // 书的归属作者，创建时固定，不可变
    title       string
    slug        string    // 唯一，格式同 post slug
    description string
    coverImage  string    // 封面图 URL（可空）
    status      string    // draft / published
    sections    []SeriesSection
}

// SeriesSection 书内卷/部（可选层级）
type SeriesSection struct {
    id        shared.ID
    title     string
    sortOrder int
}
```

- **书是两层目录，不是扁平文章列表**：`SeriesSection` 表达卷/部；章节可挂某个 section，也可不分卷直接挂书根（前言/后记/短书）。第一版只支持「书 → 卷/部 → 章」两层，不做无限树。
- **章节不内嵌在 Series 聚合里**：章节归属由 `posts.series_id + posts.series_section_id + posts.chapter_order` 承载。章节仍是完整 Post 聚合，保留独立 URL、版本、评论与批注。
- 不变量：挂章校验 `post.author_id == series.author_id`；一章只属一书；`series_section_id` 非空时必须属于同一本书；section 与 chapter 顺序均手动维护。
- **章节可见性独立于书**：书页只列出 `status = published` 的章节；draft/archived 章节隐藏但归属保留。
- 权限模型对齐 post 域（书管理是文章管理的延伸）：`series:view` / `series:create` / `series:update` / `series:delete`。

### 数据库（migration 100 起，与 feat/chat 的 083-097 错开）

- **100**：`series(id uuid pk, author_id uuid ref users, title, slug unique, description, cover_image, status, created_at, updated_at)`。
- **101**：`series_sections(id uuid pk, series_id uuid ref series on delete cascade, title, sort_order, created_at)`；唯一索引 `(series_id, sort_order)`。
- **102**：`posts` 加 `series_id uuid null ref series`、`series_section_id uuid null ref series_sections`、`chapter_order int null`；索引 `(series_id, series_section_id, chapter_order)`。
- **103**：seed `series:view/create/update/delete` 权限码 + menu 节点 `series`。

### API（/api/v1，写操作走现有 SessionAuth + CSRF）

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/series` | 公开 | 书架（仅 published），page/limit |
| GET | `/series/{slug}` | 公开 | 书籍详情 + 两层目录（根章节 + sections[]） |
| POST | `/series` | `series:create` | 建书（draft 起步） |
| PATCH | `/series/{id}` | `series:update` + owner | 改标题/简介/封面/发布状态 |
| DELETE | `/series/{id}` | `series:delete` + owner | 解散书：解绑所有章节，不删文章 |
| POST | `/series/{id}/sections` | `series:update` + owner | 建卷/部 |
| PUT | `/series/{id}/sections/order` | `series:update` + owner | 卷/部全量调序 |
| POST | `/series/{id}/chapters` | `series:update` + owner | 挂章 `{post_ids[], section_id?, after_chapter?}` |
| DELETE | `/series/{id}/chapters/{postId}` | `series:update` + owner | 摘章 |
| PUT | `/series/{id}/chapters/order` | `series:update` + owner | section 内或根章节全量调序 |

- 文章详情 DTO 扩展：`series {slug, title, chapter_no}` + `prev_chapter/next_chapter {slug, title}`（同为 published 的相邻章节）。
- 分页用项目惯例 page/limit：书是低频列表（非 feed，无顶部持续插入），不引入 cursor。

### 前端（FSD）

- **lab 原型期（T0，先于实现）**：`/lab/series?variant=<A|B|C>&surface=<shelf|detail|reader>`。三套**完整书籍体验**，每套同时覆盖书架、书籍页与阅读器；底部浮动条切 variant，页内切 surface。禁止再做「头部 × 目录 × 卡片」零件拼盘。
  - A 阅读应用：消费级阅读器结构——书架、继续阅读、书籍详情、阅读进度。
  - B 技术书：GitBook / Rust Book 结构——全书侧栏、正文版心、当前章 TOC、键盘上一章/下一章。
  - C 编辑出版：纸书版心与卷/部/章目录——强调扉页、章启页、留白与连续阅读。
- **书封规则**：有封面显示真实图片；无封面复用生产 `PostCard` 规则（`bg-muted` + `ImageOff`），不生成渐变块、假排版封面或拟物色带。设置/更换封面是管理端明确动作。
- **AI 封面生成（T5，P2 期，不阻塞主线）**：书编辑页封面区加「AI 生成」入口。生成结果落素材库后设为封面；端点不支持时置灰提示。
- 路由：`series.index.tsx`（书架）、`series.$slug.tsx`（书籍页）、现有文章详情页在 series 上下文中进入阅读器壳。
- **阅读器是双层导航**：左侧全书目录（卷/部/章），右侧当前章文内 TOC，中间复用现有 ArticleContent 版心；移动端两套导航分别进抽屉/Sheet，不能合并成一个 TOC。
- 挂章入口两处：admin-posts 批量「挂到书」；书管理页内添加章节、分卷与拖拽排序。

### 装配

- `app/series_container.go` 手工 DI（同其它模块），挂 `container.go`。
- 路由挂 `interfaces/http/routing/router.go` 公开区（GET）+ admin 权限区（写操作）。

## Testing Decisions

- **聚合根**：slug、状态机、authorID 不可变；section 标题/排序；section 必须属于同书。
- **service**：挂章归属校验；根章节与 section 章节调序；跨 section 移动；删 section 时章节回到根还是拒绝删除（实现前固定一种，本 PRD 默认拒绝非空 section 删除）。
- **可见性**：目录过滤 draft/archived 章节；draft 书不出现在书架但作者可预览。
- **handler**：匿名 GET 通过、无权限写 403、owner 校验失败 403。
- **导航**：末章无 next、首章无 prev；跨 section 的相邻章可连续导航；隐藏章节被跳过。
- 不测：拖拽像素细节、原型切换器本身。

## Out of Scope

- **一书多章节形态（一文多书）**：`series_id` 单值，明确不支持；确有需求再谈多对多。
- **书级评论**：章节评论已存在，书是聚合视图不重复建评论面。
- **MCP / RSS 暴露 series**：RSS 每章已是独立条目（挂书不改 RSS 行为）；MCP 暂不新增 series resource，需求出现再议。
- **协作写书（多人共著）**：书只能装 owner 自己的文章；与 post 域 Editor 协作模型暂不打通。
- **章节内容改写/重排的书版本快照**：书不存内容副本，无书级版本。
- **购买/付费书**：远期，不做。

## 难逆决策

- **章节归属放 posts 表（series_id 列）而非独立关联表**：读取路径（文章页取归属、书页取目录）都是单表直查；代价是 posts 表多了两个 nullable 列、一文一书成为物理约束（这恰好是当前想要的）。若将来要一文多书需迁出到关联表（破坏性迁移）。
- **chapter_order 全量调序（无插入算法持久化）**：排序权威是调序接口一次性全量写入，插入/摘章由用例重排整段序号。简单可靠；代价是高频调序时写放大（书场景频率极低，可忽略）。
- **书页是聚合视图不存副本**：永不担心书内容与文章不同步；代价是书页渲染依赖 N 篇文章查询（一章一查或一次 in 查询，列表页足够）。
- **series 权限对齐 post 域而非 tweet 登录即可**：书管理是内容管理动作，与 tweet 的轻量 UGC 定位不同。若将来开放全员建书，需要重走权限模型。

## 业界参考

- **series/合订模式**：Hexo/Hugo 的 series 分类约定、Medium Publications、掘力计划专栏——连载博客的主流形态都是「章节保留独立 URL + 系列页聚合导航」，无一次性合并转换的先例。
- **手动章节序**：各连载平台的章节管理均为手动拖拽（发布时间序无法表达中途补章）。
- **聚合视图不存副本**：与本项目 tweet `quote_of`、公告头像组「衍生不落表」的既有哲学一致。
