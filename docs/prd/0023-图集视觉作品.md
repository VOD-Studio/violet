# PRD: 图集视觉作品

## Problem Statement

PhotoStack 已经解决了图集封面的拖拽与换位表现，但组件只负责展示。系统还缺少清晰的图集产品模型：作者怎样组织图片，保存中的修改何时对外生效，图片与素材库如何关联，图集应出现在哪些页面，都没有稳定契约。

旧方案把图集做成登录用户即发即出的相册，混入视频、用户主页、下架状态和独立封面字段。这个边界与 Violet 的内容管理方式不一致，也让媒体引用、发布和治理互相缠绕。旧实现及 110–112 迁移已经删除，本 PRD 不承担兼容。

## Solution

图集是一件可发布的视觉作品，与文章、推文平级。第一版只服务具备内容管理权限的作者，只接受图片。

作者先创建工作稿，从素材库选择或上传图片，调整顺序并填写说明。保存只更新工作稿；发布时，系统一次性把完整工作稿设为公开版本。已发布图集继续编辑时，访客仍看到上一个公开版本，直到作者再次发布。

公开浏览流使用 PhotoStack。组件默认只露出三层堆叠，但接收图集的完整有序缩略图列表，后续图片在切换时进入堆叠。详情页展示完整图片序列和灯箱。公开地址使用稳定 slug，标题变化不自动修改地址。

封面不单独选择。公开版本中的第一张图片就是首图，作者通过排序决定封面。

### 关键场景

| 场景 | 行为 |
|---|---|
| 新建图集 | 创建空工作稿，逐步选图、排序和填写文字；未发布前公开侧不可见 |
| 首次发布 | 校验标题和图片后生成稳定 slug，工作稿成为公开版本 |
| 修改已发布图集 | 第一次保存时生成独立工作稿，公开版本保持不变 |
| 更新发布 | 原子切换公开版本并清理已经失效的旧快照 |
| 撤回公开 | 清空公开版本，保留工作稿和 slug，公开地址返回 404 |
| 删除图集 | 删除工作稿与公开版本，释放全部素材引用；审计记录仍保留 |
| 调整封面 | 把目标图片拖到第一位，不维护独立封面引用 |
| 并发编辑 | 过期工作稿保存返回 409，前端提示重新载入，不静默覆盖 |

## User Stories

1. 作为作者，我要创建一个空图集工作稿，先保存作品再逐步补齐内容。
2. 作为作者，我要从现有素材中一次选择多张图片，避免重复上传。
3. 作为作者，我要在图集编辑器中直接上传新图片，上传结果进入素材库并可立即选用。
4. 作为作者，我要拖拽调整全部图片的顺序，让视觉叙事按预期展开。
5. 作为作者，我要给每张图片填写图集语境下的说明，不修改素材本身的描述。
6. 作为作者，我要覆盖某张图片的无障碍文本，让同一素材在不同作品中有合适的表达。
7. 作为作者，我要保存未完成的工作稿，而不让访客看到半成品。
8. 作为作者，我要预览工作稿，确认浏览流、详情和灯箱效果后再发布。
9. 作为作者，我要发布满足要求的工作稿，得到稳定的公开地址。
10. 作为作者，我要继续编辑已发布图集，同时让访客仍看到上一个公开版本。
11. 作为作者，我要明确执行“更新发布”，让所有改动一次生效。
12. 作为作者，我要撤回公开图集，但保留内容以便以后重新发布。
13. 作为作者，我要删除自己的图集，并释放它占用的素材引用。
14. 作为作者，我要在两个编辑窗口发生版本冲突时收到提示，而不是丢失较早的修改。
15. 作为只读运营人员，我要进入图集管理页查看作品状态，但不能修改内容。
16. 作为审核人员，我要撤回或删除其他作者的图集，不获得替对方改稿的能力。
17. 作为访客，我要浏览按发布时间倒序排列的公开图集，并在 PhotoStack 中连续切换全部图片。
18. 作为访客，我要通过 slug 打开图集详情，查看原顺序图片、说明和无障碍文本。
19. 作为访客，我要在灯箱中使用鼠标、触摸和键盘逐张浏览。
20. 作为分享者，我要复制一个不会因标题修改而变化的图集地址。

## Implementation Decisions

### 领域边界

- Gallery 是独立 bounded context，不建立通用 `contents` 表，也不复用 Post 或 Tweet 的状态机。
- 图集是视觉作品，不是用户相册。第一版没有私密相册、地点、人物、自动归档或用户主页相册入口。
- 图集只引用素材 ID。文件 URL、MIME、尺寸和缩略图仍由媒体域负责，图集不复制这些事实。
- 图集项保存 position、caption 和可选 alt override。素材的 alt text 是默认值，图集项只在当前作品中覆盖。
- 首图由 position 最小的图集项派生，不保存独立 cover ID。

### 工作稿与公开版本

- Gallery 持有 `working_revision` 与可空的 `published_revision`。两者相同表示工作内容已经发布；第一次继续编辑时执行 copy-on-write。
- 已被公开版本引用的 revision 不可原地修改。
- 保存接收完整文档，包括标题、摘要和有序 items。应用层计算增删与排序差异，不提供 AddItem、MoveItem、DeleteItem 等浅接口。
- 每次写入携带 `expected_version`。版本不匹配返回 409。
- 发布把当前工作稿原子设为公开版本；撤回只清空公开指针，不删除工作稿。
- 系统最多保留当前工作稿和当前公开版本。被替换且不再被指针引用的 revision 在事务内删除。
- slug 在首次发布时生成并占用；撤回、重发和修改标题都不改变 slug。

### 发布约束

- 工作稿允许空标题和零张图片。
- 发布要求标题去空白后非空，长度不超过 120 个 Unicode 字符。
- 发布要求 2–50 张图片，同一 revision 内不能重复引用同一素材。
- summary 可空，长度不超过 500 个 Unicode 字符。
- caption 可空，长度不超过 500 个 Unicode 字符；alt override 可空，长度不超过 300 个 Unicode 字符。
- 所有图片必须属于图集作者，状态为 ready、未删除且 MIME 匹配 `image/*`。
- 第一版没有视频。上传器和公开 DTO 不为未来视频预埋字段。

### 数据与事务

- 使用全新 `galleries`、`gallery_revisions`、`gallery_revision_items` 三表，不复用已删除迁移的 schema。
- `gallery_revision_items` 对 `(revision_id, position)` 和 `(revision_id, file_id)` 建唯一约束，position 由服务端归一为连续序列。
- Gallery 的 author ID 创建后不可变。revision 和 item 随 Gallery 删除。
- Gallery revision 对 File 使用限制删除的引用；软删除仍由媒体域的引用计数规则控制。
- 工作稿保存、发布、撤回、删除、revision 清理与 File 引用计数变化必须在同一个 PostgreSQL 事务中完成。应用层不做“先加计数、失败再补偿”。
- fresh migration 从实施时 `release/2.0` 的下一个可用编号开始。当前基线最高为 104，因此预计从 105 开始；实施前重新检查。
- 公开列表按 `(published_at DESC, id DESC)` 使用 cursor 分页。后台管理列表使用 page/limit。

### 应用接口

- Authoring seam 负责 CreateDraft、Save、Publish、Unpublish 和 Delete，隐藏 revision、素材校验、引用计数和事务。
- Reading seam 负责 BrowsePublished、GetPublished、ListForEditor 和 GetForEditor，隐藏公开可见性、作者信息与媒体投影。
- 保存输入是完整 Gallery document。调用方不计算数据库 diff，也不提交 position 数字；数组顺序就是权威顺序。
- 公开列表投影返回每个图集的完整有序缩略图数组，不把业务数据截断为三张。图片资源使用缩略图变体并懒加载。
- 详情投影同时提供网格图片与灯箱所需资源，原图只在进入详情或灯箱后加载。

### HTTP API

公开接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/galleries` | 公开图集浏览流，cursor/limit |
| GET | `/api/v1/galleries/{slug}` | 公开图集详情 |

内容管理接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/admin/galleries` | 创建空工作稿，返回 201 |
| GET | `/api/v1/admin/galleries` | 管理列表，支持状态和作者筛选 |
| GET | `/api/v1/admin/galleries/{id}` | 读取工作稿与公开状态 |
| PUT | `/api/v1/admin/galleries/{id}` | 全量保存 Gallery document |
| POST | `/api/v1/admin/galleries/{id}/publish` | 发布或更新发布 |
| POST | `/api/v1/admin/galleries/{id}/unpublish` | 撤回公开版本 |
| DELETE | `/api/v1/admin/galleries/{id}` | 永久删除，返回 204 |

- JSON 字段沿用项目现状使用 snake_case。
- 未认证返回 401；缺少权限或操作他人内容返回 403；公开版本不存在返回 404；校验失败返回 400；并发冲突返回 409。
- 公开详情用 slug，管理接口用不可变 ID。

### 权限与治理

- `gallery:view`：显示图集管理入口并读取管理列表和工作稿。
- `gallery:manage`：创建、保存、发布、撤回和删除自己的图集。作者操作总是成组授予，不拆成细粒度 CRUD 权限。
- `gallery:moderate`：撤回或删除其他作者的图集，不允许替其他作者修改工作稿。
- 三个权限默认 seed 给 admin；superadmin 继续走 root 通配。普通注册用户默认没有图集创作权限。
- 路由中间件负责模块入口；own-or-moderator 判断在应用层完成。
- 审计记录 created、published、unpublished、deleted 和 moderated。普通保存不写审计，避免自动保存产生噪音。

### 前端接入

- PhotoStack 保持无业务知识，只消费图片数组、当前索引和交互回调。
- `/lab/gallery` 继续使用静态 mock，不导入生产 Gallery 类型或 API。
- 新增 Gallery entity、编辑动作、公开浏览 widget 和详情 widget；路由只负责 loader、鉴权与页面组合。
- 在接入图集前，先把已经被文章、公告和设置页复用的素材选择器提升到 Media entity 公共接口。图集编辑器不直接依赖 `admin-media` feature。
- 内容管理区增加图集列表和编辑器；公开导航在浏览流与详情闭环稳定后再增加图集入口。
- 第一版不修改公开用户主页。现有领域约定明确该页面只聚合公开资料与推文。
- 编辑器在本地即时完成排序和预览，防抖保存完整工作稿；发布是独立显式动作。
- PhotoStack 的静态态只显示三层，切换时使用完整 items 列表补位和淡入，不能把数据源截成三项。

### 分发与可访问性

- 公开 canonical route 为 `/galleries/{slug}`。
- 页面标题、摘要和首图生成 SEO/OpenGraph 信息。
- 图片优先使用图集项 alt override，没有覆盖时使用素材 alt text，再缺失时回退为图集标题与序号。
- 灯箱支持方向键、Escape、触摸拖拽和可见焦点；关闭后焦点返回触发图片。
- 第一版不接首页推荐、全局搜索、RSS、MCP 或通知。

## Testing Decisions

- 主要验收 seam 是 Authoring 与 Reading 两个应用接口。测试外部行为，不断言 revision clone 的内部调用顺序。
- Authoring 测试覆盖空工作稿、完整保存、首次发布、已发布后继续编辑、更新发布、撤回、删除、版本冲突、素材归属、素材状态、MIME、重复图片和数量边界。
- Reading 测试覆盖只返回公开版本、撤回后 404、完整有序缩略图投影、cursor 稳定性和无 N+1 读取。
- PostgreSQL 集成测试覆盖 save/publish/delete 与 File 引用计数的同事务提交和失败回滚，以及唯一约束和级联清理。
- Handler 测试覆盖公开匿名读取、管理端 401/403、owner 与 moderator 边界、400/404/409 映射和 snake_case 契约。
- 前端以编辑器完整用户流为测试面：选图、排序、自动保存、冲突提示、发布和撤回。沿用 admin post editor 的表单测试方式，不测试拖拽库内部实现。
- PhotoStack 继续由现有 motion 和组件测试覆盖全部图片轮转、边界回弹与动画收口；Gallery 测试只验证 DTO 到组件 props 的映射。
- 浏览器验收覆盖触摸拖拽、快速轻扫、首尾反方向回弹、键盘灯箱、移动端布局和图片懒加载。

## Out of Scope

- 视频、音频或任意文件附件。
- 普通注册用户创建图集，以及用户主页图集 tab。
- 私密、仅链接可见或关注者可见图集。
- 评论、点赞、收藏、单图互动和浏览统计。
- 首页推荐、全局搜索、RSS、MCP、通知和站内聊天卡片。
- 完整修订历史、回滚、固定 revision 分享和多人协作编辑。
- 手动选择独立封面、AI 生成封面和封面裁切工具。
- 地点、人物、拍摄时间线和自动归档等相册能力。
- 按单个 item 增删移动的 HTTP API。
- 把 Post、Tweet、Series、Gallery 合并为通用内容表。
