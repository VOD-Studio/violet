# PRD: 友链功能（friend-links：申请制互换链接）

## Problem Statement

博客没有友链能力。博主想展示推荐/互换的站点没有载体——关于页社交矩阵承载的是站长自己的社交账号，不是他人站点；其他博主想与本站互换链接，也没有任何申请通道，只能靠评论区或站外联系，流程不正式、无状态跟踪。

需要一个经典博客友链能力：**访客申请 → 站长审核 → 前台展示**。

## Solution

新增独立 bounded context **`friendlink`**，与 announcement / project 平级（站点级内容，无 author 归属）：

- **申请制**：访客在 `/friends` 页弹窗提交申请（站名/URL/头像/描述/称呼/回链页），站长后台审核通过后前台展示。
- **双轨申请**（镜像评论认证模型）：登录用户直接提交；匿名访客走邮箱验证码两步流（发码 → 填码 → 提交），联系邮箱必填（仅留存不公开）。
- **四态状态机**：`pending`（待审核）/ `approved`（展示中，唯一前台展示态）/ `rejected`（已拒绝，保留记录）/ `disabled`（曾通过但被下柜，可恢复）。
- **前台** `/friends`：独立页 + 顶级导航入口（「项目」后「关于」前），卡片网格按 `sort_order` 排序。
- **后台** `/admin/friend-links`：DataTable + 状态筛选 + 行内审核操作 + 手动添加（直接 approved）+ pending 计数角标。
- **无邮件通知**：新申请仅靠后台 pending 计数发现；审核结果不回执申请人（对方回访页面自见分晓）。
- **视觉先行**：界面好看与创意是一等验收标准。先做 `friends-lab` 静态原型多方向对比，目验收选定后才写生产组件（镜像 announcement-lab 工作流）。

## User Stories

1. 作为访客，我要在 `/friends` 看到全部已互换的站点卡片（头像/站名/描述/域名），按站长编排的顺序展示。
2. 作为访客，点击友链卡片在新标签页打开对方站点。
3. 作为访客，友链列表为空时看到设计过的空态而非裸页面。
4. 作为登录用户，我要在 `/friends` 页点「申请友链」弹窗填写站点信息直接提交，看到「已提交，待审核」反馈。
5. 作为匿名访客，申请时先填邮箱收验证码，填码后才能提交。
6. 作为匿名访客，没填验证码或填错时提交被明确拒绝。
7. 作为申请人（匿名或登录），我已有申请在审核中时，重复提交被 409 拒绝并告知原因。
8. 作为申请人，我的站点 URL 已在列表（非 rejected）时，重复申请被拒绝。
9. 作为申请人，申请被拒绝后我可以修正信息重新申请同一 URL。
10. 作为申请人，我可以选填「我把你的链接挂在哪页」（回链页地址），方便站长确认真互换。
11. 作为站长，后台菜单能看到友链待审核计数角标。
12. 作为站长，我要按状态（pending/approved/rejected/disabled）筛选友链列表。
13. 作为站长，审核时能看到申请人填的回链页地址并可点开核对。
14. 作为站长，批准申请后它立即出现在前台 `/friends`。
15. 作为站长，拒绝申请后它不进前台，但记录保留可复查。
16. 作为站长，误拒时能把 rejected 改判为 approved。
17. 作为站长，对方站点失效或单方撤链时，我要能下柜（disable）而非删除，保留资料；恢复（restore）后重新展示。
18. 作为站长，我要能手动添加友链（不走申请流，直接 approved）。
19. 作为站长，我要能编辑友链字段与排序值，调整前台展示顺序。
20. 作为站长，我要能物理删除友链记录；全部管理操作进审计日志。
21. 作为无权限用户，访问友链管理端点返回 403。

## Implementation Decisions

### 领域模型（domain/friendlink）

```go
// FriendLink 聚合根
type FriendLink struct {
    shared.AggregateRoot
    name         string    // 站点名称（必填，≤30 rune）
    url          string    // 站点 URL（必填，http/https）
    avatarURL    string    // 头像 URL（可空，空则前端首字母占位）
    description  string    // 一句话描述（可空，≤80 rune）
    ownerName    string    // 站长称呼（可空，展示用）
    linkbackURL  string    // 回链页地址（可空，审核参考）
    contactEmail string    // 联系邮箱（匿名必填，登录取自 user 资料；不公开）
    userID       string    // 登录申请者 id（可空，双轨制）
    status       string    // 四态状态机，默认 pending
    sortOrder    int       // 排序值（越小越靠前）
    ipHash       string    // 申请 IP 的 SHA256（配额与反垃圾元数据）
    // timestamps
}
```

- 状态转换：`pending → approved | rejected`；`approved ↔ disabled`（下柜/恢复）；`rejected → approved`（改判）；任意态可物理删除。
- 领域事件：`friendlink.created / approved / rejected / disabled / restored / updated / deleted`，经 EventBus 进审计订阅（项目标准事件驱动审计流程）。
- 手动添加：`NewManual` 构造路径直接置 `approved`，无 userID/ipHash。

### 数据库（migration 076 起，连续链）

- **076**：`friendlinks(id uuid pk, name text, url text, avatar_url text, description text, owner_name text, linkback_url text, contact_email text, user_id uuid null ref users, status text default 'pending', sort_order int default 0, ip_hash text, created_at, updated_at)`。
- **url 部分唯一索引**：`UNIQUE(url) WHERE status != 'rejected'`——approved/disabled/pending 占住 url，rejected 不阻塞重新申请。
- **配额唯一索引**：`UNIQUE(ip_hash, contact_email) WHERE status = 'pending'`——同一申请身份同时仅一个 pending，数据库层兜底（service 层先判返回 409）。
- 权限码 seed：menu `friendlink`，action `friendlink:view` / `friendlink:manage`，随迁移进 permissions 表并授权给管理员角色（超管通配符自动覆盖）。

### API（/api/v1，写操作走 SessionAuth/OptionalAuth + CSRF double-submit）

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/friend-links` | 公开 | 仅 approved，按 sort_order 升序（同权重按 created_at） |
| POST | `/friend-links` | OptionalAuth + 限流 | 申请（双轨：登录跳过验证码；匿名必须 code） |
| POST | `/friend-links/code` | 独立限流 | 匿名申请发邮箱验证码 |
| GET | `/admin/friend-links?status=&page=&limit=` | `friendlink:view` | 后台列表（状态筛选） |
| GET | `/admin/friend-links/pending/count` | `friendlink:view` | pending 计数（菜单角标） |
| POST | `/admin/friend-links` | `friendlink:manage` | 手动添加（直接 approved） |
| PATCH | `/admin/friend-links/{id}` | `friendlink:manage` | 编辑字段/排序 |
| POST | `/admin/friend-links/{id}/approve` | `friendlink:manage` | 批准（pending/rejected → approved） |
| POST | `/admin/friend-links/{id}/reject` | `friendlink:manage` | 拒绝（pending → rejected） |
| POST | `/admin/friend-links/{id}/disable` | `friendlink:manage` | 下柜（approved → disabled） |
| POST | `/admin/friend-links/{id}/restore` | `friendlink:manage` | 恢复（disabled → approved） |
| DELETE | `/admin/friend-links/{id}` | `friendlink:manage` | 物理删除 |

- **限流**：新增 `FriendLinkRateLimit`（申请提交）与 `FriendLinkCodeRateLimit`（发码）两个维度，与 CommentRateLimit 同构。
- **业务配额**：同一 `(ip_hash, contact_email)` 已有 pending 申请 → 409「你的申请正在审核中」；approved/rejected 后放行。service 层判定，唯一索引兜底。
- **验证码**：复用 CodeStore + EmailSender 两步流（场景前缀 `friendlink`，与 comment/verify/reset 的 key 空间隔离）。

### 前端（FSD）

- `features/friend-links`：公开页 `/friends`（卡片网格 + 空态 + 骨架屏）+ 申请弹窗（双轨两步流：匿名「填邮箱发码 → 填码」步骤切换；登录直接填表提交）。
- `features/admin-friend-links`：后台页 `/admin/friend-links`（DataTable + 状态 Segmented 筛选 + 行内操作 + 手动添加/编辑弹窗 + sort_order 填数）。
- 路由：`friends.tsx`、`admin.friend-links.tsx`；`shared/config/nav.ts` 顶级导航加「友链」（「项目」后「关于」前）；admin 菜单加友链项（pending 计数角标）。
- 视觉：见下节，生产组件必须按 lab 选定方向实现。

### 视觉设计（一等验收标准）

- **原型先行**：新增 `friends-lab.tsx` 实验路由（静态 mock 数据、不接 API），把候选创意方向做成可交互并排原型，目验收选定后才写生产组件（镜像 announcement-lab 工作流，lab 页保留作参考）。
- **候选方向**（lab 至少对比 2-3 个）：
  1. **名片墙**：方角头像 tile + 站名 + mono 域名行 + 描述，hairline 边框 + hover 浮起发光，最贴全站语言。
  2. **信笺/明信片墙**：编辑感纸质卡片 + 邮戳式互换标记 + mono 打字机字体，错落排布。
  3. **星图/网络**：友链为节点、SVG 连线成图，hover 节点展开卡片（需想清移动端降级）。
  4. **终端清单**：mono `$ ls friends/` 终端风列表，行 hover 展开预览浮层。
- **申请弹窗**也在 lab 探索仪式感（两步流 =「交换名片」的交互叙事），不做默认裸 Dialog 表单。
- 生产实现基线：页头对齐全站内容页语言（mono eyebrow + 大标题），动效用 motion/react whileInView + stagger，空态/骨架屏用 shared 既有范式，react-bits 已装组件优先。

### 装配

- `app/friendlink_container.go` 手工 DI（同其它模块）。
- 路由：`routing/router.go` 公开区（GET/申请/发码）+ `admin_router.go`（管理端点，权限码组）。
- 审计订阅：按项目事件驱动审计标准流程接入（领域事件 → EventBus → 审计订阅者映射）。

## Testing Decisions

好测试 = 只测外部可观察行为（状态机转换、校验拒绝、HTTP 语义、配额冲突），不测实现细节。全部镜像评论域既有 seam：聚合根单测 + application service（mock 仓储/CodeStore/EmailSender/EventBus）+ handler（stub service）三层，不新增测试基建。

- **聚合根**：必填校验（name/url 空拒绝、url 非 http/https 拒绝、长度边界）；四态转换合法性（含 approved↔disabled 互转、rejected→approved 改判、非法转换拒绝）；手动添加构造直接 approved。
- **service**：双轨申请（登录跳过验证码；匿名校验码失败/缺码拒绝）；配额冲突 409（同 (ip,email) 已有 pending）；url 重复 409（非 rejected 占用）；rejected 后同 url 再申请放行；审核四操作 + 改判；手动添加；状态筛选列表与 pending 计数；事件发布断言。
- **handler**：匿名 GET 200；匿名申请缺 author 字段 400；匿名带无效 code 拒绝；未登录管理操作 401、无权限码 403。
- **不测**：限流中间件本身、验证码基建本身（评论域已覆盖）、gorm 序列化细节。

## Out of Scope

- **回链自动校验**（爬虫核对对方是否挂本站链接）：v2 候选，scraper 域能力可复用。
- **favicon/头像自动抓取**：v1 纯 URL 输入，避免 SSRF 面。
- **RSS 地址与「朋友最新文章」聚合**：不收字段不做功能。
- **双向邮件通知**：新申请靠后台 pending 计数；审核结果不回执。
- **MCP 通道**（reader/posts 均不暴露友链）。
- **友链分组/分类**：平铺列表即全部组织方式。
- **软删回收站**：物理删除，追溯靠审计事件。
- **申请人自助查询申请状态**：提交后无状态通道，批准即出现在页面。

## 难逆决策

- **申请制形态**（vs 纯站长维护）：引入审核状态机与公开写端点。上线后若回退纯展示，需废掉申请数据与审核流。
- **四态合并单字段 status**（disabled 不拆正交 enabled 开关）：前台展示谓词恒为 `status='approved'`；后期拆正交需迁移存量数据。
- **物理删除**：无回收站。审计追溯靠 audit 域事件，不靠业务表留尸。
- **url 部分唯一（rejected 不阻塞）**：唯一性语义决策；改模型需重建索引并处理存量冲突。

## 业界参考

- **申请-审核制**：Halo（开源博客系统）links 模块——访客提交、管理员审核、可填对方回链页。
- **双轨认证 + 邮箱验证码两步流**：本仓评论域（PRD-0001），基建与限流范式直接镜像。
- **原型先行工作流**：本仓 announcement-lab（CONTEXT.md 公告节）——静态 mock 并排对比、选定后写生产组件。
