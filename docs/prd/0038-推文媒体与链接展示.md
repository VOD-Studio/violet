# PRD：推文媒体与链接展示

状态：实现与验收中。

日期：2026-10-28。功能分支：`feat/tweet-media-links`，基于 `release/2.0`。本 PRD 与拆分 issue、后续实现保留在同一功能分支。

## 用户要完成什么

用户在本站发布推文时贴链接、传图片。当前两个体验缺口：

1. 正文里的 URL 是纯文本，不可点击，也没有预览卡片。
2. 图片用评论九宫格组件展示，`background-image` + `bg-cover` 固定裁剪（1 张锁 16:10、2/4 张锁 4:3、3 张锁 1:1），完全不看原图比例；竖图被裁、长图被切。

目标：本站推文卡片的媒体与链接展示对齐 `@violetjs/react-tweet` 已有能力——单图保持原比例、竖图组同高横向滚动条、其余方格；正文 URL 渲染为可点击链接并附带 OG 链接卡片。OG 卡片按通用能力建设（独立后端模块 + 通用端点 + 前端共享组件），推文是第一个消费方，评论、文章等位置后续按需接入。

## 首版范围

| 能力 | 首版行为 |
| --- | --- |
| 图片布局 | 复用 `TweetPhotos`：单图保比例（钳制 0.4–1.8）、竖图为主多图横向滚动条、其余方格；尺寸来自推文图片引用自带的 width/height |
| 正文链接 | 完善 tokenizer：`http(s)://`、`www.`、裸域名（TLD 白名单）、Unicode 路径、尾部标点剥离、超长中间截断 |
| 链接安全 | 协议白名单（仅 http/https）、`rel="noopener noreferrer nofollow"`、新标签打开 |
| OG 卡片 | 每链一卡；封面落本站存储；TTL 惰性重抓；发布时抓首次、历史推文首浏览补抓 |
| 降级 | 抓取失败/无 OG/非 HTML → 不出卡片，链接仍可点击 |
| 接入位置 | 仅本站推文卡片（时间线、主页、详情正文区）；引用卡片小拼图、详情页大图舞台、外链推文（X 转发）不动 |

首版不做：robots.txt 检查、favicon、视频卡片、t.co 类短链展开、链接点击统计。不承诺反爬站点可抓取；上游 403 保留原文链接，不伪造预览。

## 已验证事实（2026-10-28 源码核对）

- 裁剪来源：`web/src/shared/ui/image-grid/ImageGrid.tsx` 用 `bg-cover bg-center` + 固定 aspect 渲染，被 `TweetCardImages` 复用。
- 本站推文卡片布局来自 `@violetjs/react-tweet` 的 `TweetCard`（slot 注入形态），`TweetPhotos`（含竖图组滚动条 `MediaRail`）已存在于 `web/packages/react-tweet/src/tweet/photos.tsx`，但未从包入口导出——需扩 `unstyled.ts`/`index.ts` 导出。
- 外链推文（X 转发）已通过 `EmbeddedTweet` 使用完整 `TweetPhotos` 布局，行为可参照。
- `Tweet.images` 前后端均为 `string[]`（URL 列表），无尺寸；上传模块 `upload.File` 已存每张图 `width/height`（`SetDimensions`），推文图片 purpose=`tweet` 均经过它——尺寸只被聚合根丢弃，无需扫图回填，migration 按 URL 关联 `uploads` 回填即可。
- 正文 `TweetContent` 只解析 `#话题#` 与 `[emote]`；`TweetSegment` 类型（外链推文用）已有 `kind: "url"` 形态可参照。
- 安全传输层 `ssrf.NewSafeTransport`、本地存储、图片处理器（解码/像素上限/缩略图）均已存在，PRD-0031 外链推文抓取已复用，OG 抓取走同一层。

## 数据模型与不变量

### 推文图片引用

`tweets.images` 从 `string[]` URL 数组升级为 JSONB 数组，元素 `{url, width, height}`：

- 聚合根 `images []ImageRef`；创建时由应用层按 URL 从 uploads 补尺寸（沿用现有归属校验查询，不加新请求）。
- 不变量：≤4 张；`url` 非空；`width/height` 可空（历史图片 uploads 记录缺失时为 null，前端退方格，与 `TweetPhotos` 缺尺寸降级路径一致）。
- migration：现有数组按 `uploads.url` 关联回填宽高，关联不上的置 null；不可编辑语义不变。
- 上限、所有权检查、纯图/纯文规则全部沿用。

### 链接卡片缓存

新增 `link_cards` 表，独立 `linkpreview` 领域模块，不进 tweet：

| 字段 | 含义与约束 |
| --- | --- |
| `id` | 本站 UUID |
| `url` | 规范化后的原文 URL，唯一索引；跨内容共享（推文、评论引用同一 URL 只有一行） |
| `title` / `description` / `site_name` | OG/Twitter meta 解析结果，可空；无 `og:title` 时回退 `<title>`，再回退域名 |
| `image_url` | 封面在本站 `uploads/link-previews/` 的访问路径；通过图片处理器校验后按页面键与内容哈希保存，不建立用户上传记录；下载失败不阻塞卡片 |
| `status` | `ok` / `failed` / `pending` |
| `fetched_at` / `expires_at` | 快照时间与 TTL 过期点（拟 7 天） |
| `last_error` / `fail_count` | 脱敏错误与连续失败数；失败退避：失败后 24 小时内不再重抓，连续失败不删除已有旧快照 |

推文与卡片的关联不建表：推文正文 URL 由 tokenizer 确定性提取（前后端同一套规则），DTO 组装时按 URL 批量查 `link_cards`。

## 接口

### 推文 DTO 扩展

列表与详情 DTO 的 `images` 改为 `[{url, width, height}]`，并新增 `link_cards: [{url, title, description, site_name, image_url}]`，无卡时为空数组（服务端批量查询组装，与 PRD-0031「批量加载、避免逐卡查库」同一原则）：

- 命中且未过期 → 返回快照。
- miss / 过期 / 失败退避已过 → 返回现有结果（无则无卡），同时触发后台异步抓取。响应不等待网络抓取；前端查询明确的 pending 状态并就地回填。
- 同 URL 并发抓取合并；进程最多 4 个完整抓取任务，不为超额请求创建无界等待 goroutine。

### 通用取卡片端点

`POST /api/v1/link-cards/lookup`（body: `{urls: string[]}`，上限 10 个）返回 `{cards, pending, unavailable}`。`cards` 按规范 URL 映射快照；`pending` 包含等待、正在抓取或过期重抓的 URL；`unavailable` 表示本轮已结束但无可展示快照。前端按 URL 共享查询缓存，挂载时同轮去重、每批 10 个；仅 pending 每 2 秒继续查询，成功、失败或最后一个消费方卸载后停止。游客写请求先获取 CSRF cookie。

### 发布时抓取

推文创建事务提交后异步触发首次抓取（登记 URL），不阻塞发布响应、不影响发布限额判定。

## OG 抓取约束

| 项目 | 实现值 |
| --- | --- |
| 传输层 | 复用 `ssrf.NewSafeTransport`（内网拦截、重定向逐跳复检），仅 http/https |
| HTML 超时 / 上限 | 6 秒 / 2 MiB，仅 `text/html` |
| 封面下载 | 15 秒、10 MiB、2,000 万像素；复用图片处理器校验，内容哈希 URL 不可变，刷新失败保留旧封面 |
| 解析字段 | `og:title`、`og:description`、`og:site_name`、`og:image`、`twitter:title/description/image` 回退 |
| URL 规范化 | 剥常见跟踪参数不强制；同 URL 不同大小写主机/默认端口归一，避免重复行 |
| 单进程抓取并发 | 4，同 URL 合并；进程级失败退避见上表 |
| 重定向 | 上限 5 次，每次复检 SSRF |

封面图相对路径按最终响应 URL 解析为绝对地址后下载。封面 URL 与页面 URL 都经过 SSRF 检查。

## 前端结构

| 位置 | 职责 |
| --- | --- |
| `web/packages/react-tweet` | 新增导出 `TweetPhotos`（含 props 类型）；组件本体不动 |
| `web/src/shared/lib/linkify` | 通用 URL tokenizer：识别、尾部标点剥离、超长截断显示形态；纯函数，含 TLD 白名单与 Unicode 路径支持 |
| `web/packages/ui/src/components/link-card` | 通用 `LinkCard`，仅接收原生链接属性与展示字段；X 式小卡片，左缩略图、右侧标题/摘要/域名，重复信息去重，无图片不留图位 |
| `web/src/entities/link-preview` | DTO、批量请求、URL 级查询缓存及自动回填；图片代理与加载状态留在站点实体层 |
| `web/src/features/tweets/ui/TweetContent` | 接入 linkify：URL 段渲染 `<a>`；切分优先级 URL > `#话题#` > `[emote]`（URL fragment 中的 `#` 不被话题吞并） |
| `web/src/features/tweets/ui/TweetCardImages` | 改用 `TweetPhotos`，图片带宽高；点击仍走本站灯箱 |
| 推文卡片 | 正文下方渲染 `link_cards`，每链一卡；卡片点击整卡新标签跳转 |

视觉约束沿用仓库红线：功能圆角 ≤ `rounded-2xl`、无硬投影、无缩放/滑入动效。保留正常描边，hover 不高亮边框；键盘聚焦环保留。缩略图桌面宽 96px、窄容器宽 80px，裁剪为紧凑图位。

## 失败处理

| 情况 | 行为 |
| --- | --- |
| 链接不可达 / 超时 / 非 HTML | `status=failed`，退避 24h；不出卡片，正文链接仍可点 |
| OG 缺失（无 title/description/image） | 用 `<title>`/域名兜底；仅无封面时纯文本卡 |
| 封面下载失败 | 不阻塞，出纯文本卡；首次 `image_url` 为空，重抓失败保留旧封面 |
| 目标站反复失败 | 保留最后成功快照继续展示（若有），仅记录 fail_count |
| SSRF 命中（内网/环回/非法端口） | 直接 failed，不请求，记脱敏错误 |

## 验收

- 用户启动的本地 5173 页面真实发布含链接推文，观察异步就地出卡与图片加载；已命中缓存的 SSR 直出预览，无可展示元数据时只保留正文链接。
- TTL 过期（测试中缩短）后再次浏览触发重抓换新；失败退避期内浏览不重抓。
- 同一 URL 第二条推文复用缓存行，不重复抓取。
- SSRF 用例：`http://127.0.0.1`、`http://169.254.169.254` 被拦截。
- 图片布局：横图单张保比例、竖图组滚动条、混合方格、历史无尺寸图退方格；点击灯箱不触发卡片导航。
- tokenizer：中文路径、尾部句号/右括号剥离、`#话题#` 与 URL fragment 混排、超长截断，均有单测样本。
- 站内 X 转发详情输出共享原文的正文和首张媒体为 OpenGraph 摘要；引用推文提供次级回退。元数据图片转为绝对地址。
- `make api-test` / `make web-test`（容器路径）与 lint、typecheck、OpenAPI 契约全绿。
