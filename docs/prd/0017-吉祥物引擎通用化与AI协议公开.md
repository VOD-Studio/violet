# PRD: 吉祥物引擎通用化与 AI 协议公开（mascot standalone）

## Problem Statement

堇喵引擎目前困在实验室 feature 内，三个缺口让「别人接入」不可能：

1. **引擎不可分发**。`web/src/features/lab/mascot/engine/` 是纯 TS、零 React 依赖的 SVG 渲染引擎（弹簧物理、表情状态机、37 套动作），但只对 `/lab/mascot` 一个页面可见。其他站点想接入只能抄源码，没有包边界、没有版本、没有公开 API 承诺。
2. **AI 消息协议没有跨边界驱动方式**。`handleAIMessage` 只存在于 React 宿主（`MascotStage`）的 ref 上——外部 agent 拿不到组件实例引用；iframe、油猴脚本、其他框架宿主全部无法驱动。协议也没有公开 schema，SDK 展示区的「AI 对接」目前是超前描述（协议真实、消费方为零）。
3. **项目可能独立出去**。引擎成熟后应可作为独立分发物，其他博客/站点/个人主页也能用。独立前需要先在 monorepo 内验证包 API 稳定性，仓促抽仓库只会制造双份漂移。

## Solution

三层通用化，把「实验室展品」变成「可分发组件 + 公开协议」：

1. **包化（T1）**：engine 提为 workspace 包 `@violet/mascot`（`web/packages/mascot`），纯引擎 + React 宿主 + Web Component 三入口（subpath exports）。lab feature 改为消费包，行为零变化。
2. **协议公开化与多通道驱动（T2）**：
   - AI 消息协议定型 `{ emotionId: string, tips?: string }` 并发布 JSON Schema（包内常量 + 文档页）；
   - 驱动通道从「仅 JS ref」扩为三种：**JS API**（现状，站内宿主）、**DOM CustomEvent**（`violet-mascot:message`，window 级，任意脚本可派发）、**postMessage**（`type: "violet-mascot:message"`，跨 iframe/跨窗口）。
   - Web Component `<violet-mascot>`：非 React 站点一行 script + 一个自定义元素接入，`emotion` 属性驱动。
3. **分发与文档（T3）**：npm 发布流程、接入文档页（含协议 schema 与表情 ID 目录）、最小示例。

### 接入矩阵（T2 完成后）

| 接入方 | 通道 | 示例 |
|---|---|---|
| violet 站内 React 页面 | `@violet/mascot/react` + ref API | lab、未来站内 AI 助手 |
| 任意框架/无框架站点 | `<violet-mascot>` custom element | 静态页、Vue/其他框架站 |
| 外部脚本（油猴/agent 注入） | `window.dispatchEvent(CustomEvent)` | agent 输出协议 JSON → 脚本转发 |
| 跨 iframe 宿主 | `iframe.contentWindow.postMessage` | 嵌入式挂件场景 |

## User Stories

1. 作为其他站点的开发者，我想通过一行 script + `<violet-mascot>` 接入堇喵，不需要引入 React 或 fork 引擎。
2. 作为 agent 开发者，我想拿到公开的 AI 消息协议 schema 与表情 ID 目录，让我的 agent 输出能驱动任何嵌了该组件的站点（思考中/出错了/任务完成等代理工作态）。
3. 作为站点接入方，我想通过 postMessage 驱动 iframe 内的吉祥物，用于嵌入式挂件。
4. 作为 violet 维护者，我想让 lab 与未来站内 AI 助手消费同一个包，避免引擎双份维护。
5. 作为接入方，我想自定义表情包数据（palette/动作/台词），不 fork 引擎也能换成自家吉祥物（P2）。

## Implementation Decisions

### T1 包化：workspace 包，不建独立仓库

```
web/packages/mascot/
  src/
    engine/       # 现有纯 TS 引擎原样迁移（expressions/eyes/body/mascot）
    react/        # MascotStage 从 lab 上提
    protocol.ts   # AIMessage/AIMessageResult 类型 + JSON Schema 常量
    element.ts    # <violet-mascot> Web Component（T2）
  package.json    # exports: "." / "./react" / "./element"
```

- workspace 协议依赖（`"@violet/mascot": "workspace:*"`），Vite 直接消费 TS 源码，无需预构建。
- lab feature 保留展馆 UI（舞台/目录/SDK 区），引擎 import 改指向包，删除本地 engine 目录——**净迁移，不留壳**。
- **不直接抽独立仓库**：独立时机 = 协议公开（T2 落地）+ 有第一个真实外部用户之后。monorepo 内先锁 API 边界，避免仓促独立的维护断档。

### T2 协议与多通道

- **协议定型**（`protocol.ts`）：

```ts
export interface AIMessage {
  /** 表情 ID；未知值回退待机 "00"，不报错 */
  emotionId: string;
  /** 对白气泡台词；缺省用该表情默认描述 */
  tips?: string;
}
```

- **CustomEvent 通道**：组件挂载时监听 `window` 上的 `violet-mascot:message`，`event.detail` 即 AIMessage。事件名命名空间化防撞。
- **postMessage 通道**：同组件监听 `message` 事件，`data.type === "violet-mascot:message"` 且 `data.payload` 为合法 AIMessage 时生效；非同源消息只按 type 匹配、不信任 origin（协议本身只读表情态，无敏感面）。
- **Web Component**：attribute `emotion`（初始/受控）、`data-*` 透传尺寸类；无 JS 环境降级为空占位（SSR 安全）。
- **回退语义保持**：未知 emotionId → 待机，三条通道共用同一归一化入口（现有 `MascotStage.handleAIMessage` 逻辑上提到包层）。

### T3 分发与文档

- npm 发布（公共包名 `@violet/mascot` 或独立名，T3 时定）；CI 发版对齐仓库 release-please 流程（changesets 或 release-please 多包模式，T3 评估）。
- `/lab/mascot` SDK 区升级：从「示意代码」变为「真实协议文档」——链接包内 schema、表情 ID 全目录（37 套即协议枚举源）、三通道接入示例（CodeCard）。

### 权限与后端

**零改动**。纯前端包化与协议公开，不新增端点、不新增权限点。

## 交付分期

| 期 | 内容 | 验收 |
|---|---|---|
| T1 | engine + MascotStage 迁入 workspace 包，lab 改消费 | lab 行为零变化（37 表情/交互全回归）；typecheck/test 全绿；lab 内无 engine 残留 |
| T2 | protocol.ts + CustomEvent + postMessage + `<violet-mascot>` | 三通道在 demo 页各自驱动成功；未知 ID 回退；包导出三入口 |
| T3 | npm 发布 + 文档页 + SDK 区升级为真实协议文档 | 第三方站点按文档接入成功一次（真实用户验收）；SDK 区链接 schema |
| P2 | 表情包数据驱动化（自定义 palette/动作）、独立仓库抽取 | 外部用户自定义表情包成功；独立仓库 CI 与发布闭环 |

## Out of Scope

- 表情包自定义与主题系统（P2，等第一个外部真实用户再设计）。
- MCP 侧暴露表情能力——agent 驱动前端组件的正确路径是**协议 JSON + 通道**，不是服务端 tool；MCP resource 形式（表情目录）若未来站内 AI 助手需要再评估。
- 吉祥物进前台博客页面（看板娘挂件位）——是消费方之一，等站内 AI 助手立项时一并接。
