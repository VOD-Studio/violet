# PRD: 图块导出与移动端体验（全屏 + 捏合缩放 + a11y + 测试补全）

## Problem Statement

图块缩放平移已在 PRD-0011 落地阅读端，但对照「博客场景完整样本」（BookStack Mermaid Viewer）与 GitHub 新版 mermaid 体验（GitLab Issue [#398629](https://gitlab.com/gitlab-org/gitlab/-/issues/398629) 在追赶），仍存四类缺口：

1. **无导出能力**：读者看完图无法保存。PRD-0011 已预告「导出 PNG/SVG/PDF 为下一档」。GitHub、Notion、VSCode mermaid preview 均把导出做成标配。
2. **移动端放大缺位**：`useDiagramViewport` 只跟踪单指针（`DragSession` 单 `pointerId`），解锁态移动端只能单指拖拽 + 点 `+/−` 按钮缩放，无法双指捏合缩放——触屏放大看细节的本能手势缺失。
3. **超大图正文栏裁切**：缩放受限于正文栏宽度，即便解锁放大，视野仍被栏宽裁切，无全屏/模态查看入口（GitHub 新体验核心即全屏 + 导航区）。
4. **a11y 与测试债**：缩放/平移/锁定无键盘等价操作；`aria-label="流程图"` 是写死泛词，未反映图表语义；React 组件层（`DiagramBlock`/`DiagramViewport`/编辑弹层）零单测。

## Solution

四块能力在同一 PRD 内按 issue 独立交付，彼此低耦合，可并行/分序实现：

- **导出**：阅读端图块工具条新增「导出 SVG / PNG」，复用渲染管线的已清理 SVG，不引库
- **全屏查看**：图块新增「全屏」入口，React Portal 模态层复用 `DiagramViewport`（锁/解锁 + 缩放 + 导出全继承），脱离正文栏宽度约束
- **移动端捏合缩放**：`useDiagramViewport` 的指针跟踪从单指针升级为多指针缓存（[MDN pinch 模式](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events/Pinch_zoom_gestures)），复用已有纯函数 `zoomAtPoint`，不引库
- **a11y + 测试补全**：键盘缩放、`aria-label` 语义化、补全 React 组件层与编辑弹层单测

## User Stories

1. 作为访客，我想把文章里的流程图导出为 SVG/PNG 存档或贴到别处，这样离线/跨平台都能用
2. 作为访客（移动端），我想双指捏合缩放流程图，这样在窄屏上也能看清节点细节
3. 作为访客，当流程图非常大时，我想点「全屏」进入模态查看，这样视野不被正文栏裁切
4. 作为访客（键盘/读屏用户），我能用键盘缩放/平移图块，读屏能读到图表实际语义，这样图块信息对我可访问
5. 作为维护者，图块交互组件有单测兜底，这样后续改动不致回归

## Implementation Decisions

### 1. 导出 SVG / PNG（不引库）

- **SVG 导出**：渲染管线已产出 DOMPurify 清理后的 SVG 字符串（`renderMermaid` 返回的 `svg`），直接 `Blob` + `URL.createObjectURL` + `<a download>` 触发下载。无需二次渲染。关键：序列化时注入 XML 声明与命名空间（`<?xml ...?>` + `xmlns="http://www.w3.org/2000/svg"`），否则独立打开 SVG 缺命名空间
- **PNG 导出**：SVG → 位图走 `Image` + `canvas`。`const img = new Image(); img.src = SVG_BLOB_URL; img.onload → ctx.drawImage → canvas.toBlob`。需处理跨 taint（blob URL 不会 taint canvas，安全）。导出尺寸/比例默认取 SVG 原始 viewBox；可选按当前缩放倍率导出（首期不做，取原始尺寸）
- **后端不参与**：导出 100% 在阅读端完成，与 ADR-0004 浏览时渲染一致——后端只存 `data-source`，不产图
- 工具条新增「导出」按钮（`Download` 图标），点击弹小菜单（SVG / PNG 二选一）；PDF 不做（依赖额外库且需求弱，见 Out of Scope）

### 2. 全屏查看（React Portal + 复用 DiagramViewport）

- 入口：阅读端图块工具条新增「全屏」按钮（`Maximize` 图标）
- 模态：`createPortal` 到 `document.body` 的全屏遮罩（`fixed inset-0 z-50 bg-background/95 backdrop-blur`），内层复用 `DiagramViewport`——锁/解锁、缩放平移、导出按钮全继承，零额外交互逻辑
- 关闭：Esc 键 / 点遮罩空白 / 右上关闭按钮
- 焦点管理：打开时聚焦模态容器，关闭后焦点回全屏按钮（`focusTrap` 首期不做，仅 Esc + 关闭按钮可达）
- 与 PRD-0005/0011 的关系：全屏是 PRD-0011 `DiagramViewport` 设计为「纯 UI 容器、不感知 mermaid」的直接收益——同组件在正文栏与全屏态各挂载一次

### 3. 移动端捏合缩放（自研，复用 zoomAtPoint）

- **不引库**。复用现有纯函数 `zoomAtPoint(state, factor, pointX, pointY)`（已接受任意中心点）。捏合只需把「两指中点 + 距离比」喂给它
- 指针跟踪从单指针 `DragSession` 升级为多指针：维护 `Map<pointerId, {x,y}>` 活跃指针缓存
  - `pointerdown`：写入缓存
  - `pointermove`：更新匹配指针坐标；若缓存有 **2 个指针**，算两指欧氏距离 `curDist`，`factor = curDist / prevDist`，缩放中心 = 两指中点 → `zoomAtPoint`
  - `pointerup/cancel`：移出缓存；缓存降到 ≤1 个指针时切回单指拖拽平移
- 增量约 30–40 行，对齐 PRD-0011「自研不引库，可控无新依赖」决策。参照 [MDN Pinch zoom gestures](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events/Pinch_zoom_gestures)
- 单指拖拽平移逻辑不变（缓存仅 1 个指针时走原 `DragSession` 路径）

### 4. a11y

- **键盘缩放**：`DiagramViewport` 内容容器加 `tabIndex={0}`，`onKeyDown` 处理：`+`/`=` 放大、`-` 缩小、方向键平移（与拖拽平移同 translate 改动）、`0` 重置、`Enter` 切换锁/解锁。锁定态下方向键让位页面滚动
- **aria-label 语义化**：图块节点 `role="img"` 的 `aria-label` 从写死「流程图」改为读图块 carrier 属性——首期取 mermaid 源码首行的注释或标题节点（mermaid `%%{title}%%` 或图块周边文本），无则降级「Mermaid 图表」。对齐「字段注释规范：领域对象字段语义自表达」的精神，让屏幕阅读器读到图表实际含义
- 工具条按钮已有 `aria-label` + `title`（PRD-0011 已做），本期补内容容器的键盘契约

### 5. 测试补全

- **`useDiagramViewport` 捏合**：多指针缓存写入/移除、两指距离比 → factor、中点计算、缓存降到单指切回平移
- **`DiagramViewport` 组件层**：工具条按钮渲染（锁定/解锁态）、键盘事件 → transform 变更、`tabIndex` 聚焦
- **`DiagramBlock` 组件层**：主题 MutationObserver 触发重渲、复制按钮反馈、失败降级 `<details>` 渲染
- **导出纯函数**：抽 `serializeSvg(svg): string`（注入 XML 声明）与 `svgToPngBlob(svg): Promise<Blob>` 为纯函数，单测覆盖序列化正确性与 taint 安全
- 编辑弹层（`DiagramPopoverView`/`DiagramEditPanel`）单测：弹层开闭契约、防闪烁（沿用上一帧 SVG）、Esc/外部点击关闭

## Component Boundaries

| 模块 | 位置 | 职责 |
|------|------|------|
| 导出工具 | `shared/ui/diagram/export.ts`（新） | SVG 序列化 + SVG→PNG canvas 转换，纯函数 |
| 全屏模态 | `shared/ui/diagram/DiagramFullscreen.tsx`（新） | Portal 遮罩 + 复用 DiagramViewport |
| 捏合缩放 | `shared/ui/diagram/useDiagramViewport.ts`（改） | 多指针缓存 + 复用 zoomAtPoint |
| 阅读端接入 | `shared/ui/diagram/DiagramBlock.tsx`（改） | 工具条加导出/全屏入口、aria-label 语义化 |
| 键盘交互 | `shared/ui/diagram/DiagramViewport.tsx`（改） | tabIndex + onKeyDown 缩放平移 |

## Testing Decisions

- 纯函数优先抽离测：`zoomAtPoint`/`clamp`（已有）、`serializeSvg`/`svgToPngBlob`（新增）、多指针中点/距离计算（新增纯函数 `pinchFactor` / `midpoint`）
- React 组件层用 `@testing-library/react`：渲染断言 + `fireEvent.keyDown` / `pointerDown` 事件模拟
- 不测：真实 mermaid 渲染（沿用 PRD-0011 手动验证先例）、拖拽手感（手动验证）、PNG 像素级正确性（测 taint 安全与 canvas 调用即可）

## Out of Scope

- **PDF 导出**：SVG→PDF 需额外库（pdfmake/jspdf），且博客场景 PDF 需求弱；PNG 已覆盖「位图存档」需求
- **导出尺寸/分辨率选项**：首期取 SVG 原始 viewBox 尺寸，不提供 @2x / 自定义分辨率
- **图内元素交互（点击节点跳转）**：mermaid 原生交互能力，PRD-0005 已声明独立决策
- **多图表格式（plantuml 等）**：与本期正交，`renderers.ts` 注册表已预留
- **编辑弹层预览缩放 / 小屏适配**：PRD-0011 划出本期，「后台」优先级仍低于读者侧
- **焦点陷阱（focusTrap）**：全屏模态首期仅 Esc + 关闭按钮可达，不做完整 Tab 循环陷阱

## Further Notes

### 决策来源与参照

- **GitHub 新版 mermaid 体验**：全屏查看 + 缩放导航区 + 导出，GitLab [#398629](https://gitlab.com/gitlab-org/gitlab/-/issues/398629) 明确在追赶
- **MDN Pinch zoom gestures**：官方 Pointer Events 多指针模式，自研捏合缩放的标准路径
- **BookStack Mermaid Viewer**（PRD-0011 已对齐）：导出是博客场景完整样本的下一块拼图
- **pinch-to-zoom 自研 vs 引库**：现有 `zoomAtPoint(state, factor, pointX, pointY)` 已接受任意中心点，捏合只需多指针缓存 + 距离比 + 中点喂给它，增量 ~30–40 行，零新依赖。引 `react-zoom-pan-pinch` 为单一 SVG 整库不值，与 diagram 模块「自研 + 轻依赖」架构一致

### 与既有 PRD 的关系

- PRD-0011 的「导出 PNG/SVG/PDF 下一档」 → 本期兑现（PDF 除外，见 Out of Scope）
- PRD-0011 的「DiagramViewport 设计为纯 UI 容器，后续接入弹层是纯增量」 → 本期全屏模态正是此设计的直接收益
- PRD-0005「图内元素交互独立决策」 → 本期延续 Out of Scope

### 已否决（grill 阶段）

- 引 `react-zoom-pan-pinch` 做捏合缩放：现有 pointer 基础设施 + `zoomAtPoint` 纯函数已足够，整库过重
- 服务端导出（headless browser 渲染）：与 ADR-0004 浏览时渲染架构相悖，且后端只存 `data-source`，引 headless chrome 成本极高
- 导出走 `<canvas>` 全图重绘（mermaid `render` 之外再画一遍）：复用已清理 SVG → canvas 即可，无需重绘
