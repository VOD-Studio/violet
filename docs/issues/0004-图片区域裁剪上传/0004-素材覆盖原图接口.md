## What to build

新增后端接口 `POST /uploads/replace`：multipart 收裁剪后的新文件 + 目标素材 fileId，把该素材记录的存储指针（path/url/size/mimeType/fileHash/thumbnail/width/height）更新为新文件，旧物理文件保留。仅 owner 可覆盖自己上传的素材。

**秒传安全（核心约束）**：File 记录的 `file_hash` 更新为裁剪后新文件的 SHA-256。这样未来上传与「原文件」相同内容时，按旧 hash 查不到本记录（hash 已改）→ 正常新建，不误命中；未来上传与「裁剪后文件」相同内容 → 按新 hash 命中本记录 → 秒传，符合预期。**绝不能只改物理字节不改 hash**（会让旧 hash 秒传命中错文件）。

接口挂在现有 `/uploads` group，复用 SessionAuth + UploadRateLimit。前端配套加 `useReplaceMediaFile` mutation。
