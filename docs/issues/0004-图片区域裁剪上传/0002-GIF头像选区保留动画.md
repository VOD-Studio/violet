# Issue-0017：GIF 头像选区（保留动画）

## Parent

spec：`../../superpowers/specs/2026-07-07-image-region-crop-upload-design.md`
plan：`../../superpowers/plans/2026-07-07-image-region-crop-upload.md`

## What to build

扩展 Issue-0016 建立的架构，让 GIF 头像也能选区裁剪且**无损保留动画**。GIF 不重编码文件（重编码必丢动画），改为把归一化坐标编码进 URL 查询参数 `?crop=x,y,w,h`，显示层用 CSS 视觉裁剪聚焦选区。

本切片交付：
- `cropUrl.ts` 坐标 URL 编解码（withCrop/parseCrop）
- `crop-to-style.ts` transform 纯函数（rect + 容器比例 → CSS transform）
- `CroppedImage` 扩展 GIF 视觉裁剪路径（解析 `?crop=` → CSS transform）
- `avatarUrl` 对 GIF 剥除所有动态处理参数（format=webp 会让后端解码 GIF 取第一帧，动画静默丢失）
- `CropUploadDialog` 的 GIF 分支（上传原图后拼 `?crop=`）

## Acceptance criteria

- [ ] 新增 `web/src/features/upload/lib/cropUrl.ts`：`withCrop(path, rect)` / `parseCrop(url)`，归一化坐标编码进 `?crop=x,y,w,h`，保留其他查询参数，幂等覆盖，含边界校验（非法/超界 parseCrop 返回 null）
- [ ] cropUrl 单测覆盖：附加/保留已有参数/幂等覆盖/4 位小数舍入/解析各种边界
- [ ] 新增 `web/src/shared/ui/image-cropper/lib/crop-to-style.ts`：`cropToStyle(rect, containerAspect)` 返回 `{ transform }`，object-fit:cover 下聚焦选区中心
- [ ] crop-to-style 单测覆盖：无选区/正方形居中/宽选区+高容器/高选区+宽容器/偏移选区
- [ ] `CroppedImage` 扩展：解析 src 的 `?crop=` → cropToStyle → CSS transform；无参数仍退化 object-cover（不破坏 Issue-0016 的静态图）
- [ ] 改 `web/src/features/upload/lib/imageUrl.ts` 的 `avatarUrl`：检测 path 剥查询后以 `.gif` 结尾时，**返回原 path 不追加任何处理参数**（w/thumb/format/quality/rotate 全剥）；静态图走原逻辑
- [ ] avatarUrl 单测覆盖：空 path/静态图/GIF 剥参/GIF 保留已有 crop 参数
- [ ] `CropUploadDialog` 填充 GIF 分支：上传原图拿 url → `withCrop(url, rect)` → onConfirm
- [ ] `make web-test && make web-typecheck && make web-lint` 全绿
- [ ] 手动验证：选 GIF → 裁剪 → 头像 URL 含 `?crop=` 且**动画保留**（关键：avatarUrl 已剥 format=webp，CroppedImage 对 GIF 只用 ?crop + CSS）

## Blocked by

## 实现指引

参考 plan 的 Task F2（cropUrl）、F3（crop-to-style）、F5（CroppedImage 扩展）、F6（avatarUrl GIF 特判）、F8（CropUploadDialog GIF 分支）。

**关键约束**：GIF 动画保留的必要条件是「GIF 不走任何后端图片处理参数，只用 `?crop` + CSS」。`avatarUrl` 对 GIF 剥参是这条链路的命门，漏了就丢动画。

crop-to-style 的 transform 公式以单测断言为准，若浏览器实际渲染偏移，调试公式后回填测试。
