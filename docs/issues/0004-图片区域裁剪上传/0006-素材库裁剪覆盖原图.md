# Issue-0021：素材库裁剪覆盖原图

## Parent

spec：`../../superpowers/specs/2026-07-07-image-region-crop-upload-design.md`
plan：`../../superpowers/plans/2026-07-07-image-region-crop-upload.md`

## What to build

扩展 Issue-0020 的素材库裁剪弹窗，加「覆盖原图」checkbox（默认不勾）。用户勾选后，裁剪确认走 Issue-0019 的 `useReplaceMediaFile` 覆盖原素材记录指针（file_id 不变，url/path/hash/size/thumbnail 更新为裁剪后文件）；不勾走原新建路径。

**适用范围**：仅静态图显示 checkbox。GIF 不重编码（文件字节不变，覆盖无意义），不显示。Owner 校验由后端 Issue-0019 兜底（非 owner 调 replace 返回 403）。

## Acceptance criteria

- [ ] `web/src/routes/admin.media.tsx` 的裁剪 Modal footer 加「覆盖原图」checkbox，**仅当 `cropFile.mime_type` 不含 gif 时显示**
- [ ] 裁剪确认分流：
  - 勾覆盖 + 静态图：`cropImageToBlob` → `new File([blob], name.webp)` → `replaceMedia.mutateAsync({ fileId: cropFile.id, file })` → invalidate lists → toast「已覆盖原图」
  - 不勾：走 Issue-0020 的新建路径
  - GIF：不显示 checkbox，走 Issue-0022 的复制 URL 路径
- [ ] 覆盖中显示 loading（`replaceMedia.isPending`），按钮禁用
- [ ] 覆盖失败（含 403 非 owner）toast 错误信息
- [ ] `make web-typecheck && make web-lint` 全绿
- [ ] 手动验证：自己的图片 → 裁剪 → 勾覆盖 → 原记录 url/size 更新（file_id 不变、owner/refCount 不变）；不勾 → 新增记录；别人的图片勾覆盖 → 403 toast

## Blocked by

- Issue-0019（后端 replace 接口 + useReplaceMediaFile mutation）
- Issue-0020（素材库裁剪弹窗 + 新建路径）

## 实现指引

参考 plan 的 Task F12 Step 3 的 `handleCropConfirm`（overwrite 分支）。checkbox 用原生 `<input type="checkbox">` 或项目 Checkbox 组件（若无则用原生）。

**覆盖的本质**：不产生新素材记录，原 file_id 的指针指向新文件。refCount 不变意味着所有引用该素材的地方（如已发布的文章封面）自动拿到新内容——这是期望行为。
