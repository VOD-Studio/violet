# Issue-0004：用户社交与动态接口

## Parent

PRD：`../../prd/0008-mimo-music-phase-4.md`（user stories 18-22；Implementation Decisions - 用户模块）

## What to build

扩展 User 能力域，补充用户的社交关系与活动流接口：关注列表、粉丝列表、动态、播放记录、等级信息。

在 0003 建好的 User 子接口骨架上新增方法：`Follows(ctx, userID, limit, offset)` / `Followeds(ctx, userID, limit, offset)` / `Events(ctx, userID, limit, offset)` / `Record(ctx, userID, type)`（播放记录，type 0=本周 1=所有）/ `Level(ctx, userID)`。

netease 实现：Follows 走 `/weapi/user/getfollows`；Followeds 走 `/weapi/user/getfolloweds`；Events 走 `/weapi/event/get`；Record 走 `/weapi/v1/play/record`；Level 走 `/weapi/user/level`。

service 层：关注/粉丝/等级做缓存（24h，低频变化）；动态和播放记录做短缓存（10 分钟，相对活跃）。

HTTP 端点：GET /api/v1/users/{id}/follows、/followeds、/events、/record、/level。

SDK 同步增加。

## Acceptance criteria

- [ ] User 子接口新增 Follows / Followeds / Events / Record / Level 五个方法
- [ ] 各方法有对应 Result 类型
- [ ] `provider/netease/user.go` 实现五个方法
- [ ] service 层缓存（关注/粉丝/等级 24h，动态/播放记录 10min）
- [ ] 五个 HTTP 端点注册到 router
- [ ] SDK 五个方法 + DTO
- [ ] service 层 mock 测试
- [ ] netease converter 测试
- [ ] 所有导出符号有 godoc 注释
