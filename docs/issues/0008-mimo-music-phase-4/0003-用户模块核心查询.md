## What to build

新建 `UserService`，落地用户模块的核心查询接口：账号信息、用户详情、数量统计、用户歌单列表、按昵称查、互相关注判断。

用户是网易云中心实体，歌单管理（0005）依赖用户歌单列表，必须先做。

改动链路：

- `proto/netease/music/v1/user.proto`（新 proto）：定义 `UserService` + 首批 rpc——Account（账号信息，需登录）/ Detail / SubCount（数量统计）/ Playlist（用户歌单列表，带 playlist_filter）/ DetailByName（按昵称查 uid）/ FollowEachOther（互相关注判断）。User 实体 message 复用首批 5 实体中已有的（proto common 或 user.proto 里定义的 `User`）。新建 message：`UserSubCount`（eventCount/playlistCount/followeds/follows/...）、`UserPlaylistResponse`（repeated Playlist + total）。
- `internal/netease/endpoint/user/`（新目录）：每接口一个 endpoint 声明。Account 网易云 `/weapi/w/nuser/account/get`（`Meta.Auth=AuthLoggedIn`）；Detail `/weapi/v3/user/detail`；SubCount `/weapi/user/subcount`；Playlist `/weapi/user/playlist`（带 limit/offset）；DetailByName `/weapi/v1/w/user/info/detail`（以实际为准）；FollowEachOther 两次请求判断。
- `internal/service/user.go`（新文件）：UserService，每个方法恒一行。
- model 复用：`MapResponse` 调 `model.MapUser` / `model.MapPlaylist` 组装。用户歌单的 `MapResponse` 调 `model.MapPlaylists`。
- 缓存：Detail/SubCount/Playlist `CachePolicy` TTL 24h（用户资料低频变化）；Account `CachePolicy=nil`（账号信息敏感，且需登录态，不缓存）；DetailByName/FollowEachOther TTL 24h。

用户歌单列表 proto 响应带完整列表，请求的 `playlist_filter`（ALL/CREATED/SUBSCRIBED）在 `MapResponse` 内按 `userId==creator.userId` 过滤。
