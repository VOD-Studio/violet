## What to build

在 `PlaylistService` 上扩展歌单写操作接口：收藏/取消、新建、删除、更新元信息、添加/删除歌曲、歌单排序、歌曲排序。

写操作与 0005 的浏览类（读）严格区分。全部 `CachePolicy=nil`（写操作不缓存），`Meta.Auth=AuthLoggedIn`。

proto `PlaylistService` 加 rpc：

- **Subscribe**（收藏/取消，toggle）：`SubscribeRequest{playlist_id}`，响应 `{code, subscribed}`。网易云 `/weapi/playlist/subscribe`。
- **Create**（新建）：`CreateRequest{name, privacy}`，响应 `Playlist`。网易云 `/weapi/playlist/create`。
- **Delete**：`DeleteRequest{playlist_id}`。网易云 `/weapi/playlist/delete`。
- **UpdateName** / **UpdateDesc** / **UpdateTags**：各自 `UpdateXxxRequest{playlist_id, value}`。网易云 `/weapi/playlist/update/name|desc|tags`。
- **UpdateTracks**（添加/删除歌曲）：`UpdateTracksRequest{playlist_id, op, track_ids}`（op=add/del）。网易云 `/weapi/playlist/manipulate/tracks`。
- **UpdateOrder**（歌单排序）：`UpdateOrderRequest{ids}`。网易云对应端点。
- **UpdateSongOrder**（歌单内歌曲排序）：`UpdateSongOrderRequest{playlist_id, song_ids, ...}`。网易云对应端点。

写成功后不主动失效缓存（cache 在 Execute 内，endpoint 无法回填失效逻辑）——读类接口 24h TTL 自然过期即可。

`MapResponse` 多数写操作的网易云返回简单（`{code:200, ...}`），不涉及 model map 函数，直接读 code 判断成败。Create 返回的歌单调 `model.MapPlaylist` 复用。
