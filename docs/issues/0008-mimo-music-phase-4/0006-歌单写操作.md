# Issue-0006：歌单写操作（收藏/新建/删除/更新/排序）

## Parent

PRD：`../../prd/0008-mimo-music-phase-4.md`（user stories 31-37；Implementation Decisions - 歌单管理）

## What to build

扩展 Playlist 能力域，补充歌单写操作接口：收藏/取消收藏、新建、删除、更新元信息、添加/删除歌曲、歌单排序、歌曲排序。

写操作与 0005 的浏览类（读）区分。在 `provider.Playlist` 接口新增方法：`Subscribe(ctx, playlistID, cookie)`（收藏/取消，toggle）/ `Create(ctx, name, cookie)`（新建）/ `Delete(ctx, playlistID, cookie)`（删除）/ `UpdateName(ctx, playlistID, name, cookie)` / `UpdateDesc(ctx, playlistID, desc, cookie)` / `UpdateTags(ctx, playlistID, tags, cookie)` / `UpdateTracks(ctx, playlistID, op, trackIDs, cookie)`（添加或删除歌曲，op 区分 add/del）/ `UpdateOrder(ctx, ids, cookie)`（歌单排序）/ `UpdateSongOrder(ctx, playlistID, songIDs, cookie)`（歌单内歌曲排序）。

netease 实现：均走 weapi 端点（Subscribe `/weapi/playlist/subscribe`；Create `/weapi/playlist/create`；Delete `/weapi/playlist/delete`；UpdateName/Desc/Tags 走 `/weapi/playlist/update/*`；UpdateTracks 走 `/weapi/playlist/manipulate/tracks`；排序走对应端点）。

service 层：写操作不做缓存，直接透传 provider。全部需登录态走 cookie 轮换。写成功后使相关缓存失效（如收藏歌单后刷新用户歌单缓存）。

HTTP 端点：POST /api/v1/playlists/{id}/subscribe、POST /api/v1/playlists、DELETE /api/v1/playlists/{id}、PATCH /api/v1/playlists/{id}、POST /api/v1/playlists/{id}/tracks。

SDK 同步增加。写操作的 SDK 方法接收 cookie 参数（对齐 auth/recommend/fm 的模式）或由服务端自动轮换。

## Acceptance criteria

- [ ] Playlist 子接口新增 Subscribe / Create / Delete / UpdateName / UpdateDesc / UpdateTags / UpdateTracks / UpdateOrder / UpdateSongOrder 九个方法
- [ ] `provider/netease/playlist_extra.go` 实现九个方法
- [ ] service 层不做缓存，全部走 cookie 轮换
- [ ] 写成功后相关缓存失效（用户歌单、歌单详情等）
- [ ] HTTP 端点注册（写操作用 POST/DELETE/PATCH）
- [ ] SDK 九个方法 + DTO
- [ ] service 层 mock 测试：cookie 轮换、缓存失效
- [ ] netease 测试（请求参数构造正确性）
- [ ] 所有导出符号有 godoc 注释
