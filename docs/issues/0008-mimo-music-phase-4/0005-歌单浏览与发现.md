# Issue-0005：歌单浏览与发现

## Parent

PRD：`../../prd/0008-mimo-music-phase-4.md`（user stories 25-30；Implementation Decisions - 歌单管理）

## What to build

扩展 Playlist 能力域，补充歌单浏览类（读）接口：精品歌单、精品歌单标签、歌单分类、网友精选碟（热门歌单）、歌单收藏者列表、歌单全量歌曲分页。

在现有 `provider.Playlist` 接口（只有 Detail）上新增方法：`HighQuality(ctx, limit, offset, cat)`（精品歌单，可按标签）/ `HighQualityTags(ctx)`（精品歌单标签）/ `CatList(ctx)`（歌单分类列表）/ `Hot(ctx, cat, order, limit, offset)`（网友精选碟/热门歌单，可按分类和排序）/ `Subscribers(ctx, playlistID, limit, offset)`（收藏者列表）/ `AllTracks(ctx, playlistID, limit, offset)`（全量歌曲分页，区别于 Detail 的一次性返回）。

netease 实现：HighQuality 走 `/weapi/playlist/highquality/list`；HighQualityTags 走 `/weapi/playlist/highquality/tags`；CatList 走 `/weapi/playlist/catalogue`；Hot 走 `/weapi/playlist/list`；Subscribers 走 `/weapi/playlist/subscribers`；AllTracks 走 `/weapi/v6/playlist/detail` 的分页变体或 `/weapi/playlist/track/all`。

service 层全部做缓存（24h，歌单浏览低频变化）。

HTTP 端点：GET /api/v1/playlists/highquality、/highquality/tags、/categories、/hot、/{id}/subscribers、/{id}/tracks。

SDK 同步增加。

## Acceptance criteria

- [ ] Playlist 子接口新增 HighQuality / HighQualityTags / CatList / Hot / Subscribers / AllTracks 六个方法
- [ ] 各方法有对应 Result 类型，分页接口带 Total 字段
- [ ] `provider/netease/playlist_extra.go`（或 playlist.go 扩展）实现六个方法
- [ ] service 层缓存（24h）
- [ ] 六个 HTTP 端点注册到 router
- [ ] SDK 六个方法 + DTO
- [ ] service 层 mock 测试：缓存命中/未命中
- [ ] netease converter 测试
- [ ] 所有导出符号有 godoc 注释
