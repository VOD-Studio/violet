# Issue-0003：用户模块骨架与核心查询

## Parent

PRD：`../../prd/0008-mimo-music-phase-4.md`（user stories 12-16, 23-24；Implementation Decisions - 用户模块）

## What to build

新增 `User` 能力域（provider 子接口），落地用户模块的骨架与核心查询接口：账号信息、用户详情、数量统计、用户歌单列表。

这是 Phase 4 最关键的新能力域——用户是网易云中心实体，歌单管理（0005）依赖用户歌单列表。

改动链路：

- `provider/provider.go`：新增 `User` 子接口 + `Client.User() User` accessor。User 接口首批方法：`Account(ctx, cookie)`（账号信息，需登录）/ `Detail(ctx, userID)` / `SubCount(ctx, userID)`（歌单/收藏/mv/dj 数量统计）/ `Playlist(ctx, userID, limit, offset)`（用户歌单列表）。各方法定义对应 Result 类型（UserResult / UserSubCountResult / UserPlaylistResult）。
- `provider/netease/user.go`（新文件）：实现 User 子接口。Account 走 `/weapi/w/nuser/account/get`（需 cookie）；Detail 走 `/weapi/v3/user/detail`；SubCount 走 `/weapi/user/subcount`；Playlist 走 `/weapi/user/playlist`。
- `service/user.go`（新文件）：UserService 编排。Detail/SubCount/Playlist 做缓存（24h，用户资料低频变化）；Account 需登录态走 cookie 轮换。
- `internal/server/handler/user.go`（新文件）：HTTP 端点。
- `internal/server/router.go`：注册用户路由。
- `internal/bootstrap/wire*.go`：新增 UserService 的 wire provider。
- `pkg/mimomusic/user.go` + `types.go`：SDK 方法 + DTO。
- 用户歌单列表内部可区分创建/收藏（按 `userId == creator.userId`），但本切片先返回完整列表，创建/收藏的过滤留到 service 层可选参数。

## Acceptance criteria

- [ ] `provider/provider.go` 新增 `User` 子接口，含 Account / Detail / SubCount / Playlist 四个方法
- [ ] `Client` 新增 `User() User` accessor，编译期断言 `var _ provider.Provider = (*Client)(nil)` 通过
- [ ] 各方法有对应 Result 类型（UserResult / UserSubCountResult / UserPlaylistResult）
- [ ] `provider/netease/user.go` 实现四个方法，正确解析网易云返回结构
- [ ] `service/user.go` UserService：Detail/SubCount/Playlist 缓存（24h），Account 走 cookie 轮换
- [ ] wire 装配 UserService，`make wire` 生成成功
- [ ] HTTP 端点：GET /api/v1/user/account（需登录）、GET /api/v1/users/{id}、GET /api/v1/users/{id}/subcount、GET /api/v1/users/{id}/playlists
- [ ] SDK 四个方法 + DTO
- [ ] service 层 mock 测试：缓存命中/未命中、cookie 轮换
- [ ] netease converter 测试
- [ ] 所有导出符号有 godoc 注释

## Blocked by

无 —— 用户模块是歌单管理（0005）的前置依赖，应优先实现。
