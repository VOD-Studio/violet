# Issue-0001：搜索 type 多类型扩展

## Parent

PRD：`../../prd/0008-mimo-music-phase-4.md`（user stories 1-7；Implementation Decisions - 搜索 type 扩展）

## What to build

扩展现有搜索能力，支持网易云的 9 种搜索类型（type 参数），不只搜单曲。当前 `provider/netease/services.go` 的 `Search` 硬编码了 `params.Set("type", "1")`，只搜单曲。

改动链路：

- `provider/provider.go`：`Search` 接口的 `Search` 方法签名增加 `searchType int` 参数；定义 type 常量（`SearchTypeSong=1` / `SearchTypeAlbum=10` / `SearchTypeArtist=100` / `SearchTypePlaylist=1000` / `SearchTypeUser=1002` / `SearchTypeMV=1004` / `SearchTypeLyric=1006` / `SearchTypeDJ=1009` / `SearchTypeVideo=1014` / `SearchTypeAll=1018`）。`SearchResult` 扩展为联合结构，容纳各类型结果（Albums / Artists / Playlists / Users / MVs / Videos 等 slice，按 type 填充对应字段）。
- `provider/netease/services.go`：`Search` 透传 searchType 到上游 `type` 参数；按 type 解析不同的网易云返回结构，转成扩展后的 `SearchResult`。不同 type 的上游返回字段差异较大（搜专辑返回 album 数组、搜歌手返回 artist 数组等），converter 逻辑按 type 分支。
- `service/search.go`：`Search` 方法签名加 searchType，缓存 key 加 type 维度（`search:{type}:{keyword}:{limit}`），避免不同 type 缓存串。
- `internal/server/handler/search.go`：读 query 的 `type` 参数（默认 1 单曲），透传 service。
- `pkg/mimomusic/search.go` + `types.go`：SDK 的 `Search` 增加 `WithType(t int)` option，`SearchResult` 扩展联合字段。

这是 Phase 4 的入口切片——搜索是核心能力，且改动集中在现有链路，风险低。

## Acceptance criteria

- [ ] `provider.Search` 的 `Search` 方法接收 `searchType int` 参数
- [ ] provider 包定义全部 10 个 SearchType 常量（单曲/专辑/歌手/歌单/用户/MV/歌词/主播/视频/综合）
- [ ] `SearchResult` 支持返回各类型结果（不止 Songs），不同 type 填充对应字段
- [ ] netease 实现透传 type 到上游，按 type 正确解析不同返回结构
- [ ] service 缓存 key 包含 type 维度，不同 type 不串缓存
- [ ] handler 读取 query `type` 参数，默认单曲（type=1）
- [ ] SDK `Search` 支持 `WithType` option
- [ ] service 层 mock 测试：不同 type 缓存隔离、provider 被正确调用
- [ ] netease converter 测试：各 type 的结构转换正确
- [ ] 所有导出符号有 godoc 注释

## Blocked by

无 —— 搜索扩展现有链路，是 Phase 4 入口。
