# Issue-0001：搜索 type 多类型扩展

## Status: ✅ 已完成（commit `0d50b680`）

## Parent

PRD：`../../prd/0008-mimo-music-phase-4.md`（user stories 1-7；Implementation Decisions - 搜索 type 扩展）
前置：地基阶段完成（SearchService 已迁移到新架构，搜索单曲 type=1 可用）

## What to build

扩展现有搜索能力，支持网易云的 9 种搜索类型（type 参数），不只搜单曲。当前地基阶段迁移的搜索只支持 type=1 单曲。

改动链路（新架构，非旧四层）：

- `proto/netease/music/v1/search.proto`：`SearchRequest` 加 `SearchType type` 字段，定义 enum（`SEARCH_TYPE_SONG=1` / `ALBUM=10` / `ARTIST=100` / `PLAYLIST=1000` / `USER=1002` / `MV=1004` / `LYRIC=1006` / `DJ=1009` / `VIDEO=1014` / `ALL=1018`）。`SearchResponse` 扩为联合 message，各类型独立字段（`repeated Song songs` / `repeated Album albums` / `repeated Artist artists` / `repeated Playlist playlists` / `repeated User users` / `repeated MV mvs` / `repeated Video videos` 等），按 type 填充对应字段。
- `internal/netease/endpoint/search/search.go`：现有 Search endpoint 声明的 `MapRequest` 透传 type 到上游 `type` 参数；`MapResponse` 按 type 分支调对应 model map 函数（搜歌手 `model.MapArtists`，搜专辑 `model.MapAlbums`，搜歌单 `model.MapPlaylists`，搜单曲 `model.MapSongs`）。
- cache key 加 type 维度（`search:{type}:{keyword}:{limit}`），避免不同 type 串缓存。`CachePolicy.Key` 从 req 取 type+keyword+limit 算 key。
- `internal/service/search.go`：service 方法签名随 proto 变化更新，仍恒一行 `return engine.Execute(...)`。

MV/Video 实体本期在 proto 里定义最小 message（歌手扩展 issue 0007 会充实），搜索返回的 MV/Video 只取核心字段（id/name/封面）。

这是 Phase 4 的入口切片——搜索是核心能力，且改动集中在现有 endpoint 链路，风险低。

## Acceptance criteria

- [ ] `proto search.proto` 的 `SearchRequest` 含 `SearchType type` enum 字段，定义全部 10 个枚举值
- [ ] `SearchResponse` 是联合 message，各类型独立 repeated 字段
- [ ] endpoint 声明的 `MapRequest` 透传 type 到网易云上游 `type` 参数
- [ ] `MapResponse` 按 type 分支正确解析不同返回结构，调对应 model map 函数
- [ ] `CachePolicy.Key` 含 type 维度，不同 type 不串缓存
- [ ] service 方法恒一行，无独立逻辑
- [ ] endpoint 的 `MapRequest` / `MapResponse` 纯函数测试：各 type 的网易云 JSON fixture → proto 响应字段正确
- [ ] engine 集成测试：不同 type 缓存隔离
- [ ] `make proto`（buf generate）生成 Go stub + Rust stub + OpenAPI 成功
- [ ] 所有导出符号有 godoc / proto 注释

## Blocked by

无 —— 搜索扩展现有链路，是 Phase 4 入口。前置是地基阶段完成。
