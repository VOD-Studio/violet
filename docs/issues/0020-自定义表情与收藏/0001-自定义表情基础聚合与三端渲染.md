# Issue-0001：自定义表情基础聚合、自助上传与三端渲染

## Parent

PRD-0020（`../../prd/0020-自定义表情与收藏.md`）

## What to build

新增独立于 `domain/emoji` 的自定义表情能力地基：用户能在评论/推文/聊天任一处上传属于自己的表情、在自己的表情选择器里选用发送，任何人（不限收藏与否）都能在这三处看到渲染出的图。删除自己的表情后，历史内容里的引用降级为占位文本。管理员能在后台调整单用户表情份额上限。

本 issue 不包含收藏（右键菜单在 Issue-0002）、不包含管理员对他人表情的强制下架（Issue-0003）——`DELETE` 目前只放开 `actor == owner`。

## Acceptance criteria

### 领域模型（domain/customemoji）

- [ ] `entity.go`：`CustomEmoji` 聚合根，字段 id（UUID）/ownerID/name/url/createdAt/deletedAt
- [ ] 创建校验：`name` trim 后非空；同一 `ownerID` 下 `name` 唯一，跨 owner 允许重名（不做全局唯一校验）
- [ ] 无 `Update` 方法；软删除（`deletedAt`）后视为不可选用
- [ ] `entity_test.go`：覆盖上述创建校验与软删除后的可用性判定

### 数据库（migration 092、093）

- [ ] 092：`custom_emojis(id uuid pk, owner_id uuid ref users on delete cascade, name varchar(50) not null, url varchar(512) not null, created_at, deleted_at)`，唯一索引 `(owner_id, name) where deleted_at is null`
- [ ] 093：`custom_emoji_favorites(user_id uuid ref users on delete cascade, emoji_id uuid ref custom_emojis on delete cascade, created_at, primary key(user_id, emoji_id))`——本 issue 只建表，收藏读写逻辑留给 Issue-0002，但表结构在此一并建好避免 Issue-0002 再开迁移链
- [ ] 对应 `.down.sql`

### 应用层与共享 resolver（application/customemoji）

- [ ] `Service`：`Create`（校验份额 + 同 owner 唯一名 + 复用现有 `/uploads/emoji` 产出的 URL）、`Delete`（仅 `actor == owner`）、`ListMine`（owned；favorited 分支本 issue 恒空）
- [ ] `ResolveByIDs(ctx, ids, viewerID) map[uuid]CustomEmojiRef`：本 issue 只实现 `owned`/`none` 两态（`favorited` 留 Issue-0002），下架/不存在的 ID 返回未命中而非报错
- [ ] 份额校验：读 `site_settings.custom_emoji_max_per_user`，0（未配置）时 fallback env `CUSTOM_EMOJI_MAX_PER_USER`（默认 100），按当前 owned 数量（favorited 恒 0）与上限比较
- [ ] 单测覆盖：超份额拒绝、同 owner 重名拒绝、跨 owner 同名允许、下架后 `ResolveByIDs` 未命中

### API（interfaces/http，均挂 SessionAuth）

- [ ] `POST /custom-emojis`：body `{name, url}`
- [ ] `GET /custom-emojis/mine`：返回 `{owned: [], favorited: []}`（favorited 本 issue 恒空数组）
- [ ] `DELETE /custom-emojis/{id}`：仅 `actor == owner`，否则 403
- [ ] handler 集成测试覆盖以上三个端点的成功/校验失败路径

### 表情解析接线（comment / tweet / chat 三域）

- [ ] `comment_container.go` 的 `emojiLookupAdapter.FindByNames`、`tweet_container.go` 的 `tweetEmojiLookupAdapter.FindByNames`：新增分支——token 含 `:` 且冒号后段是合法 UUID 时委托给共享 resolver，否则走现状按名查找；两分支合并进同一个返回 map
- [ ] `domain/chat` message DTO / SSE `EventDTO` 新增 `CustomEmote map[string]CustomEmojiRefDTO` 字段，由 `chat.Service` 在 `toDTO`/`notifyEvents` 路径解析正文中的 `[name:uuid]` token 后填充
- [ ] 回归测试：正文只含系统表情 `[name]` 时，`Emote`/渲染结果与改动前完全一致（零回归）
- [ ] 新增测试：正文含 `[name:uuid]` 且该 ID 是 viewer 自己的表情时，解析结果 `relation=owned`；ID 不存在/已下架时该 token 不命中（前端按占位文本兜底）

### 前端：EmojiPicker 与表情插入

- [ ] `EmojiPicker` 新增内部数据源：登录态下额外请求 `GET /custom-emojis/mine`，渲染"我的表情" tab（owned 分组 + 上传按钮 + 简单删除；favorited 分组本 issue 恒空，不展示"收藏来的"子分组）；未登录不显示该 tab
- [ ] 上传走"选文件 → `POST /uploads/emoji` → 拿到 URL → `POST /custom-emojis`"两步，复用现有 10MB + jpg/png/gif/webp 校验，不新增上传端点
- [ ] `Emoji` 前端读模型新增可选字段 `custom_emoji_id?: string`（本 issue 暂不需要 `relation`，Issue-0002 补）
- [ ] `useRichTextInput.insertEmoji`（评论/聊天输入/推文回复共用）与 `TweetComposer.tsx` 的 `handleEmojiSelect`：`custom_emoji_id` 存在时插入 `` `[${name}:${custom_emoji_id}]` ``，否则维持现状 `` `[${name}]` ``
- [ ] `EmojiText.tsx`/`ChatMessageContent.tsx` 的 token 匹配正则不改动（验证现有 `/\[([^\]]+)\]/g` 天然兼容新 token 形态）
- [ ] 组件/hook 测试覆盖：选中自定义表情时插入新 token 形态、选中系统表情时行为不变

### 站点设置

- [ ] `domain/settings.SiteSettings` 新增 `CustomEmojiMaxPerUser int`（`json:"custom_emoji_max_per_user"`），`fromMap`/`UpdateInput`/`application/settings` 的 `GeneralView` 三处接线，方式对齐 `CommentsModeration`
- [ ] 后台设置页新增对应输入框（数字输入，和现有站点设置表单同一处）
- [ ] env 变量 `CUSTOM_EMOJI_MAX_PER_USER`（默认 100）接线到 fallback 分支
