# Issue-0006：B4 项目时间轴（复用 releases 数据）

## Parent

PRD-0009（`../../prd/0009-about-redesign.md`）

## What to build

实现 B4 项目时间轴区块：把更新日志（releases 数据）嵌进"建站 → 里程碑 → 各版本发布"的叙事时间轴，而非孤立的版本列表。

与 B3 的区别：B3 是"按版本平铺的更新日志列表"；B4 是"把版本节点编织进一条更长的项目历程叙事线"——可能混入手工里程碑（如"v1.0 首次上线""重构为 DDD"等非 release-please 生成的事件），形成完整的项目自述。

端到端切片：复用 Issue-0005 的 releases 数据 → 可选手工里程碑设置项（settings 新增）→ 前台项目时间轴区块（按时间合并 releases + 里程碑，叙事渲染）。

## Acceptance criteria

### 后端（settings，可选）
- [ ] 若支持手工里程碑：settings 新增里程碑数据（如 `project_milestones` JSON 数组：`[{date, title, description, link}]`）加入链路
- [ ] 里程碑数据走 `GetPublic` 白名单公开

### 前台区块（features/about/ui）
- [ ] 项目时间轴区块：按时间倒序/正序合并 releases 节点 + 手工里程碑节点
- [ ] releases 节点复用 Issue-0005 的数据源（`useReleases`）
- [ ] 时间轴视觉化（垂直时间线 + 节点卡片，区分版本发布 vs 里程碑两类节点）
- [ ] 空数据（无 releases 且无里程碑）时优雅降级

### 测试（Seam 1 延续）
- [ ] 时间轴正确合并两类节点并按时间排序
- [ ] releases 与里程碑混合渲染时类型区分正确

### 验收
- [ ] 前台项目时间轴区块正确展示叙事线
- [ ] `make web-typecheck` / `make web-test` / lint 全绿
