# T2 [tweet] 推文接入：images 尺寸链路与 DTO 内嵌卡片

前置：T1（linkpreview 应用服务与 migration 就位）。

## 目标

推文聚合根 `images` 从 `[]string` 升级为 `[]ImageRef{url,width,height}`；创建/列表/详情链路补尺寸；推文 DTO 内嵌 `link_cards` 并触发惰性刷新；发布后异步登记正文 URL。

## 改动点

- `api/internal/domain/tweet/entity.go`：`images []ImageRef`，不变量沿用（≤4、url 非空、宽高可空）；`ReconstructTweet` 签名同步。
- `application/tweet/service.go`：创建时按 URL 从 uploads 补尺寸（并入现有归属校验查询）；DTO 组装批量查 link_cards（URL 提取用与前端同规则的 Go 版 tokenizer，共享规则常量），miss/过期触发后台抓取不阻塞响应；事务提交后异步登记 URL。
- `infrastructure/persistence/gorm/tweet_repo.go` + model：images JSONB 映射。
- migration `144`：`tweets.images` 数组 → JSONB 对象数组，按 `uploads.url` 回填宽高，关联不上置 null；down 逆转换。
- handler/OpenAPI：`images: [{url,width,height}]`、可空 `link_cards`。
- 前端 `web/src/entities/tweet/model/types.ts` 与 API 层类型同步（本 ticket 仅类型对齐，渲染改造在 T3/T5）。

## 验收

- migration up/down/up 往返：现有推文图片宽高正确回填，无 uploads 记录的置 null。
- 聚合根/应用层单测：创建补尺寸、缺 uploads 记录宽高为 null、非空与上限不变量不变。
- 集成测试：发布含链接推文后 DTO 带 link_cards（夹具卡片），同 URL 复用。
- 既有推文测试全部适配通过；`make api-test`、`web-typecheck` 全绿。
