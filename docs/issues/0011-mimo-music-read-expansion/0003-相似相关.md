# Issue-0003：相似/相关（按返回实体归属各 service）

## Parent

PRD：`../../prd/0011-mimo-music-read-expansion.md`（user stories 22-26；Implementation Decisions）
前置：地基阶段完成（SongService/PlaylistService/UserService 已存在）

## What to build

5 个相似/相关接口，**按返回实体归属各 service**（不建 SimilarService）。排除相似 MV（#33，归 MV/视频 Context）。

5 个接口的归属：

- 相似歌单（#32，传 songId → `repeated Playlist`）→ PlaylistService，rpc 名 `SimilarPlaylists`
- 相似音乐（#34，传 songId → `repeated Song`）→ SongService，rpc 名 `SimilarSongs`
- 听歌的人（#35，传 songId → `repeated User`）→ UserService，rpc 名 `SimilarUsers`
- 相关歌单（#74，传 playlistId → `repeated Playlist`）→ PlaylistService，rpc 名 `RelatedPlaylists`
- 相关歌单推荐（#305，传 playlistId → `repeated Playlist`）→ PlaylistService，rpc 名 `RelatedPlaylistRecommend`

4 个独立 rpc（PlaylistService 3 个、SongService 1 个、UserService 1 个）。`MapResponse` 各调对应 model map 函数（MapPlaylists/MapSongs/MapUsers）。全部读类，AuthAnonymous，TTL 24h。

rpc 名带 Similar/Related 前缀表达业务语义，service 归属按返回实体（和 Phase 4 的 ArtistService.Similar 一致）。

## 实现备注

- **范围调整（5 → 4 接口）**：原 #74「相关歌单」（`/related/playlist`，HTML 抓取）网易云官方文档已标注**废弃失效**（"现已无法抓取歌单"），推荐改用 #305「相关歌单推荐」。故不实现 #74，实现其替代 #305 RelatedPlaylistRecommend（`/api/playlist/detail/rcmd/get`，eapi）。
- **rpc 命名**：#305 用 `RelatedPlaylistRecommend`（非 `RelatedPlaylists`），与上游「推荐」语义一致，避免与废弃的 #74 混淆。
- **#305 走 eapi**：`/api/playlist/detail/rcmd/get` 默认 crypto=eapi（依赖 Step 0 的 eapi engine 修复）。
- **SimilarSongs 字段名差异**：相似音乐接口返回 `artists`/`album`/`duration` 全名（非 rawSong 的 `ar`/`al`/`dt` 缩写），故本地定义 rawSimilarSong + toProto，不复用 model.MapSong。
