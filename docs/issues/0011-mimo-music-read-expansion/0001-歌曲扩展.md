# Issue-0001：歌曲扩展（深化 SongService）

## Parent

PRD：`../../prd/0011-mimo-music-read-expansion.md`（user stories 1-14；Implementation Decisions）
前置：地基阶段完成（SongService 已存在）、cookie 重构完成（PRD 0010）

## What to build

在 `SongService` 上扩展歌曲深化能力：喜欢音乐、垃圾桶、不感兴趣（写）、逐字歌词（独立 rpc）、可用检查、喜欢列表、本地匹配、音质详情、红心数量、是否喜爱、动态封面、副歌时间、创作者信息（读）。

改动链路（Phase 4 模式）：

- `proto song.proto`：SongService 加 rpc——Like（喜欢/取消 toggle）、Trash（垃圾桶）、DisallowRecommend（不感兴趣）、CheckAvailable、LikedList、MatchLocal、QualityDetail、LikeCount、IsLike、DynamicCover、ChorusTime、CreatorInfo、GetWordLyric。逐字歌词新建 `WordLyric` message（结构化时间戳：repeated WordLyricLine，每行含开始时间 + repeated WordLyricWord，每字含开始/持续时长）。
- `internal/netease/endpoint/song/`：每接口一个 endpoint 声明。写类（Like/Trash/DisallowRecommend）`Cache=nil`、`Auth=AuthLoggedIn`；读类按性质定 TTL（可用检查/音质 24h、红心数量/是否喜爱 10min）。
- `internal/service/song.go`：读类恒一行 `Execute`，写类恒一行 `executeOverride`（cookie 在 context）。
- model 复用：`MapResponse` 调 `model.MapSong` 等。逐字歌词新建 `model.DecodeWordLyric` 解析 yrc 格式。

## Acceptance criteria

- [ ] `proto song.proto` 的 SongService 加 rpc + message（含 WordLyric 结构化时间戳 message）
- [ ] 13 个 endpoint 声明，写类 Cache=nil+AuthLoggedIn，读类按性质 TTL
- [ ] 逐字歌词 GetWordLyric 独立 rpc + WordLyric message（不合并进 GetLyric）
- [ ] service 13 个方法，读类 Execute 一行/写类 executeOverride 一行
- [ ] endpoint MapRequest/MapResponse 纯函数测试（song_test.go，含逐字歌词 yrc fixture 解析）
- [ ] `make proto` 生成成功
- [ ] 所有导出符号有 godoc / proto 注释
