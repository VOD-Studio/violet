# Issue-0001：歌曲扩展（深化 SongService）

## Parent

PRD：`../../prd/0011-mimo-music-read-expansion.md`（user stories 1-14；Implementation Decisions）
前置：地基阶段完成（SongService 已存在）、cookie 重构完成（PRD 0010）

## What to build

在 `SongService` 上扩展歌曲深化能力：喜欢音乐、垃圾桶、不感兴趣（写）、逐字歌词（独立 rpc）、可用检查、喜欢列表、音质详情、红心数量、是否喜爱、动态封面、副歌时间、创作者信息（读）。

> **范围调整**：原列 13 个接口中的「本地匹配」（MatchLocal / #273）已剔除——网易云私有音频指纹（rawdata）算法无公开源，实现一个无法构造合法指纹的接口无交付价值。实际实现 12 个。

改动链路（Phase 4 模式）：

- `proto song.proto`：SongService 加 rpc——Like（喜欢/取消 toggle）、Trash（垃圾桶）、DisallowRecommend（不感兴趣）、CheckAvailable、LikedList、QualityDetail、LikeCount、IsLike、DynamicCover、ChorusTime、CreatorInfo、GetWordLyric。逐字歌词新建 `WordLyric` message（结构化时间戳：repeated WordLyricLine，每行含开始时间 + repeated WordLyricWord，每字含开始/持续时长）。
- `internal/netease/endpoint/song/`：每接口一个 endpoint 声明。写类（Like/Trash/DisallowRecommend）`Cache=nil`、`Auth=AuthLoggedIn`；读类按性质定 TTL（可用检查 1h、音质/封面/副歌/创作者 24h、红心数量/是否喜爱 10min）。
- `internal/service/song.go`：读类恒一行 `Execute`，写类恒一行 `executeOverride`（cookie 在 context）。
- model 复用：`MapResponse` 调 `model.MapSong` 等。逐字歌词新建 `model.DecodeWordLyric` 解析 yrc 格式（行头 `[startMs,durMs]` + 逐字 token `(startMs,durMs,0)text`）。
- **前置 engine 修复**（独立 commit `ff05cd63`）：eapi 加密从 AES-CBC 改 AES-ECB + digest path `/eapi/`→`/api/` 转换。本 issue 8 个 eapi 接口依赖此修复。
