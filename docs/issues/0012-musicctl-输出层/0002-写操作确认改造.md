# Issue-0002:写操作确认改造(--yes 直通 + 非 TTY 报错)

## Parent

PRD:`../../prd/0012-musicctl-输出层.md`(user stories 6,7)

## What to build

写操作确认交互适配脚本场景,11 个写命令全部接入。

- `ConfirmWrite` 签名改为 `(确认 bool, 错误 error)`:
  - `--yes` → 直通返回 true
  - stdin 非 TTY 且无 `--yes` → 返回用法错误(退出码 2),提示加 `--yes`
  - TTY → 保持 y/N 提示,取消返回 false(打印「已取消」,退出码 0)
- 接入命令:song like/trash/disallow-recommend、album subscribe/unsubscribe、artist subscribe、playlist subscribe/create/delete/update-name/update-desc/update-tags/update-tracks(共 15 个 case)
- 「已删除/已更新」等动作确认消息保持 stdout(git/kubectl 惯例)

## Acceptance criteria

- [ ] ConfirmWrite 四态单测:yes 直通/非 TTY 报错/TTY 取消/TTY 确认
- [ ] `song like --id 1 --yes` 无交互完成(真实会话真机验证,或 ConfirmWrite 替身)
- [ ] 非 TTY 写操作无 `--yes` 报退出码 2
- [ ] TTY 交互确认行为与现状一致
- [ ] 全部写命令编译通过,无遗漏旧签名调用

- Issue-0001(需要 kit 全局 Yes 状态与退出码体系)
