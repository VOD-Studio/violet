# Issue-0001：渲染核心与安全防线（tracer bullet）

## Parent

PRD：`../../prd/0005-图块流程图.md`

## What to build

图块功能的地基切片，不依赖任何编辑器/阅读端改动。封装两个纯函数：(1) `renderMermaid(source, theme)` —— 动态加载 mermaid、`securityLevel: strict` 初始化、单图渲染、**返回经 DOMPurify 二次清理的 SVG 字符串**；(2) `getThemeVariables(isDark)` —— 把站点 CSS 变量（oklch）映射成 mermaid `themeVariables`（hex），框架对齐站点明暗但节点填色保留 mermaid 默认彩色。

这是安全命门：mermaid 支持 per-diagram `%%{init}%%` 指令覆盖全局 strict（docmost CVE-2026-23630 的攻击路径），第一道 strict 挡常规注入，第二道 DOMPurify 兜底剥 `on*`/`<script>`/foreignObject 可执行内容。必须有单测覆盖 XSS payload 被清理。

## Acceptance criteria

- [ ] 新增 `web/src/shared/ui/diagram/` 目录
- [ ] `renderMermaid(source, theme): Promise<{ svg: string } | { error: string }>` 纯函数：动态 `import('mermaid')` → `mermaid.initialize({ startOnLoad: false, securityLevel: 'strict', theme: 'base', themeVariables })` → `mermaid.render(id, source)` → DOMPurify 二次清理（`USE_PROFILES: { svg: true, svgFilters: true }`，剥 `on*` 事件属性、`<script>`、foreignObject 内可执行内容）

## 实现指引

- mermaid v11+ 用 `mermaid.render(id, source)` 返回 `Promise<{ svg }>`，不用 `mermaid.run()`（那是静态站批量扫描）
- DOMPurify 已是 mermaid 的传递依赖，但仍建议显式 `pnpm add dompurify` + `@types/dompurify`，避免依赖 mermaid 内部
- mermaid themeVariables 只认 hex（官方 theming 文档），oklch→hex 转换可用浏览器原生 `CSS.supports` + 临时 canvas/element getComputedStyle 拿 computed color 再转 hex
- 参考 `web/src/shared/ui/katex/katex-core.ts` 的「单一职责纯函数模块」形态，以及 `__tests__/katex-core.test.ts` 的纯函数单测先例
