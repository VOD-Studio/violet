# Issue-0004：弹层编辑交互（tracer bullet）

## Parent

PRD：`../../prd/0005-图块流程图.md`

## What to build

为 diagramBlock 节点接入弹层编辑（ADR-0005 模型）：文档内显示渲染结果，点击选中弹出跟随浮层（等宽 textarea 源码输入 + 实时预览 + 删除按钮）。最大化复用数学公式已验证的浮层基础设施（`@floating-ui/dom` absolute 策略 + portal 进编辑器滚动容器 + Esc/外部点击关闭契约），只是面板内容从 LaTeX 换成 mermaid 源、预览核心从 KaTeX 换成 `renderMermaid`。

## Acceptance criteria

- [ ] 新增 `DiagramPopoverView` 组件（参照 `web/src/features/editor/ui/MathPopoverView.tsx` 结构）：`NodeViewWrapper` 渲染渲染结果 + portal 浮层面板
- [ ] 文档内渲染：调 #1 的 `renderMermaid(source, theme)` 把 SVG 写入 `NodeViewWrapper`（与阅读端同渲染核心，保证所见即所得）
- [ ] 复用浮层定位机制（参照 `useFloatingMathPanel.ts`）：`@floating-ui/dom` `computePosition` absolute 策略 + `offset` + `flip({boundary: scrollContainer})` + `shift({padding:8})`，portal 渲染进编辑器滚动容器
- [ ] 面板内容：等宽 `<textarea>`（多行，rows 随源码行数自适应）源码输入 + 实时预览区（`renderMermaid` 实时调用，useMemo 缓存）+ 删除按钮
- [ ] 开闭契约：点击图块 → `setNodeSelection(pos)` → `selected` 上升 → `popoverOpen`；独立 `popoverOpen` state（不直接绑 Tiptap `selected` prop），`selected` 下降沿 rAF 延迟一帧确认 PM selection 确实不再选中此节点（跳过假 deselectNode 竞态）
- [ ] 关闭：Esc 或外部 pointerdown（panel/anchor 命中则不关）→ 关闭并把光标移到图块之后 `editor.commands.focus(pos + node.nodeSize)`
- [ ] 删除：走 `chain().setNodeSelection(pos).deleteSelection().focus()`（atom 节点被弹层抢焦点，Backspace 不可用，故显式按钮）
- [ ] source 更新：复用 `update-math-latex.ts` 同事务重建 NodeSelection 的 helper 模式（atom 节点 `setNodeMarkup` 会把 NodeSelection 降级为 TextSelection，必须 `tr.setSelection(NodeSelection.create(tr.doc, pos))` 规避）
- [ ] 编辑器 `extensions/index.ts` 把 diagramBlock 的 NodeView 接到 `DiagramPopoverView`（参照 `MathView.tsx` 的 `createMathExtensions()` 工厂）
- [ ] 静态 `import` mermaid CSS（若有）进该 chunk，随异步加载
- [ ] `make web-typecheck && make web-lint` 全绿
- [ ] 手动验证：点击图块 → 弹层弹出并跟随定位 → 改源码 → 预览实时更新 → 滚动编辑器浮层跟随 → Esc/外部点击关闭 → 删除按钮移除节点

## 实现指引

- 1:1 参照数学公式弹层实现：`MathPopoverView.tsx`（开闭/关闭/删除/Portal）、`useFloatingMathPanel.ts`（floating-ui 定位）、`MathEditPanel.tsx`（面板布局）、`update-math-latex.ts`（同事务更新 helper）
- 面板 textarea 参照 `LatexSourceField.tsx` 的多行模式（`rows = min(8, max(2, 行数))`），但**首期不做 mermaid 语法补全**（LatexSourceField 的补全链路不移植）
- mermaid 渲染异步（返回 Promise），预览区需 loading 态（KaTeX 是同步 `renderToString`，这是差异点）—— 预览可用 Suspense fallback 或局部 loading 指示
- 编辑器内渲染的 mermaid 也走 DOMPurify（与阅读端同防线），不因「作者自己写的」而豁免——作者可能粘贴外部 mermaid 源
