# Issue-0001：后端评论改为登录模式 + 提交者可见 pending

## Parent

PRD-0001（`docs/prd/0001-锚点批注评论.md`）

## What to build

把评论创建从「匿名访客填昵称+邮箱」改为「登录强制、作者信息取自会话用户记录」。同时让评论列表返回 `approved` 联合「当前会话用户自己的 `pending`」，使提交者能在审核通过前看到自己刚提交的评论（带「审批中」语境）。

端到端行为：
- 未登录 `POST /api/v1/posts/{postId}/comments` → 401。
- 已登录提交：`author_name` / `avatar_url` 从会话用户记录填充，请求体不再接收这些字段。
- `GET /api/v1/posts/{postId}/comments`：返回该文章所有 `approved` 评论，**外加**当前会话用户自己的 `pending` 评论（他人 `pending`/`spam`/`deleted` 仍不可见）。
- `CommentDTO` 新增 `status` 字段，让前端能渲染「审批中」徽章。
- 限流沿用 `CommentRateLimit`（3/min/IP），不变。

本 issue **不**做 anchor 字段（Issue-0003）、不做 pictures 接线（Issue-0003）、不碰前端 UI（Issue-0002）。

## Acceptance criteria

- [ ] `POST /comments` 路由挂上 Auth middleware；未登录返回 401。
- [ ] `CreateCommentRequest` 删除 `author_name` / `author_email` / `author_url` / `avatar_url` 字段；service 从会话上下文取 UserID，从用户记录拷贝 `author_name` / `avatar_url` 作为快照。
- [ ] `Comment.NewComment` 构造函数改为接受 `UserID`，校验非空。
- [ ] `application/comment` 仓储查询改为 `(status='approved' OR created_by=:viewer) AND post_id=:post`，service 接受 `viewerUserID` 参数。
- [ ] handler 注入 viewer：从请求上下文取会话 user_id（沿用现有 `middleware.GetUser` 范式），透传给 service。
- [ ] `CommentDTO` 序列化新增 `status` 字段；`is_author` 留给后续 issue，本期不做。
