# Issue-0001：后端评论双轨认证 + 匿名留言板模式 + 提交者可见 pending

## Parent

PRD-0001（`docs/prd/0001-锚点批注评论.md`）

## What to build

建立评论的**双轨认证 + 匿名留言板模式**：

- **登录用户**：作者信息从会话填充，无配额，提交后立即看到自己 pending 评论带「审批中」徽章，看得到所有 approved 评论，可回复/反应，可划线批注。
- **匿名用户（留言板模式）**：必须填昵称 + 邮箱 + **邮箱验证码**两步流提交；**黑洞可见性**（看不到任何评论，含自己刚提交的）；**一篇一次**配额（同一 `(ip_hash, normalized_email)` 在同一文章下仅一次）；匿名回复/反应失效（看不到对象，逻辑自洽）。

端到端行为：
- `POST /comments` 不带 `anchor` 时：登录用户直接提交；匿名用户需带 `code`（邮箱验证码），校验 + 配额。
- `POST /comments` 带 `anchor` 时：强制登录；未登录 401。
- 新增 `POST /posts/{postId}/comments/code { email }`：匿名发码接口（仅匿名需要）。
- `GET /posts/{postId}/comments`：匿名 viewer 返回**空数组**（黑洞）；登录 viewer 返回 approved ∪ 自己 pending。
- `CommentDTO` 新增 `status` 字段。

本 issue **不**做 anchor 字段本身（Issue-0003）、不做 pictures 接线（Issue-0003）、不碰前端 UI（Issue-0002）。

## Acceptance criteria

### 路由与认证
- [ ] `POST /comments` 路由**不**全局挂 Auth（保留匿名评论能力）；handler 内部按需校验：请求体含 `anchor` 非空对象 → 取会话 user_id，为空 → 401。
- [ ] 新增 `POST /posts/{postId}/comments/code` 路由（发码），挂 `CommentCodeRateLimit`（5/min/IP，防邮件轰炸，与提交限流隔离）。
- [ ] `POST /comments` 限流沿用 `CommentRateLimit`（3/min/IP），不变。

### 发码 command（复用现成基础设施）
- [ ] `application/comment/service.go` 新增 `SendCode(ctx, SendCodeInput{PostID, Email})`：
  - 复用 `appshared.CodeStore.Store(ctx, "comment", normalizedEmail, SHA256(code), TTL=10min)`（prefix=`"comment"` 与 auth 的 `"verify"`/`"reset"` 隔离）。
  - 复用 `infraemail.Sender.SendVerificationCode`（Resend 实现）；devMode 失败仅 warn 不阻塞（沿用 auth 模式）。
  - `generateVerificationCode` / `sha256Hash` 从 auth 包提到 `application/shared`（或在 comment 包复制，二者都很短），避免跨模块私有依赖。
- [ ] 邮件 `EmailSender` 接口在 comment 包重声明（Go 隐式接口，复用 Resend 实现，避免 import auth 包）。

### 提交校验链（匿名路径）
- [ ] `CreateInput` 新增 `Code string`（匿名必填）+ handler 填充的 `IPHash string`。
- [ ] handler `Create`：匿名态（无会话 user_id 且无 anchor）从请求体取 `code` + `author_email`，调 service。
- [ ] service `Create` 匿名分支：
  - `Email` 归一化（小写 + trim）。
  - `CodeStore.Verify(ctx, "comment", email, SHA256(code))` 失败 → `ErrInvalidCode`（一次性，Lua 原子，5 次错误锁定，沿用 auth）。
  - 通过 → per-post 配额：`repo.CountByPostAndAnon(postID, ipHash, email) >= 1` → `ErrAnonQuotaExceeded`。
  - 通过 → 落库 status=pending，填充 `ip_hash`。
- [ ] service `Create` 登录分支：跳过验证码、跳过配额，author_* 从会话填充。
- [ ] handler `Create`：**接线 `ip_hash`**（之前半成品，本期必做）—— 用 `middleware.GetClientIP(r)` + SHA256 填充 `IPHash`，传给 service。这是配额的硬依赖。

### 黑洞可见性

- [ ] handler 注入 viewer：从请求上下文取会话 user_id（可能为 nil 表示匿名）。
- [ ] **匿名 viewer（viewer=nil）→ service 直接返回空数组**（不查 DB），实现黑洞模式。
- [ ] `CommentDTO` 序列化新增 `status` 字段；`is_author` 留给后续 issue。
