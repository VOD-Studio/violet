# Issue-0008：管理员审核区分批注（标识 + 锚定原文摘录）

## Parent

PRD-0001（`docs/prd/0001-锚点批注评论.md`）

## What to build

增强管理员审核体验：审核列表里区分「批注」与「自由评论」，批注展示锚定的原文摘录（`anchor_selected_text`），让管理员快速判断上下文。复用现有 `admin-comments` 接口（`/admin/comments/*`），主要改动在 DTO 返回 anchor + 前端审核 UI。

端到端行为：
- `GET /admin/comments/pending` 和 `GET /admin/comments` 的 DTO 返回 `anchor`（nullable）。
- 前端审核列表：批注行展示 anchor 的 `selected_text` 作为引言（截断 + 省略号），自由评论行不展示。
- 列表加筛选 tab：「全部 / 批注 / 自由评论」（基于 anchor 是否为空过滤）。
- 批量审核通过 / 标记垃圾 / 删除沿用现有 `BatchUpdateStatus` 接口，不变。
- 待审核数量角标沿用现有 `CountPending`，不变。

## Acceptance criteria

- [ ] 后端 admin 评论 DTO（`AdminComment` 或扩展 `CommentDTO`）返回 `anchor` 字段（含 `selected_text`、`block_id` 等）。
- [ ] 前端 `features/admin-comments/` 审核列表：
  - 批注行展示 `anchor.selected_text` 引言（截断 ~80 字 + 省略号）。
  - 自由评论行不展示引言区。
  - 筛选 tab：「全部 / 批注 / 自由评论」（前端按 anchor 是否为空过滤，或后端加 `?type=annotation|free` query 参数——本 issue 选前端过滤即可，YAGNI）。
- [ ] 批量操作（approve / spam / delete）沿用现有接口，不变。
- [ ] 待审核角标沿用 `CountPending`，不变。
- [ ] 视觉：批注引言区用 neon-cyan 左色条 + font-mono（与正文高亮 severity 同构），让管理员一眼识别「这是批注」。
- [ ] 测试：
  - 后端 admin handler 测试：DTO 含 anchor 字段（接 Issue-0001 的 handler 测试 seam）。
  - 前端审核列表：mock 含 anchor 的评论 → 引言区渲染；不含 anchor → 不渲染（RTL）。
