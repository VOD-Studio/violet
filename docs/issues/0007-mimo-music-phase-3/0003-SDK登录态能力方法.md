# Issue-0003：SDK 登录态能力方法（auth / recommend / fm）

## Parent

PRD：`../../prd/0007-mimo-music-phase-3.md`（user story 3；Implementation Decisions - SDK 包）

## What to build

在 0001 的 client 骨架上填充登录态相关能力方法，覆盖 mimo-music 的鉴权与个性化端点：验证码下发、手机登录、二维码登录与轮询、登录状态查询、登出、每日推荐、私人 FM。按能力分文件（`auth.go` / `recommend.go` / `fm.go`）。

**登录态模型（基于实际架构修正）**：mimo-music 采用服务端 session 管理——登录成功后 cookie 由 mimo-music 自己持有并存入 SessionStore（Redis），HTTP 响应不返回 cookie。因此：
- 登录类方法（`LoginByCellphone` / `LoginByQrcode` / `CheckQrcode`）触发 mimo-music 自身登录，调用方拿不到也无需管理 cookie。
- recommend/fm 端点的 cookie 由 mimo-music service 内部用 SessionRotator 从 store 轮换获取，SDK 调用时无需传入 cookie。
- 仅 `LoginStatus` / `Logout` 需要 cookie（查询/登出特定 session），经 mimo-music 约定的 `X-Cookie` header 传递。

二维码登录的轮询语义（800 失效 / 801 等待 / 802 扫描 / 803 确认）在返回 DTO 里体现，SDK 不在内部自动轮询。

## Acceptance criteria

- [x] `auth.go`：`SendCaptcha` / `LoginByCellphone` / `LoginByQrcode` / `CheckQrcode` / `LoginStatus` / `Logout`
- [x] `recommend.go`：`GetDailyRecommend(ctx)`，cookie 由服务端 SessionStore 轮换，调用方无需传入
- [x] `fm.go`：`GetPersonalFM(ctx)`，同上
- [x] 登录类方法触发服务端登录，HTTP 不返回 cookie（服务端自管 session）
- [x] `LoginStatus` / `Logout` 的 cookie 经 `X-Cookie` header 传递（mimo-music 约定）
- [x] httptest.Server 单测覆盖登录成功、各二维码轮询状态、X-Cookie 传递、服务端返回未授权
- [x] 所有导出方法有 godoc 注释
