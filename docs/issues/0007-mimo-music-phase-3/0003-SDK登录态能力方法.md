# Issue-0003：SDK 登录态能力方法（auth / recommend / fm）

## Parent

PRD：`../../prd/0007-mimo-music-phase-3.md`（user story 3；Implementation Decisions - SDK 包）

## What to build

在 0001 的 client 骨架上填充登录态相关能力方法，覆盖 mimo-music 的鉴权与个性化端点：验证码下发、手机登录、二维码登录与轮询、登录状态查询、登出、每日推荐、私人 FM。按能力分文件（`auth.go` / `recommend.go` / `fm.go`）。

登录态方法的关键差异是 Cookie 传递：SDK 需支持调用方传入登录后拿到的 Cookie（作为请求头或 client 选项），用于 `/auth/status`、`/recommend/daily`、`/fm` 等需登录端点。登录类方法（`LoginByCellphone` / `LoginByQrcode` / `CheckQrcode`）的响应携带 `Set-Cookie`，SDK 需把会话凭证暴露给调用方，由调用方决定如何持久化与后续注入。二维码登录的轮询语义（pending / scanned / confirmed / expired）在返回 DTO 里体现，不在 SDK 内部自动轮询。

## Acceptance criteria

- [ ] `auth.go`：`SendCaptcha` / `LoginByCellphone` / `LoginByQrcode` / `CheckQrcode` / `LoginStatus` / `Logout`
- [ ] `recommend.go`：`GetDailyRecommend(ctx, cookie)` → `model.RecommendResult`
- [ ] `fm.go`：`GetPersonalFM(ctx, cookie)` → `model.FMResult`
- [ ] 登录类方法暴露会话凭证（Cookie），调用方可取出持久化并在后续请求注入
- [ ] 需登录端点支持调用方注入 Cookie，未注入时返回明确的未授权 error（走 0001 错误映射）
- [ ] httptest.Server 单测覆盖登录成功、Cookie 注入、未授权、二维码各轮询状态
- [ ] 所有导出方法有 godoc 注释
