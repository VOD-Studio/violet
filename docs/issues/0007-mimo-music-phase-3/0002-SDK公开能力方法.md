# Issue-0002：SDK 公开能力方法（playlist / song / search / album / artist）

## Parent

PRD：`../../prd/0007-mimo-music-phase-3.md`（user story 3、9；Implementation Decisions - SDK 包）

## What to build

在 0001 的 client 骨架上填充无需登录态的公开能力方法，覆盖 mimo-music 五类公开端点：歌单详情、歌曲详情/播放 URL/歌词、搜索、专辑详情、歌手信息。按能力分文件（`playlist.go` / `song.go` / `search.go` / `album.go` / `artist.go`），每个方法对应一个 HTTP 端点，返回 `model` 包的 DTO（与 HTTP 响应结构一致，调用方无需维护两份 DTO）。

方法签名一例：`func (c *Client) GetPlaylist(ctx context.Context, id string) (model.PlaylistResult, error)`。入参用原生类型，出参用 model DTO，error 走 0001 建好的错误映射。URL 拼装、query 参数、JSON 反序列化都在 client 内部完成，调用方零 HTTP 知识。

## Acceptance criteria

- [ ] `playlist.go`：`GetPlaylist(ctx, id)` → `model.PlaylistResult`
- [ ] `song.go`：`GetSongDetail(ctx, id)` / `GetSongURL(ctx, id)` / `GetLyric(ctx, id)` → 对应 model DTO
- [ ] `search.go`：`Search(ctx, keyword, opts)` → `model.SearchResult`（opts 含分页参数）
- [ ] `album.go`：`GetAlbum(ctx, id)` → `model.AlbumResult`
- [ ] `artist.go`：`GetArtist(ctx, id)` → `model.ArtistResult`
- [ ] httptest.Server 单测覆盖每个方法的成功路径与至少一个错误码路径
- [ ] 返回类型与 mimo-music HTTP 响应结构一致，无额外 DTO 转换层
- [ ] 所有导出方法有 godoc 注释

## Blocked by

- Issue-0001（SDK 骨架与错误映射）。client 构造与错误映射就绪后才能挂方法。
