# Issue-0004：限流熔断装饰器

## Parent

PRD：`../../prd/0006-mimo-music-phase-2.md`（user stories 5-6；Implementation Decisions - 限流熔断装饰器）

## What to build

`provider/decorator.go` 用装饰器模式包装 provider 实现，叠加两层：重试（指数退避，最多 3 次）和熔断（连续 5 次失败后短路 30 秒）。装饰器对外仍实现 Provider 接口，业务代码无感知。熔断状态切换（open / half-open / closed）记日志并更新 Prometheus 指标。这是防雪崩的关键——网易云限流或抖动时，自动退避 + 短路，避免把上游打挂或被反向封 IP。

## Acceptance criteria

- [ ] `provider/decorator.go` 实现重试装饰器：指数退避（如 200ms / 400ms / 800ms），最多 3 次
- [ ] `provider/decorator.go` 实现熔断装饰器：连续 5 次失败后 open，30 秒后 half-open 探测，成功则 closed
- [ ] 装饰器实现 Provider 接口，可任意叠加包装现有 netease provider
- [ ] 熔断状态切换记日志（Warn）+ 更新 Prometheus 指标
- [ ] 重试只针对可重试错误（网络错误 / 限流），不重试确定性错误（如 404）
- [ ] 装饰器测试：mock 上游连续失败 → 验证重试次数和退避；连续失败达阈值 → 验证短路（快速返回错误）
- [ ] 不侵入现有 provider 实现（netease provider 代码无改动）
- [ ] 所有导出符号有 godoc 注释
