# Issue-0009：歌单解析端到端

## Parent

PRD：`../../prd/0005-mimo-music-phase-1.md`（user stories 7-8）

## What to build

实现歌单详情解析的完整垂直切片：provider 拉取网易云歌单（含全量歌曲列表）→ service 缓存编排 → handler 暴露 HTTP 端点 → OpenAPI 文档。

这是博客播放器的核心功能——获取一个歌单的所有歌曲。必须真正拉取全量歌曲列表（不是桩函数），解决 mimo-blog 现有 FetchPlaylist 只返回单曲的问题。

登录态由 service 自动从 store 取 Cookie 注入 provider（匿名也可拿公开歌单，但 VIP 内容需登录）。

## Acceptance criteria

- [ ] `mimo-music/provider/netease/playlist.go`：Playlist 能力实现
  - Detail(ctx, playlistID) → model.Playlist（含全量歌曲列表）
  - 分页拉取：歌单歌曲超过限制时自动翻页，返回完整列表
- [ ] `mimo-music/service/playlist.go`：歌单编排
  - Get(ctx, playlistID) → 先查缓存 → 未命中调 provider → 写缓存（TTL 24h）
  - 从 store 取 Cookie 注入 provider（登录态可选）
- [ ] `mimo-music/cache/redis/cache.go`：Cache 的 Redis 实现（复用 internal/infra/redis 连接）
- [ ] `mimo-music/internal/server/handler/playlist.go`：`GET /api/v1/playlists/:id` 端点
- [ ] `mimo-music/openapi/paths/playlist.go`：歌单端点 path 定义
- [ ] service 层测试（mock provider + mock cache）：
  - 缓存命中时直接返回，不调 provider
  - 缓存未命中时调 provider，结果写入缓存
  - provider 返回 ErrRateLimited 时 service 的降级行为
- [ ] 手动验证：用一个真实网易云歌单 ID，返回完整歌曲列表（需联网）
- [ ] 日志含 platform / cache_hit / upstream_latency_ms 字段
- [ ] 所有导出符号有 godoc 注释
