# Issue-0006：登录能力（provider auth + store + service）

## Parent

PRD：`../../prd/0005-mimo-music-phase-1.md`（user stories 1-5）

## What to build

实现网易云登录全流程：手机号 + 验证码登录、二维码登录、发送验证码、查询登录态、登出。这是博客播放器能拿到 VIP 歌曲 URL 的前提——匿名只能拿试听片段。

登录成功后 Cookie 存入 SessionStore（Redis），按 user_id 索引。service 层编排：调 provider 发登录请求 → 拿到 Cookie → 存入 SessionStore。

provider/netease/auth.go 用 client.go + crypto.go 发送登录请求到网易云端点。SessionStore 实现并发安全（分布式锁防 Cookie 竞态）。

## Acceptance criteria

- [ ] `mimo-music/provider/netease/auth.go`：实现 Auth 能力接口
  - SendCaptcha(ctx, phone) —— 发送验证码
  - LoginByCellphone(ctx, phone, captcha) —— 手机号登录，返回 Session
  - LoginByQrcode(ctx) —— 获取二维码（返回 qrimg + key）
  - CheckQrcode(ctx, key) —— 轮询二维码登录状态
  - LoginStatus(ctx, cookie) —— 查询登录态
  - Logout(ctx, cookie) —— 登出
- [ ] `mimo-music/store/redis/session_store.go`：SessionStore 的 Redis 实现
  - Get(ctx, userID) → Cookie
  - Save(ctx, userID, cookie, expireAt)
  - Delete(ctx, userID)
  - 并发安全（分布式锁或原子操作）
- [ ] `mimo-music/cache/noop.go`：Cache 空实现（SDK 模式用）
- [ ] `mimo-music/service/auth.go`：登录编排
  - SendCaptcha → 调 provider
  - LoginByCellphone → 调 provider → 存 Cookie 到 store
  - LoginByQrcode / CheckQrcode → 调 provider
  - LoginStatus → 从 store 取 Cookie → 调 provider 验证
  - Logout → 调 provider 登出 + 删 store
- [ ] service 层测试（mock provider + mock store）：
  - 登录成功后 Cookie 存入 store
  - 登录态查询时从 store 取 Cookie
  - 登出后 store 中 Cookie 删除
  - provider 返回错误时 service 正确传递
- [ ] 日志脱敏：手机号和 Cookie 不明文出现在日志（依赖 Issue-0002 的 redact handler）
- [ ] 所有导出符号有 godoc 注释
