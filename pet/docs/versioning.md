# 规则版本与配置变更（R-04）

#520 的评审输出。目标：升级规则、修改配置或变更存档格式后，既有个体不会变脸，也不会因此突然死亡；拒绝不支持的版本而不是猜测。**已实现**与**策略（待服务实现）**分开标注。

## 两类版本

| 版本 | 含义 | 现状 |
|---|---|---|
| `rules_version` | 出生派生与结算规则的整体版本，整数 | **已实现**：`Pet.rules_version` 与证书的 `context.rules_version`；当前只有 1 |
| 存档格式 | `Pet` 的 JSON 形态 | **已实现**：新增字段用 `serde(default)` 兼容旧存档（`rules_version` 缺省为 1，余数字段缺省为 0），有测试 |

## 出生派生：永久冻结

- 每个 `rules_version` 的出生派生永久保留。提升版本等于新增一套派生，旧个体与旧证书继续用旧派生核验与呈现。
- **16 组黄金出生向量**（`scenario/golden-births.json`）锁定 v1 的结果，测试 `golden_births_never_change` 在任何派生改动时失败（已用变异检查确认）。修改派生必须提升版本并保留旧派生，**不得重新生成向量让测试通过**。
- 证书验证按证书里的 `rules_version` 选择派生；当前实现不支持的版本返回 `unsupported_rules`（已实现）。

## 结算规则：显式迁移，不猜测

- `act` 只接受当前实现支持的 `rules_version`，否则返回 `unsupported_rules`，不结算、不改状态（已实现，有测试）。
- 升级结算规则时，由**服务**在加载个体时执行显式的 `migrate(pet, from, to)`，迁移后持久化；客户端不迁移。迁移须满足不变量：
  1. 不使阶段恶化（健康不变为生病，存活不变为死亡）；
  2. 迁移发生在一个「离开」边界上，即把迁移前后的间隔按离开处理，不会越过死亡线；
  3. 出生身份、基因、稀有度与物种不变。
- 这套迁移函数尚未实现（只有 v1），在第一次提升版本的 PR 中随新规则一起提交，并附迁移不变量测试。

## 配置变更（策略，待 #525 与 #526 实现）

| 类别 | 例子 | 对在世个体的生效方式 |
|---|---|---|
| 出生类 | 五档权重 | 只影响之后的新出生；已出生个体不变 |
| 节奏类 | 衰减速度、预警与生病线 | 自变更时刻起生效，不回溯。服务保存配置纪元；第一次结算若跨越变更，整个间隔按「离开」处理，因此变更本身不可能让宠物死亡 |
| 寿命类 | 自然寿命开关与物种差异 | 开启只对开启后出生的个体生效。若接入方选择应用到在世个体，须有不少于 30 天的公告期，年龄自生效时刻起算，且不得让在世个体当场死亡。关闭立即对所有个体生效 |

自然寿命与「离开」的关系：自然年龄只在被观察的时间里累积，离开期间不推进，与病程一致，保证回归不会遇到老死。

## 拒绝行为

| 场景 | 行为 |
|---|---|
| 个体的 `rules_version` 不被支持 | `act` 返回 `unsupported_rules`，状态不变 |
| 证书的 `rules_version` 不被支持 | 验证结果 `unsupported_rules` |
| 存档缺少新字段 | 使用默认值，不报错 |
| 存档含未知字段 | 当前被忽略（serde 默认）；是否改为拒绝在 #525 固化存档格式时决定 |

## 纪念的可读性

死亡个体与纪念记录的读取是只读投影，不需要结算，因此不依赖当前实现支持其 `rules_version`：即使规则已升级到无法结算旧版本，纪念与出生核验仍可读（待服务实现时用测试固化）。

## 对应验收

AC-19 的三项：旧出生凭据仍可验证（黄金向量与证书验证）、历史形态仍可解释（派生冻结）、纪念可读（只读投影，待实现）。
